【CTFHub】Web-SSRF DNS重绑定 Bypass Writeup

操作者：何芊宏 | 操作日期：2026.9.26 | 分类：CTF | 标签：CTFHub, Web, SSRF, DNS重绑定, 公网服务利用

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - SSRF / DNS重绑定 Bypass
  • 题目名称：DNS重绑定 Bypass
  • 环境：浏览器直接访问。
  • 目标：利用 DNS 重绑定技术，绕过服务器对内网 IP 的检测，成功访问 127.0.0.1/flag.php。

2. 解题思路与知识点

通俗理解：什么是 DNS 重绑定（DNS Rebinding）？

这道题的核心是利用了“时间差”和“解析差异”。我们可以把攻击过程拆成两个角色：

  • 后端的安全检查（门卫）：收到我们传入的域名时，会进行一次 DNS 解析。如果解析出的 IP 是内网地址（如 127.0.0.1），就直接拦截。
  • 底层的请求库（翻译官，如 cURL）：在真正发起请求时，会进行第二次 DNS 解析，然后访问解析出的 IP。

利用公开的 DNS 重绑定服务（如 rbndr.us），可以构造一个域名，让它在第一次解析时返回公网 IP（骗过门卫），在第二次解析时返回内网 IP（实际攻击目标）。由于两次解析之间存在时间差，且 cURL 会默认跟随解析结果，导致安全校验形同虚设。

Payload 构造与原理：

本关使用了公开服务 rbndr.us。它的格式是 http://[IP1十六进制].[IP2十六进制].rbndr.us/。该服务会在这两个 IP 之间随机切换解析结果。

  • 7f000001：127.0.0.1 的十六进制。
  • 7f000002：127.0.0.2 的十六进制（在 Linux 中同样是本机回环地址）。

我们通过多次刷新请求，利用其随机性，让后端的“第一次解析”恰好返回一个能够绕过黑名单检测的 IP，而“第二次解析”返回真正的 127.0.0.1，从而成功请求到内网文件。

3. 详细步骤

第一步：探测拦截规则

操作： 浏览器直接访问 ?url=http://127.0.0.1/flag.php。

回显结果：页面提示 hacker! Ban Intranet IP。

获得信息：确认后端对“127”等内网 IP 字符串进行了黑名单校验。

第二步：构造 DNS 重绑定 Payload 并发起攻击

Payload： ?url=http://7f000001.7f000002.rbndr.us/flag.php

执行目的：使用 rbndr.us 服务，让域名在两次解析中返回不同的 IP，从而绕过黑名单。

回显结果：经过几次刷新后，页面成功返回 ctfhub{27002719be1cace3b343cd9f}。

获得信息：成功利用 DNS 重绑定绕过了内网 IP 检测，获取 Flag。

4. 踩坑记录与复盘

  • 坑1：使用 127.0.0.1 直接被拦截。 后端严格匹配了“127”字符串，直接请求内网 IP 被阻断。
  • 坑2：公共重绑定服务存在概率性。 使用 rbndr.us 时，每次请求解析出的 IP 是随机的。如果恰好返回了内网 IP，就会被拦截。解决方案是多次刷新页面，直到某次解析恰好返回了能绕过检测的 IP，同时第二次解析返回了 127.0.0.1。
  • 坑3：诱饵 IP 的选择。 最初使用了 192.168.0.1 作为诱饵，但可能被后端识别为内网网段。后换用 127.0.0.2（十六进制 7f000002）作为诱饵。由于 Linux 系统中 127.0.0.2 同样指向本机，但字符串形式上不含 127.0.0.1，成功绕过了部分过滤逻辑。

5. 知识总结

  • DNS 重绑定攻击的核心： 利用 DNS 解析的随机性和时间差，让安全校验和实际请求解析出不同的 IP，从而绕过基于 IP 的访问控制。
  • 防御建议： 开发者在防御 SSRF 时，不能依赖一次 DNS 解析的结果。应当在同一时间解析并校验 IP，或者直接禁用不必要的协议，并对目标 IP 进行严格的网段限制（禁止访问内网网段）。
