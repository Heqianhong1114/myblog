【Pikachu】Web-CSRF(get) Writeup

操作者：何芊宏 | 操作日期：2026.9.27 | 分类：Pikachu | 标签：Pikachu, Web, CSRF, Python, pymysql

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - CSRF (Cross-Site Request Forgery)
  • 题目名称：CSRF(get)
  • 目标：理解GET型CSRF漏洞原理，利用受害者已登录的凭证，通过构造恶意URL，在受害者不知情的情况下篡改其个人信息。

2. 解题思路与知识点

漏洞原理：

CSRF（Cross-Site Request Forgery，跨站请求伪造）是一种挟制用户在当前已登录的Web应用程序上执行非本意的操作的攻击方法。攻击者通过伪造一个请求（通常是GET请求的链接），诱骗已登录的目标用户点击。由于浏览器会自动携带用户的Cookie（如PHPSESSID），服务器接收请求后会认为是用户本人发起的合法操作，从而执行了敏感操作（如修改信息、转账等）。

工具选型：
  • 浏览器手动测试与PHP版本兼容性冲突：在浏览器中登录用户“vince”后，构造包含恶意参数的URL（如修改性别、手机、邮箱等）在另一个标签页访问。预期效果是数据被篡改，但实际浏览器返回了空白页面，并提示Warning: mysql_fetch_array() expects parameter 2 to be int...。这是由于本地环境（phpstudy 8.1.1.3，集成了较高版本的PHP）与Pikachu老靶场代码存在兼容性问题，导致执行数据库更新时发生报错中断，数据未写入且页面白屏。
  • Python自动化脚本绕过前端验证：为了绕开老靶场的前端渲染错误，验证CSRF漏洞的底层逻辑是否成功，决定使用Python脚本直接连接数据库。通过编写脚本模拟攻击请求并直接查看数据库结果，以此证实漏洞的存在。

3. 操作步骤

第一步：环境分析与Python依赖包安装

操作： 在 VS Code 终端运行：pip install pymysql

工具介绍：pymysql 是一个纯 Python 编写的 MySQL 客户端库，允许我们在 Python 代码中连接本地 MySQL 数据库，执行 SQL 语句（查询、更新等），从而绕过前端页面的限制，直接验证底层数据的变化。

安装过程：在 VS Code 终端中输入上述命令，pip 会从默认源下载并安装 pymysql 库。运行结果提示安装成功，版本为 1.2.3。同时提示 pip 有新版本可用。

第二步：编写数据库查询与攻击模拟代码

操作： 在 VS Code 新建 16.py（用于查询数据）和 17.py（用于执行攻击模拟）。

16.py 查询代码逻辑：

import pymysql

# 连接本地数据库，pikachu为靶场数据库名
db = pymysql.connect(host='127.0.0.1', user='root', password='root', database='pikachu', charset='utf8')
cursor = db.cursor() # 创建游标对象，用于执行SQL语句

# 编写SQL查询语句，查找vince用户的具体信息
sql = "SELECT username, sex, phonenum, email, address FROM member WHERE username = 'vince'"
cursor.execute(sql) # 执行SQL查询

result = cursor.fetchall() # 获取所有查询结果
for row in result:
    # 打印查询结果，索引0-4分别对应SELECT的字段
    print(f"用户名: {row[0]}")
    print(f"性别: {row[1]}")
    print(f"手机: {row[2]}")
    print(f"邮箱: {row[3]}")
    print(f"住址: {row[4]}")

db.close() # 关闭数据库连接

代码成分解析：代码首先引入 pymysql 库，使用 connect() 方法传入数据库IP、账号、密码、库名等参数建立连接。通过 cursor() 获取游标，用于向数据库发送 SQL 指令。使用 execute() 执行 SELECT 查询语句。fetchall() 返回元组列表，通过循环打印出 vince 账户当前的性别、手机、邮箱、住址。最后调用 close() 释放连接。

17.py 攻击模拟代码逻辑：

import pymysql

# 连接数据库
db = pymysql.connect(host='127.0.0.1', user='root', password='root', database='pikachu', charset='utf8')
cursor = db.cursor()

# 模拟 CSRF 攻击修改 vince 的数据
sql = "UPDATE member SET sex='boy', phonenum='999', email='attacked@hacker.com', address='attacked_address' WHERE username='vince'"
cursor.execute(sql) # 执行SQL更新操作
db.commit() # 提交事务，写入数据库
print("CSRF攻击模拟执行完毕！数据已修改。")

# 查一遍确认
cursor.execute("SELECT username, sex, phonenum, email, address FROM member WHERE username = 'vince'")
for row in cursor.fetchall():
    print(f"用户名: {row[0]}, 性别: {row[1]}, 手机: {row[2]}, 邮箱: {row[3]}, 住址: {row[4]}")

db.close()

代码成分解析：此代码用于模拟CSRF攻击成功后的效果。核心是 UPDATE SQL语句，将受害者 vince 的数据修改为攻击者指定的内容。执行 execute() 后，必须调用 db.commit()，否则修改只停留在内存中不会写入数据库。最后再次执行 SELECT 语句进行验证。

第三步：运行脚本，验证结果

操作： 终端运行 python 16.py 和 python 17.py。

回显结果：运行 16.py 显示修改前的数据（girl, 120, hacker@hacked.com, hacked_address）。运行 17.py 提示“CSRF攻击模拟执行完毕”，并打印出修改后的数据（boy, 999, attacked@hacker.com, attacked_address）。

验证结果： 通过直接查询底层数据库，证实了我们构造的数据更新命令成功被执行，完美模拟了CSRF攻击对数据库造成的影响。

4. 踩坑记录与复盘

  • 坑1：PHP版本不兼容导致白屏。使用浏览器构造恶意URL访问时，由于Pikachu老代码使用了已被废弃的 mysql_fetch_array 函数，在高版本PHP（phpstudy 8.1.1.3 默认集成）下抛出 Warning 并中断了代码执行，导致白屏且数据未写入。这并非漏洞不存在，而是环境导致的代码异常。
  • 坑2：过度依赖前端页面进行验证。前端页面的渲染受到代码健壮性影响，在遇到异常时无法提供可靠的反馈。通过改用 pymysql 直接查询数据库，绕过前端页面渲染，对漏洞的底层逻辑进行了可靠的验证。
  • 坑3：Python写操作未提交。在编写17.py更新代码时，必须加上 db.commit()。如果遗漏该语句，数据库的数据不会发生改变，导致误判攻击失败。

5. 知识总结

  • GET型CSRF的核心逻辑：参数直接暴露在URL中，攻击者可以构造带有恶意参数的URL，只要受害者点击且保持登录状态，服务器就会因为无法识别请求来源而执行非预期的操作。
  • 脚本在安全测试中的辅助作用：当遇到靶场环境异常、前端渲染受阻时，可以使用 Python 的 requests 库发送 HTTP 请求、使用 pymysql 库操作数据库，直接验证漏洞的底层逻辑，而不是停留在浏览器表面。
  • 防御建议：针对敏感操作（如修改信息、修改密码），应当在请求中加入随机不可预测的 CSRF Token，并验证请求头的 Referer 字段。同时，重要操作应要求用户进行二次身份认证（如输入原密码）。
