【CTFHub】Web-SSRF内网访问 Writeup

操作者：何芊宏 | 操作日期：2026.9.25 | 分类：CTF | 标签：CTFHub, Web, SSRF, 内网探测

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - SSRF / 内网访问
  • 题目名称：内网访问
  • 环境：通过 BP 自带浏览器访问靶场环境（因为懒得给普通浏览器装代理，直接用 BP 自带浏览器最省事）。
  • 目标：利用服务端请求伪造漏洞，让靶场服务器去请求它自己本地的 flag.php，从而绕过外网无法直接访问内网的限制。

2. 解题思路与知识点

本关核心考点：SSRF（服务端请求伪造）的基础原理。服务器没有对用户传入的 URL 进行严格过滤，导致我们可以“借服务器的刀，杀内网的鱼”。

3. 步骤

第一步：认识漏洞点与空白页的启发

操作： 打开靶场环境，观察地址栏。

执行目的：寻找真正的注入点位置。

回显结果：页面一片空白，地址栏显示 http://challenge-xxx...:10800/?url=_。

获得信息：确认漏洞参数是 URL 后面的 url。页面空白是因为服务器不知道要去请求哪里，我们需要传入一个完整的 URL。

第二步：构造内网请求（借刀杀人）

Payload： ?url=http://127.0.0.1/flag.php

执行目的：让服务器去请求本机（127.0.0.1）的 flag.php 文件。

操作过程：在浏览器地址栏的 ?url= 后面输入 payload。这里我因为手误输入成了 ?url=?url=http://...，虽然侥幸执行成功，但这是错误的格式。

回显结果：页面直接回显 ctfhub{c76ee823cb70ffed772265e2}。

获得信息：成功利用SSRF读取到内网敏感文件，通关。

4. 踩坑记录与复盘

  • 易慌点：没加参数导致空白。 刚打开靶场页面是一片空白，因为地址栏只有 ?url=_，服务器不知道该请求哪里。必须显式地传入完整的URL。
  • 坑2：手误导致参数拼接重复。 我在实测时写了 ?url=?url=http://...。虽然本次后端过滤宽松放行了，但如果在严格解析 URL 的后端环境中，多写的 ?url= 会被当成目标URL的一部分而导致请求失败。实战中不能依赖这种侥幸。

5. 知识总结

  • SSRF的本质：服务器端没有对用户输入的URL做校验，导致可以访问外网无法访问的内网系统（127.0.0.1，192.168网段等）。
  • 未来的进阶：本关只是最简单的一关。后续还有“伪协议读取文件（file://）”、“POST请求构造（gopher://）”、“数字IP绕过”等，核心都是围绕“如何构造出服务器能解析的URL”来展开。
