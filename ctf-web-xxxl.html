【微方法论】Web 信息泄露漏洞基础利用手法小结（基于CTFHub）

操作者：何芊宏 | 操作日期：2026.9.20 | 分类：Web安全 | 标签：信息泄露, 微方法论, CTFHub, 版本控制, 工具

1. 简介与核心逻辑

信息泄露漏洞的本质，是由于服务器配置不当、开发人员疏忽或运维安全意识薄弱，导致服务器上的敏感文件、源代码、配置信息或版本控制数据被未授权的攻击者直接获取。

在 CTF 及真实渗透测试中，这类漏洞通常不会直接导致服务器被接管，但泄露的数据往往是后续渗透（如 SQL 注入、文件上传、RCE）的敲门砖。其核心攻击逻辑只有一个：收集信息，顺藤摸瓜，找到敏感文件或直接获取 Flag。

2. 常见泄露类型与利用手法汇总

结合 CTFHub 的实战经历，我将信息泄露分为三大类，其利用手法如下：

第一类：直接暴露类

  • 目录遍历（Directory Listing）：服务器开启了目录索引功能。利用手法是直接通过浏览器手工点击，或者构造 ../ 路径穿越。注意，Python 的 requests 库可能会自动解析并抵消 ../，此时手工点击浏览器反而最快。
  • PHPINFO：开发人员未清理测试文件。页面包含大量环境变量、配置信息。利用手法是使用 Ctrl+F 快速搜索 flag 或 ctfhub 等关键字，避免肉眼硬看浪费时间。

第二类：静态文件泄露类

  • 备份文件下载：源码包被直接留在 Web 根目录。利用手法是使用字典配合 Python 脚本（requests 库）进行目录爆破。常见后缀 .zip、.tar.gz、.bak，常见前缀 web、www、backup。下载后进行源码审计（优先查看文件名带有 flag、config 的文件）。

第三类：版本控制泄露类（Git / SVN / HG）

这是信息泄露中最容易被坑、也最考验底层理解的一类。核心在于开发人员将 .git、.svn、.hg 隐藏目录连同代码一起部署到了线上。

  • Git 泄露：
    • Log：Flag 曾提交后被删。git log 查看，git reset --hard HEAD^ 回退版本。
    • Stash：Flag 被藏进草稿箱。git stash list 查看，git stash pop 弹出。
    • Index：Flag 被 git add 进暂存区未提交，工作区被删。git status 查看，git checkout-index -a 恢复。
  • SVN 泄露：下载 .svn/wc.db（SQLite数据库）。查询 NODES 表找文件名，如果被删则去 PRISTINE 表找哈希，拼接出 /.svn/pristine/哈希前两位/剩余哈希.svn-base 路径访问。
  • HG 泄露（Mercurial）：下载 .hg/store/00manifest.i 等文件，利用 CyberChef 解压（Drop bytes 64 -> Zlib Inflate）获取真实文件名。

3. 常用工具获取与说明

本次信息泄露系列实战中，主要依赖以下工具。这些工具在 Windows 环境下均有较好的兼容性：

  • 基础运行环境：
    • Python 3.12.6：本次实战使用的版本。很多安全脚本（如 GitHack、目录爆破脚本）都基于 Python。
    • Git for Windows：官网 gitforwindows.org 下载。安装时在选择环境变量界面务必勾选 "Git from the command line and also from 3rd-party software"，这样才能在 VS Code 的终端里直接使用 git 命令。
  • Git 泄露工具：
    • GitHack：GitHub 仓库 https://github.com/lijiejie/GitHack，点击 Code 下载 ZIP 解压即可。适合快速获取当前版本源码，但会丢失历史记录。
    • GitHacker：通过命令行安装：pip install githacker。用于抓取包含完整历史记录的 Git 仓库，是做 Log、Stash、Index 题目的首选。
  • SVN 泄露工具：
    • DB Browser for SQLite：官网 https://sqlitebrowser.org/dl/，下载 "Standard installer for 64-bit Windows"。用于可视化查看 wc.db 数据库，直观查找文件名和哈希值。
  • HG 泄露工具：
    • dvcs-ripper：GitHub 仓库 https://github.com/kost/dvcs-ripper。里面包含 Perl 脚本，但在 Windows 原生环境下往往缺少 Perl 模块（如 LWP::UserAgent），不推荐新手折腾。
    • CyberChef：在线版 https://gchq.github.io/CyberChef/（也可下载本地 HTML 版本）。网络安全界的“瑞士军刀”，不用配置环境，直接在网页上拖拽 Drop bytes 64 和 Zlib Inflate 就能解压 HG 的文件，极其实用。
  • 编辑器与终端（其实应该不用多说）：
    • VS Code：整合了终端、文件管理和全局搜索，处理下载后的源码时效率极高。

4. 经验总结与避坑指南（核心）

核心法则：先试根目录！！！！！
一旦从任何泄露源（版本控制、备份文件、目录遍历、数据库等）获取到了真实文件名，第一反应必须是去网站根目录直接访问它（http://target/文件名）。
如果成功，直接拿 Flag；如果 404，再按照版本控制的逻辑去深入挖掘。不要一开始就被复杂的目录结构限制住思维。
  • 不要迷信自动化工具：不同系统的环境兼容性差异巨大（如 Windows 下的 Perl 无法直接运行 rip-hg.pl），且 WAF 可能会对特定路径进行拦截。工具报错或失效时，回归手工下载、拼接、解压是解决问题的关键。
  • 警惕 WAF 的 404 伪装：访问带有敏感词（如 flag）的 URL 时，服务器故意返回 404 而不是 403，这是一种常见的拦截干扰策略。此时应尝试 URL 编码绕过、参数污染等手段。
  • 不要被终端假死卡住：在 Git Bash 或 PowerShell 中运行 git log 等命令时，常会卡在带冒号 : 的界面。按 q 无效时，果断关掉当前终端重开，不要在界面上死磕。

5. 安全防御建议

  • 持续集成/持续部署（CI/CD）自动化：严格使用自动化部署流程，确保 .git、.svn、.hg 等版本控制目录绝不被部署到 Web 服务器。
  • Web 服务器配置加固：
    • 关闭目录索引功能（Nginx 中的 autoindex off;）。
    • 使用 location 规则拦截对隐藏目录的请求（如 location ~ /\.(git|svn|hg) { deny all; }）。
  • 及时清理环境：上线前彻底删除测试文件（如 phpinfo.php）、源码备份压缩包及敏感配置文件。
