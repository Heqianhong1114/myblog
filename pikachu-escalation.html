【Pikachu】Web-越权-水平越权(Horizontal Privilege Escalation) Writeup

操作者：何芊宏 | 操作日期：2026.9.29 | 分类：Pikachu | 标签：Pikachu, Web, 越权, 水平越权, 参数篡改

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - Over Permission (水平越权)
  • 题目名称：水平越权
  • 目标：利用后端未校验用户身份与请求参数匹配关系的缺陷，通过篡改 HTTP 请求中的用户标识参数，查看其他同等权限用户的敏感信息。

2. 解题思路与知识点

漏洞原理：

水平越权（Horizontal Privilege Escalation）是指攻击者尝试访问与自身权限相同的其他用户资源。产生的原因通常是后端代码在查询或修改数据时，**仅根据客户端提交的参数（如用户名、用户ID）来定位数据，而没有校验当前登录 Session 中记录的用户是否与该参数一致**。

水平越权与垂直越权的区别：
  • 水平越权：同级用户之间的越权访问（如用户 A 查看用户 B 的订单）。
  • 垂直越权：低权限用户越权访问高权限功能（如普通用户执行管理员操作）。

3. 操作步骤

第一步：获取测试账号并登录

操作： 点击页面右上角的“点一下提示”按钮，获取靶场预置的测试账号：lucy/123456、lili/123456、kobe/123456。

登录： 使用 lucy / 123456 登录系统。登录成功后，页面跳转至会员中心 op1_mem.php。

第二步：触发请求并分析参数

操作： 点击页面上的“点击查看个人信息”按钮。

回显特征： 页面成功显示 lucy 的个人信息。此时观察浏览器地址栏，URL 变为：

http://127.0.0.1/pikachu/vul/overpermission/op1/op1_mem.php?username=lucy&submit=点击查看个人信息

参数分析： 后端通过 GET 请求接收 username 参数，并根据该参数的值去数据库查询用户信息。这意味着该参数完全由客户端可控。

第三步：篡改参数实施水平越权

操作： 在地址栏中，将 username=lucy 修改为 username=lili。

构造 URL： http://127.0.0.1/pikachu/vul/overpermission/op1/op1_mem.php?username=lili&submit=点击查看个人信息

回显特征： 页面不需要重新登录，直接显示了用户 lili 的姓名、性别、手机号、住址和邮箱信息。水平越权漏洞利用成功。

代码组成详细解释：

  • username：后端用于接收目标用户名的参数名。
  • lili：攻击者传入的恶意参数值，后端会将其作为查询条件去数据库中检索，忽略了当前 Session 属于 lucy 这一事实。
  • submit=点击查看个人信息：表单提交按钮的标识，用于触发后端的信息查询逻辑。

第四步：源码推测

后端逻辑： 后端代码大概率如下：

$username = $_GET['username'];
$sql = "SELECT * FROM users WHERE username = '$username'";
$result = mysqli_query($conn, $sql);
// 直接输出查询结果，未验证当前登录用户是否为 $username

4. 踩坑记录与复盘

  • 坑1：手工修改 URL 导致参数名重复。 初次尝试水平越权时，将 URL 错误地修改为 ?username=username=lili&submit=...。由于参数值被拼接成了字面量 username=lili，后端查询了一个不存在的用户，导致页面回显空白。
    解决办法： 仔细检查 URL 结构，删除多余的参数名，确保格式为 ?username=lili&submit=...，重新发送请求后成功显示目标用户信息。

5. 知识总结

  • 漏洞本质：水平越权的本质是“身份验证失效”。后端过度信任客户端提交的数据（如用户 ID、用户名），将其作为查询依据，而没有强制绑定服务端 Session 中的身份信息。
  • 防御措施：在服务端执行数据查询或修改操作时，不应信任客户端提交的用户标识参数。应该从当前登录的 Session 中获取用户身份（如 $_SESSION['user_id']），并以此为依据进行数据库查询。如果需要查询其他用户的信息，必须进行严格的权限判定。
  • 实战启发：遇到包含用户标识（如 username、user_id、order_id）的 URL 参数或 POST 数据时，应优先测试越权漏洞。建议结合 Burp Suite 进行抓包，通过修改参数值观察响应内容是否发生变化。
