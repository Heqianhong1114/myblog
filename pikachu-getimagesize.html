【Pikachu】Web-不安全的文件上传-getimagesize Writeup

操作者：何芊宏 | 操作日期：2026.9.28 | 分类：Pikachu | 标签：Pikachu, Web, 文件上传, getimagesize绕过, 图片马, 文件包含, 环境排查

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - Unsafe Fileupload (服务端内容检查)
  • 题目名称：getimagesize
  • 目标：利用后端调用 getimagesize() 检查文件内容的缺陷，通过构造“图片马”（在真实图片数据尾部追加 PHP 代码），绕过内容检测并上传。最终结合文件包含漏洞（LFI）执行代码。

2. 解题思路与知识点

漏洞原理：

这一关的后端代码使用了 PHP 内置的 getimagesize() 函数来检测上传文件是否为合法的图片。如果直接上传纯 PHP 文件或仅伪造 MIME 类型，该函数会读取不到图片头，返回 false 从而拦截。
解决方案是构造“图片马”：将 PHP 代码追加到真实图片的二进制数据尾部。这样文件保留了完整的图片文件头，能通过 getimagesize() 的检测。由于最终保存为 .jpg 无法直接执行，需要配合本地文件包含漏洞（LFI）来触发 PHP 解析。

3. 操作步骤

第一步：准备文件与编写 Python 脚本合成图片马

文件准备： 在本地桌面新建文件夹 muma，将准备好的真实图片 1.jpg 和 PHP 代码文件 shell.php 放入该文件夹中。

操作： 在 VS Code 中打开 muma 文件夹，新建脚本 make_image_mar.py，写入以下代码：

with open('1.jpg', 'rb') as img_file:
    img_data = img_file.read()

with open('shell.php', 'r') as php_file:
    php_data = php_file.read()

with open('shell_mar.php', 'wb') as out_file:
    out_file.write(img_data)
    out_file.write(php_data.encode())

print("图片马生成成功！")

代码组成详细解释：

  • open('1.jpg', 'rb')：以二进制模式读取原始图片，获取其完整字节流。
  • open('shell.php', 'r')：以文本模式读取 PHP 代码文件。
  • open('shell_mar.php', 'wb')：创建新文件，以二进制写入模式打开。
  • out_file.write(img_data)：先写入图片数据，保留合法的文件头。
  • out_file.write(php_data.encode())：接着写入 PHP 代码的字节流。

终端操作与运行：

在 VS Code 终端中，由于默认工作目录不在桌面，直接运行脚本会导致找不到文件的报错。需要先切换工作目录：

cd C:\Users\heqianhong\Desktop\muma
python make_image_mar.py

执行结果： 终端输出“图片马 shell_mar.php 生成成功！”。在 muma 文件夹内出现新生成的 shell_mar.php 文件。

第二步：使用 Burp 篡改上传请求

操作： 开启 Burp 拦截，在浏览器上传 muma 文件夹中的图片马，并在请求中修改以下内容：

  1. 文件名修改为：filename="shell_mar.jpg"（后端严格校验扩展名，不能用 .php）。
  2. MIME 类型修改为：Content-Type: image/jpeg。
  3. 保留底部的图片二进制数据（不能删，否则无法通过 getimagesize 检测）。
  4. 确保请求体尾部包含 submit 字段及结束分隔符。

回显特征： 页面提示“上传成功”，并返回重命名后的路径：uploads/2026/09/28/1891656aba6fabf068908688958.jpg。证明绕过内容检测成功。

第三步：利用文件包含（LFI）验证漏洞链

操作 1（盲目猜测路径）： 尝试在 LFI 关卡包含该图片马，URL 传参 filename=../../unsafeupload/...。

报错信息： Warning: include(include/../../unsafeupload/...): failed to open stream: No such file or directory...。

原因分析： 后端源码拼接了硬编码前缀 include/，路径计算出现偏差。

操作 2（使用 Python 确认文件物理位置）：

为了排查文件是否真实存在于服务器磁盘上，在桌面新建 search_file.py 并运行：

import os
search_root = r"D:\phpstudy_pro\WWW"
target_filename = "1891656aba6fabf068908688958.jpg"
for root, dirs, files in os.walk(search_root):
    if target_filename in files:
        print(f"找到文件: {os.path.join(root, target_filename)}")
        break

执行结果： 脚本遍历全盘后未找到该文件。结合 PHP 报错，确认了一个重要事实：文件上传虽然回显成功，但实际物理文件并未落盘（可能是目录无写权限或被安全软件拦截）。这是靶场环境配置问题，并非攻击链路的技术错误。

操作 3（验证 LFI 逻辑本身）： 为了证明路径计算无误，包含一个已知存在的文件。

Payload： http://127.0.0.1/pikachu/vul/fileinclude/fi_local.php?filename=../../unsafedownload/down_nba.php&submit=提交

回显特征： 页面成功解析并输出了 NBA 球员的下载界面。这证明 include/../../ 的前缀抵消逻辑和相对路径计算是完全正确的。

4. 踩坑记录与复盘

  • 坑1：Python 脚本执行目录错误导致 FileNotFoundError。在 VS Code 中直接运行脚本时，终端工作目录默认在 VS Code 安装目录下，导致脚本找不到放在桌面 muma 文件夹中的 1.jpg 和 shell.php，报错 FileNotFoundError: [Errno 2] No such file or directory: '1.jpg'。
    解决办法： 在终端先使用 cd C:\Users\heqianhong\Desktop\muma 切换到脚本所在目录，再执行 python make_image_mar.py，成功生成图片马。
  • 坑2：后端扩展名与 MIME 双重校验。初次上传尝试直接传 shell_mar.php 被拦截，提示后缀名不符合。解决办法是将文件名修改为 shell_mar.jpg，保留 MIME 为 image/jpeg，成功绕过。
  • 坑3：文件包含路径硬编码干扰。后端 include() 函数拼接了 include/ 目录前缀。在构造 Payload 时，如果盲目猜测路径层级会导致报错。解决思路是根据 PHP 的报错信息反推源码结构，并利用 Python 脚本的 os.walk 确认文件的实际物理位置，从而计算出正确的相对路径。
  • 坑4：环境权限导致的“幽灵文件”。上传操作返回了成功并告知了路径，但使用 Python 遍历整个 Web 根目录均找不到该文件，导致最终文件包含失败（No such file or directory）。这在真实渗透测试中很常见，说明服务器返回的“上传成功”不代表文件真正落盘。面对这种情况，应使用已知存在的文件验证漏洞链的底层逻辑是否畅通，而非死磕某个不存在的文件。

5. 知识总结

  • 漏洞本质：不安全的文件上传通常是一系列校验绕过的组合。构造“图片马”绕过内容检测，并利用 LFI 执行图片中的代码，是经典的漏洞链利用方式。
  • 防御措施：服务端应校验文件真实内容（结合白名单），限制上传目录的脚本执行权限（如 Nginx 配置 location ~ \.php$ { return 403; }）。同时，应对上传失败的情况进行严格判断，不能轻易向客户端返回“成功”。
  • 实战启发：渗透测试中，环境复杂多变。不仅要懂得攻击技术，还要懂得利用 Python 等工具进行自动化环境探测（如文件搜索）、日志分析（如 PHP Warning 信息），从而精准定位问题所在。
