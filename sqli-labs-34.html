【SQLi-Labs】Less-34 POST型宽字节注入 Writeup

操作者：何芊宏 | 操作日期：2026.10.27 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, POST注入, 宽字节注入, Burp Suite

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-34 (POST - Bypass addslashes)
  • 提示：POST 登录框，后端使用 addslashes() 转义，数据库连接使用 GBK 编码。

2. 工具配置与操作环境

本关卡为 POST 请求，需拦截并修改 HTTP 请求体，继续使用 Burp Suite。

  • 浏览器代理：设置代理为 127.0.0.1:8080。
  • 操作模块：使用 Burp 的 Proxy (代理) 模块拦截请求，发送至 Repeater (重放器) 进行调试。

3. 核心原理：POST 环境下的宽字节注入

本关卡的核心防御机制是 addslashes()，它会在单引号 '（十六进制 0x27）前加上反斜杠 \（十六进制 0x5C）。正常输入会导致单引号被转义为 \'，无法闭合语句。

宽字节绕过机制：

  1. 由于数据库采用了 GBK 双字节编码，在底层解析时，会将两个连续的字节（范围符合 GBK 规则）组合成一个汉字。
  2. 在 uname 字段输入 %df'（十六进制 0xDF 0x27）。
  3. 后端转义后，字节流变为 0xDF 0x5C 0x27。
  4. GBK 解析器将高位字节 0xDF 和转义符 0x5C 组合成了一个合法的汉字（如“運”），从而将反斜杠“吃掉”，导致末尾的单引号 0x27 成功逃逸，闭合了原 SQL 语句。

4. 操作步骤与解析

第一步：抓包与探测

在登录页面随意输入账号密码，开启 Burp 拦截，点击登录。将拦截到的 POST 请求发送至 Repeater。

在请求体（Body）中，利用联合查询进行探测。因为登录框原查询语句为 SELECT username, password FROM users ...，固定为 2 列，所以 UNION SELECT 后面必须凑齐 2 列。

请求体 Payload：

uname=-1%df' union select 1,database()-- -&passwd=123&submit=Submit

回显现象：页面渲染出 Your Login name:1 和 Your Password:security。

解释与原理：-1%df' 成功闭合了原有的 username='$uname'。由于不存在 id 为 -1 的用户，前置查询结果为空。系统将第 1 列（数字 1）展示在 username 位置，第 2 列（database() 的结果）展示在 password 位置。

第二步：爆出表名

请求体 Payload：

uname=-1%df' union select 1,group_concat(table_name) from information_schema.tables where table_schema=database()-- -&passwd=123&submit=Submit

回显现象：Your Password:emails,referrers,uagents,users。

解释与原理：将 database() 替换为查询表名的子查询语句。使用 group_concat() 将多行表名合并为一行字符串，放在第 2 列输出。

第三步：脱库获取账号密码

请求体 Payload：

uname=-1%df' union select 1,group_concat(username,0x3a,password) from users-- -&passwd=123&submit=Submit

回显现象：Your Password:Dumb:Dumb,Angelina:I-kill-you,Dummy:p@ssword,admin:p@ssw0rd...。

解释与原理：直接查询 users 表，利用 group_concat 把用户名和密码以冒号（0x3a）拼接输出。虽然在登录框，但不需要正确的密码，利用 UNION 联合查询可以直接将数据库数据作为“密码”打印出来。

5. 踩坑记录与复盘

  • 原始字节传输：在 Burp 的 Raw 面板或浏览器地址栏中，必须直接写 %df 代表原始字节。若使用了工具自带的 URL 编码功能，% 会被二次编码为 %25，导致宽字节解析失败，注入失效。
  • 列数精准匹配：本关原查询固定返回 username 和 password 两列。如果 UNION SELECT 写入 3 列会直接报错，必须保持 2 列。
  • 注释符使用：在 POST 请求体中，-- (注意末尾需有空格或换行) 或 # 均可使用，用于注释掉后端 SQL 语句末尾的单引号及 LIMIT 限制。

6. 知识点总结

  • POST 宽字节注入：利用 POST 传参，结合 GBK 字符集双字节特性绕过 addslashes() 等转义函数。
  • 基于回显点的 UNION 注入：深刻理解联合查询必须保证前后字段数一致，且根据页面渲染逻辑，将 Payload 放置在能回显的正确列上。
