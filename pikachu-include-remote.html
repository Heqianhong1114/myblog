【Pikachu】Web-文件包含-远程文件包含(File Inclusion remote) Writeup

操作者：何芊宏 | 操作日期：2026.9.28 | 分类：Pikachu | 标签：Pikachu, Web, 文件包含, RFI, 远程包含

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - File Inclusion (远程文件包含)
  • 题目名称：File Inclusion(remote)
  • 目标：利用后端未严格过滤的文件包含函数（如 include()），通过构造指向外部恶意文件的 URL，让靶场服务器拉取并执行该远程文件中的 PHP 代码。

2. 解题思路与知识点

漏洞原理：

远程文件包含漏洞（RFI）产生的前提条件有两个：一是后端代码允许用户控制要包含的文件路径；二是 PHP 配置中开启了 allow_url_include=On。攻击者通过构造指向恶意服务器的 URL，让靶场服务器将远程文件下载到本地并当作 PHP 代码执行，从而可直接获取 Webshell 控制权。

本地文件包含（LFI）与远程文件包含（RFI）的区别：
  • File Inclusion (local)：只能包含服务器本地已有的文件。利用方式主要是读取敏感配置文件或配合文件上传漏洞执行 Webshell 代码。
  • File Inclusion (remote)：允许包含远程服务器上的文件。前提是 PHP 配置中开启了 allow_url_include=On。攻击者可直接包含恶意脚本，危害更大。

3. 操作步骤

第一步：环境配置与错误处理

操作： 进入 File Inclusion (remote) 关卡，发现页面顶部抛出红色警告信息：warning:你的allow_url_include没有打开,请在php.ini中打开了再测试该漏洞,记得修改后,重启中间件服务!。

修复过程： 根据提示，在 PHPStudy 的 PHP 配置文件（此处为 php7.3.4nts/php.ini）中，搜索并修改 allow_url_include=Off 为 allow_url_include=On。修改后保存并重启 Nginx/Apache 服务使配置生效。

第二步：编写模拟远程恶意文件

操作： 由于靶场在本地，我们在 Web 根目录（D:\phpstudy_pro\WWW）下使用 VS Code 新建文件 shell.txt，写入以下代码并保存：

<?php echo "pikachu_rfi_success"; ?>

代码组成解释：

  • <?php：PHP 代码的起始标记。在这个标签内部的代码会被 PHP 解析器执行。
  • echo：PHP 的输出语句，用于向页面输出一个或多个字符串。
  • "pikachu_rfi_success"：字符串常量，也就是我们期望在页面上看到的具体内容。
  • ;：PHP 语句结束符，表示一条语句的结束。
  • ?>：PHP 代码的结束标记。

文件验证： 浏览器直接访问 http://127.0.0.1/shell.txt，页面显示的是代码本身而非执行结果。原因是 .txt 文件不会被 Web 服务器作为 PHP 解析，这是正常现象，不影响后续被包含时的执行。

第三步：实施远程文件包含攻击

攻击 Payload： 构造包含远程 URL 的恶意请求。

构造 URL： http://127.0.0.1/pikachu/vul/fileinclude/fi_remote.php?filename=http://127.0.0.1/shell.txt&submit=提交

回显特征： 页面顶部成功输出了 pikachu_rfi_success。漏洞利用成功。

攻击 URL 组成详细解释：

  • http://127.0.0.1/pikachu/vul/fileinclude/fi_remote.php：目标靶场脚本的访问路径。
  • ?：URL 参数起始符。
  • filename=：参数名，告诉后端我们要控制名为 filename 的变量。
  • http://127.0.0.1/shell.txt：参数值，就是我们精心准备的恶意远程文件地址，通过 HTTP 协议拉取。
  • &submit=提交：拼凑的表单提交参数，用于触发后端逻辑。

第四步：源码验证

操作： 打开 Visual Studio Code，查看 vul/fileinclude/fi_remote.php 源码。

后端源码代码组成详细解释：

  • $filename = $_GET['filename'];：从 HTTP GET 请求中获取参数名为 filename 的值，并赋值给变量 $filename。
  • include($filename);：将变量 $filename 传入 include() 函数。该函数会尝试读取并包含指定路径的文件，并将其作为 PHP 代码执行。由于这里没有过滤，攻击者可以传入远程 URL 实现 RFI。

4. 踩坑记录与复盘

  • 坑1：allow_url_include 未开启导致利用失败。进入关卡时页面直接抛出红色警告。解决办法是定位 PHP 配置文件，将 allow_url_include=Off 改为 On 并重启中间件服务。这也是 RFI 漏洞利用的硬性前提条件，实战中需先探测该配置项状态。
  • 坑2：直接访问 shell.txt 显示源码而非执行结果。在验证远程文件时，直接访问 http://127.0.0.1/shell.txt 只会看到 <?php ... ?> 源代码。原因是 Web 服务器根据 .txt 后缀判定为静态文件，未交给 PHP 解析器。在实际 RFI 漏洞利用中，只要远程文件包含 PHP 代码，且目标服务器的 include() 成功拉取该文件，文件中的代码就会被解析执行，不需要远程文件本身具有可执行权限。

5. 知识总结

  • 漏洞本质：远程文件包含漏洞的本质是“引用的越权”。应用允许用户控制包含路径，并且允许包含远程 URL，从而让攻击者将恶意代码带入服务器内部执行。
  • 防御措施：在生产环境中，应确保 allow_url_include=Off。同时，对包含的文件名使用白名单限制，严格过滤 http://、https://、ftp:// 等协议前缀，以及绝对路径和路径穿越符。
  • 实战启发：文件包含漏洞利用需要结合文件上传漏洞。攻击者可以先将含有恶意代码的图片或文档上传到服务器，再通过 LFI 包含该上传文件，从而绕过 RFI 的配置限制，实现代码执行。
