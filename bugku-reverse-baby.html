【Bugku CTF】Reverse-入门逆向 Writeup

操作者：何芊宏 | 操作日期：2026.9.13 | 分类：CTF | 标签：Bugku, Reverse, Ghidra

1. 题目信息

  • 平台：Bugku CTF
  • 分类：Reverse（逆向工程）
  • 题目名称：入门逆向
  • 描述：来源: XJNU

2. 解题思路

下载附件并解压，得到一个 baby.exe 程序。根据题目名称判断这是一道逆向入门题。因为程序是 32 位 PE 文件，计划使用 Ghidra 工具进行反汇编，查看 _main 函数内部的代码逻辑，从而提取隐藏的字符串。

3. 操作步骤

  1. 下载附件，解压得到 baby.exe。
  2. 安装 Java 环境（JDK 21），并下载、解压 Ghidra。
  3. 启动 Ghidra，新建一个 Non-Shared Project。通过 File -> Import File 导入 baby.exe。
  4. 双击打开导入的文件，点击 Analyze 进行自动分析。
  5. 左侧符号树中找到 _main 函数，双击进入。在中间的 Listing（汇编代码）窗口，定位到 CALL printf 之前。
  6. 发现程序并没有直接使用 printf 打印 flag，而是使用多行 MOV 指令，逐个将字符压入栈中。
  7. 提取这些十六进制字节：66 6C 61 67 7B 52 65 5F 31 73 5F 53 30 5F 43 30 4F 4C 7D。
  8. 手动拼接这些 ASCII 码，得到最终 Flag：flag{Re_1s_S0_C0OL}。提交平台，验证通过。

4. 踩坑记录与复盘（极其曲折的纯键盘历险记）

这是一次极其特殊且曲折的逆向排障实战，因为室友在睡觉，我强迫自己全程不使用鼠标，用纯键盘和代码来解决问题，结果经历了一连串的“乌龙”：

  • 脚本套娃与奇葩搜索：我先写了一个 Python 脚本自动搜索文件，结果脚本因为名字里带 baby，把自己（run-baby.py）给读取了。换用全盘搜索后，搜到了腾讯软件自带的 baby-carriage.svg（婴儿车）图标，完全跑偏。
  • 终端环境混淆：试图在 PowerShell 终端里执行 CMD 的 dir 命令报错，并且长时间找不到目标文件。最后才发现桌面上只有一个 file.zip，连解压都没解压！解压后才拿到了真实的 baby.exe。
  • 反编译器未显示 Flag：用 Python 读取 baby.exe 只发现了编译器垃圾字符串，用 Python 运行它，它只说了句 Hi~ this is a babyre。用 Ghidra 反编译后，右侧的 Decompiler 也没直接显示 flag，因为出题人用了逐字节入栈的方式，反编译器认为这是无意义的操作。
  • O和0的视觉陷阱：在提取出十六进制数据并转换成字符串后，C0OL 和 C00L 极其相似。第一次提交 C00L 提示错误，最后反复比对十六进制里的 30 和 4F（0 和 O），才确认正确的拼写是 C0OL（数字0 + 字母O + 字母L）。
