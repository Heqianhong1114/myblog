1. 题目信息

  • 平台：CTFHub
  • 分类：Web - 文件上传 / 双写后缀
  • 题目名称：双写后缀
  • 提示：黑名单过滤绕过

2. 解题思路

本题目的是通过“双写后缀”来绕过服务器的黑名单过滤。后端源码中通常使用 str_ireplace 将文件名里的 php 等危险后缀替换为空。如果上传 shell.pphphp，过滤掉中间的 php 后，剩下的正好拼接成 shell.php，从而绕过检测。由于浏览器可能存在前端限制，采用 Python 的 requests 库直接构造 POST 请求上传 Webshell，然后通过访问该文件执行系统命令读取 Flag。

3. 操作步骤

第一步：构造 Webshell 与发送上传请求（踩坑）

准备 PHP Payload：<?php system('ls /'); ?>，将其命名为 shell.pphphp。在 Python 中构造上传请求时，初期遇到 FileNotFoundError（路径错误）。改用直接发数据包的方式，构造 files 参数发送，但始终返回 200 且只回显页面源码，未能触发上传逻辑。

第二步：分析后端源码补充触发参数（关键）

查看页面源码，发现表单中存在 <input type="submit" name="submit" value="Submit" />。通过注释还发现了黑名单数组 $blacklist = array("php", "php5", ...) 和替换函数 str_ireplace。

修正 Python 脚本，额外添加 data={'submit': 'Submit'} 参数，同时发送 files 和 data。

第三步：上传成功与查找文件（成功上传）

再次运行脚本，终端回显 <script>alert('上传成功');</script>上传文件相对路径<br>upload/shell.php。证明文件已成功写入服务器 /upload/shell.php 路径。

浏览器访问 /upload/shell.php，成功执行 ls / 命令，列出根目录文件夹。

第四步：全盘搜索与读取文件内容（踩坑与最终突破）

修改 Payload 为 find / -name "flag*" 2>/dev/null 重新上传并刷新，成功找到文件路径：/var/www/html/flag_1811921187.php。

尝试使用 cat 读取该文件，返回页面空白（因 PHP 源码被浏览器当作代码执行隐藏）。最终修改 Payload 为 <?php echo htmlspecialchars(file_get_contents('/var/www/html/flag_1811921187.php')); ?>，重新上传并刷新，成功拿到 Flag。

4. 踩坑记录与复盘

  • 本地文件路径导致的失败：在 Windows 上读取本地文件容易遇到隐藏后缀或权限问题。改用直接构造数据包的方式（files 传参）不仅绕过了本地文件读取，而且更贴近 HTTP 协议的底层发包逻辑。
  • 表单字段缺失的教训：仅仅发送 files 可能不会触发后端的处理逻辑。后端代码往往依赖 submit 按钮的名字来判断是否要处理上传，必须同时发送 data 参数与之匹配。
  • 浏览器渲染机制带来的陷阱：直接读取 PHP 源码时，cat 出的 <?php ?> 会被浏览器当作标签解析而不显示。使用 file_get_contents 结合 htmlspecialchars 将内容转义为纯文本，是 CTF 源码审计读取的常用技巧。

5. 知识总结

  • 双写绕过原理：利用后端替换函数执行一次的特性，通过构造重叠的恶意后缀（如 pphphp），使得替换后正好拼接成可执行脚本（shell.php）。
  • Python requests 发包技巧：同时传递 files 和 data 参数可以构造完整的带文件的表单请求，这是自动化漏洞利用脚本的核心技能。
  • Webshell 进阶命令：除了 ls 和 cat，利用 find 命令全盘搜索敏感文件，以及使用 file_get_contents 绕过渲染限制读取源码，都是实际渗透测试中非常有用的技巧。
