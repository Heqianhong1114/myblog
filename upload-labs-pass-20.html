【Upload-Labs】Pass-20 save_name 参数与 pathinfo 绕过 Writeup

操作者：何芊宏 | 操作日期：2026.11.03 | 分类：CTF | 标签：Upload-Labs, Web, 文件上传, 逻辑漏洞, WebShell

1. 题目信息

  • 平台：Upload-Labs (本地 phpStudy 环境)
  • 分类：Web - 文件上传
  • 题目名称：Pass-20 (save_name 与 pathinfo 绕过)
  • 提示：页面表单提供了一个隐藏参数 save_name，用于控制最终保存的文件名。

2. 核心原理与前置分析

本关卡源码在保存文件时，使用的是 POST 请求中的 save_name 参数（$file_name = $_POST['save_name'];），而不是上传的原始文件名。

随后，代码通过 pathinfo($file_name, PATHINFO_EXTENSION) 来提取后缀进行黑名单比对。若设置 save_name 为 shell.php.（末尾带点），pathinfo 提取出的后缀为空字符串，不在黑名单内，从而绕过检测。

最终在 Windows 环境下保存该文件时，系统会自动剥离末尾的点，实际落地的文件名为 shell.php。由于访问时携带尾随点（shell.php.）也能被解析，成功触发代码执行。

3. 工具配置与操作步骤

工具配置：Burp Suite 与 中国蚁剑

  • 中国蚁剑：URL 地址：http://127.0.0.1:8081/upload/shell.php.；连接密码：cmd；编码：UTF-8。

操作步骤与解析：

第一步：抓包并篡改 save_name 参数

开启 Burp Suite 拦截上传请求。在请求包的底部找到 name="save_name" 字段：

Content-Disposition: form-data; name="save_name"

upload-19.jpg

将其值修改为带尾随点的 shell.php.：

Content-Disposition: form-data; name="save_name"

shell.php.

点击 Forward 放行。

第二步：验证与连接

在浏览器中访问 http://127.0.0.1:8081/upload/shell.php.，页面呈现纯白，说明代码被成功解析执行。

打开蚁剑，填入该带点的 URL 及密码 cmd，成功连接并获取服务器权限。随后清理大量由上一关产生的占位文件夹及测试文件。

4. 踩坑记录与复盘

  • 参数名与参数值的混淆：在 Burp 中修改时，误将表单的 name 属性（name="save_name"）改成了 Payload，而保留了原本的默认值。导致服务端无法提取正确的 POST 参数，提示上传出错。
  • 尾随点的处理差异：在 Windows 系统中，保存时会剥离末尾的点，但访问时保留 shell.php. 依然能被 FastCGI 正常解析。

5. 知识点总结

  • pathinfo 逻辑漏洞：利用 pathinfo 对非法后缀（如尾随点、空字符）的解析特性，构造出不在黑名单内的空后缀文件名。
  • 参数劫持：当服务端依赖客户端提交的特定参数（如 save_name）来决定保存路径时，篡改该参数即可完全控制文件的落地名称。
