【Bugku CTF】Misc-linux Writeup

操作者：何芊宏 | 操作日期：2026.9.13 | 分类：CTF | 标签：Bugku, Misc, Python

1. 题目信息

  • 平台：Bugku CTF
  • 分类：Misc（杂项）
  • 题目名称：linux
  • 描述：linux基础问题
  • 提示：key{}

注意：这道题的提交格式是 key{}，不是 flag{}。

2. 解题思路

下载附件后得到一个 1.tar 文件（在 Windows 系统中显示为 1.tar，但实际可能是 1.tar.gz）。因为这道题考察的是 Linux 基础，而 Windows 系统对 Linux 的压缩格式支持极差，直接在 Windows 里解压会报错或产生巨大的空洞文件。所以我决定写一个 Python 脚本，使用内置的 tarfile 库直接读取压缩包内容，绕过 Windows 系统的限制。

3. 操作步骤

  1. 在 VS Code 新建文件 decode_tar.py。
  2. 粘贴下面的代码，使用 Python 直接读取压缩包，并过滤掉空字节，提取出真正的 key{...}：
import os
import tarfile
import re

# 桌面的 linux 文件夹路径
folder_path = r"C:\Users\heqianhong\Desktop\linux"
found_file = None

# 自动扫描，找出名字以 1.tar 开头的文件
for filename in os.listdir(folder_path):
    if filename.startswith("1.tar"):
        found_file = os.path.join(folder_path, filename)
        break

if not found_file:
    print("[-] 没找到 1.tar 文件")
else:
    print(f"[+] 正在读取: {found_file}")
    with tarfile.open(found_file, "r:*") as tar:
        for member in tar.getmembers():
            f = tar.extractfile(member)
            if f:
                content = f.read()
                # 核心逻辑：找到所有非空的字符段落（长度大于2的连续可读字符）
                strings = re.findall(rb"[^\x00]{3,}", content)
                print(f"\n[*] 文件 {member.name} 里的所有非空数据：")
                for s in strings:
                    try:
                        decoded = s.decode('ascii')
                        if "key" in decoded.lower() or "{" in decoded or "}" in decoded:
                            print(f"  -> {decoded}")
                    except:
                        pass
  1. 按 Ctrl + S 保存，点击右上角的 ▶ 运行。
  2. 终端成功输出真实的 Flag：key{feb81d3834e2423c9903f4755464060b}。
  3. 复制结果去平台提交，验证通过。

4. 踩坑记录与复盘

  • Windows 解压 Linux 文件的连环坑：直接双击 1.tar，Windows 提示“位置不可用”（因为试图解压到 Temp 目录但被锁死）。改用系统自带的“全部解压缩”后，解压出来的却是一个 14MB 的 flag 文件，里面全都是 00。后来发现是因为 Linux 稀疏文件在 Windows 下被填充成了空洞，真正的数据被藏到了隐蔽的位置。
  • 后缀名隐藏坑：双击解压出来的 flag 文件，Windows 弹窗提示“选择应用以打开此 .gz 文件”，说明这个文件实际是 .tar.gz，只是 Windows 隐藏了后缀。点几次弹窗后会陷入死循环，千万不要硬刚，直接关掉。
  • 正则表达式的坑：第一次用 Python 搜 rb"key\{.*?\}"，因为文件里全都是 00 空字节，正则匹配到了 key{} 就结束了，什么都拿不到。后来改成 re.findall(rb"[^\x00]{3,}", content)，先把所有非空字符提取出来再筛选，才成功拿到正确的 key。
