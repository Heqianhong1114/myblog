【CTFHub】Web-SQL注入整数型 Writeup

操作者：何芊宏 | 操作日期：2026.9.23 | 分类：CTF | 标签：CTFHub, Web, SQL注入, 整数型, Union联合查询, information_schema

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - SQL注入 / 整数型注入
  • 题目名称：整数型注入
  • 环境：通过 Open Browser 打开外部浏览器访问靶场环境。
  • 目标：页面提供了一个 ID 输入框，输入数字搜索新闻数据。页面源码直接暴露了后端SQL语句。目的是利用未过滤的输入拼接，查询并获取隐藏的Flag。

2. 解题思路与知识点

整数型注入原理：后端接收参数后，未进行类型检查与参数化查询，直接将用户输入拼接进SQL语句。由于参数本身是数字，因此注入时不需要单引号闭合，可直接通过 and 构造真假条件来探测，或通过 union select 进行联合查询注入。

通俗比喻（快递分拣员）：相当于快递分拣员拿单号找包裹。正常单号是数字（如id=1）。如果用户恶意输入“-1 union select 1,2”，管理员没区分“单号”和“指令”，直接把这两句话当成一个命令执行。因为 -1 号包裹不存在，大脑（数据库）转而去执行后半句“把财务账本（敏感数据）拿给我”的指令（联合查询），导致信息泄露。

URL编码说明：浏览器在地址栏提交时，会自动将空格转为 + 或 %20，逗号转为 %2C，括号转为 %28。这都是正常的URL编码，不影响Payload功能。

3. 操作步骤

第一步：漏洞探测（判断存在整数型注入）

在输入框中依次输入以下内容，并观察页面回显和页面打印出的SQL语句：

  • 输入 1：页面正常显示，回显SQL语句为 select * from news where id=1，结果 Data: ctfhub。（正常业务逻辑）
  • 输入 1 and 1=1：回显正常。因为 1=1 是永远为真的条件，相当于 and 真，不影响原查询结果。
  • 输入 1 and 1=2：回显为空。因为 1=2 是永远为假的条件，相当于 and 假，把整个 where 条件变成假，数据库查不到任何数据。

结论：这里参数没有引号包裹，输入的数字直接拼接到了 SQL 语句的 id= 后面，确认存在整数型注入。拼接部分 and 1=1 与 and 1=2 的作用，就是用来验证我们的恶意条件是否被数据库当作代码执行了（即验证漏洞是否存在）。

第二步：判断字段数（列数）

使用 order by 探测查询结果的列数，目的是为了后续的 union select 做铺垫：

  • 输入 1 order by 2：页面正常回显。说明查询结果至少有 2 列。
  • 输入 1 order by 3：页面无数据回显或报错。因为超出了列数限制，数据库无法按第3列排序。

结论：当前表共有 2个字段。后续的 union select 必须严格对齐2列，否则会报错。

第三步：寻找黄金回显点

输入 -1 union select 1,2，页面成功回显 ID: 1，Data: 2。

原理解析：为什么用 -1？如果写 1 union select 1,2，因为数据库里确实存在 id=1 的数据，后端会把前半句查到的数据显示出来，页面就看不到我们注入的数字了。而 -1 在数据库里是不存在的，前半句 select * from news where id=-1 查不到任何东西，页面就不得不显示后半句 union select 1,2 的结果。

结论：数字 1 和 2 成功显示在页面上，这两个位置就是“黄金回显点”，是我们后续替换为查询语句的“广告位”。

第四步：联合查询脱库（查库名、表名、字段名、数据）

利用找到的回显点，配合 MySQL 自带库 information_schema 进行脱库：

  • 查库名：输入 -1 union select 1,database()。页面回显 Data: sqli。database() 是MySQL内置函数，用来返回当前使用的数据库名。确定当前数据库为 sqli。
  • 查表名：输入 -1 union select 1,group_concat(table_name) from information_schema.tables where table_schema=database()。页面回显 Data: flag,news。原理解析：information_schema.tables 是MySQL自带的“户口本”，记录了所有表的信息。group_concat() 能把查到的多行表名拼成一行显示。where table_schema=database() 限定只查当前库。发现目标表 flag。
  • 查字段名：输入 -1 union select 1,group_concat(column_name) from information_schema.columns where table_name='flag'。页面回显 Data: flag。原理解析：在 columns 表里查 flag 表里有哪些列（字段），确定字段名为 flag。
  • 获取数据：输入 -1 union select 1,flag from flag。页面成功回显最终的Flag，提交至CTFHub，通关成功。

4. 踩坑记录与复盘

  • 拼接部分的作用：输入 1 and 1=1 / 1 and 1=2 是用来验证我们的恶意条件是否被数据库当作代码执行了。如果执行了，真条件正常，假条件无数据，说明存在注入。
  • 为什么必须用-1：联合查询必须保证前后查询的列数一致（这里我们判断出是2列）。同时，为了让我们注入的 select 1,2 显示出来，必须让前面语句查询为空（用不存在的负数如 -1 使得前半句查询失败）。
  • URL编码带来的困扰：浏览器在地址栏提交时，会自动将空格转为 + 或 %20，逗号转为 %2C，括号转为 %28。在手动输入长Payload时容易出错，建议后续使用 Burp Suite 重放器进行操作。
  • information_schema目录的作用：MySQL的 information_schema 库是核心，其中 tables 表记录所有表名，columns 表记录所有字段名，是SQL注入脱库的必经之路。

5. 知识总结

  • 标准注入流程：判断注入类型（数字/字符） -> 判断字段数（order by） -> 确定回显位置（union select） -> 利用 information_schema 查库名、表名、字段名 -> 脱取数据。
  • 聚合函数使用：当回显位置有限，但查询结果有多行时，使用 group_concat() 在一行中拼接多个查询结果，便于快速获取全量信息。
  • 系统函数与内置库：熟练记忆 database()，以及 information_schema.tables 和 information_schema.columns 这两张核心表。
