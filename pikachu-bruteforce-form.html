【Pikachu】Web-暴力破解-基于表单的暴力破解 Writeup

操作者：何芊宏 | 操作日期：2026.9.26 | 分类：Pikachu | 标签：Pikachu, Web, 暴力破解, Burp Suite, Intruder

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - 暴力破解 (Burte Force)
  • 题目名称：基于表单的暴力破解
  • 环境：使用 Burp Suite 社区版自带浏览器（Proxy -> Intercept -> Open Browser）访问靶场，避免更改系统代理导致校园网断连。
  • 目标：登录表单未设防（无验证码、无锁定），通过 Burp Intruder 交叉爆破，找出正确的账号密码并成功登录。

2. 解题思路与知识点

漏洞原理：

登录页面未采取任何防护措施（如验证码、登录失败次数限制、IP 限制等），攻击者可以通过抓包，利用工具批量提交不同的账号密码组合进行穷举尝试。

Intruder 攻击类型选择：
  • Sniper（狙击手）：单一 Payload 集，依次替换每个标记位，适合单参数爆破。
  • Cluster bomb（集束炸弹）：多个 Payload 集交叉组合（笛卡尔积），本关核心选择，用于同时爆破用户名和密码。
判定爆破成功的核心指标：
  • Status code：通常均为 200，无法直接区分。
  • Response received：可能因报错信息长短出现波动，存在误导性（如本次遇到的 105 干扰项）。
  • Length（响应包长度）：这是最准确的判断依据，登录成功和失败的页面长度通常有显著差异。
  • Response 直接搜索成功关键字（如 success）。

3. 操作步骤

第一步：抓包与发送至 Intruder

操作： BP 自带浏览器访问靶场 → 输入错误账号（admin / 123） → BP 开启 Intercept is on → 点击 Login 抓包 → 右键选择 Send to Intruder（Ctrl+I） → 关闭拦截（Intercept is off）。

执行目的：捕获标准的 POST 提交请求，准备交给 Intruder 模块进行批量修改重放。

获得信息：确认请求体格式为 username=admin&password=123&submit=Login。

第二步：配置攻击点 (Positions)

操作： 进入 Intruder -> Positions → 点击 Clear § 清空默认标记 → 选中 admin 点击 Add § → 选中 123 点击 Add § → 攻击类型下拉框选择 Cluster bomb。

执行目的：精确标记需要替换的变量位置，并设置交叉组合攻击模式。

获得信息：底部提示 2 payload positions。

第三步：配置字典 (Payloads)

操作： 进入 Payloads 标签页 → Payload set 选 1 (用户名) → 类型选 Simple list → 在输入框内逐个手动输入并点击 Add 添加：admin、root、test、pikachu → 切换 Payload set 为 2 (密码) → 逐个手动添加：123456、password、000000、admin888、12345678、abc123。

执行目的：为两个变量分别装载测试字典。

获得信息：Payload count 分别为 4 和 6，Request count 显示为 24（4x6=24 个请求）。

第四步：发起攻击 (Start Attack)

操作： 点击右上角 Start Attack → 弹出的社区版限速警告框点击 OK → 耐心等待 24 个请求全部跑完（约二十秒左右）。

第五步：分析结果与验证

操作： 观察 Length 列。发现绝大多数请求 Length 均为 35111，而第 39 行（test / abc123）的 Length 为 35087，存在明显差异。

执行目的：过滤冗余请求，精准定位成功页面。

回显结果：双击第 39 行 → 底部 Response 搜索 success，显示 1 match，页面上渲染出 login success。

获得信息：成功获取正确凭据：test / abc123。去浏览器实际输入，页面返回 login success，通关。

4. 踩坑记录与复盘

  • 坑1：误判 Response received 为成功指标。第一次跑字典时（未加 abc123），发现 root / 000000 的 Response received 为 105（其他为 5-28）。以为成功了，但浏览器验证失败。深究发现：Response received 只是服务器压缩后返回的字节数，报错语句不同会导致大小波动。实战中应以 Length 或搜索关键字为准。
  • 坑2：字典漏配导致失败。Pikachu 内置了多组账号密码，第一次字典太基础（没有 abc123），导致全部试错。后续参考 WP 补充了 test/abc123 才成功。
  • 坑3：代理冲突。直接用系统代理会断校园网。解决方式是使用 Burp 自带浏览器（自带代理与证书），避免了插件与网络环境配置冲突。
  • 坑4：社区版限速。Burp 社区版会弹出 Intruder 限速警告，直接 OK 即可。小字典（<50条）耐心等待即可，无需折腾专业版。

5. 知识总结

  • Burp Suite Intruder 核心攻击模式的适用场景：单变量爆破用 Sniper，多变量交叉爆破用 Cluster bomb。Payload 可以手动逐个 Add，也可以 Load 大字典。
  • 精准判断爆破成功：不要迷信单一数据（如 Response received），结合 Length 排序，并在 Response 渲染页用 Ctrl+F 搜索关键字（success / 成功），是最稳妥的验证组合拳。
  • 暴力破解防御方案：增加服务端校验的验证码、限制错误登录次数（如 5 次锁定账号）、IP 频率限制、甚至引入双因素认证（2FA）。
