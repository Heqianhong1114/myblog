【SQLi-Labs】Less-42 登录框堆叠注入与 WebShell Writeup

操作者：何芊宏 | 操作日期：2026.10.28 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, 堆叠注入, POST注入, WebShell

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-42 (POST - Stacked Query Injection - String)
  • 提示：POST 登录框，后端使用 mysqli_multi_query() 支持堆叠，密码字段无转义。

2. 核心原理与前置分析

本关卡将注入场景转移到了 POST 登录框中。源码对 login_user 进行了转义，但 login_password 未做任何防御，且底层使用 mysqli_multi_query() 支持堆叠执行。

逻辑错位现象：当构造包含堆叠语句的 Payload 时，第一条 SELECT 登录查询通常失败并触发页面重定向（显示 failed.php 嘲讽页），但由于堆叠执行不受第一条查询结果影响，后续的写文件语句依然会被成功执行。

3. 工具配置与操作步骤

工具配置：Burp Suite 与中国蚁剑

  • Burp Suite：拦截 POST 请求体并修改 Payload。
  • 中国蚁剑：连接生成的 WebShell，操作步骤与 Less-38 一致。修改 URL 为 http://localhost/sqli-labs-master/Less-42/shell.php，密码为 cmd。

操作步骤与解析：

第一步：抓包与构造堆叠注入

抓取登录请求，修改请求体，在 login_password 中注入闭合单引号及写文件语句：

login_user=admin&login_password=1'; select '' into outfile 'D:/phpstudy_pro/WWW/sqli-labs-master/Less-42/shell.php'-- -&mysubmit=Login

第二步：验证与连接

回显现象：页面重定向并显示 BUG OFF YOU SILLY DUMB HACKER（因第一条 SELECT 查询失败）。

本地验证：前往本地物理路径 Less-42 目录，确认 shell.php 已成功生成（1KB）。

使用蚁剑成功连接，获得文件管理权限。

4. 踩坑记录与复盘

  • 页面回显与底层执行的剥离：不要被 "BUG OFF" 页面迷惑。由于多语句执行机制，第一条查询失败引发的页面跳转，不影响后续写文件语句的最终执行。
  • POST 注入点：需敏锐识别出登录框中未被转义的密码字段才是突破口。

5. 知识点总结

  • POST 堆叠注入：在表单提交中利用分号执行非 SELECT 语句。
  • 业务逻辑与 SQL 执行的差异：前端提示失败不代表后端数据库操作失败。
