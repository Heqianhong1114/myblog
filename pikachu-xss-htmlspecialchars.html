【Pikachu】Web-XSS-xss之htmlspecialchars Writeup

操作者：何芊宏 | 操作日期：2026.9.27 | 分类：Pikachu | 标签：Pikachu, Web, XSS, htmlspecialchars, 伪协议, 上下文逃逸

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - Cross-Site Scripting (XSS)
  • 题目名称：xss之htmlspecialchars
  • 目标：后端使用了 htmlspecialchars() 函数转义 HTML 特殊字符，无法直接注入标签。需要结合上下文，利用 javascript: 伪协议绕过过滤触发弹窗。

2. 解题思路与知识点

漏洞原理：

后端通过 htmlspecialchars() 把 <、>、" 等特殊字符转义成了 HTML 实体，导致我们无法伪造闭合标签。但是，当输入点位于 HTML 标签的 href 属性内部时，我们不需要尖括号，可以利用 javascript: 伪协议让链接在被点击时执行 JS 代码。

为什么可以使用 javascript:？
  • 后端只转义了 HTML 标签字符（尖括号），但 javascript: 是合法的 URL 协议。
  • 浏览器解析 href 属性时，识别到该协议，会将其作为 JavaScript 代码执行。这是典型的“上下文逃逸”利用。

3. 操作步骤

第一步：探测输出点与上下文（F12）

操作： 输入 test 提交，按 F12 审查生成的 HTML 源码。

结果： 发现回显结构为 <a href="test">test</a>。

分析： 输入被放置在 <a> 标签的 href 属性中，且由于 htmlspecialchars，无法闭合标签注入事件。常规的 <script> 或 <img> 标签全部失效。

第二步：构造针对性 Payload

Payload： javascript:alert(1)

在输入框中填入该 Payload 并提交。

第三步：触发执行

操作： 页面下方生成了一个超链接 <a href="javascript:alert(1)">javascript:alert(1)</a>。点击该超链接。

结果： 浏览器成功弹出 127.0.0.1 显示 1 的对话框，漏洞利用成功。

4. 踩坑记录与复盘

  • 复盘总结：渗透测试中，输出点的“上下文（Context）”决定了 Payload 的构造方式。如果输出在标签体内部，需要闭合标签；如果输出在属性内部（如 href/src），则优先尝试伪协议或闭合属性注入事件（如 ' onmouseover='alert(1)）。

5. 知识总结

  • htmlspecialchars 的局限性：它主要防范在 HTML 标签体内部的注入。如果开发者将其用在属性上下文，且没有做好协议校验，依然可能被 javascript: 伪协议绕过。
  • 防御建议：除了对输入进行转义外，输出到 href 时，应严格检查协议头，禁用 javascript:、data: 等危险协议，或者强制给 URL 加上 http:// 前缀确保协议安全。
