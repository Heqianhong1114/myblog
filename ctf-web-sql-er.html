【CTFHub】Web-SQL注入报错注入 Writeup

操作者：何芊宏 | 操作日期：2026.9.23 | 分类：CTF | 标签：CTFHub, Web, SQL注入, 报错注入, updatexml, 整数型

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - SQL注入 / 报错注入
  • 题目名称：报错注入
  • 环境：通过 Open Browser 打开外部浏览器访问靶场环境。
  • 目标：页面无正常回显位，但开启了报错回显。利用数据库的报错机制，通过构造非法函数参数，将数据外带。

2. 解题思路与知识点

报错注入原理：在联合查询无法回显数据时，利用 MySQL 某些函数（如 updatexml()）的特性。当传入不符合语法规则的参数时，数据库会抛出错误，并在错误信息中拼接我们传入的非法参数（即我们查询的数据），从而实现数据外带。

新增核心代码组成详细解析（通用公式拆解）：
  • 1 和 and：1 是合法的查询ID，and 是逻辑与拼接符。因为我们确认了是整数型，所以不需要加单引号和注释符。
  • updatexml(1, concat(0x7e, 子查询), 1)：updatexml 是 MySQL 修改 XML 的函数。它的第二个参数必须是合法的 XPath 路径格式。我们强行传入拼接后的非法数据，就会触发 XPATH syntax error（XPath语法错误），从而带出数据。
  • 0x7e：这是字符 ~ 的十六进制表示。用它作为前缀拼接在报错信息中，方便我们一眼看到目标数据从哪里开始，避免和报错信息的固定文字混淆。
  • concat(A, B)：字符串拼接函数，将 ~ 与我们子查询查到的数据拼成一个整体。
  • 子查询 (select ...)：将我们想要查询的库名、表名等，以子查询的形式嵌套在 concat 内，作为报错数据源。
  • group_concat()：因为报错信息只能在一行字符串中显示，该函数将多行查询结果（如多张表名）合并到一个字符串中，用逗号隔开。

3. 操作步骤

第一步：判断注入类型

Payload 1： 1 and 1=1

Payload 2： 1 and 1=2

回显现象：两者均显示“查询正确”。

代码分析：输入 1 时，回显 SQL 为 select * from news where id=1，没有引号包裹。加上 and 构造逻辑条件，页面不报错且逻辑不生效（因为后端只校验语法错误，不关心结果集是否为空），但足以确认这是整数型注入。不需要闭合引号，不需要注释符。

第二步：验证报错函数机制（核心步骤）

Payload： 1 and updatexml(1,concat(0x7e,database()),1)

回显现象：查询错误: XPATH syntax error: '~sqli'

代码分析：

  • database()：MySQL内置函数，返回当前数据库名。
  • concat(0x7e, database())：把 ~ 和数据库名拼在一起，变成 ~sqli。
  • 为什么用 0x7e 而不是 '~'：减少单引号的使用，避免干扰SQL语句的解析。
  • 整体执行逻辑：我们把 ~sqli 强塞给 XML 处理函数 updatexml。因为它不符合 XPath 规范，数据库直接报错并抛出：XPATH syntax error: '~sqli'。至此，我们成功获取库名 sqli。

第三步：联合查询脱库（报错外带）

  • 查表名：

    1 and updatexml(1,concat(0x7e,(select group_concat(table_name) from information_schema.tables where table_schema=database())),1)

    回显：XPATH syntax error: '~flag,news'

    代码分析：将 database() 替换为子查询 (select group_concat(table_name) from information_schema.tables where table_schema=database())。子查询从系统库（information_schema.tables）中查出当前库（sqli）的所有表名，并用 group_concat() 拼成一行 flag,news。注意，子查询外面必须加括号，整体作为 concat 的参数。发现目标表 flag。

  • 查字段名：

    1 and updatexml(1,concat(0x7e,(select group_concat(column_name) from information_schema.columns where table_name='flag')),1)

    回显：XPATH syntax error: '~flag'

    代码分析：子查询换成了查 information_schema.columns，限定条件为 table_name='flag'。注意：'flag' 作为字符串，在 SQL 中必须加单引号。确定字段名为 flag。

  • 获取数据：

    1 and updatexml(1,concat(0x7e,(select flag from flag)),1)

    回显：XPATH syntax error: '~ctfhub{8fa3aa074a1d874493982168}'

    代码分析：子查询直接查数据：select flag from flag。将查到的Flag结果拼接到 ~ 后面，通过报错信息完美外带。提交Flag，通关成功。

4. 踩坑记录与复盘

  • 坑1：无回显位，盲目使用union select。报错注入场景下，页面正常查询并不输出数据。必须转换思路，使用updatexml等报错函数。
  • 坑2：误以为是字符型。测试1 and 1=1时页面无报错，且源码回显id=1无引号，确认为整数型。无需加'和#。
  • 坑3：括号层级嵌套错误。Payload结构为updatexml(1, concat(0x7e, (子查询)), 1)，这里有四层括号。少打或多打一个括号，都不会报出数据，而是直接语法错误。
  • 坑4：URL编码干扰。浏览器地址栏会把空格、逗号、括号转义成 %20、%2C、%28，肉眼极易看错。强烈建议直接打开 Burp Suite 重放器进行URL改写和请求发送。

5. 知识总结

  • 三种注入场景切换：
    • 联合查询注入：页面有正常回显位。
    • 报错注入：页面无正常回显位，但开启了报错显示（本关）。
    • 盲注：页面无回显也无报错，靠布尔状态或时间差判断（下一关）。
  • 报错注入核心公式：熟记 and updatexml(1,concat(0x7e,(select 查询语句)),1)。另一种常用函数是 extractvalue(1,concat(0x7e,(select ...)))。
  • 系统库信息：熟练使用 database()，以及 information_schema.tables 和 information_schema.columns 查表名和字段名。
