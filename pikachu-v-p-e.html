【Pikachu】Web-越权-垂直越权(Vertical Privilege Escalation) Writeup

操作者：何芊宏 | 操作日期：2026.9.29 | 分类：Pikachu | 标签：Pikachu, Web, 越权, 垂直越权, 接口越权

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - Over Permission (垂直越权)
  • 题目名称：垂直越权
  • 目标：利用低权限用户（pikachu）的登录状态，寻找并调用高权限用户（admin）专属的后台接口，实现添加用户等敏感操作，验证垂直越权漏洞。

2. 解题思路与知识点

漏洞原理：

垂直越权（Vertical Privilege Escalation）是指低权限用户尝试执行高权限用户的操作。前端页面通常通过隐藏“添加用户”、“删除”等按钮来限制普通用户的视线，但真正的后端接口（如 op2_admin.php、op2_admin_edit.php）如果没有对当前 Session 的角色进行二次校验（如判定 $_SESSION['role'] == 'admin'），普通用户就能通过直接访问接口来越权操作。

本关实战结论：
  • 直接访问 op2_admin.php 和 op2_admin_add.php 会被后端重定向回登录页（严格校验了 Session 角色）。
  • 访问 op2_admin_edit.php 时成功渲染了表单，且提交数据在数据库层面写入成功，证明该接口存在越权漏洞。
  • 后端逻辑为“先执行数据库写入，后校验 Session 权限”，导致前端虽然重定向，但数据已越权写入。

3. 操作步骤

第一步：获取测试账号并登录

操作： 点击“点一下提示”按钮，获取测试账号：管理员 admin/123456，普通用户 pikachu/000000。

登录： 使用普通用户 pikachu 登录系统。

第二步：尝试直接访问管理页面（失败记录）

操作 1： 在浏览器地址栏输入 http://127.0.0.1/pikachu/vul/overpermission/op2/op2_admin.php。

回显： 页面被重定向回登录页 op2_login.php。

操作 2： 尝试访问 op2_admin_add.php。

回显： 同样被重定向回登录页。

原因分析： 这两个页面在代码入口处加入了 Session 权限校验，检测到当前用户不是管理员，直接执行 header('Location: op2_login.php'); exit();。

第三步：寻找未授权接口并成功执行越权

思路调整： 查找处理添加用户表单的后端文件 op2_admin_edit.php，该文件可能仅校验了登录状态，未校验角色。

操作： 在普通用户 pikachu 登录状态下，直接在浏览器地址栏输入：

http://127.0.0.1/pikachu/vul/overpermission/op2/op2_admin_edit.php

回显特征： 页面正常加载，顶部显示“hi,pikachu,欢迎来到后台管理中心”，并成功渲染出添加用户的表单（用户、密码、性别、电话、邮箱、地址）。这证明该接口存在垂直越权漏洞。

代码组成详细解释（表单提交逻辑）：

  • form action="op2_admin_edit.php" method="POST"：表单会将数据通过 POST 请求提交给 op2_admin_edit.php。
  • input type="text" name="username"：接收用户名的输入字段。
  • input type="password" name="password"：接收密码的输入字段。
  • 提交后，后端代码执行类似 INSERT INTO users (username, password, ...) VALUES ('$username', '$password', ...) 的 SQL 语句。

越权提交： 在表单中填入新用户信息（用户：hacker01，密码：123456，性别：boy，电话：13800000000，邮箱：hacker01@test.com，地址：china），点击“创建”。

第四步：验证隐蔽成功与复盘

初步回显： 点击“创建”后，页面被重定向回登录页 op2_login.php，看起来像是提交失败。

漏洞最终验证： 退出普通用户，重新以管理员 admin / 123456 登录。观察用户列表，发现**刚才创建的 hacker01 已经出现在列表中**。

原因分析： 后端代码在执行时，**数据库插入操作在前，权限校验逻辑（重定向）在后**。虽然前端页面被强制重定向了，但数据实际上已经成功写入数据库。这正是垂直越权漏洞最隐蔽、也最危险的体现。

4. 踩坑记录与复盘

  • 坑1：死磕错误的管理接口路径。初次尝试时，直接访问 op2_admin.php 和 op2_admin_add.php，均被后端通过 Session 角色校验重定向回登录页。后调整思路，分析出处理“添加用户”的表单提交接口为 op2_admin_edit.php，并成功利用该接口的权限缺失完成了越权。这说明在垂直越权测试中，应重点关注**表单处理接口**，而不仅仅是页面展示接口。
  • 坑2：后端先执行操作、后校验权限导致的“隐蔽成功”。普通用户提交添加用户表单后，页面被重定向回登录页，初步判断为攻击失败。然而在用管理员账号复查时，发现该用户已被成功添加。
    原因排查： 后端代码逻辑存在严重缺陷，先执行了 SQL 插入语句，再执行了 header("Location: ...") 进行权限拦截。这导致前端展示失败，但后端数据库已被恶意篡改。
    解决办法（反思）： 在渗透测试中，不能仅凭前端回显（如重定向、报错）来判断攻击是否成功。应结合数据库变化（如管理后台的对比查看）或使用 Burp Suite 查看响应状态码来综合判断。
  • 坑3：越权创建的新账号无法正常登录（靶场代码缺陷）。利用垂直越权漏洞，普通用户成功在数据库中创建了新用户 hacker01（管理员后台可见）。但尝试用该账号登录时提示失败。
    原因分析： 靶场源码在插入数据时可能缺少了必要的角色字段，或者密码加密逻辑与登录模块不匹配。这属于靶场功能实现上的局限性，不影响垂直越权漏洞本身的认定。渗透测试只需证明“非授权用户执行了管理员操作”即可，无需追求完整的新账号登录流程。

5. 知识总结

  • 漏洞本质：垂直越权源于后端接口只校验“是否登录”，不校验“角色权限”。任何已登录用户，只要能找到管理接口，就能执行管理操作。
  • 防御措施：所有敏感接口必须同时调用登录校验和角色校验函数；使用 RBAC 模型精细划分权限；服务端应从 Session 获取身份，绝不信任客户端参数。此外，应将权限校验代码放置在业务逻辑执行之前。
  • 实战启发：遇到垂直越权测试失败时，不要轻易放弃。应结合 Burp Suite 抓包分析和 Python 自动化脚本，尝试寻找其他未受保护的接口或参数。同时，即使攻击被拦截，也要记录下防御机制的具体表现（如重定向、响应长度变化），并注意验证数据是否已经在数据库层面被篡改。
