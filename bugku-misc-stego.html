【Bugku CTF】Misc-隐写 Writeup

操作者：何芊宏 | 操作日期：2026.9.12 | 分类：CTF | 标签：Bugku, Misc, 隐写, PNG

1. 题目信息

  • 平台：Bugku CTF
  • 分类：Misc（杂项）
  • 题目名称：隐写
  • 描述：BUGKU(xxx)

注意：这道题的提交格式是 BUGKU{}，不是常见的 flag{}，提交的时候别习惯性写错了。

2. 解题思路

下载附件后得到一张名为 2.png 的图片。双击打开时，系统直接报错“加载图片出错”。我猜测出题人可能篡改了图片的宽高数据，导致图片无法正常解析。一开始我以为是用 LSB（最低有效位）隐写，写了个 Python 脚本但什么都没提取出来。后来去看了题目评论区，有大佬提示这是“图片长宽修复”题，并给了一个在线修复工具的网址，试了一下果然跑通了。

3. 操作步骤

  1. 下载并解压附件，得到 2.png。
  2. 用 VS Code 的 Hex Editor 插件打开，发现文件头 89 50 4E 47 是正常的 PNG 头，宽高数据是 00 00 01 F4（宽500）和 00 00 00 A4（高420）。按 Ctrl + F 搜索 BUGKU 找不到任何明文。
  3. 我尝试写 Python 脚本提取 LSB 数据，但脚本报错找不到文件（被 Windows 隐藏扩展名坑了），而且图片本身结构也有问题，这条路走不通。
  4. 去评论区找线索，看到有人推荐了在线工具：https://tools.qsnctf.com/#//misc/png_dim_fix。
  5. 打开这个网址，把 2.png 上传上去。工具检测出 IHDR CRC 校验错误，点击“修复宽高”按钮。
  6. 下载修复后的图片，直接双击打开，图片下半部分露出了明文：BUGKU{a1e5aSA}。
  7. 复制这串字符去平台提交，验证通过。

4. 踩坑记录与复盘

  • Windows 隐藏扩展名又搞事：写 Python 代码时，路径写的是 2.png，但系统提示 No such file or directory。这是因为 Windows 默认把文件的后缀名藏起来了。以后写路径，最稳妥的方法是直接把文件拖进编辑器的引号里，或者去文件夹的“查看”菜单里把“文件扩展名”勾选上。
  • PIL 库缺失：写脚本时终端报错 ModuleNotFoundError: No module named 'PIL'。解决办法是直接在终端输入：pip install pillow -i https://pypi.tuna.tsinghua.edu.cn/simple 来安装这个图像处理库。
  • 别死磕代码，善用工具：CTF 比赛时时间有限，虽然用 Python 写脚本很酷，但遇到像“PNG 高度修复”这种有现成在线工具的场景，直接上传图片秒出答案，效率更高。这个在线工具网站（qsnctf）可以记到小本本上。
  • PNG 结构小知识：PNG 图片的宽高信息以及 CRC 校验码是连在一起的。如果出题人故意把高度改小，超出的那一部分在正常查看时就会被裁掉，只有把高度改大，才能看到隐藏区域（也就是 flag 的位置）。
