【Upload-Labs】Pass-03 黑名单后缀绕过 Writeup

操作者：何芊宏 | 操作日期：2026.11.02 | 分类：CTF | 标签：Upload-Labs, Web, 文件上传, 黑名单绕过, WebShell

1. 题目信息

  • 平台：Upload-Labs (本地 phpStudy 环境)
  • 分类：Web - 文件上传
  • 题目名称：Pass-03 (服务端黑名单校验)
  • 提示：任务为上传一个 webshell 到服务器。页面提示不允许上传特定后缀文件。

2. 核心原理与前置分析

本关卡的核心漏洞在于黑名单校验机制的不全面性。

分析源码可知，服务端定义了一个数组 $deny_ext = array('.asp','.aspx','.php','.jsp');。如果上传的文件后缀在这个数组中，则拒绝上传。黑名单机制最大的缺陷是“永远列不全”，由于 Apache 等 Web 服务器通常配置了多种脚本解析后缀（如 .php3、.php4、.php5、.phtml 等），我们可以寻找未在黑名单中但能被服务端解析的“漏网之鱼”。

此外，源码中 $img_path = UPLOAD_PATH.'/'.date("YmdHis").rand(1000,9999).$file_ext; 表明，服务端会将上传的文件重命名为“时间戳+随机数+后缀”，因此上传后无法直接猜出文件名。

3. 工具配置与操作步骤

工具配置：Burp Suite、浏览器开发者工具 与 中国蚁剑

  • 中国蚁剑：URL 地址需填写带有随机数的真实路径；连接密码：cmd；编码：UTF-8。

操作步骤与解析：

第一步：准备 Payload 并修改后缀

将包含 <?php @eval($_POST['cmd']); ?> 的文件重命名为 shell.php5。由于 .php5 不在黑名单内，且本机 Apache 配置了该后缀的解析规则。

第二步：上传并获取真实文件名

通过 Burp Suite 抓包，将请求中的 filename="shell.php5" 正常发送。由于服务端存在重命名逻辑，页面虽然提示上传成功，但文件名已被篡改。

在浏览器按下 F12 打开开发者工具，或者直接查看网页源代码。使用快捷键 Ctrl+F 搜索 /upload，快速定位到类似 <img src="../upload/202611021912206125.php5" ...> 的代码，从而直接提取出真实的随机文件名。

第三步：验证与连接

在浏览器中直接访问该真实路径 http://127.0.0.1:8081/upload/202611021912206125.php5，页面呈现纯白空白状态，证明 PHP 代码已被执行。

在蚁剑中配置该随机文件名路径和密码 cmd，成功连接并进入服务器目录。

4. 踩坑记录与复盘

  • 忽略服务端重命名机制：直接尝试访问 upload/shell.php5 会导致 404 错误。在黑盒测试中，必须仔细检查 HTTP 响应体或使用浏览器开发者工具追踪文件落地的真实路径。
  • 快速定位路径技巧：在遇到随机文件名重命名时，由于直接查找困难，可以通过在网页源码或 F12 开发者工具中搜索关键词 /upload，快速定位到 <img src="..."> 标签，高效提取出最终生成的绝对路径。
  • 后缀选择：在 phpStudy 的 FastCGI 环境下，需要确认哪些后缀被配置为可执行。参考本地通关手册，.php5 是最稳妥的绕过后缀之一，而 .php7 等未配置的后缀无法执行。

5. 知识点总结

  • 黑名单绕过：利用服务器支持解析但黑名单未覆盖的特殊后缀（如 .php3、.php5、.phtml）进行绕过。
  • 文件重命名下的路径获取：在遇到随机文件名重命名时，通过搜索 /upload 定位响应源码，提取最终生成的绝对路径。
