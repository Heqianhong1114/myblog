【Bugku CTF】Web-eval Writeup

操作者：何芊宏 | 操作日期：2026.9.13 | 分类：CTF | 标签：Bugku, Web, PHP, 代码执行

1. 题目信息

  • 平台：Bugku CTF
  • 分类：Web
  • 题目名称：eval
  • 描述：eval
  • 提交格式：flag{}

2. 解题思路

启动场景后，页面直接给出了 PHP 源码，核心逻辑是 eval("var_dump($a);");。这是一个典型的 PHP 代码执行漏洞。由于 $a 直接来源于 $_REQUEST['hello'] 且没有任何过滤，我们可以通过传入特定的字符串来“闭合”原来的代码结构，然后注入我们自己的 PHP 函数来读取文件。

3. 操作步骤

  1. 启动场景，获取靶场地址（例如：http://160.202.254.160:18948）。
  2. 构造 Payload，使用 1); 闭合 var_dump 的括号，用 // 注释掉多余的尾部代码，并在中间插入我们的执行命令。
  3. 第一次尝试（系统命令）：输入 ?hello=1);system('ls');//，页面无回显。判断服务器可能禁用了 system 等系统命令执行函数。
  4. 第二次尝试（PHP 原生函数）：改用 PHP 自带的文件读取函数 highlight_file 直接读取源码：
    ?hello=1);highlight_file('flag.php');//
  5. 由于单引号在某些环境可能被拦截，使用 URL 编码 %27 代替单引号，最终 URL 为：
    http://160.202.254.160:18948/?hello=1);highlight_file(%27flag.php%27);//
  6. 回车后，页面成功高亮显示了 flag.php 的源码，里面包含了真正的 Flag：flag{4337ac6cc6bbca395fc6390648c11bc}。
  7. 复制去平台提交，验证通过。

4. 踩坑记录与复盘

  • 系统命令被禁用：第一反应是用 system('ls') 或 system('cat flag.php') 去执行系统命令，但页面死活没回显。这通常是因为服务器的 php.ini 中配置了 disable_functions，把 system、exec、shell_exec 等危险函数都禁用了。以后遇到这种情况，要立刻想到换成 PHP 原生的文件操作函数，如 highlight_file()、show_source() 或 file_get_contents()。
  • 构造闭合 Payload 的技巧：拼接的 Payload 必须破坏原有的语法结构。本题原代码是 eval("var_dump($a);")，传入 1); 命令; // 后，拼接结果变成 eval("var_dump(1); 命令; //);")，刚好让我们的命令成功逃逸出来执行，这就叫“闭合绕过”。
  • 关于靶场架构的观察（题外话）：
    在完成了多道 Bugku Web 题后，我注意到所有这些题的访问地址都共用同一个公网 IP 160.202.254.160，但端口号一直在变（如 18525、18324、12412、18948 等）。这说明 Bugku 平台采用了“单台服务器 + 不同端口映射（Docker 容器）”的架构。这个观察让我真实体会到了“一个公网 IP 背后可能藏着成百上千个内部服务”的系统运维常识。
    另外，在真实的渗透测试记录（Writeup）中，除非是公开的靶场，否则一定要对真实的 IP 和域名进行脱敏处理（如写成 http://靶机IP:端口/），这是从业者必须遵守的职业素养和安全底线。
