【CTFHub】Web-RCE 命令注入-无过滤 Writeup

操作者：何芊宏 | 操作日期：2026.9.26 | 分类：CTF | 标签：CTFHub, Web, RCE, 命令注入, 盲注排错, 内存取证

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - RCE / 命令注入
  • 题目名称：命令注入-无过滤
  • 环境：浏览器 + 输入框提交。
  • 目标：利用无过滤的命令注入漏洞，通过 Linux 系统命令定位并读取隐藏的 Flag 文件。

2. 解题思路与知识点

本关核心考点：命令注入漏洞利用、盲注排错技巧、Base64 编码读取与内存取证。

知识点（比喻说明）：
  • 命令注入的本质： 后端代码使用 exec("ping -c 4 {$_GET['ip']}")。它就像一家餐厅的“传菜员”，你跟他说“去拿4号桌的菜单”，他照做；但如果你说“去拿4号桌的菜单；把保险柜的钥匙给我”，他会把后面的命令也当成工作指令一起执行。
  • 盲注与回显： exec() 函数默认只捕获“标准输出（stdout）”，不捕获“标准错误（stderr）”。当文件不存在或没有权限时，报错信息会丢失，页面一片空白。此时需要使用 2>&1 将错误重定向到标准输出，让报错现形。
  • Base64 读取技巧： 目标文件可能包含纯 PHP 代码（如 <?php // flag... ?>），直接 cat 会被 PHP 引擎解析导致空白。使用 base64 命令将其转为纯文本字符串，再本地解码，即可绕过解析器的干扰。

3. 详细步骤

第一步：源码审计与漏洞定位

<?php
$res = FALSE;
if (isset($_GET['ip']) && $_GET['ip']) {
    $cmd = "ping -c 4 {$_GET['ip']}";
    exec($cmd, $res);
}
?>

代码逐行解析：

  • $cmd = "ping -c 4 {$_GET['ip']}";：直接拼接用户输入，无任何过滤。
  • exec($cmd, $res);：执行命令，并将输出存入 $res 数组。

获得信息：存在无过滤的命令注入漏洞，可通过分号 ; 拼接系统命令执行。

第二步：探测目录与寻找目标

Payload： 127.0.0.1; ls -la

回显结果：发现当前目录下存在 index.php 和一个可疑的随机命名文件 28894297862778.php（42字节）。

获得信息：这个 42 字节的文件极有可能包含了 Flag。

第三步：排错与盲注探测（关键步骤）

为什么要输入：直接 cat 文件没有回显，需要排查是命令被禁用、文件不存在还是文件内容被隐藏。

  • 测试 cat /etc/passwd：成功回显，证明 cat 命令正常。
  • 测试 cat /flag 2>&1：报错 No such file or directory，证明根目录无 flag 文件。
  • 测试 env：发现 FLAG=not_flag，这是一个故意设置的假 Flag 烟雾弹。

获得信息：真正的 Flag 藏在那个 42 字节的文件里，但直接读取显示空白，需要进行编码绕过。

第四步：Base64 编码读取并解码 Flag

Payload： 127.0.0.1; base64 28894297862778.php

回显结果：得到 Base64 字符串 PD9waHAgLy8gY3RmaHViezlmYzBkMDJkMGJhOTEwN2EzZTRhYzNi...

操作： 将字符串复制到在线工具 https://base64.us 进行解码。

解码结果：<?php // ctfhub{9fc0d02d0ba9107a23e4ac3b}

获得信息：成功获取真实 Flag。

4. 踩坑记录与复盘

  • “幽灵文件”的迷惑： 误以为 ls / 中的 lib 或 home 是 flag 目录，浪费了大量时间尝试读取。教训：认准输出，不要主观臆测。
  • 报错被吞没（stdout vs stderr）： cat /flag 一片空白，导致排查陷入僵局。加上 2>&1 后瞬间真相大白。教训：在盲注场景下，务必记得重定向错误输出。
  • 假 Flag 的干扰（not_flag）： 环境变量里藏着 FLAG=not_flag，容易让人信以为真。
  • PHP 代码解析导致空白： 42 字节的文件里是 <?php // ctfhub{...}。直接 cat 时，<?php 被 PHP 解析器吞掉，// 将后续内容转为注释，因此页面空白。必须使用 base64 强制转码绕过解析器。

5. 知识总结

  • 命令注入的核心攻击链： 确认注入点 -> 使用 ; 或 | 拼接命令 -> 探测环境 -> 定位目标文件 -> 读取并提交。
  • 盲注排错技巧： 善用 2>&1 重定向标准错误输出，让隐藏的报错信息（如“权限不足”或“文件不存在”）浮出水面。
  • 文件读取绕过： 当 cat 读不出内容时，优先尝试 tac、nl、base64、xxd 等替代命令。
