【Bugku CTF】Web-源代码 Writeup

操作者：何芊宏 | 操作日期：2026.9.13 | 分类：CTF | 标签：Bugku, Web, JS混淆, DOM篡改

1. 题目信息

  • 平台：Bugku CTF
  • 分类：Web
  • 题目名称：源代码
  • 描述：看看源代码？
  • 提交格式：flag{}

2. 解题思路

页面只提供了一个没有 name 属性的输入框，说明常规的 POST 提交是行不通的。按 F12 查看源码，发现页面包含了一段被混淆的 JavaScript 代码，验证逻辑应该在前端。我们需要解码 JS，提取出验证条件，并通过修改 DOM 结构来欺骗前端 JS，从而拿到 Flag。

3. 操作步骤

  1. 启动场景，按 F12 查看源码，发现混淆的 JS 代码：
    eval(unescape(p1) + unescape('%35%34%61%61%32%61%61%36%34%38%63%66%36%65%38%37%61%37%31%31%34%66%31' + p2));
  2. 将 %35%34%61%61%32%61%61%36%34%38%63%66%36%65%38%37%61%37%31%31%34%66%31 部分进行 URL 解码，得到字符串 54aa2aa648cf6e87a7114f1。
  3. 结合评论区提示，使用解码工具对整段 JS 进行 unescape 解码，得到真实的验证逻辑：
    var p1 = function checkSubmit(){
      var a=document.getElementById("password");
      if("undefined"!=typeof a){
        if("67d709b2b54aa2aa648cf6e87a7114f1"==a.value) return 10;
        alert("Error"); a.focus(); return 11;
      }
    }
    document.getElementById("levelQuest").onsubmit=checkSubmit;
  4. 从解码后的 JS 逻辑可以看出两个关键信息：
    1. 真正的密码（值）是完整的： 67d709b2b54aa2aa648cf6e87a7114f1（之前我们以为 54aa2aa... 是完整的，其实是拼接后的后半截）。
    2. 验证元素： JS 是通过 id="password" 来获取用户输入的，但页面 HTML 里写的是 id="flag"。
  5. 在浏览器 F12 的“元素”面板中，双击 HTML 代码，将 <input type="input" name="flag" id="flag" /> 中的 id="flag" 修改为 id="password"。
  6. 在网页输入框中，输入完整的哈希值 67d709b2b54aa2aa648cf6e87a7114f1，点击 Submit 按钮。
  7. 页面成功弹出真实的 Flag：flag{be61014f405c2e768e015b3a13c95f4}。

4. 踩坑记录与复盘

  • Python 脚本无法触发前端 JS 逻辑：这道题我花了大量时间写 Python 脚本去盲打（尝试了 GET、POST 和无数个参数名），全部失败。因为验证逻辑（checkSubmit 函数）完全是运行在浏览器前端的 JS 中的。遇到这种题，浏览器 F12 才是真正的武器，Python 后端请求无法执行前端 JS。
  • HTML 属性（name vs id）的陷阱：提交表单时，服务器接收的是 name 属性的值（这里是 flag）；但在前端 JS 取值时，用的却是 document.getElementById("password")。这种“name”和“id”不一致的迷惑写法，导致直接用 Python 提交参数 password 无效，必须手动在浏览器里修改 id 属性骗过 JS。
  • URL 解码不完整导致卡壳：一开始我提取的哈希值只有 54aa2aa648cf6e87a7114f1，后来通过完整的解码拼接逻辑才发现，完整的值其实是 67d709b2b54aa2aa648cf6e87a7114f1，前面的部分隐藏在 p1 的 js 代码里。
  • 关于这道题的解题过程：看了评论区的提示“改一下html的id为password”后，才恍然大悟这是典型的“欺骗前端”漏洞。这也提醒我，在 Web 安全中，永远不要相信前端的一切数据，因为攻击者可以随意篡改 DOM。
