【Pikachu】Web-XSS-xss之js输出 Writeup

操作者：何芊宏 | 操作日期：2026.9.27 | 分类：Pikachu | 标签：Pikachu, Web, XSS, JS上下文逃逸

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - Cross-Site Scripting (XSS)
  • 题目名称：xss之js输出
  • 目标：输入点位于 <script> 标签内部的 JS 变量中，需要闭合变量赋值语句并注入恶意代码，实现 JS 上下文逃逸。

2. 解题思路与知识点

漏洞原理：

后端将用户输入直接拼接到了 <script> 标签内部的 JS 变量赋值语句中。由于输入被单引号包裹，直接注入 HTML 标签无效。攻击者需要闭合单引号，结束语句，注入 alert()，并用 // 注释掉后续代码，从而实现 JS 代码执行。

JavaScript 上下文逃逸：
  • 注入点环境：var $ms='输入内容';
  • 逃逸 Payload 结构：'; alert(1); //
  • 解析过程：
    1. '：闭合原变量赋值的单引号。
    2. ;：结束当前 JS 语句。
    3. alert(1);：注入执行的恶意代码。
    4. //：注释符，注释掉后面多余的代码（防止语法报错）。

3. 操作步骤

第一步：探测源码

操作： 在输入框输入 Kobe 并提交，F12 查看“源代码/来源 (Sources)”标签。

结果： 发现源码结构为 var $ms='Kobe';，输入被单引号包裹在 JS 变量内部。

第二步：构造逃逸 Payload

Payload： '; alert(1); //

在输入框填入该 Payload 并提交。

第三步：触发执行

结果： 浏览器成功弹出 127.0.0.1 显示 1 的对话框，漏洞利用成功。

现象分析： 拼合后的 JS 代码变为 var $ms=''; alert(1); //';。代码顺利执行完弹窗后，// 将后续无效代码全部注释，避免了语法错误。

4. 踩坑记录与复盘

  • 坑1：尝试使用 HTML 标签注入。初期输入 <script> 或 <img> 均无效。原因是注入环境完全处于 JS 上下文中，HTML 标签会被直接解析为字符串。
  • 坑2：忽略了 // 注释符。如果只闭合引号并写 '; alert(1);，后面原有的代码（如 $('#fromjs').text(...)）会导致语法错误，JS 可能会崩溃从而无法弹窗。带上 // 注释符是完美收尾的关键。

5. 知识总结

  • JS 上下文逃逸的核心逻辑：针对变量赋值、函数参数、对象属性等不同上下文，灵活运用单引号、双引号、分号以及注释符进行闭合和截断。
  • 防御建议：后端不应将用户输入直接拼接进 <script> 标签中。如果必须在 JS 中输出变量，推荐使用 JSON 编码（如 JSON.stringify()），对用户输入进行严格转义，防止闭合逃逸。
