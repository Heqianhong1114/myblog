【Pikachu】Web-XSS-xss之过滤 Writeup

操作者：何芊宏 | 操作日期：2026.9.27 | 分类：Pikachu | 标签：Pikachu, Web, XSS, 黑名单绕过, 标签过滤

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - Cross-Site Scripting (XSS)
  • 题目名称：xss之过滤
  • 目标：后端使用了黑名单机制过滤了特定标签（如 <script>），需要构造其他 HTML 标签绕过过滤，成功执行 JS 弹窗。

2. 解题思路与知识点

漏洞原理：

后端通过简单的黑名单匹配（如直接替换 <script> 字符串）来防止 XSS。但由于 HTML 标签和事件属性的多样性，黑名单极易被绕过。攻击者可以使用 <img> 等其它标签配合事件属性（如 onerror）执行 JS 代码。

换标签 + 事件属性：
  • 既然 <script> 被过滤，我们需要一个合法的 HTML 标签作为载体。
  • 利用 <img src=x onerror=alert(1)>：src=x 指向不存在的图片导致加载失败，触发 onerror 事件，从而执行 JavaScript 代码。

3. 操作步骤

第一步：探测过滤规则

尝试 Payload： <script>alert(1)</script>

现象： 提交后页面回显为“别说这些' >'的话...”，<script> 标签被直接删除，仅留下了 > 符号。

分析结论： 后端存在针对 <script> 的黑名单过滤，属于脆弱的防御方式。

第二步：构造绕过 Payload

Payload： <img src=x onerror=alert(1)>

将该 Payload 输入到输入框中，点击提交。

第三步：触发与验证

回显结果： 浏览器成功弹出 127.0.0.1 显示 1 的对话框。

现象分析： 页面回显区域出现了一个“破损图片”的图标，证明 <img> 标签成功逃逸出黑名单并被浏览器解析执行。

4. 踩坑记录与复盘

  • 坑1：过度依赖 <script> 标签。最初以为只要输入 <script> 就能弹窗，被过滤后意识到必须寻找替代方案。实战中 <img src=x onerror=...> 或 <svg/onload=...> 绕过黑名单的成功率极高。
  • 复盘总结：这关虽然没有难度，但深刻揭示了黑名单过滤的不可靠性。只针对特定字符串（如 <script>）的过滤，可以通过使用其他 HTML 标签和事件属性轻松绕过。真正的防御必须采用白名单策略或完整的 HTML 实体转义。

5. 知识总结

  • 绕过黑名单的常见思路：大小写混淆（<sCript>）、换标签（<img>、<svg>）、换事件（onerror、onload）、编码绕过等。
  • 防御建议：不要试图穷举并过滤恶意字符（黑名单），应使用 OWASP 推荐的输出编码方案（如 PHP 的 htmlspecialchars()），将用户输入强制转换为纯文本。
