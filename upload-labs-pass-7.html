【Upload-Labs】Pass-07 尾随空格绕过 Writeup

操作者：何芊宏 | 操作日期：2026.11.02 | 分类：CTF | 标签：Upload-Labs, Web, 文件上传, 尾随空格, WebShell

1. 题目信息

  • 平台：Upload-Labs (本地 phpStudy 环境)
  • 分类：Web - 文件上传
  • 题目名称：Pass-07 (服务端黑名单校验 - 尾随空格绕过)
  • 提示：黑名单完善，且服务端存在重命名逻辑。

2. 核心原理与前置分析

本关卡的核心漏洞在于代码未对上传的文件名进行去空格处理（未使用 trim() 函数）。

在 Windows 环境下，文件系统通常会自动去除文件名末尾的空格。攻击者通过 Burp Suite 抓包，在 filename 字段的末尾添加一个空格（如 shell.php ）。服务端在校验黑名单时，提取到的后缀为 .php （带空格），不在拦截范围内，从而通过校验。当文件落地到系统时，系统自动去除尾随空格，最终生成合法的 .php 文件。

环境实测：本机环境的重命名逻辑为 date("YmdHis").rand(1000,9999).$file_ext，需在上传后通过 F12 或响应包获取真实的随机文件名。

3. 工具配置与操作步骤

工具配置：Burp Suite 与 中国蚁剑

  • 中国蚁剑：URL 地址需指向随机命名的真实路径；连接密码：cmd；编码：UTF-8。

操作步骤与解析：

第一步：抓包并添加尾随空格

开启 Burp Suite 拦截，上传本地 shell.php。在请求包的 Content-Disposition 字段中，将文件名修改为：

filename="shell.php "

（注意：在 php 与 " 之间必须有一个空格）。

第二步：放行并获取真实路径

点击 Forward 放行。服务器由于未过滤空格，接受文件并重命名保存。查看 HTTP 响应包或在前端使用 F12 审查元素，找到上传后的真实路径（如：../upload/202611022044237560.php）。

第三步：连接与清理

访问该真实路径，页面返回纯白，代码执行成功。使用蚁剑连接该路径，密码 cmd，成功获取权限。连接后删除生成的 .php 文件。

4. 踩坑记录与复盘

  • 实战获取真实路径的技巧：由于没有物理目录的查看权限，实战中必须依赖 HTTP 响应回显。通过 F12 查看源代码或直接检查 Burp 的 Response 标签，搜索关键词 upload/，利用前端回显的 <img src="..."> 标签来提取带时间戳和随机数的真实文件名。
  • 环境差异：部分 Windows 环境在接收带空格的路径时，如果不配合解码，可能会导致 Apache 寻找文件时产生 404 错误。在实际测试中，需根据目标特性灵活结合“尾随点（shell.php.）”等变体进行绕过。

5. 知识点总结

  • 尾随字符绕过：利用系统特性（如 Windows 自动去空格/点）与代码校验逻辑之间的差异，通过添加特殊字符（空格、点）欺骗黑名单检测。
  • 重命名环境下的路径提取：在文件被随机重命名的场景下，信息收集能力（查看源码、抓包分析）决定了能否成功连接到木马。
