【CTFHub】Web-请求方式 Writeup

操作者：何芊宏 | 操作日期：2026.9.15 | 分类：CTF | 标签：CTFHub, Web, HTTP, Python

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - HTTP协议
  • 题目名称：请求方式
  • 提示：Use CTF**B Method, I will give you flag. Hint: If you got [HTTP Method Not Allowed] Error, you should request index.php.

2. 解题思路

页面提示当前方法是 GET，并要求使用 CTF**B 方法。结合平台名可知，我们需要构造一个 HTTP 请求，方法为 CTFHUB，路径为 index.php。我分别尝试了浏览器和 Python 两种方式，并记录了踩坑过程。

3. 操作步骤

解法一：浏览器控制台 Fetch（成功）

按下 F12 打开开发者工具，点击 控制台 (Console) 标签页。在控制台输入以下 JavaScript 代码并回车：

fetch("index.php", {method: "CTFHUB"}).then(r => r.text()).then(console.log)

结果：控制台直接输出了包含 Flag 的页面内容：good job! ctfhub{79a74e6e7ac980d18098457c}。这种方法是最轻量、最直接的解法。

解法二：Python requests 脚本（失败，踩坑记录）

为了验证能否用 Python 自动化脚本实现，我编写了如下代码尝试发送自定义 HTTP 方法：

import requests

url = "http://challenge-a2ed730887ee46bd.sandbox.ctfhub.com:10800/index.php"
headers = {
    'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36',
    'Referer': 'http://challenge-a2ed730887ee46bd.sandbox.ctfhub.com:10800/index.php'
}

r = requests.request(method="CTFHUB", url=url, headers=headers)
print(r.text)

结果：报错 405 Not Allowed，返回内容为 openresty/1.21.4.2。服务器直接拦截了 Python 发出的请求。

4. 踩坑记录与复盘

  • 浏览器与脚本请求的环境差异：为什么 fetch() 能成功，而 Python 失败？因为浏览器在执行 fetch 时，会自动携带当前页面产生的 Cookie、Referer、以及浏览器的安全请求头（如 sec-ch-ua、sec-fetch-mode 等），这构成了完整的浏览上下文。而 Python 即使伪造了 User-Agent 和 Referer，在 WAF 看来依然是一个“缺少指纹”的裸请求，直接被拦截。
  • 工具选择的优先级：在做这种纯前端的 HTTP 方法测试时，最优先使用 F12 控制台，成功率高且速度快。当脚本被 WAF 拦截时，应立刻意识到“环境差异”的问题，不要死磕脚本，果断换用浏览器。
  • HTTP 请求方法的多样性：HTTP 协议中除了常见的 GET 和 POST，还可以自定义请求方法（如本题的 CTFHUB）。这是 Web 安全基础信息收集的一部分。

5. 知识总结

  • HTTP 请求方法 (HTTP Methods)：
    • GET：请求获取资源（常用于查询）。
    • POST：提交数据（常用于表单提交、登录）。
    • HEAD：类似 GET，但只返回响应头，用于探测资源是否存在。
    • PUT：上传/修改资源。
    • DELETE：删除资源。
    • OPTIONS：探测服务器支持哪些请求方法。
    • 自定义方法：本题的 CTFHUB 就是一个由开发者自定义或框架处理的方法，常用于绕过常规的 WAF 检查。
  • HTTP 状态码 (Status Code)：
    • 200 OK：请求成功。
    • 405 Method Not Allowed：服务器接收到了请求，但拒绝执行该方法。本题中就是 Python 脚本的请求方法被 WAF 拦截，返回了 405。
    • 404 Not Found：请求的资源不存在。
  • 浏览器 Fetch API：在 F12 控制台中，fetch() 是一个基于 Promise 的现代网络请求 API。它能直接继承当前页面的上下文（Cookie、Session、浏览器指纹），非常适合在 CTF 中快速构造自定义请求（如修改 Method、添加 Headers 等），避免环境配置带来的干扰。
