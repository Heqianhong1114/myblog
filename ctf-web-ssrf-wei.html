【CTFHub】Web-SSRF伪协议读取文件 Writeup

操作者：何芊宏 | 操作日期：2026.9.25 | 分类：CTF | 标签：CTFHub, Web, SSRF, 伪协议, file协议, view-source

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - SSRF / 伪协议读取文件
  • 题目名称：伪协议读取文件
  • 环境：通过浏览器访问靶场环境。
  • 目标：尝试去读取 Web 目录下的 flag.php。利用 SSRF 漏洞配合伪协议，读取服务器本地文件源码，绕过外部访问限制。

2. 解题思路与知识点

本关核心考点：利用 file:// 等伪协议读取服务器本地文件。同时考察当回显内容出现乱码时，如何利用浏览器特性提取原始数据。

工具思考：为什么 php://filter 失败，而 view-source 成功？
  • 为什么 php://filter 空白？ 可能是后端过滤了该伪协议，或者 Docker 环境配置禁用了此类封装器。
  • 为什么 file:// 会出现 ???？ 服务器读取 flag.php 后直接输出，但内部包含 <?php 标签和注释。浏览器试图将其渲染为 HTML，识别失败后变成了 ??? 乱码。
  • view-source 的妙用： view-source: 是浏览器级别的命令，强制不渲染页面，直接展示原始文本，从而让藏在 PHP 注释或代码中的 Flag 原形毕露。

3. 详细步骤

第一步：测试伪协议连通性

Payload： ?url=file:///etc/passwd

执行目的：确认 file:// 协议是否被允许，以及目标系统的文件系统结构。

回显结果：成功回显大量 Linux 系统用户信息（如 root:x:0:0...）。

获得信息：确认 SSRF 可以读取本地文件，且确定 Web 服务在 Linux 环境下运行。

第二步：尝试读取目标文件（踩坑）

Payload： ?url=file:///var/www/html/flag.php

尝试绕过 Payload： ?url=php://filter/read=convert.base64-encode/resource=/var/www/html/flag.php

执行目的：读取 Web 目录下的 flag.php。

回显结果：使用 file:// 时回显 ???；使用 php://filter 时回显空白。

获得信息：文件存在但被浏览器渲染成了乱码，且 php://filter 协议在此环境中可能被拦截或禁用。

第三步：使用 view-source 查看源码（终极解法）

Payload： view-source:http://challenge-xxx...:10800/?url=file:///var/www/html/flag.php

执行目的：强制浏览器不渲染乱码，直接以文本形式展示服务器原始响应内容。

回显结果：页面直接显示 PHP 源码，其中包含 // Flag is ctfhub{e641e8a250cc8b16b204732b}。

获得信息：成功提取 Flag，提交通关。

4. 踩坑记录与复盘

  • 坑1：不要迷信标准答案。 网上很多 WP 都是说用 php://filter。但环境在变，遇到读不出或者空白时，不要死磕，赶紧换思路。
  • 坑2：乱码不等于没读到。 出现 ??? 说明服务器发回了内容，只是浏览器处理坏了。这时候在浏览器地址栏最前面加 view-source:，或者在 BP 的 Repeater 里点 Raw，是排查此类问题的黄金法则。

5. 知识总结

  • file:// 协议： 读取本地文件系统的一把好手，无视 Web 服务器路由，直接读底层文件。
  • view-source: 技巧： 这不是黑客技术，而是浏览器调试技巧。当怀疑源码被浏览器错误渲染时，一定要想到它。
  • 协议过滤对抗： SSRF 环境可能对协议进行黑白名单过滤（比如禁用 php://），遇到卡壳时，可以用 file:// 读源码的方式绕过。
