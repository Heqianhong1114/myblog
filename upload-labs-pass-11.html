【Upload-Labs】Pass-11 双写绕过 Writeup

操作者：何芊宏 | 操作日期：2026.11.02 | 分类：CTF | 标签：Upload-Labs, Web, 文件上传, 双写绕过, WebShell

1. 题目信息

  • 平台：Upload-Labs (本地 phpStudy 环境)
  • 分类：Web - 文件上传
  • 题目名称：Pass-11 (服务端黑名单替换 - 双写绕过)
  • 提示：服务端不再使用黑名单数组比对，而是使用字符串替换函数过滤危险后缀。

2. 核心原理与前置分析

本关卡的核心漏洞在于后端过滤函数 str_ireplace() 的执行逻辑。

源码中使用了 str_ireplace($deny_ext, "", $file_name) 将黑名单词汇（如 php）从文件名中删除。然而，该函数是从左向右扫描字符串，一旦匹配到连续的目标字符就将其删除，然后继续向后扫描，且不会造成重叠匹配。

因此，攻击者可以通过“双写”技巧，构造形如 root.pphphp 的文件名。代码找到中间的 php 并删除后，剩余的首尾部分拼接起来，恰好还原成了合法的 root.php，从而实现绕过。

3. 工具配置与操作步骤

工具配置：Burp Suite、浏览器开发者工具 与 中国蚁剑

  • 中国蚁剑：URL 地址：http://127.0.0.1:8081/upload/root.php；连接密码：cmd；编码：UTF-8。

操作步骤与解析：

第一步：抓包构造双写 Payload

开启 Burp Suite 拦截上传请求，将本地文件 shell.php 的请求字段修改为：

filename="root.pphphp"

点击 Forward 放行请求。

第二步：发现过程与逻辑推演（关键复盘）

上传完成后，直接访问 root. 路径时，页面回显了完整的 PHP 源码（<?php @eval($_POST['cmd']); ?>），且蚁剑连接失败。这引发了对 str_ireplace 执行逻辑的深度质疑。

起初的误判：以为 str_ireplace 会把 root.php 里的 php 再次删除，导致文件变成 root.。

真相的发掘：通过重新审查前端 F12 开发者工具，搜索 /upload，发现真实的回显路径为 <img src="../upload/root.php">。结合函数特性推演：root.pphphp 在扫描时，中间的 php 被删除，剩下的 root.p 和 hp 拼合，刚好形成了 root.php。之前的报错是因为访问 URL 时遗漏了 php 后缀。

第三步：验证与连接

访问真实的纯净路径 http://127.0.0.1:8081/upload/root.php，页面呈现纯白状态。使用蚁剑填入该 URL 和密码 cmd，测试连接成功。随后清理 root.php。

4. 踩坑记录与复盘

  • 对替换函数的误解：在处理字符串替换逻辑时，容易理所当然地认为过滤是“全局彻底”的。实际上，非重叠的单次替换（从左到右扫描）正是双写绕过的生存土壤。
  • URL 路径的完整性：在构造 WebShell 的访问路径时，必须确保后缀的完整性。代码回显源码往往是因为后缀不完整（如只有 root.）导致 Apache 未能触发 PHP 解析器。

5. 知识点总结

  • 双写绕过：利用后端替换函数的单向、非重叠匹配特性，通过嵌套构造危险后缀，使得替换后的字符串重新组合成合法的可执行后缀。
  • 基于回显的源码推理：在遇到回显异常时，利用 F12 审查真实路径并结合代码逻辑反推过滤机制，是黑盒测试中的核心能力。
