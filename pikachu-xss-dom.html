【Pikachu】Web-XSS-DOM型XSS Writeup

操作者：何芊宏 | 操作日期：2026.9.27 | 分类：Pikachu | 标签：Pikachu, Web, XSS, DOM型XSS, javascript伪协议

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - Cross-Site Scripting (XSS)
  • 题目名称：DOM型xss
  • 环境：Burp Suite 自带浏览器，通过 F12 审计前端代码进行漏洞发现与利用。
  • 目标：不经过服务端，利用前端 JavaScript 直接操作 DOM 节点的漏洞，触发弹窗。

2. 解题思路与知识点

漏洞原理：

DOM 型 XSS 完全发生在客户端。前端 JS 获取了用户的输入，并将其赋值给了 innerHTML 等属性，导致浏览器将其解析为 HTML 结构。

【知识点】Payload 上下文决定攻击方式：
  • 若注入点在 HTML 独立标签中，可使用 <script> 或 <img onerror>。
  • 若注入点在标签属性内（如 href），由于浏览器将其视为字符串，无法直接用 HTML 标签突破。
  • 此时必须使用 javascript: 伪协议。该协议告诉浏览器不发起网络跳转，而是将后面的内容作为 JavaScript 代码直接执行。

3. 操作步骤

第一步：探测行为与前端代码审计

操作： 在输入框输入 hello，点击 click me! 按钮。

现象： 页面未回显 "hello"，而是生成了 what do you see? 的文本。

审计过程： 按 F12 打开开发者工具，选中生成的文本元素，发现其 DOM 结构为：<div id="dom"><a href="hello">what do you see?</a></div>。

分析结论： 输入的值被前端的 JS 代码直接拼接到了 a 标签的 href 属性内部。

第二步：构造针对性 Payload 并触发

Payload： javascript:alert(1)

操作： 将 javascript:alert(1) 输入到输入框中，点击 click me!。此时页面会生成一个包含该 Payload 的超链接。

验证： 点击该超链接，浏览器成功弹出对话框 127.0.0.1 显示 1。漏洞利用成功。

4. 踩坑记录与复盘

  • 复盘：为什么选择 javascript: 伪协议？通过 F12 发现，输入内容并没有作为 HTML 标签独立呈现，而是被放进了 <a href="输入内容"> 的引号内。若此时注入 HTML 标签会被当作非法 URL，无法触发解析。因此直接使用 javascript: 伪协议让链接点击时执行代码，是最精准的解法。
  • 坑1：审计代码时大海捞针。在 F12 的 Console 或 Elements 中直接搜 document 或 var 命中了大量第三方库的代码，导致难以定位。正确方法是通过右键“检查”目标元素，或者在搜索框中直接搜 innerHTML 等精确关键词。

5. 知识总结

  • DOM 型 XSS 特点：非持久化，漏洞完全在客户端触发，不经过服务端。常用于前端获取 URL 参数后直接渲染等场景。
  • Payload 上下文的重要性：渗透测试需要先进行细致的“代码审计”，再根据输出点的位置（HTML 标签内、属性内、JS 代码内）精准构造不同的 Payload。
  • 防御建议：前端尽量避免使用 innerHTML、document.write 等危险方法。应使用 innerText 或 textContent 来输出用户输入，这样即使输入了 JS 代码，也会被当作纯文本处理，无法执行。
