1. 题目信息

  • 平台：CTFHub
  • 分类：Web - HTTP协议
  • 题目名称：响应包源代码
  • 提示：HTTP响应包源代码查看

2. 解题思路

题目要求查看“HTTP响应包源代码”。由于浏览器在渲染页面时，会自动解析 HTML，并忽略掉注释（<!-- -->）和隐藏标签，因此直接在页面上看不到 Flag。我们需要使用 F12 开发者工具中的“网络（Network）”面板，抓取并查看服务器返回的原始响应体（Response Body）。

3. 操作步骤

第一步：查看页面与需求分析（踩坑）

开启题目后，页面显示的是一个玩“贪吃蛇”游戏的界面。尝试在页面上右键查看源代码，或者直接按 F12 找元素，都没有发现明显的 Flag。

第二步：F12 抓包与缓存踩坑（踩坑）

按下 F12 打开开发者工具，切换到网络（Network）标签。由于没有历史请求，面板提示“正在录制网络活动...执行某项请求或按 Ctrl+R 即可记录重新加载”。点击刷新（F5）后，抓到了请求，但响应状态码显示为 304（Not Modified）。由于浏览器缓存机制，服务器没有返回完整的响应体源码。

注：这里遇到了缓存坑，普通刷新无法看到完整的源码。

第三步：强制刷新与查看响应（成功）

按住键盘上的 Ctrl + F5 进行强制刷新，绕过本地缓存。再次抓到请求，状态码变为 200（OK）。点击该请求，在右侧面板切换到响应（Response）标签页。在返回的 HTML 源码第14行，成功发现了隐藏在注释中的 Flag。

<!-- ctfhub{587fb62109d0c44eb3e6556e} -->

提取出 Flag 并在平台提交，顺利通关。

4. 踩坑记录与复盘

  • 浏览器渲染机制的障眼法：浏览器的职责是“展示”而不是“原样输出”。它把 HTML 渲染成漂亮的画面，遇到注释符 <!-- --> 会直接跳过，导致用户直接在页面里看不到敏感信息。我们要学会看“原始快递”，而不是“拆包后的商品”。
  • 304 缓存的阻碍：普通 F5 刷新会带上本地缓存标识，服务器返回 304 状态码，不带响应体。一定要养成遇到 Network 抓不到源码时，使用 Ctrl + F5 强制刷新（强制服务器重新下发）的习惯。
  • 全局搜索的重要性：在庞大的响应体里找 Flag，可以善用开发者工具右上角的搜索图标，或者在全屏源代码里按 Ctrl + F 搜索 ctfhub 关键字。

5. 知识总结

  • HTTP 响应包结构：HTTP 响应分为“响应头（Headers）”和“响应体（Body）”。响应头包含状态码（200/304）、服务器信息等；响应体则是服务器发给浏览器的实际 HTML、CSS、JS 源码。
  • 浏览器缓存机制：状态码 304 Not Modified 是浏览器缓存生效的标志，此时没有响应体。Ctrl + F5 可以强制刷新获取状态码为 200 OK 的完整响应。
  • 前端信息泄露漏洞：“前端的一切都是透明的”。开发者千万不要将测试账号、API 密钥、敏感逻辑写在 HTML 注释或前端代码中，因为攻击者可以通过抓包轻松获取。
