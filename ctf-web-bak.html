【CTFHub】Web-bak文件 Writeup

操作者：何芊宏 | 操作日期：2026.9.16 | 分类：CTF | 标签：CTFHub, Web, 信息泄露, 源码审计

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - 信息泄露 / 备份文件下载
  • 题目名称：bak文件
  • 提示：开发者将代码备份文件放在了 web 目录下，导致源码泄露。

2. 解题思路

页面直接给出了提示：“Flag in index.php source code.”。由于 PHP 文件在服务器端会被解析执行，浏览器无法直接查看其源码。但开发者在修改代码时，经常会留下 .bak 后缀的备份文件（如 index.php.bak）。这类文件在服务器上不会被当作 PHP 执行，而是被当作纯文本返回给浏览器，导致源码泄露。

3. 操作步骤

第一步：开启环境与信息收集

开启题目后，页面显示 Flag in index.php source code.。目标非常明确：需要获取 index.php 的源代码。

第二步：构造备份文件 URL（触发下载）

在浏览器地址栏的 URL 末尾拼接备份后缀，访问：http://challenge-xxx.sandbox.ctfhub.com:10800/index.php.bak。按下回车后，浏览器并没有像访问 index.php 那样解析页面，而是直接弹出了“新建下载任务”窗口，说明成功触发了源码泄露。

第三步：源码审计获取 Flag（成功）

下载 index.php.bak 文件（大小仅 204 字节），直接拖入 VS Code 打开。搜索关键字 ctfhub，一眼就在源码第 9 行的注释中找到了 Flag：

ctfhub{b08b31f7db7611edc8989b0a}

提交至平台，顺利通关。

4. 踩坑记录与复盘

  • 源码文件被解析 vs 被下载：PHP 源码之所以在浏览器里看不见，是因为服务器把它“炒熟”了（执行成了 HTML）。而 .bak 后缀是服务器不认识的“生肉”，只能作为静态文件原样传送，这就是信息泄露的本质。
  • 习惯用 VS Code 审计源码：不要用浏览器直接查看源码文件（排版乱、易看漏），直接拖进 VS Code，用代码编辑器的语法高亮和全局搜索，能最快定位 Flag。

5. 知识总结

  • bak 文件泄露：编辑器在保存文件时可能会自动生成 .bak 或 ~ 等备份文件，若被遗忘在 Web 目录下，攻击者可直接通过 URL 拼接下载源码。
  • 源码审计基础：拿到源码后，直接搜索 flag、password、key 等敏感词汇，是 CTF 和真实渗透中最快的突破手段。
  • 安全防御建议：上线前清理临时/备份文件，并在 Web 服务器配置中直接拒绝访问 .bak、.swp、.log 等后缀。
