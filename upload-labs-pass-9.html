【Upload-Labs】Pass-09 ::$DATA 绕过 Writeup

操作者：何芊宏 | 操作日期：2026.11.02 | 分类：CTF | 标签：Upload-Labs, Web, 文件上传, NTFS数据流, WebShell

1. 题目信息

  • 平台：Upload-Labs (本地 phpStudy 环境)
  • 分类：Web - 文件上传
  • 题目名称：Pass-09 (服务端黑名单校验 - 交换数据流绕过)
  • 提示：黑名单过滤严密，且包含服务端随机重命名逻辑。

2. 核心原理与前置分析

本关卡利用了 Windows NTFS 文件系统的交换数据流（Alternate Data Streams, ADS）特性。

在 NTFS 系统中，文件名后加上 ::$DATA 可以指向文件的默认数据流。后端代码在校验黑名单时，提取到的后缀包含 ::$DATA，因此不在黑名单内。当文件通过 move_uploaded_file 落地到 Windows 硬盘时，系统会自动剥离 ::$DATA，将其还原为正常的文件流。

注意：本关卡存在随机重命名机制（date("YmdHis").rand(1000,9999)），最终实际生成的文件名形如 2026xxxxxx.php，我们需要通过前端回显提取真实路径，并且在访问时必须剥离 ::$DATA 伪装。

3. 工具配置与操作步骤

工具配置：Burp Suite、浏览器开发者工具 与 中国蚁剑

  • 中国蚁剑：URL 地址需指向剥离伪装后的随机文件名路径；连接密码：cmd；编码：UTF-8。

操作步骤与解析：

第一步：抓包并追加数据流后缀

开启 Burp Suite 拦截，上传本地 shell.php。在请求包中修改文件名为：

filename="shell.php::$DATA"

点击 Forward 放行。

第二步：F12 搜寻真实路径并卸下伪装

由于服务端重命名，上传后无法直接访问 shell.php。在浏览器按下 F12，搜索关键词 /upload。

在 Elements 面板中，可以看到回显的路径为 <img src="../upload/202611022115153249.php::$data">。

关键操作：在浏览器或蚁剑中访问时，必须将 ::$DATA 部分删除，仅保留基础 PHP 文件名，访问 http://127.0.0.1:8081/upload/202611022115153249.php。

第三步：连接与清理

页面返回纯白，说明代码已被解析。打开蚁剑，使用剥离伪装后的纯净地址连接，密码 cmd，成功获取服务器权限。连接后删除生成的随机 .php 文件。

4. 踩坑记录与复盘

  • 随机重命名下的路径偏差：本关既有数据流伪装，又有随机重命名机制。如果单纯访问 shell.php 会返回 404 错误。必须通过 F12 找到带有时间戳的完整文件名，并在访问时手动去掉 ::$DATA。
  • 伪装与卸妆的分离：在 Burp 中发送带有 ::$DATA 的请求是为了“骗过门卫”（绕过黑名单），而在浏览器和蚁剑中访问纯净的 .php 后缀，是因为“卸妆后”的文件才是真实落地的文件。

5. 知识点总结

  • NTFS 交换数据流（ADS）：Windows 系统中利用 ::$DATA 隐藏文件内容或实现后缀绕过的底层特性。这是 Windows 靶场独有的特殊绕过方式。
  • 信息收集能力：在黑盒测试中，遇到文件名被修改或重命名时，通过 F12 审查元素和响应包查找真实回显，是建立连接的必经之路。
