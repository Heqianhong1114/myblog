【Pikachu】Web-RCE-远程命令执行(exec "ping") Writeup

操作者：何芊宏 | 操作日期：2026.9.28 | 分类：Pikachu | 标签：Pikachu, Web, RCE, 命令注入

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - RCE (Remote Command Execute)
  • 题目名称：exec "ping"
  • 目标：利用后端应用未严格过滤的输入点，通过命令拼接符注入并执行系统命令，获取服务器本地信息。

2. 解题思路与知识点

漏洞原理：

远程命令执行（RCE）漏洞产生的原因，在于应用程序在实现特定功能（如 ping 测试）时，需要调用操作系统底层命令。若开发者未对用户输入的参数进行严格的过滤或转义，直接将用户输入拼接到了系统命令中，攻击者就可以利用系统支持的“命令拼接符”，在原有命令的基础上，追加执行恶意的系统指令。

命令拼接符解析及系统差异：
  • ;：顺序执行。先执行前面的命令，再执行后面的命令。（主要适用于 Linux 系统）
  • &：顺序执行。无论前面的命令执行成功与否，均执行后面的命令。（Windows / Linux 均支持）
  • |：管道符。将前一个命令的输出结果，作为后一个命令的输入参数。（Windows / Linux 均支持）
  • &&：逻辑与。只有前面的命令执行成功，才会执行后面的命令。
  • ||：逻辑或。只有前面的命令执行失败，才会执行后面的命令。

3. 操作步骤

第一步：正常功能测试与目标系统环境判断

操作： 在输入框内输入合法的 IP 地址 127.0.0.1，点击 ping 提交。

回显特征： 页面返回了 ping 命令的执行结果，但中文部分出现大量“”乱码，且回显中明确显示 TTL=128。

原理分析： 乱码是因为靶场运行在中文 Windows 系统下，cmd 命令行默认使用 GBK 编码输出，而网页采用 UTF-8 编码解析导致。TTL=128 是 Windows 操作系统的典型特征（Linux 通常为 TTL=64）。

结论： 后端代码确实执行了系统 ping 命令，且目标环境为 Windows 系统，后续构造 Payload 需使用 Windows 支持的拼接符。

第二步：注入恶意命令并获取执行结果

探测 Payload： 127.0.0.1 ; whoami

回显结果： 无额外命令执行回显。原因在于 ; 是 Linux 的命令分隔符，Windows cmd 无法解析，因此 whoami 未被当作独立命令执行。

攻击 Payload 1： 127.0.0.1 & whoami

回显结果： 先输出完整的 ping 结果，末尾追加输出了 desktop-efb77t1\heqianhong。

攻击 Payload 2： 127.0.0.1 | whoami

回显结果： 仅输出 desktop-efb77t1\heqianhong。

代码成分解释：

  • 127.0.0.1：作为合法参数，用于闭合后端原有的 ping 命令。
  • &：在 Windows 中代表顺序执行。因此系统首先执行了 ping 127.0.0.1，随后忽略了 ping 的成功与否，接着执行了 whoami。所以页面同时出现了 ping 的回显和 whoami 的回显。
  • |：在 Windows 中代表管道符。系统将 ping 127.0.0.1 产生的所有输出流，作为输入传递给了 whoami 命令。由于 whoami 不需要任何输入参数，它直接忽略传入的数据，执行自身逻辑并输出了当前用户名。因此 ping 的回显被管道拦截，未显示在页面上。
  • whoami：Windows 系统内置命令，用于查询当前执行命令的用户身份（此处输出为计算机名\用户名，即 desktop-efb77t1\heqianhong）。

后端源码推测： 根据回显可以断定，后端 PHP 代码存在类似 system("ping " . $_POST['ipaddress']); 的逻辑。变量 $_POST['ipaddress'] 未经任何过滤直接拼接到了 system 函数中，导致了命令注入漏洞。

4. 踩坑记录与复盘

  • 坑1：命令拼接符的系统兼容性问题。初次尝试使用 Linux 常见的 ; 进行命令分割，导致注入失败。复盘原因在于未事先确认目标操作系统类型。通过观察回显中的 TTL=128 和乱码特征，确认了目标为 Windows，及时将 Payload 替换为 & 和 | 后利用成功。在渗透测试中，明确目标操作系统的类型，是构造正确 Payload 的前提条件。
  • 坑2：中文 Windows 系统的回显乱码。输入正常 IP 时出现乱码，对判断漏洞是否执行成功造成了干扰。此问题不影响命令的实际执行。通过比对回显结构（如 TTL、IP 等关键英文字段），依然可以准确判断命令执行状态。

5. 知识总结

  • 漏洞本质：RCE 漏洞的核心在于“信任边界”被打破。用户输入的数据未经处理跨越边界，被当作系统指令执行。
  • 防御措施：针对远程命令执行，最安全的做法是避免在 Web 层直接调用系统命令。若必须调用，应使用严格的白名单机制（例如：只允许输入合法 IP 的正则表达式），或者使用 escapeshellarg() 和 escapeshellcmd() 等函数对用户输入进行彻底转义，隔离数据与指令。
  • 实战启发：在后续的渗透测试中，遇到类似 ping 等调用系统底层命令的功能点时，应优先测试命令注入。构造 Payload 时务必结合目标操作系统的特性（Linux 与 Windows 在编码及命令语法上有巨大差异）。
