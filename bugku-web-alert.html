【Bugku CTF】Web-alert Writeup

操作者：何芊宏 | 操作日期：2026.9.11 | 分类：CTF | 标签：Bugku, Web, JavaScript

1. 题目信息

  • 平台：Bugku CTF
  • 分类：Web
  • 题目名称：alert
  • 描述：flag{}

2. 解题思路

点击“启动场景”后，网页开始无限循环弹窗，根本关不掉。尝试右键查看源码，发现右键被禁用了。按 F12 打开开发者工具，控制台被弹窗卡死，页面源码也刷不出来。我决定放弃常规操作，直接绕过 JS 执行来看原始源码。

3. 操作步骤

  1. 在浏览器地址栏的网址最前面，手动加上 view-source:，比如 view-source:http://160.202.254.160:15894/，按回车。这样浏览器就会直接显示纯文本源码，不再执行任何 JavaScript 弹窗。
  2. 在源码页面按 Ctrl + F 搜索 flag。
  3. 在页面最底部发现了一长串被注释掉的字符：<!--flag{...}-->。
  4. 把这段编码（从 f 开始到 } 结束）全部复制下来。
  5. 新建一个网页标签页，打开开发者工具（F12），切换到“控制台 (Console)”。
  6. 在控制台输入下面这三行代码，把编码变成明文：
var str = "把刚才复制的f...编码粘贴到这里";
var result = str.replace(/&#(\d+);/g, function(match, dec) { return String.fromCharCode(dec); });
console.log(result);
  1. 按回车，控制台打印出 flag{16bf28d2f5d8c747c23b6f26d7d4dac7}。
  2. 把这个 flag 复制去 Bugku 平台提交，验证通过。

4. 踩坑记录与复盘

  • 别跟弹窗硬刚：一开始我以为猛点“确定”就能关掉弹窗，结果点了几十下还在弹。遇到这种无限弹窗的死循环，第一反应应该是想办法阻断前端 JS 执行。这次用的 view-source: 就是个非常直接的方法。
  • 浏览器的控制台被卡死：因为弹窗太多，F12 的控制台有时候会卡住不响应。所以我是先关掉了弹窗页，新开了一个空白页，再打开 F12 的控制台，最后才把代码复制进去运行的。这个顺序很重要，在靶场页面直接跑代码很容易被弹窗打乱。
  • 手动补括号：复制那串编码的时候，因为太长，很容易漏掉最后一个分号或花括号。我当时就漏了一个，导致解码出来的 flag 少了一个右大括号 }，最后是自己手动补上才提交成功的。
  • 什么是 HTML 实体编码：遇到 &#数字; 这种格式，不需要背字典，它就是 HTML 实体编码，对应的是 ASCII 码。用 JS 的 String.fromCharCode() 转换，或者直接去搜“HTML实体编码 在线解码”就能解决。
