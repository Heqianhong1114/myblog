【CTFHub】Web-默认口令 Writeup

操作者：何芊宏 | 操作日期：2026.9.17 | 分类：CTF | 标签：CTFHub, Web, 密码口令, 默认口令, 信息搜集

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - 密码口令 / 默认口令
  • 题目名称：默认口令
  • 提示：系统上线时未修改初始化密码，导致默认口令泄露。

2. 解题思路

开启环境后，发现是一个“亿邮邮件网关”的登录界面。由于页面包含了验证码（Captcha），无法使用 Burp Suite 进行自动化爆破。因此，破局点转向“信息搜集（OSINT）”。根据系统名称“亿邮邮件网关”，在搜索引擎上查找该产品的出厂默认账号密码，从而直接登录获取 Flag。

3. 操作步骤

第一步：尝试弱口令与用户枚举漏洞（踩坑）

尝试输入常见的用户名（如 admin）和弱口令（如 123456）。系统返回 user is not exists，这说明该系统存在“用户名枚举漏洞”，即先校验用户名是否存在，再校验密码。这提示我们需要寻找特定的默认用户名，而不是盲目猜密码。

第二步：搜索引擎信息收集

直接百度/Google搜索关键词“亿邮邮件网关 默认口令”。在搜索结果中，找到了一篇总结了常见设备默认密码的技术文章，其中明确列出了“亿邮邮件网关”的默认凭据：用户名 eyougw，密码 admin@(eyou)。

第三步：登录系统获取 Flag（成功）

返回登录页面，输入默认用户名 eyougw，密码 admin@(eyou)，并正确填写验证码。点击登录后，成功进入后台，页面直接回显了 Flag：

ctfhub{7186b685ce18c05a36d7b55c}

提交至平台，顺利通关。

4. 踩坑记录与复盘

  • 验证码机制阻断自动化爆破：尝试使用 Burp Suite 爆破时，由于每次请求验证码都会变化，自动化脚本难以识别。这体现了验证码在安全防御中的有效性，也强制我们改变攻击策略（从暴力破解转为信息搜集）。
  • 用户枚举漏洞（User Enumeration）：当返回“用户不存在”而非“用户名或密码错误”时，攻击者可以借此枚举出系统内所有真实的用户名。这是信息泄露的一种，为后续攻击提供了极大便利。

5. 知识总结

  • 默认口令漏洞：设备或系统出厂时自带的初始密码。若管理员在部署上线时未及时修改，攻击者只需知道设备型号，即可通过搜索引擎查到默认口令并直接登录系统。
  • 信息搜集（OSINT）：在渗透测试中，信息搜集的价值往往大于直接攻击。了解目标系统的品牌、型号、版本，是寻找公开漏洞和默认凭据的基础。
  • 安全防御建议：设备上线前必须强制修改出厂默认密码；登录失败应使用模糊提示（如“用户名或密码错误”）以防止用户枚举；必须部署验证码机制。
