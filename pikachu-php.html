【Pikachu】Web-PHP反序列化漏洞 Writeup

操作者：何芊宏 | 操作日期：2026.9.29 | 分类：Pikachu | 标签：Pikachu, Web, PHP反序列化, XSS

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - PHP反序列化 (PHP Unserialization)
  • 题目名称：PHP反序列化漏洞
  • 目标：利用后端未过滤的 unserialize() 函数，构造恶意的序列化字符串，还原对象并触发魔术方法，实现 XSS 攻击或代码执行。

2. 解题思路与知识点

漏洞原理：

PHP 序列化（serialize()）用于将对象转换为便于存储或传输的字符串；反序列化（unserialize()）则将该字符串还原为对象。如果后端代码直接接收并反序列化用户可控的输入字符串，攻击者就可以伪造恶意的对象数据。在对象还原过程中，PHP 会自动触发魔术方法（如 __construct、__destruct、__wakeup），从而可能导致敏感信息泄露、代码执行或 XSS 漏洞。

序列化字符串的语法结构：
  • O:长度:"类名":属性数量:{...}：代表一个 Object（对象）。
  • s:长度:"属性名";：代表 String（字符串）类型的属性名。
  • s:长度:"属性值";：代表 String 类型的属性值。

3. 操作步骤

第一步：查看后端源码，审计漏洞点

操作： 使用 VS Code 打开靶场源码文件 vul/unserilization/unser.php，进行白盒审计。

源码分析： 源码定义了一个类 S，包含属性 $test 和一个魔术方法 __construct()。

class S {
    var $test = "pikachu";
    function __construct(){
        echo $this->test;
    }
}

注入点： 后端通过 $_POST['o'] 接收用户输入，并直接传入 unserialize($s) 函数。反序列化成功后会通过 {$unser->test} 输出属性值。源码还留有注释提示：//O:1:"S":1:{s:4:"test";s:29:"<script>alert('xss')</script>";}。

第二步：构造并提交 Payload，触发漏洞

攻击 Payload：

O:1:"S":1:{s:4:"test";s:29:"<script>alert('xss')</script>";}

操作： 将 Payload 粘贴到输入框并点击“提交”。

回显特征： 页面成功弹出内容为 xss 的 JavaScript 警告框。

第三步：Payload 代码组成详细拆解

为了方便理解，我们将上述 Payload 的每一个字符成分进行逐一拆解：

  • O:1:"S"：
    • O：表示这是一个 Object（对象）。
    • 1：表示类名的长度为 1 个字符。
    • "S"：表示类名为 S（对应源码中的 class S）。
  • 1：表示该对象内部含有 1 个属性。
  • { 和 }：大括号用于包裹对象的所有属性键值对。
  • s:4:"test"：
    • s：表示属性名是 String（字符串）类型。
    • 4：表示属性名的长度为 4 个字符。
    • "test"：具体的属性名为 test（对应源码中的 var $test）。
  • ;：代表属性键值对之间的分隔符。
  • s:29:"<script>alert('xss')</script>"：
    • s：表示属性值是 String（字符串）类型。
    • 29：表示属性值字符串的实际长度。计算方式：<script>(8个字符) + alert('xss')(12个字符) + </script>(9个字符) = 29 个字符。
    • "<script>alert('xss')</script>"：属性的具体值，即恶意的 XSS 攻击代码。

第四步：漏洞触发链条分析

后端执行逻辑：

  1. 接收用户 POST 提交的 o 参数。
  2. 调用 unserialize() 函数，将序列化字符串还原为类 S 的对象。
  3. 对象属性 test 被赋值为 <script>alert('xss')</script>。
  4. 代码通过 {$unser->test} 将该属性值输出到页面 HTML 中。
  5. 浏览器将输出的内容解析为 JavaScript 脚本并执行，弹窗出现。

4. 踩坑记录与复盘

  • 坑1：F12 无法查看后端代码。初次测试时，尝试在浏览器按 F12 搜索 class 关键字，结果匹配到的全是 CSS 和 JS 前端库文件。
    原因排查： F12 只能查看 HTML、CSS 和 JS 代码，无法查看运行在服务器端的 PHP 代码。必须使用 VS Code 打开源码文件进行白盒审计。
  • 坑2：序列化字符串长度计算错误导致解析失败。初次构造 Payload 时，将属性值的长度误算为 33（s:33:"...";），提交后页面提示“大兄弟,来点劲爆点儿的!”，反序列化失败。
    原因排查： unserialize() 函数严格按照字符串中声明的长度来解析数据。长度不匹配会导致解析过程直接中断。
    解决办法： 精确计算攻击代码的字节数，修改为正确的长度 29，成功触发 XSS 弹窗。

5. 知识总结

  • 漏洞本质：PHP 反序列化漏洞的本质是“信任边界失效”。后端信任了用户提交的序列化字符串，在还原对象时触发了不可控的魔术方法，导致恶意代码被执行。
  • 防御措施：禁止将用户输入直接传递给 unserialize() 函数。如果必须使用，应对序列化字符串进行严格的签名验证（如 Hash 校验），确保数据未被篡改。建议使用 JSON 等更安全的数据格式代替 PHP 序列化。
  • 实战启发：遇到接收序列化数据的接口，应立即查看后端源码，找出定义的类、属性及魔术方法，根据源码逻辑构造对应的序列化 Payload。在构造过程中，必须极其严谨地计算字符串的字节长度，包括转义符号。
