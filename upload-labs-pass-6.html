【Upload-Labs】Pass-06 大小写绕过与环境坑突破 Writeup

操作者：何芊宏 | 操作日期：2026.11.02 | 分类：CTF | 标签：Upload-Labs, Web, 文件上传, 大小写绕过, 环境配置, WebShell

1. 题目信息

  • 平台：Upload-Labs (本地 phpStudy 环境)
  • 分类：Web - 文件上传
  • 题目名称：Pass-06 (服务端黑名单校验 - 大小写绕过)
  • 提示：黑名单中封堵了各类常见脚本后缀（包括混合大小写），且服务端存在文件重命名逻辑。

2. 核心原理与前置分析

本关卡的核心漏洞在于黑名单匹配缺乏统一的格式化处理。

分析源码可知，黑名单数组 $deny_ext 中包含了 .php、.php5 甚至 .pHp 等各种组合，但代码并未使用 strtolower() 将所有输入统一转换为小写，且遗漏了全大写形式 .PHP。由于 Windows 操作系统及 Apache 在匹配文件后缀时对大小写不敏感（能识别 .PHP 为 PHP 脚本），因此可以通过全大写后缀绕过黑名单限制。

环境坑注意：本机为 mod_fcgid 环境，Apache 的 AddHandler 是不区分大小写的，因此能识别 .PHP 为脚本。但 FcgidWrapper 在注册 PHP 解释器路径时，仅针对全小写 .php 注册了解析器。这会导致访问大写 .PHP 时，Apache 找不到对应的解析器，从而返回 500 Internal Server Error。

3. 工具配置与操作步骤

工具配置：中国蚁剑

  • 中国蚁剑：URL 地址指向带随机数的真实文件名；连接密码：cmd；编码：UTF-8。

操作步骤与解析：

第一步：准备 Payload 并上传

将包含 <?php @eval($_POST['cmd']); ?> 的文件重命名为 test.PHP，在网页直接上传。

由于服务端存在 date("YmdHis").rand(1000,9999) 的重命名机制，需在本地物理目录 D:\phpstudy_pro\WWW\upload-labs\upload 中查找到上传后的真实文件名（例如 202611022034121897.PHP）。

第二步：处理环境坑（500 错误修复）

浏览器访问该文件时，返回 500 Internal Server Error。此时需在物理目录下手动创建 .htaccess 文件，强制为 .PHP 后缀补上解释器映射。写入内容如下：

AddHandler fcgid-script .PHP
FcgidWrapper "D:/phpstudy_pro/Extensions/php/php5.4.45nts/php-cgi.exe" .PHP

保存后，再次访问该 .PHP 文件，页面返回纯白，PHP 代码被成功解析。

第三步：连接与清理

使用蚁剑连接该带随机数的真实路径，密码填 cmd，成功获取权限。连接后立即删除目录下的 .htaccess 及上传的 .PHP 文件，避免配置残留。

4. 踩坑记录与复盘

  • 网页上传 .htaccess 被拦截：尝试通过网页表单直接上传 .htaccess 被服务端拒绝，说明本关黑名单已补充了该配置文件的拦截。解决方法为直接进入物理目录手动创建该文件。
  • 遗漏了文件重命名逻辑：上传后直接访问原名 test.PHP 导致 404，因为在 Pass-03 之后，服务端普遍开启了随机文件名重命名。需建立先查看物理目录或源码找到真实文件名的习惯。

5. 知识点总结

  • 大小写绕过：利用代码中未对后缀进行统一小写化处理的缺陷，使用全大写后缀（如 .PHP）绕过黑名单检测。
  • FcgidWrapper 机制：明确了在 FastCGI 环境下，AddHandler 负责识别后缀，而 FcgidWrapper 负责绑定解释器。当两者在大小写处理上存在差异时，需通过配置覆盖来修复环境。
