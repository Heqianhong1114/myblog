Windows 软件卸载故障排障记录：Python Error 5

操作者：何芊宏 | 操作日期：2026.9.12 | 分类：系统运维 | 标签：Windows, 排障, Python, Error5

前情提要

为了环境兼容性，我决定把电脑上的 Python 3.14 卸载掉，重装一个更稳定的 Python 3.12.6 版本。结果在控制面板卸载时，踩到了 Windows 的一个经典报错——Error 5。

系统弹窗提示：Could not set file security for file 'D:\Config.Msi\...'. Error: 5. Verify that you have sufficient privileges to modify the security permissions for this file.

简单说就是：D盘的这个文件夹拒绝访问，权限不够，无法卸载。常规的卸载按钮点了没反应，陷入了死循环。

第一回合：常规卸载失败

操作：打开控制面板 -> 卸载程序，找到 Python 3.12.6，双击点击“卸载”。

结果：进度条卡住，反复弹出 Error 5，提示“拒绝访问”。

原因分析：我去查了一下，D:\Config.Msi 是 Windows Installer 的临时缓存文件夹。系统后台有个叫 msiexec.exe 的服务正在运行，它锁住了这个文件，导致当前用户没有权限去动它。

第二回合：尝试夺取文件所有权

既然权限不够，那就用命令行强行把权限抢过来。我以管理员身份打开了 CMD，敲了这两条命令：

takeown /f "D:\Config.Msi" /r /d y
icacls "D:\Config.Msi" /grant administrators:F /t

结果：命令跑完没报错，说明权限夺回来了。但再次去控制面板卸载，还是弹 Error 5。

原因分析：哪怕文件的所有权拿到了，后台运行的 Windows Installer 服务依然锁着它，这就好比文件在我名下，但被别人用胶水黏住了，我还是撕不下来。

第三回合：潜入安全模式

为了避开后台服务的干扰，我按住 Shift 键，点击开始菜单里的“重启”，进入了“安全模式”。

在安全模式下点击卸载按钮。

结果：弹出了新的报错——0x80070641 - 无法访问 Windows Installer 服务。

踩坑：安全模式默认不启动 Windows Installer 服务。没有这个服务，所有基于 MSI 的程序都没法安装或卸载。这条路直接被系统物理封锁了。

最终解决：用微软官方工具强拆

常规手段全都失效后，我去找了微软官方的卸载修复工具：Microsoft Program Install and Uninstall Troubleshooter（程序安装和卸载疑难解答）。

下载下来的文件后缀是 .meta.diagcab，在 Win11 系统下，需要右键点击它，然后点击“显示更多选项”，才能看到“以管理员身份运行”。

打开工具后，选择“卸载” -> 在列表中找到 Python 3.12.6 -> 点击下一步。

它绕过了常规的权限检查，强行清理了损坏的注册表和锁死的文件，最后弹出了 Uninstall was successful。终于把它扬了！

踩坑记录与复盘

  1. 血的教训——安装路径要纯英文：我最初把 Python 装在了 D:\Open Browser下载\python，这个路径里有中文“下载”和空格。这是极其错误的做法，极易引发各种莫名其妙的报错（这次卡死的 Config.Msi 就在D盘）。以后装开发环境，直接默认C盘，或者选纯英文无空格的目录。
  2. 系统排障的层级：
    • 第一层：常规卸载不行，就去任务管理器里把 Python 相关进程全结束掉，再试。
    • 第二层：权限不够，用 takeown 和 icacls 命令强行夺权。
    • 第三层：后台服务锁死，进安全模式绕过（但可能被 Win Installer 服务不启动反杀）。
    • 最终手段：直接下载微软官方的疑难解答工具，不要自己去死磕注册表，容易把系统搞崩。
  3. 不要动不动就重装系统：遇到这种报错，先搜索报错代码（如 Error 5, 0x80070641），大概率能找到同款受害者，按照他们的步骤来，省时省力。
