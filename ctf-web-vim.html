【CTFHub】Web-vim缓存 Writeup

操作者：何芊宏 | 操作日期：2026.9.16 | 分类：CTF | 标签：CTFHub, Web, 信息泄露, 源码审计, vim缓存

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - 信息泄露 / 备份文件下载
  • 题目名称：vim缓存
  • 提示：开发人员在使用 vim 编辑器时，异常退出会留下缓存文件，引发源码泄露。

2. 解题思路

Vim 是 Linux 下常用的代码编辑器。在编辑 index.php 时，Vim 会自动生成隐藏的交换文件 .index.php.swp。如果编辑过程中 SSH 断线或异常退出，该缓存文件会被留在服务器上。通过 URL 拼接直接下载该文件，即可获得源码快照。由于 .swp 是二进制格式，需要使用 VS Code 的十六进制查看器或 strings 命令来提取可读字符串。

3. 操作步骤

第一步：开启环境与信息收集

开启题目后，页面提示“flag 在 index.php 源码中”。

第二步：构造 Vim 缓存文件 URL

在浏览器地址栏拼接 Vim 交换文件后缀（注意前面有个点）：http://challenge-xxx.../.index.php.swp。回车后，浏览器触发文件下载任务，文件大小 12.02 KB。

第三步：十六进制查看器审计（成功）

下载文件后，直接拖入 VS Code。由于 .swp 是二进制文件，直接以 UTF-8 格式打开会出现大量乱码。此时启用 VS Code 的十六进制查看模式，或直接搜索 ctfhub。最终在二进制数据中，成功提取出字符串 Flag：

ctfhub{6d2620078e6306285a01466d}

提交至平台，顺利通关并销毁环境。

4. 踩坑记录与复盘

  • 二进制文件与文本文件的区别：.bak 文件是纯文本，直接搜索即可；但 .swp 文件是 Vim 的内存原始缓冲数据（二进制），需要学会使用十六进制工具（如 VS Code 的 Hex Editor 插件或 strings 命令）来提取不可见字符中的可读文本。
  • 注意安全操作习惯：开发人员在使用 vim 编辑完文件后，应正常 :wq 保存退出，避免异常退出留下敏感的缓存文件。

5. 知识总结

  • vim 缓存漏洞：文件名为 .文件名.swp（如 .index.php.swp）。该文件包含当前编辑缓冲区的完整内容。
  • 十六进制分析基础：在安全审计中，大量日志、内存转储、二进制程序都是十六进制。学会直接看 Hex 甚至 ASCII 转换，是进阶安全研究的必修课。
  • 安全防御建议：在服务器上设置禁止访问以 .swp、.swo 等开头的文件，并及时清理编辑器的临时目录。
