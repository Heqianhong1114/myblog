【Pikachu】Web-XXE漏洞Payload构造与深度解析 Writeup

操作者：何芊宏 | 操作日期：2026.10.1 | 分类：Pikachu | 标签：Pikachu, Web, XXE, Payload解析

1. 背景信息

在 Pikachu 靶场 XXE 关卡中，我们通过提交特制的 XML 数据，成功读取了服务器本地系统文件 win.ini。本文档专门针对我们构造的 Payload 进行逐一拆解与深度解析，以彻底理解 XML 外部实体注入漏洞的运作机制。

2. 构造的 Payload 原文

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE root [
<!ENTITY xxe SYSTEM "file:///C:/Windows/win.ini">
]>
<root>&xxe;</root>

3. Payload 代码组成详细拆解

3.1 XML 声明部分

<?xml version="1.0" encoding="UTF-8"?>

  • <?xml：XML 处理指令的开始标志，告知解析器即将处理 XML 数据。
  • version="1.0"：指定解析器使用的 XML 版本。
  • encoding="UTF-8"：指定文档的字符编码格式。
  • ?>：XML 处理指令的结束标志。

3.2 文档类型定义（DTD）部分

<!DOCTYPE root [ ... ]>

  • <!DOCTYPE root：声明文档的根元素为 root。
  • [ ... ]：方括号内部是 DTD 的实体定义区域，用于声明自定义实体。

3.3 外部实体声明部分

<!ENTITY xxe SYSTEM "file:///C:/Windows/win.ini">

  • <!ENTITY：声明一个 XML 实体。
  • xxe：实体的名称。后续在 XML 中可以通过 &xxe; 来引用它。
  • SYSTEM：关键字，表明该实体的内容来源于外部资源，而非直接写在 XML 内的普通字符串。
  • "file:///C:/Windows/win.ini"：**恶意攻击载荷**。使用 file:// 协议指定了本地文件系统的路径。这里的 URI 指向了 Windows 系统下的 win.ini 配置文件。解析器在遇到该实体时，会去读取该文件的内容并加载。

3.4 实体引用与触发部分

<root>&xxe;</root>

  • <root>：文档的根元素。
  • &xxe;：引用我们刚才声明的实体 xxe。此时，解析器会将 win.ini 文件的实际内容替换到该位置。
  • </root>：根元素闭合。

4. 后端解析逻辑与数据流向

4.1 后端代码逻辑

靶场源码（xxe_1.php）中的核心逻辑为：

$xml = $_POST['xml'];
$data = @simplexml_load_string($xml, 'SimpleXMLElement', LIBXML_NOENT);
if($data){
    $html.="<pre>{$data}</pre>";
}

4.2 数据流向分析

  1. 程序接收前端 POST 提交的 xml 参数，将其赋值给变量 $xml。
  2. 调用 simplexml_load_string() 函数解析该 XML。由于显式传入了 LIBXML_NOENT 参数，解析器允许加载并替换外部实体。
  3. 解析器遇到 <!ENTITY xxe SYSTEM "file:///C:/Windows/win.ini">，根据 SYSTEM 关键字指定的 URI，读取服务器上的 C:/Windows/win.ini 文件内容。
  4. 解析器遇到 &xxe;，将其替换为刚才读取到的文件内容。
  5. 解析完成，生成一个包含文件内容的 SimpleXMLElement 对象。代码将其赋值给 $data。
  6. 通过 {$data} 将内容输出到页面的 <pre> 标签中，攻击者成功获取文件内容。

5. 拓展与防御

  • 读取 PHP 源码：Payload 中的路径可以替换为 Web 目录下的 PHP 文件，如 file:///D:/phpstudy_pro/WWW/pikachu/index.php，利用 php://filter/read=convert.base64-encode/resource=... 可以防止乱码。
  • 内网探测（SSRF）：将 SYSTEM 后的协议替换为 http://，可以探测内网服务器是否开放端口（例如：<!ENTITY xxe SYSTEM "http://192.168.1.1:80">）。
  • 防御策略：应禁止使用 LIBXML_NOENT 参数，或使用 libxml_disable_entity_loader(true) 禁用外部实体加载。同时，严格过滤用户输入的 XML 数据。
