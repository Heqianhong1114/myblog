【SQLi-Labs】Less-50 ORDER BY 堆叠注入 Writeup

操作者：何芊宏 | 操作日期：2026.10.28 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, ORDER BY注入, 堆叠注入, WebShell

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-50 (GET - ORDER BY - Stacked Query)
  • 提示：注入点为 sort 参数，纯数字型 ORDER BY $id，后端支持多语句执行。

2. 核心原理：ORDER BY 堆叠注入

本关卡虽在 ORDER BY 处注入，但后端使用了 mysqli_multi_query()。这意味着我们可以利用分号 ; 强行结束当前的排序查询，并开启一条全新的 SQL 语句。

由于不受列数和查询逻辑的限制，可以直接利用 INTO OUTFILE 将木马写入磁盘，实现从 SQL 注入到系统权限的突破。

3. 操作步骤与解析

第一步：构造堆叠注入写马

输入 URL：?sort=1; select '' into outfile 'D:/phpstudy_pro/WWW/sqli-labs-master/Less-50/shell.php'-- -

回显现象：页面正常渲染了原定的用户列表。这是因为原本的 SELECT ... ORDER BY 1 被正常执行并回显，而分号后面的写入语句属于“盲执行”。

第二步：本地验证与蚁剑连接

前往物理路径 D:\phpstudy_pro\WWW\sqli-labs-master\Less-50\，确认生成了 shell.php（1KB）。

打开中国蚁剑，新建数据：

  • URL 地址：http://localhost/sqli-labs-master/Less-50/shell.php
  • 连接密码：cmd

连接成功后，进入文件管理界面，即可查看目标服务器的目录结构。

4. 踩坑记录与复盘

  • 回显错觉：在 ORDER BY 堆叠注入中，页面通常会正常显示数据，这是因为前端代码只处理了第一条 SELECT 的结果。写文件的操作虽然成功，但不会在页面抛出提示，必须依赖本地文件系统进行验证。

5. 知识点总结

  • 堆叠注入的破坏力：突破了普通注入只能查询的限制，能够直接执行写文件、改表、甚至执行系统命令（若有相应函数权限）。
