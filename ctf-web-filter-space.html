【CTFHub】Web-RCE 命令注入-过滤空格 Writeup

操作者：何芊宏 | 操作日期：2026.9.26 | 分类：CTF | 标签：CTFHub, Web, RCE, 命令注入, 过滤空格, ${IFS}, 重定向符

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - RCE / 命令注入
  • 题目名称：过滤空格
  • 环境：浏览器 + 输入框提交。
  • 目标：在空格字符被过滤的情况下，利用 Linux 特性替代空格，拼接命令并读取 Flag。

2. 解题思路与知识点

本关核心考点：命令注入中空格的绕过方式，以及输入重定向符的运用。

知识点（比喻说明）：
  • 空格替代思路： 在 Linux 命令中，空格用于分隔命令和参数。当空格被黑名单拦截时，我们就像“不能开口说话”的特工，必须用其他手势来传递信息。常用的替代品有 ${IFS}（系统内置变量，代表空格）、<（输入重定向符）、%09（Tab键的URL编码）。
  • 输入重定向符 <： cat<flag.php 相当于 cat flag.php。它不需要空格，而且与命令紧挨着，极其适合绕过空格和短字符串过滤。
  • 对比：SQL注入 vs 命令注入： 在 SQL 注入中，/**/ 是经典的注释符，能完美替代空格；但在 Linux Shell 中，/ 是路径分隔符，* 是通配符，cat/**/flag 无法解析为一个正确的文件路径，因此在此语境下无法替代空格。

3. 详细步骤

第一步：源码审计与漏洞定位

<?php
if (isset($_GET['ip']) && $_GET['ip']) {
    $ip = $_GET['ip'];
    $m = [];
    if (!preg_match_all("/ /", $ip, $m)) {
        $cmd = "ping -c 4 {$ip}";
        exec($cmd, $res);
    } else {
        $res = $m;
    }
}
?>

代码逐行解析：

  • preg_match_all("/ /", $ip, $m)：过滤了参数中的空格字符。
  • 其他逻辑与之前的命令注入相同，只需要绕过空格的限制即可。

第二步：探测目标文件（使用 ${IFS}）

Payload： 127.0.0.1;ls${IFS}/

为什么要输入：验证漏洞存在并查看根目录。使用 ${IFS} 替代原本的 `ls /` 之间的空格，Linux 会自动将 `${IFS}` 解析为空格。

回显结果：成功列出根目录，发现根目录无 flag，推测 flag 在当前目录。

Payload： 127.0.0.1;ls

回显结果：发现目标文件 flag_20149288656555.php。

第三步：使用 base64 和重定向符读取并解码 Flag

Payload： 127.0.0.1;base64<flag_20149288656555.php

为什么要输入：因为文件后缀是 .php，直接读取可能会被浏览器解析成 HTML 隐藏。使用 base64 强转编码可以规避。同时，< 是输入重定向符，将文件内容传给 base64 命令，完美替代了空格，绕过 / / 过滤。

回显结果：得到 Base64 字符串 PD9waHAgLy8gY3RmaHViezYxOTMxNjY4NzhmZmM2YTRkZDA4Yzdi

操作： 将字符串复制到在线工具 https://base64.us 进行解码。

解码结果：<?php // ctfhub{6193166878fc6a4dd08c7b}

4. 踩坑记录与复盘

  • 关于 /**/ 替代空格的误区： 受 SQL 注入影响，曾考虑使用 /**/。但在 Shell 中，这会被解析为路径和通配符，导致命令解析失败。此路不通，必须改用 ${IFS} 或 <。
  • 延续 base64 读取习惯： 直接使用 cat<flag.php 可能会因为文件内容为 <?php // ... 而返回空白。使用 base64 读取是极其稳妥的实战策略。

5. 知识总结

  • 命令注入绕过空格的方法： ${IFS}、<、%09、{cmd,arg}。
  • Web 环境下读源码的黄金组合： 读取文件（base64） + 绕过过滤（<） + 本地解码。
