操作者：何芊宏 | 操作日期：2026.9.26 | 分类：CTF | 标签：CTFHub, Web, RCE, 文件包含, 远程包含, data伪协议, 通配符绕过

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - RCE / 远程包含
  • 题目名称：远程包含
  • 环境：VS Code + 浏览器地址栏 (URL 编码)。
  • 目标：利用远程包含漏洞，配合 data:// 伪协议传输恶意代码，并使用通配符绕过关键字过滤，最终获取 Flag。

2. 解题思路与知识点

本关核心考点：远程文件包含（RFI）与 data:// 伪协议的应用，以及命令执行中的通配符绕过。

知识点（比喻说明）：
  • 远程包含（RFI）： 服务器允许 include 一个外部 URL。它就像一个“代购”，你给它一个网址（如 http://xxx/shell.txt），它会去下载并执行里面的内容。
  • 为什么需要 data:// 伪协议： 在靶场环境中，我们通常没有公网 IP 或 VPS 来让服务器远程下载我们的木马文件。这就像我们没法把武器寄到“代购”手里。data:// 伪协议允许我们在 URL 里直接“凭空捏造”一个数据流，当作文件让服务器包含，绕过了物理传输的限制。
  • 通配符绕过（fla?）： 源码依然过滤了 flag 字符串。但在 Linux 系统中，? 可以匹配任意一个字符。fla? 会被系统解析为 flag，但字符串本身并没有包含完整的 "flag"，完美骗过检测。

3. 详细步骤

第一步：源码审计与漏洞定位

<?php
error_reporting(0);
if (isset($_GET['file'])) {
    if (!strpos($_GET["file"], "flag")) {
        include $_GET["file"];
    } else {
        echo "Hacker!!!";
    }
} else {
    highlight_file(__FILE__);
}
?>
<hr>
i don't have shell, how to get flag?<br>
<a href="phpinfo.php">phpinfo</a>

代码逐行解析：

  • !strpos($_GET["file"], "flag")：检查 file 参数中是否包含 "flag"，包含则拦截。
  • include $_GET["file"];：包含漏洞点。没有限制必须以 php:// 开头，说明我们可以使用 data:// 或 http:// 等外部协议。

获得信息：提示“i don't have shell”说明服务器上没有木马，需要我们自己“运送”一个进去。

第二步：利用 data:// 协议执行系统命令寻找 Flag

Payload： ?file=data://text/plain,

URL 编码版： ?file=data://text/plain,

为什么要输入：利用 data:// 伪协议在 URL 中直接构造一段 PHP 代码，让服务器包含并执行。此时 URL 中没有 "flag" 字符串，成功绕过检测。

回显结果：成功列出根目录文件，发现目标文件 /flag。

获得信息：确认 data:// 协议有效，目标文件绝对路径已确定。

第三步：利用通配符绕过过滤读取 Flag

Payload： ?file=data://text/plain,

URL 编码版： ?file=data://text/plain,

为什么要输入：如果直接写 cat /flag，由于参数中包含 "flag"，会被 strpos 拦截报错。使用通配符 fla?，字符串本身不含完整的 "flag"，但 Linux 系统会自动将其匹配为 flag 文件。

回显结果：ctfhub{65162ad2db27e68c40a739ca}

获得信息：成功获取 Flag，提交通关。

4. 踩坑记录与复盘

  • 为什么不用 php://input？ 虽然 php://input 也能达成目的，但本关名为“远程包含”，且源码没有强制 php:// 前缀，使用 data:// 更符合漏洞场景，也更便捷（不需要抓包改 POST，直接 URL 输入即可）。
  • 为什么不用明文 /flag 读源码？ 因为 include 会把 /flag 当作 PHP 文件执行，源码可能没有回显，我们需要的是用 system 函数把它作为纯文本打印出来。
  • 通配符匹配失败的情况： 如果 fla? 匹配失败（例如系统存在多个以 fla 开头的文件），可以尝试使用 [a-z] 匹配，或者更稳妥地使用 php://filter 直接 base64 读源码，但要注意 filter 路径里不能出现 flag（可用 fla? 替代）。

5. 知识总结与横向对比

核心心得：
到这里，我们已经完成了 RCE 技能树中关于“文件包含”的三个经典关卡。这时候回头看，php://input、php://filter、data:// 这仨各有千秋，我们完全可以依照题目限制（是否强制 `php://` 前缀、是否需要回显源码）来选择对应的武器。
伪协议名称 核心用途 前置条件 典型 Payload
php://input 执行 POST 数据流中的代码 需 POST 请求，Body 里写代码 ?file=php://input
php://filter 读取文件源码，不执行 GET 请求即可，配合 Base64 编码 ?file=php://filter/read=convert.base64-encode/resource=/flag
data:// 直接空投代码，无需公网VPS 需服务器开启 allow_url_include ?file=data://text/plain,
