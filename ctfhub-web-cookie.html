【CTFHub】Web-Cookie欺骗 Writeup

操作者：何芊宏 | 操作日期：2026.9.15 | 分类：CTF | 标签：CTFHub, Web, HTTP, Cookie

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - HTTP协议
  • 题目名称：Cookie
  • 提示：Cookie欺骗、认证、伪造

2. 解题思路

题目提示“Cookie欺骗、认证、伪造”，页面显示“hello guest. only admin can get flag.”。HTTP 协议是无状态的，服务器依靠浏览器携带的 Cookie 来判断用户身份。我们需要通过浏览器的开发者工具（F12），找到服务器给我们的“身份凭证”，将其值从普通用户篡改为管理员，从而实现越权获取 Flag。

3. 操作步骤

第一步：查看页面提示

访问题目环境，页面直接显示 hello guest. only admin can get flag.。这说明服务器当前将我们识别为访客（guest），我们需要伪装成管理员（admin）。

第二步：F12 寻找并修改 Cookie（踩坑）

在页面按下 F12 打开开发者工具。第一步习惯性点进了元素（Elements）面板，但这里只能看 HTML 源码，无法修改凭证。随后点击顶部的应用（Application）面板，在左侧找到存储 -> Cookie。展开后终于看到了服务器下发的 Cookie：一个名为 admin，值为 0 的键值对。

注：此处双击值 0，直接将其修改为 1。

第三步：刷新页面获取 Flag（成功）

修改完 Cookie 后，在网页上按 F5 刷新，浏览器重新发起请求，此时请求头中携带的凭证已经变成了 admin=1。服务器信以为真，直接返回了真正的 Flag：ctfhub{73ef87515495ec7c8b82b472}。

4. 踩坑记录与复盘

  • 找错开发者工具面板：初学者很容易停留在“元素”面板找数据，修改 Cookie 必须去“应用”（Application）面板，或者使用“控制台”输入 document.cookie 来操作。
  • 修改后未重新发起请求：Cookie 修改后，如果不刷新页面，当前的浏览器内存中依然是旧的身份。按 F5 重新发送请求，服务器才能收到修改后的值。
  • 可能存在的编码防伪：这道题的 Cookie 是明文。如果遇到 Cookie 类似 YWRtaW49MA== 这种乱码，需要先 Base64 解码 -> 修改 -> 重新 Base64 编码，再替换回去。

5. 知识总结

  • HTTP 无状态与 Cookie 机制：HTTP 协议本身不记录用户状态，Cookie 就像是服务器发给浏览器的“通行证”。浏览器每次请求都会自动带上它。
  • Cookie 欺骗与越权原理：系统过度信任客户端传来的数据。如果服务端仅仅通过 Cookie 中明文的 admin=0 来判断权限，攻击者就可以篡改通行证，冒充管理员（水平/垂直越权）。
  • 安全防御思路：服务端永远不应该信任客户端的数据。正确的做法是在 Cookie 中只存无意义的 Session ID，真实的权限信息保存在服务端数据库或内存中，每次请求由服务端去查证。
