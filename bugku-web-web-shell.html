【Bugku CTF】Web-网站被黑 Writeup

操作者：何芊宏 | 操作日期：2026.9.13 | 分类：CTF | 标签：Bugku, Web, WebShell

1. 题目信息

  • 平台：Bugku CTF
  • 分类：Web
  • 题目名称：网站被黑
  • 描述：网站被黑了 黑客会不会留下后门
  • 提交格式：flag{}

2. 解题思路

启动场景后，页面显示网站被“中国灰客联盟”黑掉的篡改页（Defacement），并且提示“你的网站存在漏洞”。题目描述明确问“黑客会不会留下后门”，这暗示我们需要去找到黑客上传的 WebShell（一句话木马）。

我先查看了页面源代码（F12），搜索了 flag、shell、backdoor 等关键词，没有找到直接的文件名线索。于是我决定采用最直接的方式：访问常见的后门文件名。

3. 操作步骤

  1. 启动场景，获取靶场地址（例如：http://160.202.254.160:10065）。
  2. 按 F12 查看网页源码，页面底部有一个署名 byharry，这是一个很关键的提示。
  3. 在浏览器地址栏，尝试拼接常见后门文件路径，最终成功访问到 shell.php。
  4. 页面显示了一个蓝色的“WebShell”登录框，要求输入 PASS 密码。
  5. 尝试输入常见的弱口令 hack，点击登录。
  6. 页面直接弹出了 flag{cc0475a393fcae549efdac46e81a7cbb}。
  7. 复制 Flag 去平台提交，验证通过。

4. 踩坑记录与复盘

  • 后门文件名的猜测：在没有源码泄露的情况下，找后门文件最有效的办法就是“猜”和“扫”。常见的 WebShell 名字包括 shell.php、cmd.php、1.php、hack.php、webshell.php 等。这道题用 shell.php 一击即中。
  • 弱口令的危害：这道理非常生动地演示了黑客的心理。他们在留下后门时，往往为了方便记忆，会设置极其简单的密码（如 hack、admin）。在真实的安全加固中，一定要禁止这种弱口令后门的存在。
  • 为什么 Flag 直接吐出来了：这道题可能在设计时就是为了演示基本的渗透流程。进入 WebShell 界面后，不需要复杂的命令执行操作（比如 system('cat flag')），环境直接在页面底层暴露了 flag，属于这道题特有的“送分”环节。
