【Bugku CTF】Web-备份是个好习惯 Writeup

操作者：何芊宏 | 操作日期：2026.9.13 | 分类：CTF | 标签：Bugku, Web, PHP, MD5绕过

1. 题目信息

  • 平台：Bugku CTF
  • 分类：Web
  • 题目名称：备份是个好习惯
  • 描述：备份是个好习惯
  • 提交格式：flag{}

2. 解题思路

题目名称和描述都在强烈暗示“源码备份文件泄露”。启动场景后，页面只回显了一串空字符串的 MD5 值。我尝试在 URL 后拼接常见的备份文件后缀（如 .bak），成功下载到 index.php.bak 源码。审计源码发现，这是一道结合了字符串替换绕过与 PHP 弱类型 MD5 碰撞的经典代码审计题。

3. 操作步骤

  1. 启动场景，获取靶场地址（例如：http://160.202.254.160:19308）。
  2. 在网址后拼接 /index.php.bak，弹出下载框，下载源码并用 VS Code 打开。
  3. 审计关键源码：
    $str = str_replace('key','',$str);
    parse_str($str);
    if(md5($key1) == md5($key2) && $key1 !== $key2){ echo $flag,"取得flag"; }
  4. 构造 Payload 思路：
    • 绕过 str_replace('key', '', ...)：参数名不能直接写 key1，要写成 kkeyey1，这样替换后刚好变成 key1。
    • 满足 md5($key1) == md5($key2)：利用 PHP 的 md5() 函数不能处理数组的特性。传入数组时，md5() 返回 null，null == null 为真，同时数组本身不相等（!== 为真）。
  5. 构造最终 URL：http://靶场地址/?kkeyey1[]=1&kkeyey2[]=2
  6. 按回车，页面成功回显出真正的 Flag：flag{8c09c8d3075e429669acce2d3f070f89}。

4. 踩坑记录与复盘

  • 绕过字符串替换：这是本题的第一个坑。如果直接传 key1=1，str_replace 会把 key 过滤掉，变成 1=1，导致变量名不对。把参数名写成 kkeyey1 是一个非常巧妙的绕过方式。
  • MD5 数组绕过：这是 PHP 安全中极其经典的知识点。不要尝试去硬找两个 MD5 相同的字符串（那是密码学碰撞，极难），直接把参数写成数组（如 ?key1[]=1），让程序报错并返回空值，即可通过弱比较 ==。
  • 备份文件排查思路：以后遇到只显示一串乱码或空白，且题目提示“备份”的 Web 题，第一时间去尝试访问 index.php.bak、index.php~、www.zip 等常见备份文件，这通常是拿源码的最快路径。
