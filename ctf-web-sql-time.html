【CTFHub】Web-SQL注入时间盲注 Writeup

操作者：何芊宏 | 操作日期：2026.9.24 | 分类：CTF | 标签：CTFHub, Web, SQL注入, 时间盲注, SQLmap

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - SQL注入 / 时间盲注
  • 题目名称：时间盲注
  • 环境：通过 Open Browser 打开外部浏览器访问靶场环境。
  • 目标：页面没有任何回显数据，没有报错信息，也没有“真/假”的页面状态变化。唯一能作为判断标准的，是页面的响应时间（延时）。

2. 解题思路与知识点

时间盲注原理：当页面失去一切可视化的反馈时，只能依靠时间差。通过构造 sleep() 函数，让数据库在满足特定条件时“睡”几秒。如果页面卡住了，说明条件为真；如果秒加载，说明条件为假。这是所有盲注中最慢、最考验耐心的一种。

前期试错与信息积累：
  • 输入 1：页面正常返回。
  • 输入 1 and sleep(5)：页面卡了五六秒才加载。这证明了 SQL 语句中的 sleep() 函数被执行了，且该注入点是整数型（无引号包裹）。
  • 核心判断：将“不可见的逻辑”转换为“可见的时间延迟”，这是时间盲注的灵魂。由于手工脚本跑时间盲注耗时长且极易因网络波动失败，再加上上一题的经验，我们再次选择 SQLmap 进行降维打击。

3. 操作步骤与命令对比（核心）

第一步：使用 SQLmap 进行终极脱库

在 CMD 中进入 sqlmap 目录，执行了以下终极命令：

python sqlmap.py -u "http://challenge-xxx.sandbox.ctfhub.com:10800/?id=1" --technique=T --dbms=mysql -T flag -C flag --dump --batch --threads=1

布尔盲注与时间盲注的 SQLmap 命令对比分析：

两次行动脱库目标一致，命令绝大部分参数相同，但以下两个核心参数有本质区别：

  • --technique=B 与 --technique=T（核心不同点）：
    • 布尔盲注（上一关）使用了 --technique=B，明确告诉 SQLmap 使用“页面状态变化（真/假）”来判定。
    • 时间盲注（本关）必须使用 --technique=T，告诉 SQLmap 页面没有任何视觉变化，只能通过“测量请求响应时间”来判定真假，避免工具走弯路去测试其他无效的注入方式。
  • --string="query_success" 的有无（关键差异）：
    • 布尔盲注命令中，我们添加了 --string="query_success"，这是为了适配当时页面会出现“真/假”文字回显的特征，帮工具绕过初始判定。
    • 时间盲注命令中，去掉了 --string 参数。因为时间盲注完全不依赖页面返回了什么内容，而是依赖“卡了多少秒”。匹配字符串在这里没有意义，只会干扰工具对时间的测量。

除了这两个核心差异，其余参数如 --dbms=mysql（指定数据库类型提速）、-T flag -C flag --dump（精确指定表与字段直接脱库）、--batch（全自动运行）以及 --threads=1（强制单线程保护环境不崩溃），在两次行动中完全相同，是 SQLmap 脱库的标准姿势。

SQLmap 命令逐字详细拆解：

  • python sqlmap.py：运行 SQLmap 主程序。
  • -u "URL"：指定目标 URL，必须带上参数（如 ?id=1）。
  • --technique=T：指定使用时间盲注（Time-based blind）。
  • --dbms=mysql：指定后端数据库类型为 MySQL。
  • -T flag -C flag：直接指定目标表名（Table）为 flag，字段名（Column）为 flag。
  • --dump：导出数据（脱库）。
  • --batch：全自动模式，无需人工干预。
  • --threads=1：强制单线程，防止高并发把靶场环境跑崩溃。

执行后，SQLmap 自动调整了延时基准（日志显示：“adjusting time delay to 1 second due to good response times”），并精准完成了脱库，输出Flag：ctfhub{4dd0a14c856809933be95624}，提交通关。

4. 踩坑记录与复盘

  • 坑1：没有回显也没有布尔状态。页面完全不回显，必须转换思维，将时间差作为唯一的判断标准。
  • 坑2：盲目相信手工脚本。虽然手写脚本能锻炼逻辑，但在实战中遇到时间盲注，直接上 SQLmap 才是最高效的。
  • 坑3：SQLmap 参数混用。在时间盲注中如果错误地加上 --string，工具会去匹配页面内容，导致无法利用时间延迟判定真假，从而报错无法注入。

5. 知识总结

  • SQL 注入四大盲区：
    • 联合查询：页面有回显位置。
    • 报错注入：页面无回显，但报错信息可见。
    • 布尔盲注：页面无回显也无报错，但“真/假”状态变化可见。
    • 时间盲注：页面一切静默，仅靠响应时间差判断（本关）。
  • 时间盲注核心函数：sleep(秒数)、if(条件, sleep(5), 0)。
  • SQLmap 工具进阶认知：针对不同盲注场景，灵活切换 --technique 参数，并正确判断是否需要添加 --string。工具只是工具，只有理解了工具背后对应的注入逻辑，才能精准指挥工具解决复杂问题。
