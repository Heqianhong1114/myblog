【Pikachu】Web-RCE-远程命令与代码执行(exec "eval") Writeup

操作者：何芊宏 | 操作日期：2026.9.28 | 分类：Pikachu | 标签：Pikachu, Web, RCE, 代码执行

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - RCE (Remote Code Execute)
  • 题目名称：exec "eval"
  • 目标：利用后端未严格过滤的输入点，实现远程 PHP 代码执行，并通过 PHP 内置函数调用操作系统命令，获取服务器本地信息。

2. 解题思路与知识点

漏洞原理：

远程代码执行（RCE）漏洞中的代码执行类型，其成因在于后端代码使用了类似 eval() 这样的危险函数。该函数会将用户输入的字符串内容，直接作为后端脚本语言（本例中为 PHP）的代码来解析和执行。与命令执行的区别在于，代码执行发生在应用层，可以直接操纵 Web 应用的业务逻辑，且可以直接通过脚本语言的内置函数再次发起系统命令调用，危害层级更高。

命令执行与代码执行的区别：
  • exec "ping"（命令执行）：后端通过 system() 等函数调用操作系统命令，攻击者借用操作系统的“手”执行指令。
  • exec "eval"（代码执行）：后端通过 eval() 等函数将用户输入作为 Web 脚本语言（PHP）的代码执行，攻击者直接控制后端的“大脑”。

3. 操作步骤

第一步：代码执行验证

操作： 在输入框输入 phpinfo(); 并提交。

回显特征： 页面成功渲染出大段的 PHP 环境信息表格。其中 System 一栏显示 Windows NT DESKTOP-EFB77T1 10.0 build 26200 (Windows 10) AMD64。页面显示 PHP Version 7.3.4，底部带有 Zend Engine 标志。

原理分析： 后端代码将用户输入的 phpinfo(); 当作 PHP 代码执行了。phpinfo() 是 PHP 内置函数，用于输出当前 PHP 环境的详细信息。末尾的英文分号 ; 是 PHP 语句结束符。此步骤证明了远程代码执行漏洞存在。

第二步：通过 PHP 函数执行系统命令

攻击 Payload： system('whoami');

回显结果： 输入框上方显示 desktop-efb77t1\heqianhong。

代码成分详细解释：

  • system()：PHP 的系统执行函数。它将字符串参数作为操作系统命令执行，并返回最后的输出行。与 exec() 不同，system() 会自动将命令执行的结果直接输出到页面（flush 输出缓冲）。
  • 'whoami'：作为字符串参数传入 system 函数，指示系统执行 whoami 命令。由于是 Windows 环境，输出结果为“计算机名\用户名”。
  • ;：PHP 语句结束符。

后端源码推测： 后端代码存在类似 eval($_POST['code']); 的逻辑。这比 exec "ping" 层级更高，因为 eval 执行的是 Web 脚本语言代码（PHP），而不仅是系统命令。

4. 踩坑记录与复盘

  • 坑1：phpinfo() 撑爆页面导致输入框丢失。成功执行 phpinfo(); 后，由于输出的 HTML 表格过于庞大，导致原本位于顶部的输入框和提交按钮被挤压至底部或被隐藏，无法继续操作。
    原因排查：后端在执行 eval() 后，再次输出 HTML 表单，但 phpinfo() 输出的 HTML 标签（如 ）影响了浏览器的 DOM 结构解析。
    解决办法：按 F5 刷新页面。在浏览器弹出“确认重新提交表单”时，选择“取消”，随后按回车重新发起 GET 请求，页面即可恢复初始状态，输入框重新出现。
  • 坑2：前端提示“你喜欢的字符还挺奇怪的！”。在执行 system('whoami'); 后，页面出现此提示。
    原因分析：该表单原本的功能可能是对用户输入的字符串进行某种字符处理，而 system('whoami'); 是 PHP 代码，并非其预期的字符，因此脚本在正常执行代码后，出现了不符合预期逻辑的提示。这也侧面印证了输入被当作代码执行。

5. 知识总结

  • 漏洞本质：代码执行比命令执行更接近 Web 应用的底层逻辑，攻击者可以直接编写 PHP 脚本实现文件上传、数据库操作、后门植入等目的。
  • 防御措施：极力避免在生产环境中使用 eval()、assert() 等危险函数。如果必须使用，务必对用户输入进行严格的白名单校验，确保输入内容符合预期的数据结构（如仅允许数字、字母等），切勿直接执行用户提交的任意字符串。
  • 实战启发：遇到回显异常或前端页面显示异常时，可以借助 Burp Suite 进行抓包，在 Repeater 中手动构造 POST 请求进行代码注入测试，从而避免前端排版问题带来的干扰。
