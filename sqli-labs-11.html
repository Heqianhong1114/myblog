【SQLi-Labs】Less-11 POST型报错注入与登录绕过 Writeup

操作者：何芊宏 | 操作日期：2026.10.24 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, POST注入, Burp Suite

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-11 (POST - Error Based - String)
  • 提示：POST请求，基于报错的字符型注入，单引号闭合

2. 工具准备与环境配置

由于本关为 POST 请求，参数未在 URL 中暴露，需使用抓包工具进行拦截与修改。本次使用环境为汉化版 Burp Suite。

工具配置与避坑：

  • 浏览器代理配置：需将浏览器代理设置为 127.0.0.1:8080。
  • 界面显示问题解决：因高分屏或汉化包导致选中文字时蓝标错位、字符重叠。解决方式：在 Burp 的 设置 -> 用户界面 -> 显示 中，勾选“配置缩放设置”并设为 1.0；在 消息编辑器 中将字体修改为“宋体”或“微软雅黑”，大小设为 16pt 并重启生效。

3. 解题思路与解析

进入关卡后，页面为一个登录框（包含 Username 和 Password）。推断后台 SQL 语句为 SELECT * FROM users WHERE username='$uname' AND password='$passwd' LIMIT 0,1。

通过在用户名后添加单引号破坏原有语法，使页面报错，从而确认注入点及闭合方式。随后利用 SQL 注释符 # 或 -- 截断原语句中的密码验证逻辑，实现无需密码直接登录后台（万能密码）。

4. 操作步骤

第一步：抓取 POST 请求

在浏览器登录框随意输入用户名 admin 和密码 123456，开启 Burp 拦截，点击 Submit。将拦截到的请求发送至 Repeater（重放器）。

抓取到的请求体（Body）为：
uname=admin&passwd=123456&submit=Submit

第二步：测试注入点与报错分析

在 Repeater 的 Request 框中，将 uname 的值修改为 admin'：

uname=admin'&passwd=123456&submit=Submit

点击发送后，观察响应包。页面返回 SQL 语法错误：
You have an error in your SQL syntax... near '123456' LIMIT 0,1' at line 1

解释与原理：输入的 admin' 闭合了后台的 username='$uname'，导致后续的 AND password='123456' 语法混乱并报错。确认存在单引号字符型注入。

第三步：利用注释符进行登录绕过

使用 MySQL 注释符 # 来注释掉后续的密码验证代码。在 Request 框中将 Body 修改为：

uname=admin' #&passwd=123456&submit=Submit

点击发送。

执行结果：页面渲染区域成功回显 SUCCESSFUL，并打印出 Your Login name:admin 和 Your Password:admin。

解释与原理：# 符号将后面的 AND password='123456' LIMIT 0,1 全部注释。实际执行的 SQL 变成了 WHERE username='admin'，直接跳过了密码校验，成功以 admin 身份登录。

5. 踩坑记录与复盘

  • POST 注入的特殊性：不能再直接在地址栏修改，必须使用 Burp Suite 等抓包工具拦截请求，在请求体中修改 Payload。
  • 注释符的使用：在 POST 请求体中，# 符号可以直接生效（无需像 URL 那样编码为 %23）。注意 # 后面需跟一个空格或直接换行。
  • 万能密码的本质：不仅限于 ' OR 1=1 #，只要能用注释符截断密码验证部分，就能实现任意已知用户的免密登录。

6. 知识点总结

  • POST 注入：参数在 HTTP 请求体（Body）中传输，常用于表单提交。需要通过抓包工具进行调试。
  • 登录绕过：利用 SQL 注入漏洞，通过闭合单引号并注入注释符，消除后端原有的密码比对逻辑，实现越权登录。
