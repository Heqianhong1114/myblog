【CTFHub】Web-RCE 命令注入-过滤运算符 Writeup

操作者：何芊宏 | 操作日期：2026.9.26 | 分类：CTF | 标签：CTFHub, Web, RCE, 命令注入, 过滤运算符, 命令分隔符, base64读取

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - RCE / 命令注入
  • 题目名称：过滤运算符
  • 环境：浏览器 + 输入框提交。
  • 目标：在 `|` 和 `&` 被过滤的情况下，寻找未被过滤的命令分隔符，读取目标文件。

2. 解题思路与知识点

本关核心考点：命令分隔符的备选与 Web 环境下读取 PHP 源码的正确姿势。

知识点（比喻说明）：
  • 命令分隔符备选： 在 Linux 命令中，`|`（管道）和 `&`（后台/逻辑）是用来拼接命令的常用符号。如果它们被服务器拉黑了（就像保安没收了特定的钥匙），我们可以尝试使用备选钥匙 `;`（分号）。只要 `;` 没被禁用，它就是最可靠的分隔符。
  • 读取 PHP 源码的技巧： `.php` 文件的内容包含 `` 时，如果直接输出，会被浏览器解析为 HTML 标签（隐藏/失效）。必须使用 `base64` 命令编码后输出，再本地解码，这是突破 Web 渲染干扰的终极武器。

3. 详细步骤

第一步：源码审计与漏洞定位

<?php
if (isset($_GET['ip']) && $_GET['ip']) {
    $ip = $_GET['ip'];
    $m = [];
    if (!preg_match_all("/(\||\&)/", $ip, $m)) {
        $cmd = "ping -c 4 {$ip}";
        exec($cmd, $res);
    } else {
        $res = $m;
    }
}
?>

代码逐行解析：

  • preg_match_all("/(\||\&)/", $ip, $m)：核心过滤逻辑。`|` 代表逻辑或，`&` 代表与。正则表达式中 `(\||\&)` 表示匹配 `|` 或 `&` 任意一个。这两个符号都被拦截。
  • $cmd = "ping -c 4 {$ip}";：仍然是拼接命令，漏洞依然存在。
  • 关键发现： 源码只过滤了 `|` 和 `&`，**没有过滤分号 `;`**！这就是我们的突破口。

第二步：探测目标文件

Payload： 127.0.0.1;ls

为什么要输入：使用分号 `;` 拼接 `ls` 命令，列出当前目录下的文件，寻找 Flag 文件。

回显结果：成功发现目标文件 flag_102243129530723.php。

第三步：使用 base64 读取源码

Payload： 127.0.0.1;base64<flag_102243129530723.php

为什么要输入：因为文件后缀是 `.php`，直接读取大概率会因为 `< 是输入重定向符，能有效替代空格。

回显结果：得到 Base64 字符串 PD9waHAgLy8gY3RmaHViezYyZjA0OTdiN2MyYTk1ZjIxZmNkMzM0ZjJ9...

操作： 将字符串复制到在线工具 https://base64.us 进行解码。

解码结果：<?php // ctfhub{a98b7c2a957f21fbd3c34f2}

4. 踩坑记录与复盘

  • 没有盲目尝试 2>&1： 因为源码过滤了 `&` 字符，如果我们习惯性使用 `2>&1` 排错，反而会直接触发拦截（报 Hacker!!）。所以在命令注入中，一定要先看源码的过滤规则，不能生搬硬套排错模板。
  • 关于命令分隔符的选择： 当常规的 `|` 和 `&&`、`||` 被拦截时，果断回退到 `;`。分号在 Linux 中表示“顺序执行”，无论前面的 ping 命令是否超时或失败，后面的命令都会执行，非常适合用于盲注探测。

5. 知识总结

  • Linux 命令分隔符汇总： ;（顺序执行）、|（管道）、&（后台）、&&（逻辑与）、||（逻辑或）、%0a（换行符）。当部分被禁用时，灵活使用其他替代品。
  • Web 读取 .php 源码的黄金定律： 只要目标是 PHP 文件，优先直接上 base64 命令，绕过浏览器解析和 WAF 的字符干扰。
