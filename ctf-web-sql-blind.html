【CTFHub】Web-SQL注入布尔盲注 Writeup

操作者：何芊宏 | 操作日期：2026.9.24 | 分类：CTF | 标签：CTFHub, Web, SQL注入, 布尔盲注, Python脚本, SQLmap

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - SQL注入 / 布尔盲注
  • 题目名称：布尔盲注
  • 环境：通过 Open Browser 打开外部浏览器访问靶场环境。
  • 目标：页面无正常回显数据且无报错信息，仅通过“真/假”状态（如query_success/query_error）反馈。需要通过构造条件，编写脚本或使用工具进行逐字提取。

2. 解题思路与知识点

布尔盲注原理：当页面完全失去数据输出能力时，只能依赖页面状态的改变（如显示"query_success"或"query_error"）来作为布尔值（0或1）的反馈。通过构造逻辑判断语句，一步步推断出数据的内容。

前期试错与信息积累：
  • 输入 1：页面显示 query_success。得到了“真”的页面特征。目的：确认正常业务逻辑，寻找对照基准。
  • 输入 1 and 1=1 / 1 and 1=2：两者均显示 query_success。得到了“后端只校验语法，不校验结果集”的信息。目的与局限：证明普通逻辑判断无法让“假”反馈出现，必须转换思路。
  • 输入 1 and if(1=1, 1, 1/0) 与 if(1=2, 1, 1/0)：前者成功，后者报错。得到了“必须利用 if() 结合 1/0 强制触发除零报错来制造真假差异”的信息。目的：让不可见的盲注，变成可以通过页面状态区分的逻辑判断。
为什么我们最终放弃了 Python 脚本，而选择 SQLmap：
  • 为什么用：手写脚本虽能跑通逻辑，但盲注需要成千上万次请求。网络稍有波动，二分法判断就会出错，导致输出的字符串整体错位（如出现反引号等脏字符），难以提取出正确完整的数据。
  • 为什么可以：我们在前期探索中已经彻底摸清了这题的真假判定标准（query_success 为真，且必须使用布尔盲注）。这种有明确标准且重复性极高的工作，正是 SQLmap 最擅长处理的场景。
SQLmap 是什么？能干什么？怎么用？
  • 是什么：SQLmap 是一款开源的自动化 SQL 注入漏洞检测与利用工具，堪称“工业级脱库神器”。
  • 能干什么：自动探测注入类型（联合、报错、盲注等），识别数据库类型，并自动化脱库（获取库名、表名、字段名、具体数据），甚至支持读写文件和获取系统权限。
  • 后期使用流程：
    1. 探测注入点：python sqlmap.py -u "URL" --batch
    2. 获取所有库名：--dbs
    3. 获取指定库的表名：-D "库名" --tables
    4. 获取指定表的字段名：-T "表名" --columns
    5. 获取具体数据：-T "表名" -C "字段名" --dump

3. 操作步骤

第一步：编写 Python 脚本进行手工自动化（踩坑阶段）

编写了一个基于二分法的 Python 脚本，核心使用 ascii() 和 substr() 函数。但由于盲注请求量大，网络波动导致输出错乱，虽然理论上可行，但实战效率极低，频繁触发脏字符。

第二步：使用 SQLmap 进行终极脱库（成功阶段）

在 CMD 中进入 sqlmap 目录，执行了以下终极命令：

python sqlmap.py -u "http://challenge-xxx.sandbox.ctfhub.com:10800/?id=1" --technique=B --dbms=mysql --string="query_success" -T flag -C flag --dump --batch --threads=1

SQLmap 命令逐字详细拆解：

  • python sqlmap.py：使用 Python 运行 SQLmap 的主程序脚本。
  • -u "URL"：指定目标 URL，注意必须带上参数（如 ?id=1）。
  • --technique=B：指定使用布尔盲注（Boolean-based blind）。告诉工具不用去测联合查询或报错注入，节省时间。
  • --dbms=mysql：指定后端数据库类型为 MySQL，跳过自动指纹识别。
  • --string="query_success"：核心参数。告诉 SQLmap：“只要页面里出现 query_success 这个词，就认定条件为真。” 这直接绕过了 SQLmap 默认的启发式误判。
  • -T flag -C flag：直接指定目标表名（Table）为 flag，字段名（Column）为 flag。
  • --dump：导出数据（脱库）。
  • --batch：全自动模式，遇到询问一律选默认，无需人工干预。
  • --threads=1：强制单线程。盲注对服务器压力极大，多线程容易把靶场环境跑崩溃。

执行后，SQLmap 自动完成了所有猜解工作，输出最终Flag：ctfhub{9829615ad577b88e8b88efc1}，提交通关。

4. 踩坑记录与复盘

  • 坑1：普通逻辑测试无效。单纯的 and 1=2 无法触发“假”的状态，必须使用 if(条件, 1, 1/0) 强制制造差异。
  • 坑2：手写脚本的脆弱性。网络波动会导致二分法定位出错，引发整个字符串的错位（出现反引号、竖线等脏字符），且查错极其困难。
  • 坑3：SQLmap 的初始误判。如果不加 --string 参数，SQLmap 自带的测试逻辑会被这道题的机制欺骗，提示无法注入。必须手动指定特征字符串。

5. 知识总结

  • 布尔盲注核心公式：判断真假必须使用 1 and if(条件, 1, 1/0)。数据提取使用 ascii(substr((子查询), 位置, 1))。
  • 工具与原理的关系：SQLmap 极大地提高了效率，但其底层原理依然是我们手写脚本的逻辑。只有懂得了“为什么”，才能在使用工具报错时精准修正参数（如本次的 --string）。
  • SQLmap 标准流程：-u 指定目标 -> --technique 指定技术 -> --string 指定特征 -> --dbs/--tables/--columns/--dump 逐步脱库。
