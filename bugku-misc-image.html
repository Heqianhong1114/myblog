【Bugku CTF】Misc-这是一张单纯的图片 Writeup

操作者：何芊宏 | 操作日期：2026.9.11 | 分类：CTF | 标签：Bugku, Misc, Python

1. 题目信息

  • 平台：Bugku CTF
  • 分类：Misc（杂项）
  • 题目名称：这是一张单纯的图片
  • 描述：key{}

2. 解题思路

题目说这是一张“单纯”的图片，下载附件后，我尝试用图片查看器打开，结果报错打不开。我猜测出题人修改了图片的文件头或者尾部数据。于是决定使用 VS Code 的 Hex Editor 插件（十六进制编辑器）来打开这张图片，看看它内部的结构。

3. 操作步骤

  1. 下载附件，得到一个名为 file 的压缩包，解压后看到一个无后缀的图片文件。
  2. 打开 VS Code，点击 文件 -> 打开文件，选中这张图片。
  3. 因为是二进制文件，VS Code 会提示无法以文本显示。点击 仍然打开，然后右键文件标签页，选择 重新打开编辑器的方式，点击 十六进制编辑器。
  4. 按 Ctrl + F 搜索 key{，没有搜到明文。
  5. 按 Ctrl + End 滚动到文件最末尾。发现在图片结束标志（IEND）后面，有一长串类似 &#107;&#101;&#121;&#123;...&#125; 的 HTML 实体编码。
  6. 复制这一整段编码（从 &#107; 开始，一直到 &#125; 结束）。
  7. 打开浏览器，搜索“HTML实体编码 在线解码”，进入任意一个在线工具。
  8. 把复制的内容粘贴到“解码”输入框，点击“解码”按钮。
  9. 下方输出框里弹出明文 key{you are right}。把它复制去 Bugku 平台提交，验证通过。

4. 踩坑记录与复盘

  • Python 版本兼容性坑：最初我不想用网页工具，而是想写个 Python 脚本（用 import html）来解码这串实体编码。结果代码运行报错：ModuleNotFoundError: No module named 'html'。查了资料并且对比了 AI 的说法，原因是我安装的 Python 版本太新了（当时是 3.14.7），新版本对这种标准库做了一些更改，导致报错。当时懒得折腾了，就直接去用了在线工具。等明天我把 Python 版本降级到 3.12.6 之后，再重新试试这个脚本。
  • Windows 隐藏扩展名坑：把文件拖进代码里时，代码里写的路径是 2.png，运行提示 FileNotFoundError。后来发现 Windows 系统默认隐藏了扩展名，实际的文件名可能就叫 2，或者在文件夹里看不到后缀。写代码时如果路径不对，要学会去文件夹的“查看”菜单里勾选“文件扩展名”，看清楚了再写。
  • 关于 HTML 实体编码：遇到 &#数字; 这种格式，一般就是 HTML 实体编码。它可以通过在线工具或者 Python 的 html.unescape() 还原，以后不用怕这种东西。
