【Pikachu】Web-XSS-xss之href输出 Writeup

操作者：何芊宏 | 操作日期：2026.9.27 | 分类：Pikachu | 标签：Pikachu, Web, XSS, 伪协议绕过, 黑名单绕过

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - Cross-Site Scripting (XSS)
  • 题目名称：xss之href输出
  • 目标：输入点位于 <a> 标签的 href 属性中，后端过滤了 javascript: 等关键字。需要绕过黑名单触发弹窗。

2. 解题思路与知识点

漏洞原理：

后端将用户输入直接拼接到了 <a href="输入内容"> 的属性值中，且未做严格协议白名单校验。虽然过滤了小写的 javascript: 关键字，但由于 URL 协议不区分大小写，攻击者可以通过大小写混淆绕过黑名单，触发伪协议执行。

伪协议与黑名单绕过：
  • 在 href 属性中，使用 javascript: 伪协议可以直接执行 JavaScript。
  • 后端仅过滤小写字符串（如 str_replace("javascript:", "", ...)）。
  • 浏览器解析伪协议时不区分大小写，因此构造 JaVaScRiPt:alert(1) 即可完美绕过过滤。

3. 操作步骤

第一步：探测与尝试

尝试 Payload 1： " onclick="alert(1)（使用双引号闭合属性注入事件）。

尝试 Payload 2： # " onclick="alert(1)（试图用 # 阻止默认跳转）。

现象： 均无法触发弹窗。检查源码发现，Payload 并未被截断，但事件属性未能成功触发。推测后端过滤了事件属性，或浏览器对空 href 的默认跳转行为干扰了事件执行。

第二步：构造绕过 Payload

绕过 Payload： JaVaScRiPt:alert(1)

利用大小写混合绕过黑名单过滤。

第三步：触发执行

操作： 将 JaVaScRiPt:alert(1) 提交，F12 显示源码为 <a href="JaVaScRiPt:alert(1)">...</a>。点击生成的链接。

结果： 浏览器成功弹出 127.0.0.1 显示 1 的对话框，漏洞利用成功。

4. 踩坑记录与复盘

  • 坑1：陷入属性闭合的思维定式。一心想着闭合属性注入事件（如 onclick/onmouseover），却忽略了最基础的 `javascript:` 伪协议。在 href 属性中，伪协议是最直接的执行方式。
  • 坑2：后端黑名单的脆弱性。后端过滤了小写 `javascript:`，但遗漏了大小写混合的情况。这说明仅靠黑名单过滤是无法应对千变万化的 Payload 构造的。

5. 知识总结

  • 绕过黑名单的常见思路：大小写混淆（如 JaVaScRiPt）、换标签（<img>、<svg>）、换事件（onerror、onload）、编码绕过等。
  • 防御建议：不要试图穷举过滤（黑名单），应对输出到 URL 中的内容使用协议白名单（如只允许 http/https），并对所有的输出进行严格的 HTML 实体转义。
