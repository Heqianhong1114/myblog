【Bugku CTF】Web-头等舱 Writeup

操作者：何芊宏 | 操作日期：2026.9.12 | 分类：CTF | 标签：Bugku, Web, HTTP

1. 题目信息

  • 平台：Bugku CTF
  • 分类：Web
  • 题目名称：头等舱
  • 描述：头等舱

2. 解题思路

启动场景后，页面显示“什么也没有。”。观察题目名“头等舱”，我猜想它可能与“Header（请求头/响应头）”有关，因为“舱”和“Header”读音相似。既然页面上没有东西，那 Flag 很可能藏在 HTTP 响应头里。这时候不能用常规看源码的方式了，得用 F12 抓包。

3. 操作步骤

  1. 点击“启动场景”，进入页面，看到上面确实什么也没有。
  2. 按键盘上的 F12 打开开发者工具。
  3. 点击顶部菜单栏的 网络 (Network) 标签页。
  4. 按 F5 刷新页面，让面板捕获请求。
  5. 点击左侧列表里出现的第一个请求文件（通常是靶场的 IP 地址或端口号）。
  6. 在右侧面板里找到 标头 (Headers) 栏，往下滚动，找到 响应标头 (Response Headers) 区域。
  7. 在响应标头里发现了一行 Flag: flag{eec5bda8be2c27123b770945251b62b4}。
  8. 把这段 flag 复制出来，回到平台提交框粘贴，提交通过。

4. 踩坑记录与复盘

  • 刚开始以为又是个看源码的题：看到页面什么都没有，我的第一反应是右键查看网页源代码，结果里面除了一个“什么也没有”的 HTML 文本，干干净净，什么都没有。后面看到题目名称，才想到应该去 Network 里面看看服务器的底层响应。
  • 刷新网络面板：刚点开“网络”面板时是空的，因为它只能记录打开面板之后发生的请求。所以一定要记得按 F5 刷新一下网页，请求才会被记录下来。
  • HTTP 响应头也是藏东西的好地方：以后遇到页面没有文字、没有图片、什么提示都没有的 Web 题，可以先去“网络”面板里看看响应头（Response Headers）或者请求头（Request Headers）里有没有奇怪的自定义字段。
