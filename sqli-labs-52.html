1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-52 (GET - ORDER BY - Stacked Query - Blind)
  • 提示：注入点为 sort 参数，纯数字型 ORDER BY $id，支持多语句执行，无报错回显。

2. 核心原理与前置分析

本关卡是 Less-50 的盲注版本。后端使用了 mysqli_multi_query() 支持堆叠执行，且为纯数字型注入。

盲区特性：页面不会展示任何由第二条 SQL 语句（如 INSERT 或 INTO OUTFILE）产生的结果或报错。由于第一条 SELECT 语句能成功执行并渲染正常表格，写文件操作完全在后台静默执行，必须通过检查物理文件系统来验证是否成功。

3. 工具配置与操作步骤

工具配置：中国蚁剑

  • URL 地址：http://localhost/sqli-labs-master/Less-52/shell.php
  • 连接密码：cmd

操作步骤与解析：

第一步：构造盲堆叠 Payload 写马

输入 URL：?sort=1; select '' into outfile 'D:/phpstudy_pro/WWW/sqli-labs-master/Less-52/shell.php'-- -

回显现象：页面正常渲染用户列表（如 Dumb/Dumb 等）。没有任何写入成功的提示。

解释与原理：直接使用分号 ; 截断原有的 ORDER BY 查询，并在后方拼接写文件语句。

第二步：本地验证与连接

前往物理路径 D:\phpstudy_pro\WWW\sqli-labs-master\Less-52\，确认 shell.php 已生成（1KB）。使用蚁剑建立连接，成功进入文件管理界面，可接管服务器文件。

4. 踩坑记录与复盘

  • 盲执行的验证：在盲堆叠场景下，不能依赖页面回显来判断执行结果。必须将注意力转移到服务器物理层面（文件是否落地）。
  • 前端页面的迷惑性：页面看似正常显示表格，容易让人误以为 Payload 未执行。实际上原查询与恶意写文件操作是独立并行的。

5. 知识点总结

  • 盲堆叠注入：在彻底失去回显的情况下，利用堆叠特性直接执行写文件等高危操作。
