【Pikachu】Web-SSRF(服务端请求伪造) Writeup

操作者：何芊宏 | 操作日期：2026.10.1 | 分类：Pikachu | 标签：Pikachu, Web, SSRF, curl, file协议

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - SSRF (服务端请求伪造)
  • 题目名称：SSRF(curl)
  • 目标：利用后端使用 curl 发起网络请求且未对用户输入 URL 进行严格过滤的缺陷，构造恶意的 url 参数，读取服务器本地文件，验证 SSRF 漏洞。

2. 解题思路与知识点

漏洞原理：

SSRF（Server-Side Request Forgery，服务端请求伪造）是一种由攻击者构造请求，由服务端发起请求的安全漏洞。本关卡中，后端代码通过 $_GET['url'] 接收用户输入的 URL，并使用 curl_exec() 函数发起请求，最后将请求结果回显。由于没有对 URL 的协议和地址进行白名单过滤，攻击者可以利用 curl 支持的多种协议（如 file://、dict://、gopher:// 等）来读取本地文件或探测内网。

SSRF 与 CSRF 的区别：
  • CSRF：跨站请求伪造，攻击者诱导已登录用户去执行非预期的操作。
  • SSRF：服务端请求伪造，攻击者利用服务器作为跳板，去访问服务器本身能访问到的内部资源。

3. 操作步骤

第一步：触发正常请求并识别参数

操作： 点击页面上的“累了吧,来读一首诗吧”链接。

回显特征： 页面显示了一首诗（普希金《假如生活欺骗了你》）。观察浏览器地址栏，URL 变为：

http://127.0.0.1/pikachu/vul/ssrf/ssrf_curl.php?url=http://127.0.0.1/pikachu/vul/ssrf/ssrf_info/info1.php

参数分析： 后端通过 GET 请求接收名为 url 的参数，并使用 curl 请求了该地址，最后将返回结果输出到页面。

第二步：源码审计确认漏洞

操作： 使用 VS Code 打开源码文件 vul/ssrf/ssrf_curl.php。

源码分析： 代码逻辑如下：

$URL = $_GET['url'];
$CH = curl_init($URL);
curl_setopt($CH, CURLOPT_HEADER, FALSE);
curl_setopt($CH, CURLOPT_SSL_VERIFYPEER, FALSE);
$RES = curl_exec($CH);
curl_close($CH);
echo $RES;

结论： 后端未对 $URL 做任何协议或地址过滤，直接使用 curl 发起请求。且开发者还在代码注释中提示了 file:///etc/passwd 这种读取文件的测试载荷。

第三步：构造 SSRF 攻击 Payload 读取本地文件

操作： 根据源码审计结果，利用 curl 支持的 file:// 协议，直接读取 Web 根目录下的 index.php 源码。

攻击 Payload：

http://127.0.0.1/pikachu/vul/ssrf/ssrf_curl.php?url=file:///D:/phpstudy_pro/WWW/pikachu/index.php

回显特征： 页面成功输出了 index.php 的源码片段（包括 "); } ?> 等代码）以及“提示:欢迎使用,pikachu还没有初始化，点击进行初始化安装!”字样。SSRF 漏洞利用成功。

第四步：Payload 代码组成

  • http://127.0.0.1/pikachu/vul/ssrf/ssrf_curl.php：目标靶场接口地址。
  • ?：URL 参数起始符。
  • url=：后端接收的参数名，用于传递给 curl_init() 函数。
  • file:///D:/phpstudy_pro/WWW/pikachu/index.php：
    • file://：利用 cURL 支持的 file 伪协议，指示服务器读取本地文件。
    • /D:/...：指定目标文件的绝对路径。此处指向了 Web 根目录下的 index.php，用于验证漏洞存在。

后端执行逻辑： 后端调用 curl_init("file:///D:/...") 并执行 curl_exec()，cURL 解析到 file:// 协议后，读取了本地文件的字节流，并通过 echo $RES 输出到页面，攻击者从而获取源码内容。

4. 踩坑记录与复盘

  • 本关未遇到阻碍。 正常触发页面链接后，通过查看源码明确了参数名与过滤逻辑（无过滤），随即利用 file:// 协议构造 Payload，成功读取 Web 目录下的源码文件，漏洞利用过程顺畅，未遇到明显报错或拦截。

5. 知识总结

  • 漏洞本质：SSRF 的本质是“服务端信任边界失效”。服务器作为网络边界的一个节点，具备访问内网、本地文件的能力。一旦攻击者可以控制服务端发起请求的 URL，就相当于获得了从服务器内部发起攻击的权限。
  • 支持的协议与利用方式： cURL 支持多种协议，不同的协议对应不同的攻击手法：
    • http://：访问外部网络或内网服务，可用于端口扫描和信息探测。
    • file://：读取服务器本地文件，这是本次实战中成功利用的协议。
    • dict://：探测内网端口开放情况。
    • gopher://：可用于构造更复杂的请求，攻击内网服务。
  • 防御措施：禁用不必要的 URL 协议（如 file://、dict://、gopher://）；对用户输入的 URL 进行严格的白名单校验，只允许请求指定的外部域名或 IP；限制 open_basedir 配置，防止跨目录读取。
  • 实战启发：遇到包含 URL 参数的接口，应优先测试 SSRF 漏洞。尝试使用 file:// 读取本地文件，或使用 http://127.0.0.1:端口 探测内网服务。
