【CTFHub】Web-Git泄露(Log) Writeup

操作者：何芊宏 | 操作日期：2026.9.19 | 分类：CTF | 标签：CTFHub, Web, 信息泄露, Git, Python

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - 信息泄露 / Git泄露
  • 题目名称：Log
  • 提示：由于开发人员疏忽，将 .git 文件夹部署到了线上，导致源码泄露。尝试使用 GitHack 等工具下载源码。

2. 解题思路

题目直接点明了是“Git泄露”，且子关卡叫“Log”。这说明网站源码里应该有 Flag，但可能被隐藏在了历史提交记录里。基本的思路是：先探测线上环境是否存在 /.git/ 目录，如果有，就使用工具把整个代码库（包括隐藏的版本控制信息）扒下来，然后利用 Git 命令查看历史提交记录，寻找被“删除”的 Flag。

3. 操作步骤

第一步：环境搭建与工具准备

首先，我电脑里原本没有 Git，导师指导我下载了 Git for Windows 安装包。在安装过程中，导师提醒我务必要在选择环境变量的界面勾选 Git from the command line and also from 3rd-party software，这样才能在 VS Code 的终端里直接使用。安装完毕后，我打开 VS Code 确认了 Python 版本（python --version 结果为 3.12.6）。

接着，根据提示去 GitHub 下载了 GitHack 工具（点绿色的 Code 按钮下载 ZIP），解压到了 D:\githack 目录下。

第二步：使用 GitHack 进行初次提取

开启 CTFHub 环境，拿到目标 URL：http://challenge-ee7a38948fd855ac.sandbox.ctfhub.com:10800。在终端里进入 GitHack 目录，执行命令：

python GitHack.py http://challenge-ee7a38948fd855ac.sandbox.ctfhub.com:10800/.git/

工具成功跑通，下载并还原出了 index.html 和 50x.html。但是我用全局搜索 ctfhub 并没有找到 Flag，而且尝试在源码目录执行 git log 时报错了：fatal: not a git repository。经过导师讲解，原来 GitHack 只能抓取最新版本的“快照”，它把 .git 目录弄丢了，所以我们没法在本地查历史。

第三步：更换工具 GitHacker 提取完整历史（成功）

导师让我换用另一个更强大的工具 GitHacker。首先安装它：

pip install githacker

安装成功后，执行提取命令（注意 URL 末尾必须带 /.git/，输出到 ./source_code 文件夹）：

githacker --url http://challenge-ee7a38948fd855ac.sandbox.ctfhub.com:10800/.git/ --output ./source_code

这次工具在 source_code 目录下生成了一个长串字母数字命名的文件夹（ff8ae6e04ac77f81bf414a9635b3b67f），里面包含了完整的 Git 历史记录。

第四步：Git 穿越之旅与终端卡死

在源码文件夹里右键“在集成终端中打开”，敲下 git log。结果终端卡在了一个带冒号 : 的界面（分页器模式）。我尝试按 q 退不出来，甚至出现了乱码。导师果断让我关掉这个终端，重新开一个干净的终端。

重新打开终端后，重新执行 git log，这次看到了关键线索：最新版本是 remove flag，上一个版本是 add flag！原来是出题人写完 Flag 又把它删掉了。

第五步：回退版本，获取 Flag（成功）

因为我们知道 Flag 在上一个版本，直接使用命令让代码库“时光倒流”：

git reset --hard HEAD^

执行后，终端提示回退到了 efcb268 add flag。此时，左侧的资源管理器里凭空出现了一个名为 1149323310334.txt 的随机文件。在终端里输入 cat 1149323310334.txt，或者直接在 VS Code 里点开这个文件，Flag 赫然在目：

ctfhub{c507a64be6a4ac760afa6984}

复制并提交到 CTFHub，成功拿到了金币和经验奖励！

4. 踩坑记录与复盘

  • Git 命令的误用：安装完 Git 后，我试图用 git -v 查看版本，结果系统报错。导师告诉我应该用 git --version。这是一个新手常见的小错误，长知识了。
  • GitHack 的局限性：这题最大的坑就是直接用 GitHack 跑完后，本地只有最新的代码文件，没有 .git 版本控制文件夹，导致没法查看历史日志。这让我意识到，了解工具的底层原理很重要，遇到壁垒时要及时换工具（改用 GitHacker）。
  • 终端里 Git 日志的退出：敲下 git log 后终端陷入“假死”状态，这是因为 Git 默认使用分页器。理论上按 q 应该退出，但我那次不知道为什么卡死了。最终的解决方式是关闭当前 VS Code 终端，重新开一个。以后遇到这种卡住的界面，优先想到直接强制退出。

5. 知识总结

  • Git 泄露漏洞原理：开发人员在上线代码时，把用于版本控制的 .git 目录一并部署到了服务器上。攻击者可以通过访问 /.git/ 下载整个网站的源码以及所有的历史提交记录。
  • GitHack 与 GitHacker 的区别：GitHack 只关注“当前版本”的文件还原，轻量但丢失历史；GitHacker 能完整抓取所有 Git 对象，保留历史记录，适合这种需要回退版本的题目。
  • 核心 Git 命令：
    • git log：查看历史提交记录，看别人的改动意图。
    • git diff HEAD^：对比当前版本和上一个版本的差异，Flag 经常藏在这里的 “-” 行中。
    • git reset --hard HEAD^：强行将代码库恢复到上一个版本（HEAD^ 代表上一个，HEAD~2 代表上上个），让被删除的文件重新出现。
