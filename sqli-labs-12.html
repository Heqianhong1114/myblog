【SQLi-Labs】Less-12 POST型双引号报错注入与绕过 Writeup

操作者：何芊宏 | 操作日期：2026.10.24 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, POST注入, 双引号闭合, Burp Suite

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-12 (POST - Error Based - Double quotes - String - with twist)
  • 提示：POST请求，基于报错的字符型注入，双引号+括号闭合

2. 解题思路与前置原理

本关卡为 POST 类型的登录框，需使用 Burp Suite 抓包修改请求体（Body）中的参数。根据标题中的 "Double quotes" 与 "twist" 推断，后端 SQL 语句的闭合方式发生了变化，非单纯的单引号。需通过输入双引号及括号测试报错，还原闭合结构，进而利用注释符实现登录绕过。

3. 操作步骤与解析

第一步：抓包与测试闭合方式

在登录框输入任意账号密码（如 admin/123），使用 Burp Suite 拦截请求并发送至 Repeater。修改请求体中的 uname 参数：

uname=admin"&passwd=123456&submit=Submit

回显现象：页面抛出 SQL 语法错误，报错信息为 near '123456") LIMIT 0,1' at line 1。

解释与原理：输入的双引号成功打破了原有语法结构，且报错信息暴露了 passwd 参数外部包裹着双引号和括号。推断后台 SQL 语句为 SELECT * FROM users WHERE username=("$uname") AND password=("$passwd") LIMIT 0,1。确认闭合符为 ")。

第二步：利用注释符进行登录绕过

在 Repeater 中，将 uname 参数的值修改为利用闭合符和注释符构造的 Payload：

uname=admin") #&passwd=123456&submit=Submit

回显现象：点击发送后，页面右侧成功渲染出 SUCCESSFUL，并显示 Your Login name:admin 和 Your Password:admin。

解释与原理：Payload 拼接后变为 WHERE username=("admin") #") AND password=("123456") LIMIT 0,1。# 注释符将后续的密码验证逻辑完全截断，导致后端仅验证了用户名存在即返回成功，实现越权登录。

4. 踩坑记录与复盘

  • POST 注入的调试：必须在 Burp Suite 的 Repeater（重放器）中修改请求体，不可在浏览器地址栏直接输入。
  • 闭合符的精准匹配：遇到 POST 型注入，测试单引号无效时，应立刻尝试双引号 " 或双引号加括号 ")。以报错信息中的提示为准。
  • 登录框利用思路：在登录逻辑中，如果存在 SQL 注入，首选利用 # 或 -- 注释掉密码校验部分，快速实现后台绕过。

5. 知识点总结

  • POST 请求注入：参数隐藏在 HTTP Body 中，需借助抓包工具。
  • 双引号与括号闭合：在特定上下文中，需精准匹配双引号和括号的组合，才能成功逃逸原有字符串。
  • 登录绕过（万能密码）：利用 SQL 注释符截断逻辑判断，使查询条件恒成立或跳过密码比对。
