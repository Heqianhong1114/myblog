【CTFHub】Web-目录遍历 Writeup

操作者：何芊宏 | 操作日期：2026.9.16 | 分类：CTF | 标签：CTFHub, Web, 信息泄露, 目录遍历

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - 信息泄露
  • 题目名称：目录遍历
  • 提示：无

2. 解题思路

开启题目环境后，页面显示了一个类似于文件列表的界面，提示为 Index of /flag_in_here。这说明目标服务器配置不当，开启了目录索引功能（Directory Listing），导致我们可以像看自己电脑文件夹一样浏览服务器的目录结构。最初的思路是尝试构造 ../ 进行路径穿越，但在实际测试中遇到了阻碍，最终决定直接手动逐个点击目录来寻找 Flag。

3. 操作步骤

第一步：分析初始页面

访问题目提供的环境网址，页面直接展示了根目录 /flag_in_here/ 下的文件列表。里面包含了四个文件夹：1/、2/、3/、4/。

第二步：手动翻找目录（核心过程）

由于页面可以直接点击，我决定直接手工点开每一个文件夹进行查看。

  • 点击 1/，发现里面还有子文件夹，继续点进 1/1/，发现里面只有 Parent Directory，是个空目录。
  • 点击 2/，没有发现明显的文件。
  • 点击 3/，进入后看到了一个子目录 2/，点击进入 3/2/，发现里面有一个文件 flag.txt。

第三步：获取 Flag

直接点击 flag.txt，浏览器成功加载并显示了文件内容，拿到了 Flag。

4. 踩坑记录与复盘

  • 过度依赖工具导致卡壳：一开始看到“目录遍历”这个考点，第一反应是去用 Burp Suite 抓包改包，或者写 Python 脚本去构造 ../ 路径穿越。但在这个过程中遇到了环境报错，同时由于 Python 的 requests 库会自动解析并抵消 URL 中的 ../，导致脚本一直 404，陷入了僵局。
  • 回归最原始的方法：在工具尝试失败后，突然意识到既然服务器连目录索引都直接暴露出来了，文件就真真实实地放在服务器上。与其用复杂的工具去猜路径，不如直接利用浏览器逐层点击。最终在 3/2/ 这个较深的目录里发现了 flag.txt。
  • CTF中的心态：很多新人遇到题目容易想得太复杂，其实有时候最朴实的手工测试往往最快能出结果。

5. 知识总结

  • 目录遍历（Directory Traversal）与目录索引（Directory Listing）：本题的现象属于服务器配置不当开启了目录索引，允许用户列出目录下的文件。而严格的目录遍历漏洞，通常是指利用 ../ 参数跳出 Web 根目录，读取系统文件（如 /etc/passwd）。
  • 信息泄露的危害：服务器如果开启了目录索引，攻击者可以在没有任何技术门槛的情况下，顺着目录结构一层层翻找敏感文件（如源码备份、数据库配置文件、密码等），造成严重的信息泄露。
  • 防护建议：在 Web 服务器（如 Apache/Nginx）的配置中，应当关闭目录索引功能，禁止用户浏览文件列表。
