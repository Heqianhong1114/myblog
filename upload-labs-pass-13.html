【Upload-Labs】Pass-13 POST 型 %00 截断与替代方案 Writeup

操作者：何芊宏 | 操作日期：2026.11.02 | 分类：CTF | 标签：Upload-Labs, Web, 文件上传, 空字节截断, .htaccess, WebShell

1. 题目信息

  • 平台：Upload-Labs (本地 phpStudy 环境)
  • 分类：Web - 文件上传
  • 题目名称：Pass-13 (POST 型 %00 截断 / 环境受限)
  • 提示：白名单校验，包含 POST 请求体中的 save_path 参数。

2. 核心原理与前置分析

原考点：与 Pass-12 类似，利用空字节截断漏洞。但本关卡将 save_path 放入了 POST 请求体中，需要利用 Burp Suite 在 multipart 表单数据中插入 \x00（空字节）。

环境限制：本机 PHP 版本为 5.4.45，已彻底修复 NUL 字节截断问题，强行测试会返回“上传出错”。

替代方案：依然采用“配置文件劫持”思路。通过物理写入 .htaccess，强制将白名单允许的 .jpg 后缀解析为 PHP 脚本。

3. 工具配置与操作步骤

工具配置：中国蚁剑

  • 中国蚁剑：URL 地址需根据 F12 获取的真实随机路径填写；连接密码：cmd；编码：UTF-8。

操作步骤与解析：

第一步：放置 .htaccess 解析规则

打开物理路径 D:\phpstudy_pro\WWW\upload-labs\upload，创建 .htaccess 文件，写入配置：

AddHandler fcgid-script .jpg
FcgidWrapper "D:/phpstudy_pro/Extensions/php/php5.4.45nts/php-cgi.exe" .jpg

第二步：上传图片马并获取回显

在网页端直接上传包含 WebShell 代码的 shell.jpg。由于服务端存在重命名逻辑，上传后通过 F12 审查元素，搜索 /upload，获取类似 <img src="../upload/3620261102215012.jpg"> 的真实路径。

第三步：验证与连接

浏览器访问该路径，页面呈现纯白，说明代码已被解析。使用蚁剑填入该 URL 及密码 cmd，成功连接。随后清理 .htaccess 和图片马。

4. 踩坑记录与复盘

  • POST 截断与 GET 截断的区别：Pass-12 的截断点在 URL 参数中，浏览器/代理可能会自动解码；Pass-13 的截断点在 POST 包体中，需要保证 NUL 字节原样发送。但由于 PHP 版本限制，这两关在本机均只能走替代方案。
  • 重命名逻辑的阻碍：由于服务端将文件重命名为随机字符串，即使原考点可用，也需要考虑如何获取最终文件名；此时 F12 查找真实路径依然是不可或缺的一步。

5. 知识点总结

  • 服务端环境版本对漏洞的约束：了解 PHP 5.3.4 之后对空字节修复的历史，在实战中遇到高版本环境时，能果断放弃截断尝试，转向逻辑漏洞或配置漏洞。
  • 替代性攻击面：当目标系统的核心漏洞（如截断）被修补时，寻找同一业务逻辑下的其他薄弱环节（如漏防的配置文件解析）是红队必备的破局思路。
