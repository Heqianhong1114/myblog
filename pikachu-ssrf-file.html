【Pikachu】Web-SSRF(file_get_contents) Writeup

操作者：何芊宏 | 操作日期：2026.10.1 | 分类：Pikachu | 标签：Pikachu, Web, SSRF, file_get_contents, php://filter

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - SSRF (服务端请求伪造)
  • 题目名称：SSRF(file_get_content)
  • 目标：利用后端使用 file_get_contents() 读取用户输入文件的缺陷，结合 php://filter 伪协议读取服务器本地源码文件，验证 SSRF 漏洞。

2. 解题思路与知识点

漏洞原理：

本关卡与 SSRF(curl) 漏洞原理类似，但后端使用的是 PHP 的 file_get_contents() 函数来读取用户指定的文件。若未对该函数的输入路径进行严格过滤，攻击者即可利用 file://、php://filter 等伪协议读取服务器本地文件。

直接使用 file:// 读取 PHP 源码会导致源码中的 <?php ... ?> 标签被浏览器解析为 HTML 注释或乱码，导致回显不完整。因此，本次实战采用 php://filter 伪协议，将源码进行 Base64 编码后输出，再手动解码，确保获取完整的源码内容。

file_get_contents() 与 curl 的区别：
  • curl：功能强大的 HTTP 客户端，支持自定义请求方法、头信息等，常用于发起复杂的网络请求。
  • file_get_contents：简单的文件读取函数，主要用于读取本地文件或远程 URL 内容，也支持 php://filter 等流过滤器。

3. 操作步骤

第一步：触发正常请求并识别参数

操作： 点击页面上的“反正都读了,那就在来一首吧”链接。

回显特征： 页面显示了艾青的诗《我爱这土地》。观察浏览器地址栏，URL 变为：

http://127.0.0.1/pikachu/vul/ssrf/ssrf_fgc.php?file=http://127.0.0.1/pikachu/vul/ssrf/ssrf_info/info2.php

参数分析： 后端通过 GET 请求接收名为 file 的参数（注意与上一关的 url 区分），并使用 file_get_contents() 读取了该地址的内容。

第二步：构造 SSRF 攻击 Payload（php://filter）

操作： 利用 php://filter 伪协议读取 index.php 源码，并进行 Base64 编码。

攻击 Payload：

http://127.0.0.1/pikachu/vul/ssrf/ssrf_fgc.php?file=php://filter/read=convert.base64-encode/resource=D:/phpstudy_pro/WWW/pikachu/index.php

回显特征： 页面输出了一长串 Base64 编码字符。

第三步：解码验证漏洞利用结果

操作： 将回显的 Base64 字符串复制，使用 Burp Suite Decoder、Python 脚本或在线工具进行解码。

解码结果： 成功获取 index.php 的部分源码：

{
    $html.=
        "<p >
        <a href='install.php' style='color:red;'>
        提示:欢迎使用,pikachu还没有初始化，点击进行初始化安装!
        </a>
        </p>";
}

结论： 成功读取服务器本地源码文件，SSRF 漏洞利用成功。

Payload 代码组成详细拆解

  • http://127.0.0.1/pikachu/vul/ssrf/ssrf_fgc.php：目标接口地址。
  • ?file=：后端接收的参数名，传递给 file_get_contents() 函数。
  • php://filter：PHP 内置的流过滤器伪协议，允许在读取/写入文件时对数据流进行过滤。
  • /read=convert.base64-encode/：过滤器参数。read 表示读取操作，convert.base64-encode 表示将读取的内容进行 Base64 编码，从而避免 PHP 源码被浏览器渲染为 HTML，确保回显数据的完整性。
  • /resource=D:/phpstudy_pro/WWW/pikachu/index.php：指定目标文件的绝对路径。

后端执行逻辑： 后端执行 file_get_contents("php://filter/read=convert.base64-encode/resource=...")，伪协议读取目标文件内容后，先进行 Base64 编码，再返回给 PHP 脚本。PHP 将其作为普通字符串输出，最终在页面上显示。

4. 踩坑记录与复盘

  • 坑1：Base64 编码字符串过长导致处理困难。 使用 php://filter 读取完整源码后，回显的 Base64 字符串极其庞大（数万字符），浏览器中无法手动完整复制。
    解决办法： 放弃在浏览器里手动操作，改为使用 Burp Suite 拦截请求，将响应包发送到 Decoder 工具中直接解码；或使用 Python 的 base64.b64decode() 函数处理。

5. 知识总结

  • 漏洞本质： 与 curl 关卡的 SSRF 本质一致，均是服务端信任了用户输入的 URL/文件路径，导致攻击者可以利用服务端去访问内部资源。
  • php://filter 的优势： 在读取 PHP 源码时，直接使用 file:// 会导致源码中的 <?php 标签被当作文本解析，或者被浏览器当作 HTML 注释，输出内容可能缺失。使用 php://filter 进行 Base64 编码，能完整保留源码的所有字节流，是读取源码的标准姿势。
  • 防御措施： 禁止 file_get_contents() 等函数接收用户可控的路径参数；如果必须使用，应设置白名单，只允许读取特定目录下的特定文件；在 php.ini 中禁用危险的伪协议。
