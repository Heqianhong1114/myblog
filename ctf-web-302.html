【CTFHub】Web-302跳转 Writeup

操作者：何芊宏 | 操作日期：2026.9.15 | 分类：CTF | 标签：CTFHub, Web, HTTP, Python

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - HTTP协议
  • 题目名称：302跳转
  • 提示：HTTP临时重定向

2. 解题思路

题目提示“HTTP临时重定向”，页面显示“No Flag here!”，点击链接后依然回到原页面。这说明重定向过程掩盖了真正的Flag。我们需要使用 Python 的 requests 库，禁止自动重定向（allow_redirects=False），查看服务器返回的原始302响应体（Body），Flag 很可能就藏在那里。

3. 操作步骤（包含真实试错）

第一步：初次尝试（踩坑）

直接访问根目录 /，脚本返回 200 状态码，页面内容为“No Flag here!”。未发现 Flag。

第二步：访问 index.php 并检查响应头（踩坑）

修改 URL 为 /index.php，脚本返回 302 状态码，说明确实发生了重定向。我检查了响应头中的 Location 字段，发现被重定向到了 /index.html，但响应头中并没有 Flag。

注：第一次判断脚本错误地把页面中的 "No Flag here!" 字符串当成了成功标志，导致误报。

第三步：终极解法（成功）

禁止重定向并打印完整的响应头和响应体。发现真正的 Flag 藏在第一次请求的响应体（Response Body）中。

import requests

url = "http://challenge-e60b98367cfca618.sandbox.ctfhub.com:10800/index.php"

print("[*] 正在查看第一次请求的完整响应...")
# 禁止自动重定向
r = requests.get(url, allow_redirects=False)

print("=== 第一次请求的响应头 ===")
for key, value in r.headers.items():
    print(f"{key}: {value}")

print("\n=== 第一次请求的响应体 ===")
print(r.text)

终端成功打印出真正的 Flag：ctfhub{e8b7f6e485b9f2dec5b6b81f}。

4. 踩坑记录与复盘

  • 浏览器与脚本的“自作聪明”：浏览器和 requests 库默认都很聪明，遇到 302 会自动帮你跳转到下一个页面。这就导致你看不到中转站里到底发生了什么。使用 allow_redirects=False 是拦截重定向、查看中间细节的核心技巧。
  • Flag 不一定在响应头里：很多重定向题会把 Flag 放在 Location 或者 Set-Cookie 头部。但这道题出题人很狡猾，把 Flag 直接放在了第一次请求的 HTML 源码（Body）里。以后遇到 302 题，要把 Header 和 Body 都作为排查对象。
  • 脚本逻辑要精确：写爬虫脚本时，判断“成功”的条件不能仅仅用 "flag" in text，因为很多干扰页面也包含这个单词。更精确的做法是正则匹配 flag{...} 或 ctfhub{...} 的格式。

5. 知识总结

  • 302状态码：表示临时重定向（Moved Temporarily），服务器告诉客户端去新的地址获取资源。
  • Location 响应头：302响应中必须包含的字段，指明了重定向的目标 URL。
  • Python requests 中的 allow_redirects 参数：设置为 False 时，requests 不会自动跟随 302 跳转，而是返回 302 响应本身，这是我们在 Web 安全测试中查看中间过程的必备手段。
