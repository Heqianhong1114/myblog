【SQLi-Labs】Less-43 带括号的 POST 堆叠注入 Writeup

操作者：何芊宏 | 操作日期：2026.10.28 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, 堆叠注入, POST注入, WebShell

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-43 (POST - Stacked Query Injection - String - with twist)
  • 提示：POST 登录框，密码字段无转义，闭合符为 ')，支持堆叠执行。

2. 核心原理与前置分析

本关卡与 Less-42 逻辑一致，后端使用 mysqli_multi_query() 支持堆叠。区别在于闭合上下文变为 password=('$password')。

页面假象与盲执行：注入了带闭合符的 Payload 后，第一条 SELECT 登录校验必然失败，引发页面跳转至 BUG OFF 嘲讽页。但由于堆叠机制，分号 ; 后的 INTO OUTFILE 依然在底层被执行。

3. 工具配置与操作步骤

工具配置：Burp Suite 与中国蚁剑

  • Burp Suite：拦截并修改 POST 请求体。
  • 中国蚁剑：连接生成的木马。URL 为 http://localhost/sqli-labs-master/Less-43/shell.php，密码需严格区分大小写，填入 cmd。

操作步骤与解析：

第一步：抓包与堆叠注入写马

抓取登录请求，在密码字段构造 Payload：

login_user=admin&login_password=1'); select '' into outfile 'D:/phpstudy_pro/WWW/sqli-labs-master/Less-43/shell.php'-- -&mysubmit=Login

第二步：本地确认与连接

回显现象：页面重定向至 BUG OFF 页面。忽略该页面，直接前往物理路径 Less-43 目录下确认生成 shell.php。

使用蚁剑连接成功，进入文件管理界面。

4. 踩坑记录与复盘

  • 参数大小写敏感：PHP 的 $_POST 数组接收参数时严格区分大小写。木马中写的是 ["cmd"]，若在蚁剑配置中填了 CMD，将导致连接失败或无法执行。
  • 404 报错排查：若蚁剑测试连接时报 404 Not Found，通常是因为填入的 URL 缺失了 /shell.php 文件名，或者生成的木马文件已被本地的杀毒软件（如 Windows Defender）隔离删除。

5. 知识点总结

  • 带括号的字符型堆叠注入：上下文闭合符的精准匹配（')）是执行成功的前提。
  • 蚁剑连接排错：掌握连接失败时的排查链路（核对完整 URL 路径、核对密码大小写、检查文件是否被查杀）。
