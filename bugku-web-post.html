【Bugku CTF】Web-POST Writeup

操作者：何芊宏 | 操作日期：2026.9.12 | 分类：CTF | 标签：Bugku, Web, Python, POST

1. 题目信息

  • 平台：Bugku CTF
  • 分类：Web
  • 题目名称：POST
  • 描述：post

2. 解题思路

启动场景后，页面给出了 PHP 源代码。代码逻辑接收名为 what 的 POST 参数，并判断其值是否等于字符串 flag。若是，则输出真正的 flag。需要构造 POST 请求发送参数。

3. 操作步骤

  1. 点击“启动场景”，查看页面 PHP 源码：
    $what=$_POST['what'];
    echo $what;
    if($what=='flag') echo 'flag{****}';
  2. 编写 Python 脚本（使用 requests 库）发送 POST 请求：
    import requests

url = "http://160.202.254.160:18327/"
data = {'what': 'flag'}

r = requests.post(url, data=data)
print(r.text)
  3. 运行脚本，终端输出 flagflag{f528b9d7d0cb8fd63d81d03b9a5922c7}。其中第一个 flag 是 PHP 代码中 echo $what; 打印的输入值，后续拼接的才是真正的 Flag。
  4. 提取 flag{f528b9d7d0cb8fd63d81d03b9a5922c7} 提交，提示正确。

4. 踩坑记录

  • 路径陷阱：编写 Python 脚本时，可能会遇到因为 Windows 隐藏扩展名导致找不到文件的情况。本次解题是通过直接编写代码提交请求，没有读取本地文件，规避了此问题。
  • 字符串拼接：回显 flagflag{...} 是因为代码执行顺序先打印了输入参数（flag），又打印了系统返回的 flag（flag{...}），后续拼接在了一起。提取时需要去掉前面多余的那个单词。

5. 总结与反思

这是一道基础的 Web 传参题。与 GET 题不同的是，POST 参数不在 URL 中传递，需要通过请求体发送。掌握了 Python requests.post() 的用法，这正是自动化脚本解题的实战演练。从最初遇到环境报错的崩溃，到最终用代码成功获取 Flag，这个过程非常宝贵。
