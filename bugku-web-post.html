【Bugku CTF】Web-POST Writeup

操作者：何芊宏 | 操作日期：2026.9.12 | 分类：CTF | 标签：Bugku, Web, Python, POST

1. 题目信息

  • 平台：Bugku CTF
  • 分类：Web
  • 题目名称：POST
  • 描述：post

2. 解题思路

启动场景后，页面直接给出了 PHP 源代码。代码逻辑是接收一个名为 what 的 POST 参数，如果它的值等于字符串 flag，就会输出真正的 flag。GET 题可以直接在网址后面拼参数，但 POST 请求的参数是藏在请求体里的，不能在地址栏直接拼。所以，我决定用 Python 的 requests 库写个脚本发送 POST 请求。

3. 操作步骤

  1. 点击“启动场景”，查看页面给出的 PHP 源码：
    $what=$_POST['what'];
    echo $what;
    if($what=='flag') echo 'flag{****}';
  2. 在 VS Code 中新建文件 post_flag.py，粘贴下面的代码：
import requests

# 靶场地址（注意你自己的端口可能和我不同，要复制自己的）
url = "http://160.202.254.160:18327/"

# 构造 POST 数据
data = {'what': 'flag'}

# 发送 POST 请求
r = requests.post(url, data=data)

# 打印回显内容
print(r.text)
  1. 按 Ctrl + S 保存文件，点击右上角 ▶ 运行。
  2. 终端输出了 flagflag{f528b9d7d0cb8fd63d81d03b9a5922c7}。前面的第一个 flag 是代码里的 echo $what; 打印的，后面的才是真 Flag。
  3. 提取 flag{f528b9d7d0cb8fd63d81d03b9a5922c7}，去 Bugku 提交，验证通过。

4. 踩坑记录与复盘

  • 缺少 requests 库：运行脚本时，如果报错 ModuleNotFoundError: No module named 'requests'，说明还没装这个库。在终端输入 pip install requests -i https://pypi.tuna.tsinghua.edu.cn/simple 安装即可。
  • 字符串拼接：回显 flagflag{...} 不是出错了，而是代码执行顺序的问题：先打印了我传进去的 flag，紧接着又打印了系统的真 flag。以后遇到这种情况，提取后面带花括号的那部分就行。
  • 路径陷阱：用 Python 写文件时经常会遇到找不到文件的报错，这是 Windows 隐藏扩展名搞的鬼。这次因为直接在代码里写 URL，没有读本地文件，所以没被坑到。
