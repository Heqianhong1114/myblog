【Pikachu】Web-文件包含-本地文件包含(File Inclusion local) Writeup

操作者：何芊宏 | 操作日期：2026.9.28 | 分类：Pikachu | 标签：Pikachu, Web, 文件包含, LFI, 路径穿越

1. 题目信息

  • 平台：Pikachu 漏洞练习平台
  • 分类：Web - File Inclusion (本地文件包含)
  • 题目名称：File Inclusion(local)
  • 目标：利用后端未严格过滤的文件包含函数（如 include()），通过构造相对路径穿越目录，读取服务器本地的敏感文件（如 Windows 的 win.ini）。

2. 解题思路与知识点

漏洞原理：

本地文件包含漏洞产生的原因是，Web 应用在引用其他文件（如页面模板、库文件）时，允许用户直接控制要包含的文件路径（如通过 URL 的 filename 参数）。如果后端代码未对该参数进行严格的过滤（如未过滤 ../ 或绝对路径），攻击者就可以利用“路径穿越符”跳出 Web 目录的限制，访问并读取服务器本地任意文件的内容。

本地文件包含（LFI）与远程文件包含（RFI）的区别：
  • File Inclusion (local)：只能包含服务器本地已有的文件。利用方式主要是读取敏感配置文件或配合文件上传漏洞执行 Webshell 代码。
  • File Inclusion (remote)：允许包含远程服务器上的文件。前提是 PHP 配置中开启了 allow_url_include=On。攻击者可直接包含恶意脚本，危害更大。

3. 操作步骤

第一步：正常功能测试与参数分析

操作： 在页面的下拉框中选择一个球员（例如 Kobe），点击提交。

回显特征： 页面成功加载了 Kobe 的图片及介绍文本。同时，浏览器地址栏的 URL 发生变化，变为：http://127.0.0.1/pikachu/vul/fileinclude/fi_local.php?filename=file1.php&submit=提交。

原理分析： 后端代码通过 GET 方式接收了 filename 参数，并将其值（file1.php）传递给 PHP 的 include() 函数执行。这证明 filename 参数是用户可控的注入点。

第二步：路径穿越读取系统文件

攻击 Payload： 在浏览器地址栏修改 filename 参数，使用路径穿越符 ../ 跳出当前目录。

构造 URL： http://127.0.0.1/pikachu/vul/fileinclude/fi_local.php?filename=../../../../../../../../Windows/win.ini&submit=提交

回显特征： 页面内容发生改变，不再显示球员信息，而是直接在页面顶部输出了 Windows 系统配置文件 win.ini 的内容。回显首行为：; for 16-bit app support [fonts] [extensions] [mci extensions] [files] [Mail] MAPI=1。漏洞利用成功。

代码成分详细解释：

  • filename：后端用于接收包含文件路径的参数名。
  • ../（路径穿越符）：在目录结构中表示上一级目录。连续使用多个 ../ 可以不断向上跳转，直到跳出 Web 根目录（此处使用了 8 个 ../，因为靶场 Web 目录嵌套较深，需要足够数量的穿越符才能到达系统盘根目录）。
  • Windows/win.ini：目标系统文件。结合前几关的 RCE 测试，已经确认靶场运行在 Windows 系统。win.ini 是 Windows 的系统配置文件，常用于验证本地文件包含漏洞是否利用成功。

第三步：源码验证

操作： 打开 Visual Studio Code，查看 vul/fileinclude/fi_local.php 源码。

源码逻辑： 后端代码核心逻辑为 $filename = $_GET['filename']; include($filename);，未对 $filename 进行任何过滤与校验，直接拼接并执行，导致了路径穿越漏洞。

4. 踩坑记录与复盘

  • 坑1：前端只提供下拉框，无法直接输入 Payload。下拉框限制了用户只能选择有限的几个选项。
    解决办法： Web 安全测试中，前端限制不是真正的防御。应直接修改浏览器地址栏中的 URL 参数，或使用抓包工具修改 filename 参数的值，直接向后端发送自定义 Payload。本次通过直接修改地址栏 URL 完成了突破。
  • 坑2：路径穿越层级数量的确定。在 Windows 系统下，Web 根目录的嵌套深度未知，若 ../ 数量不足，会报错 failed to open stream: No such file or directory。本次测试中，使用了 8 个 ../ 后成功跳转至系统盘并读取到文件。在实战中，需要根据报错信息灵活调整层级数量。

5. 知识总结

  • 漏洞本质：本地文件包含漏洞的本质是“权限控制失效”。应用把引用文件的权利交给了用户，但未限制用户的引用范围。
  • 防御措施：严格限制包含的文件名，建议使用白名单机制（如只允许包含指定目录下的特定文件）。若必须动态包含，应对用户输入的 ../、..\、绝对路径等进行严格过滤，或者在 PHP 配置中通过 open_basedir 限制文件访问范围。
  • 实战启发：文件包含漏洞常配合文件上传漏洞使用，上传的恶意图片或文档若被 LFI 包含，就能直接触发代码执行，形成完整的攻击链。
