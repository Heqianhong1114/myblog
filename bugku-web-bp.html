【Bugku CTF】Web-bp Writeup

操作者：何芊宏 | 操作日期：2026.9.14 | 分类：CTF | 标签：Bugku, Web, 逻辑漏洞, Burp Suite, 密码爆破

1. 题目信息

  • 平台：Bugku CTF
  • 分类：Web
  • 题目名称：bp
  • 描述：请找出密码（提示：弱密码top1000? z?????）
  • 提交格式：flag{}

2. 解题过程（真实实战记录）

第一步：分析页面与抓包

启动场景，页面为一个登录框。在 F12 的“网络”面板里抓取提交请求，发现表单提交到 check.php，参数名为 username 和 password。根据题目提示，密码是 z 开头、共 6 位的弱密码。

第二步：常规爆破尝试

我先尝试用 Python 脚本结合常见弱密码字典进行爆破，但遇到了 WAF 限流（多线程报错 ConnectionResetError）和靶场响应极慢（约 3 秒/请求）的问题。跑了几百个密码后，没有立刻出结果。

第三步：发现逻辑漏洞（真正的解题捷径）

在翻看评论区寻找思路时，看到一位师傅提示“代码审计：/success.php?code=hacker1000”。我直接去浏览器地址栏拼接并访问了这个 URL：

http://160.202.254.160:13173/success.php?code=hacker1000

结果：页面直接弹出了 Flag！flag{b64b5859d40ea72d7cf73a3a1f6b80d5}。这属于典型的“未授权访问”逻辑漏洞，出题人预留了一个后门，无需输入密码即可通关。

提交平台，验证通过。

3. 延伸学习：体验大佬的“哈希值比对法”（非解题关键）

在提交了 Flag 之后，我对评论区大佬提到的爆破脚本产生了好奇，决定在环境里复现一下他的方法，纯粹为了体验和学习。

核心思想：错误密码返回的页面内容完全一致，我们可以计算“错误页面”的 SHA256 哈希值。爆破时，只要当前响应哈希值不等于这个错误值，就说明密码对了。

import hashlib

def sha(content):
    return hashlib.sha256(content).hexdigest()

# 错误响应的固定哈希值
wrong_hash = "247c884dd6e02d76ebdd175215b353e65ba7c93ab7514df07c802e0f7ec810f"

# 循环比对
if sha(response.content) != wrong_hash:
    print("找到密码了！")

我下载了 top1000.txt 字典，并写好了脚本运行。但跑了 49 分钟进度条才到 100%，最终并没有输出正确密码。事后复盘发现：因为我已经提交了 Flag，靶场环境已经被平台自动关闭了！此时所有的请求都打到了“环境已失效”的页面，全都是同一个结果，这导致了爆破脚本“空转”。

教训：以后拿到 Flag 就立刻收手，不要在环境关闭后去搞“延伸测试”。

4. 踩坑记录与复盘

  • 信息收集与逻辑漏洞挖掘优先于暴力破解：这道题如果真去爆破 z?????，虽然理论上能跑出来，但非常耗时。通过观察源码和尝试常见路径（如 success.php），成功绕过了密码验证，这才是最高效的解法。
  • WAF 与限速：在真实的 Web 渗透中，无脑多线程爆破极易触发防火墙拦截（ConnectionResetError），需要控制并发数或引入延迟。
  • Python 哈希校验思想：虽然这次没跑出结果，但学会了一种更高级的脚本编写思路——通过比对响应内容的哈希值，而不是简单的“长度”或“状态码”来筛选异常响应。
  • 靶场环境的生命周期：Bugku 的靶场环境有生存时间，提交 Flag 后会自动关闭。环境关闭后，所有后续的请求都会失效。
