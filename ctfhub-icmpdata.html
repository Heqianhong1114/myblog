【CTFHub】ICMP Data 流量分析 Writeup

操作者：何芊宏 | 操作日期：2026.10.21 | 分类：CTF | 标签：CTFHub, 流量分析, Wireshark, ICMP, Python, tshark

1. 题目信息

  • 平台：CTFHub
  • 分类：流量分析 - 协议流量分析 - ICMP
  • 题目名称：Data
  • 题目提示：ping 也可以携带数据？
  • 附件：包含一个约 8KB 的 icmp_data.pcap 文件

2. 工具准备与环境配置

  • tshark：Wireshark 的命令行版本。在安装了 Wireshark 的 Windows 环境下，其可执行文件通常位于 C:\Program Files\Wireshark\tshark.exe 或自定义安装目录（如 D:\wireshark\tshark.exe）。该工具主要用于处理大规模流量包或需要提取特定字段到本地文件时，通过终端命令快速过滤并输出纯文本数据，避免图形界面的卡顿。
  • Python 环境：用于编写自动化解析脚本。由于设备安全策略限制，执行 pip 命令时需采用 py -m pip install <库名> 以绕过策略拦截。
  • VS Code：作为代码编辑器，需配置 Python 插件以支持调试与运行。

3. 解题思路

题目提示 ICMP（ping 命令底层协议）可以携带数据，这指向了 ICMP 隐蔽隧道（ICMP Tunnel）技术。标准的 ping 包通常只包含固定长度的填充字节（通常用于对齐），但在隐蔽隧道中，攻击者会将敏感数据切割并隐藏在 ICMP 包的 Data 字段中，甚至为了掩盖痕迹，会填充大量无意义的垃圾字符。解题核心在于从大量的干扰数据中，利用脚本精准截取有效载荷并重组。

4. 操作步骤

第一步：分析流量特征

使用 Wireshark 打开附件，应用显示过滤器 icmp。观察数据包列表，发现所有数据包长度均为 106 字节，且 Info 列中的 seq（序列号）呈异常递增规律（如 seq=256/1, seq=512/2），这是使用脚本发包的特征。

点击任意包，展开 Internet Control Message Protocol -> Data，发现大部分数据为 4d，对应的 ASCII 字符为 M，属于无意义的填充数据。通过查看底部的十六进制面板，发现每一行真实的数据变化只出现在特定字节位置。

第二步：使用 tshark 提取原始数据

由于人工提取数百个包中的特定字节极其繁琐，打开 CMD 终端，调用 tshark 提取所有 ICMP 请求包（type == 8）的底层十六进制数据：

"D:\wireshark\tshark.exe" -r "C:\Users\heqianhong\Desktop\...\icmp_data.pcap" -Y "icmp.type == 8" -T fields -e data.data > data.txt

该命令将提取结果以十六进制字符串的形式保存到本地的 data.txt 文件中。

第三步：编写 Python 脚本进行清洗与重组

通过分析 data.txt 中的数据特征，发现每行字符串中，前 16 个字符为头部信息（时间戳/序列号等），第 17-18 个字符（索引 [16:18]）为真实载荷（Flag 的字符），其后全部为 4d（填充字符）。编写 Python 脚本提取有效字节：

import os

# 获取脚本当前所在绝对路径，避免相对路径导致的找不到文件报错
current_dir = os.path.dirname(os.path.abspath(__file__))
file_path = os.path.join(current_dir, 'data.txt')

flag = ""

# 读取文件中的十六进制数据
with open(file_path, 'r') as f:
    lines = f.readlines()

# 遍历每一行数据进行处理
for line in lines:
    line = line.strip()
    # 确保当前行长度足够，防止越界报错
    if len(line) >= 18:
        # 截取第 17-18 个字符（真实载荷）
        payload_hex = line[16:18]
        try:
            # 将十六进制转为字节，再解码为字符
            char = bytes.fromhex(payload_hex).decode('utf-8', errors='ignore')
            flag += char
        except:
            pass

print("[*] 提取到的完整内容：")
print(flag)

第四步：执行脚本获取 Flag

在 VS Code 的终端中运行脚本 py solve_icmp.py，成功打印出完整的 Flag：ctfhub{xxxxxxxxxxxxx}。

5. 踩坑记录与复盘

  • Wireshark 过滤与搜索局限：Wireshark 的 Ctrl + F 在“分组列表”模式下只能搜索摘要信息，无法深入到底层数据。对于二进制或特定偏移量的载荷提取，必须结合命令行工具（tshark）导出数据。
  • Python 相对路径陷阱：在执行 open('data.txt', 'r') 时，程序默认在终端当前所在的目录（如 D:\Open Browser...）寻找文件，而非脚本所在的目录，从而触发 FileNotFoundError。标准做法是使用 os.path.dirname(os.path.abspath(__file__)) 获取脚本绝对路径，再通过 os.path.join() 拼接文件路径，确保脚本在任何工作目录下均能正确运行。
  • 字符串未闭合异常：直接将几万行的超长十六进制数据复制粘贴到 Python 变量中，极易引发 SyntaxError: unterminated string literal。处理海量数据时，应采用文件读写的方式（I/O），避免直接硬编码在代码中。

6. 知识总结

  • ICMP 隐蔽信道：ICMP 协议虽然是用于网络诊断，但其 Data 字段对内容没有严格校验，攻击者常利用其封装 TCP/UDP 甚至 HTTP 流量，以绕过防火墙的端口限制。在流量分析中，若发现 ICMP 包大小异常、携带大量重复字符，应立刻怀疑为隐蔽隧道并提取载荷。
  • 十六进制解码与字符偏移：在网络流量中，数据常以十六进制传输。使用 Python 的 bytes.fromhex() 可将十六进制字符串转换回字节流。在提取特定的载荷时，必须根据协议头部长度或发包脚本的特征，精准计算偏移量（如本题的 [16:18]）。
