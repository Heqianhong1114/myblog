【CTFHub】Web-Git泄露(Stash) Writeup

操作者：何芊宏 | 操作日期：2026.9.20 | 分类：CTF | 标签：CTFHub, Web, 信息泄露, Git, Python

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - 信息泄露 / Git泄露
  • 题目名称：Stash
  • 提示：开发人员可能把未完成或未提交的代码放进了 Git 的暂存区（Stash），并连同 .git 目录一起部署到了线上。

2. 解题思路

题目名为“Stash”，这在 Git 中代表“暂存”或“储藏”。开发人员写了一半不想提交，就会把代码塞进 Stash 里。这题的思路依然是抓取完整的 .git 文件夹，然后使用 git stash 相关的命令，把藏起来的代码掏出来。

3. 操作步骤

第一步：环境准备与工具确认

重启电脑后，我打开了 VS Code。因为之前已经把 Git、Python 和 githacker 安装好了，所以不需要重新配置环境，直接进入工作目录 D:\githack\GitHack-master\GitHack-master> 准备开打。

第二步：提取完整 .git 仓库

开启 CTFHub 新环境，拿到目标 URL：http://challenge-53864692085c83e6.sandbox.ctfhub.com:10800。因为上一题 GitHack 丢失历史记录的教训，这次我直接使用更强大的 githacker 工具，并专门指定了一个新文件夹输出：

githacker --url http://challenge-53864692085c83e6.sandbox.ctfhub.com:10800/.git/ --output ./source_code_stash

工具成功跑完，在左侧生成了 source_code_stash 文件夹。

第三步：寻找被藏起来的记录（踩坑与转折）

在源码文件夹里右键“在集成终端中打开”，敲下查看暂存区的命令：

git stash list

终端立刻弹出了提示：stash@{0}: WIP on master: fe38bb9 add flag。非常走运，出题人留下了名为“add flag”的暂存备注。

紧接着，我使用命令把暂存区的东西拿出来合并：

git stash pop

【核心踩坑】执行完命令后，终端刷刷刷地输出了一大段红色的英文，我看到 Changes not staged for commit: modified: 50x.html, index.html 的时候，第一反应是“完了，合并冲突报错了！”。但仔细一看，并没有 Error 字眼。原来这是 Git 在说：“嘿，我从抽屉里把东西拿出来了，把这两个文件给改动了哦。”这不是报错，而是操作成功的提示！

第四步：获取 Flag（成功）

在合并暂存区内容的瞬间，左侧资源管理器里凭空多出了一个名为 27966530128400.txt 的随机文件（这类随机数字命名的文件往往是隐藏的线索）。双击打开，里面赫然写着：

ctfhub{0739ed964beec6c40e41cfa8}

复制并提交，成功拿下！

4. 踩坑记录与复盘

  • 把“提示”当成“报错”：在使用 git stash pop 时，终端经常会出现 Changes not staged for commit 或 no changes added to commit 的字眼。新手很容易被密密麻麻的英文吓到，其实这只是 Git 的日常事务提醒，意味着操作成功了。
  • Log 与 Stash 的区别：通过这两道题，我彻底理清了两个概念。Log 题的 Flag 曾被提交，后来又删了，所以要用 git reset --hard HEAD^ 回到过去找；而 Stash 题的 Flag 根本没提交，只是被“藏”在了草稿箱，用 git stash pop 直接拿出来即可。

5. 知识总结

  • Git Stash 漏洞原理：开发人员将未提交的代码存入暂存区（Stash）后，如果直接把带有 .git 目录的代码部署到了线上，攻击者就可以通过下载源码，查看暂存区记录，发现被故意隐藏的敏感数据。
  • 核心命令：
    • git stash list：列出所有暂存的记录，帮助我们判断有没有“宝贝”被藏起来。
    • git stash pop：恢复最近的一次暂存（默认 stash@{0}），并且将暂存记录从列表中删除。
