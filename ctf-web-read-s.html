【CTFHub】Web-RCE 读取源代码 Writeup

操作者：何芊宏 | 操作日期：2026.9.26 | 分类：CTF | 标签：CTFHub, Web, RCE, 文件包含, php://filter, 源码泄露, Base64识别

1. 题目信息

  • 平台：CTFHub
  • 分类：Web - RCE / 读取源代码
  • 题目名称：读取源代码
  • 环境：VS Code + 浏览器地址栏 + 在线解码工具。
  • 目标：利用 php://filter 伪协议，读取目标服务器上 /flag 文件的源代码，而非执行它。

2. 解题思路与知识点

本关核心考点：利用 php://filter 伪协议实现任意文件源码读取。

知识点（比喻说明）：
  • 为什么需要 php://filter？ 当文件包含漏洞的 include 函数执行 flag.php 时，它会直接执行 PHP 代码，而不是把源码展示给我们看。这就像是一个装着机密文件的“碎纸机”，你按下开关，它只吐纸屑（执行结果），不给你看原文。我们需要一台“复印机”，在不启动碎纸机的情况下把它的结构复印出来。
  • php://filter 的作用： 它是一个“过滤器”。通过 convert.base64-encode 编码过滤器，可以让服务器在读取文件时，先将其转换为 Base64 字符串，从而避免被 PHP 解析器执行。我们拿到 Base64 字符串后，在自己的电脑上解码，就能看到原始源码。

3. 详细步骤

第一步：源码审计与路径获取

操作： 访问靶场 URL，直接查看页面回显的 PHP 源码。

<?php
error_reporting(E_ALL);
if (isset($_GET['file'])) {
    if ( substr($_GET["file"], 0, 6) === "php://" ) {
        include($_GET["file"]);
    } else {
        echo "Hacker!!!";
    }
} else {
    highlight_file(__FILE__);
}
?>
<hr>
i don't have shell, how to get flag? <br>
flag in <code>/flag</code>

代码逐行解析：

  • substr($_GET["file"], 0, 6) === "php://"：强制要求 file 参数必须以 php:// 开头。
  • flag in <code>/flag</code>：提示明确告诉了我们目标文件的绝对路径为 /flag。

获得信息：存在文件包含漏洞，且已知目标文件路径，但需要防止代码被执行，需要使用 php://filter。

第二步：构造并输入 Payload 读取源码

Payload： ?file=php://filter/read=convert.base64-encode/resource=/flag

为什么要输入：

  • php://filter：告诉服务器我们要进行流过滤。
  • read=convert.base64-encode：指定在读取时使用 Base64 编码。
  • resource=/flag：指定我们要读取的目标文件。

回显结果：页面顶部成功回显一长串 Base64 字符串 Y3RmaHVieVzZjMzZhZmNkMTU5MTFlMzUzMDIyNTljNX0K。

获得信息：源码已成功编码输出，当前处于数据流状态。

第三步：使用在线工具解码并提交 Flag

操作： 将 Base64 字符串复制到在线工具 https://base64.us 中进行解码。

为什么用这个工具： 界面简洁，支持一键解码，且提供快捷键 `Ctrl + Enter`。对于 CTF 新手和日常快速验证非常方便。

解码结果：ctfhub{6c36afcd15911e35302259c5}

获得信息：成功获取 Flag，提交通关。

4. 课外拓展：如何快速识别 Base64 编码

在实战中，服务器不会告诉你“这是 Base64”。当你看到一段“奇怪的乱码”时，需要通过以下特征来判断它是否是需要解码的 Base64 字符串。
  • 特征1：字符集组成。只包含大小写英文字母（A-Z, a-z）、数字（0-9）、加号（+）、斜杠（/）。如果字符串里有空格、换行、中文标点，大概率不是 Base64。
  • 特征2：结尾等号。这是 Base64 最经典的“尾巴”。因为 Base64 算法把 3 个字节编码为 4 个字符，如果原文长度不是 3 的倍数，就会用 `=` 或 `==` 来补齐。（例如本次结果末尾就是 `==`）。
  • 特征3：长度规律。Base64 编码后的字符串长度通常是 4 的倍数（除去末尾的换行）。如果你拿到一串字符，长度正好是 4 的倍数，且没有标点符号，就很值得怀疑。
  • 特征4：视觉直觉与对比。
    • MD5 是 32 位纯数字和 a-f 的组合。
    • Hex 编码是 `%` 开头的 URL 编码。
    • Base64 则是大小写混合、包含 `+` `/` 和 `=`，看起来像一堆无意义的字母数字。

本次我们看到的 Y3RmaHVieVzZjMzZhZmNkMTU5MTFlMzUzMDIyNTljNX0K，大小写字母与数字交织，结尾没有 `=`，但长度正好是 4 的倍数（44 位），且明显不像正常的英文单词或代码，这就是典型的 Base64。

5. 踩坑记录与复盘

  • 直接包含 /flag 无回显（逻辑推导，非踩坑）： 初始想法可能会想直接输入 ?file=/flag，但这会被 PHP 解析器直接执行，输出可能是一片空白或者报错。这正是需要用到 php://filter 的根本原因。所以在遇到文件包含时，如果目标是“看源码”，思维要立刻切换到 filter 伪协议。
  • URL 路径与相对路径： 提示中已经写明了绝对路径 /flag，不需要去猜相对路径（如 ./flag），读取伪协议时最好以绝对路径为准。

6. 知识总结与横向对比

核心心得（对比 php://input）：
我们在上一关掌握了 php://input 用于执行代码，这一关掌握了 php://filter 用于读取源码。两者都是文件包含漏洞下的“伪协议双子星”，但用途完全不同，需要根据题目目的灵活切换。
对比维度 php://input php://filter
核心用途 执行代码（RCE），获取服务器控制权 读取文件源码，用于代码审计或直接获取 Flag
数据流向 输入流（Client -> Server 执行） 输出流（Server -> Client 读取）
请求方式 强制要求 POST 请求，Body 中传递 PHP 代码 GET 请求即可，直接在 URL 中传递 payload
结果处理 直接回显命令执行结果 回显 Base64 字符串，需要本地自行解码
应用场景 需要调用 system 等命令函数执行时 需要查看文件源代码，但文件被 PHP 引擎解析时
总结：
  • 看到 include($file) 且目标是执行命令：想想 php://input。
  • 看到 include($file) 且目标是查看源码：秒上 php://filter。
