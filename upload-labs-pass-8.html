【Upload-Labs】Pass-08 尾随点绕过 Writeup

操作者：何芊宏 | 操作日期：2026.11.02 | 分类：CTF | 标签：Upload-Labs, Web, 文件上传, 尾随点绕过, WebShell

1. 题目信息

  • 平台：Upload-Labs (本地 phpStudy 环境)
  • 分类：Web - 文件上传
  • 题目名称：Pass-08 (服务端黑名单校验 - 尾随点绕过)
  • 提示：任务为上传一个 webshell 到服务器。黑名单过滤了常见的脚本后缀，且尝试了 Pass-07 的尾随空格策略。

2. 核心原理与前置分析

本关卡的核心漏洞在于Windows 操作系统底层特性与后端代码校验逻辑之间的差异。

在 Windows 环境中，文件名是不允许以点（.）结尾的（这是为了兼容早期的 DOS 系统）。当文件保存时，Windows API 会在底层自动剥离末尾的点。后端代码虽然使用了 trim() 函数去除了首尾空格（防御了 Pass-07），但未使用 deldot() 函数去除末尾的点。

当我们上传文件名为 shell.php. 的文件时，提取到的后缀带有尾随点，不在黑名单内，从而绕过校验。文件落地到 Windows 系统后，尾随点被自动去除，恢复成合法的 shell.php。此外，本关依然存在服务端重命名逻辑，需要通过前端信息收集获取真实路径。

3. 工具配置与操作步骤

工具配置：Burp Suite、浏览器开发者工具 与 中国蚁剑

  • 中国蚁剑：URL 地址指向真实触发路径；连接密码：cmd；编码：UTF-8。

操作步骤与解析：

第一步：抓包并在文件名追加尾随点

开启 Burp Suite 拦截模式。在网页上传本地的 shell.php。在拦截到的 HTTP 请求包中，找到 Content-Disposition 字段，将文件名修改为：

filename="shell.php."

（注意：在 php 与 " 之间增加一个英文句号）。点击 Forward 放行。

第二步：前端信息收集查找真实路径

由于服务端存在 date("YmdHis").rand(1000,9999) 的重命名逻辑，直接访问 shell.php 可能会报错。在浏览器当前页面按下 F12 打开开发者工具，使用 Ctrl+F 搜索关键词 /upload。

在 Elements 面板中，可以精准定位到类似 <img src="../upload/shell.php."> 的代码（由于某种原因，本次环境并未加上随机数，而是保留了原名和尾随点）。

第三步：访问与连接

在浏览器中访问 http://127.0.0.1:8081/upload/shell.php（注意：此时 URL 里不需要带那个点，因为 Windows 底层已自动剥离）。页面呈现纯白状态，说明解析成功。

打开蚁剑，URL 填入该路径，密码填入 cmd，测试连接成功，获取服务器权限。

第四步：清理现场

在蚁剑中删除生成的 shell.php 文件，保持 upload 目录干净，避免影响后续关卡。

4. 踩坑记录与复盘

  • F12 搜索定位法的关键作用：在无法预知服务端是否开启随机重命名时，F12 搜索 /upload 是最快捷的信息收集手段。本次通过 F12 确认了路径为 shell.php.，从而明确了访问时应去掉尾随点。
  • 环境特性认知：Pass-07 的“尾随空格”在本机环境可能无法通过 URL 直接访问，但 Pass-08 的“尾随点”在文件落地时被 Windows 完美剔除。这提示我们在实战中需要根据目标服务器的操作系统类型（Windows/Linux）灵活选择尾随字符。

5. 知识点总结

  • 尾随点绕过（Windows 特性）：利用 Windows 系统在保存文件时自动去除末尾点号的特性，配合后端代码未做严格清理的缺陷，实现黑名单绕过。
  • 重命名环境下的信息收集：在文件被重命名的场景下，熟练使用浏览器 F12 和 Burp Response 定位真实回显路径，是实战中建立 WebShell 连接的关键环节。
